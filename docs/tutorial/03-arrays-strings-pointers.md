# Глава 3. Массивы, строки, указатели и память

Один `int` хранит одно число. Но алгоритмы работают с **наборами**:
отсортировать список оценок, найти слово в тексте, разложить колоду
карт. Для этого нужны три кита, на которых стоит весь Си: **массивы**
(много значений подряд), **строки** (текст) и **указатели** (адреса в
памяти). Четвёртая тема — **динамическая память**: как попросить у
системы место, когда заранее неизвестно, сколько его надо.

Глава большая, и это не случайно. Именно здесь Си показывает своё
настоящее лицо: он даёт тебе прямой доступ к памяти и **не проверяет
ни одного твоего движения**. Ошибся с индексом — программа не
остановится, она молча испортит соседние данные. Поэтому мы будем не
только писать правильный код, но и **специально ломать** программы, а
потом смотреть, что говорят компилятор, операционная система и
специальные инструменты-«ловцы ошибок».

## Что мы сделаем

К концу главы у тебя будет четыре рабочие программы:

- `code/03-arrays.c` — массив оценок: индексация, перебор, сумма,
  среднее, передача массива в функцию;
- `code/03-strings.c` — строки: длина, копирование, сравнение, чтение
  строки с клавиатуры;
- `code/03-pointers.c` — адреса, разыменование и функция `swap`,
  которая по-настоящему меняет местами две переменные;
- `code/03-dynamic.c` — `malloc`, `free` и `realloc`.

И, что не менее важно, у тебя будет привычка **проверять память
инструментами**, а не надеждой.

## Часть 1. Массив — много коробок в ряд

### Разбираем задачу руками

Представь пять оценок: 4, 5, 3, 5, 2. Пока их пять, можно завести
пять переменных: `m1`, `m2`, `m3`, `m4`, `m5`. Но посчитать их сумму
циклом уже нельзя — у цикла нет способа сказать «возьми переменную с
номером `i`». А если оценок сто? Двести имён?

Нужна другая идея: положить все пять чисел **в ряд**, дать ряду одно
имя и обращаться к элементам **по номеру**. Так на полке стоят пять
одинаковых коробок:

```text
имя: marks
        +----+----+----+----+----+
        |  4 |  5 |  3 |  5 |  2 |
        +----+----+----+----+----+
индекс:    0    1    2    3    4
```

Обрати внимание на нижнюю строчку. Нумерация начинается **с нуля**.
Это не прихоть: индекс в Си означает не «который по счёту», а **«на
сколько шагов отступить от начала»**. Первый элемент лежит в самом
начале — отступать не надо, значит 0. Третий — через два шага, значит
2. Такое соглашение позже окупится: когда мы дойдём до указателей,
станет видно, что `marks[i]` буквально означает «взять адрес начала,
прибавить `i` элементов, посмотреть, что там».

### Первая программа с массивом

```c
#include <stdio.h>

int main(void)
{
    int marks[5] = {4, 5, 3, 5, 2};
    printf("Первая оценка: %d\n", marks[0]);
    printf("Третья оценка: %d\n", marks[2]);
    return 0;
}
```

Разбор по частям:

- `int marks[5]` — объявляем массив из **5** целых чисел. `int` —
  тип каждого элемента, `marks` — имя, `5` в квадратных скобках —
  **размер**, сколько элементов. Размер фиксированный: массив на 5 не
  станет массивом на 6.
- `= {4, 5, 3, 5, 2}` — сразу заполняем пятью значениями. Фигурные
  скобки со списком через запятую — это **инициализатор** массива.
  Работает он только при объявлении: написать `marks = {1, 2}` позже
  уже нельзя.
- `marks[0]` — обращение к элементу по индексу. Квадратные скобки
  здесь читаются как «элемент номер».

Собираем и запускаем:

```text
cc -std=c11 -Wall -Wextra -O2 arrays.c -o arrays
./arrays
```

```text
Первая оценка: 4
Третья оценка: 3
```

«Третья оценка» — это `marks[2]`, и напечаталось `3` — третье число
из списка. Если бы мы написали `marks[3]`, получили бы `5`, четвёртый
элемент. Привыкай сразу: последний элемент массива из пяти — это
`marks[4]`, а не `marks[5]`.

### Перебор циклом: сумма и среднее

Массив и цикл `for` (см. главу 2) созданы друг для друга:

```c
int marks[5] = {4, 5, 3, 5, 2};
int sum = 0;
for (int i = 0; i < 5; i++) {
    sum = sum + marks[i];
}
printf("сумма: %d\n", sum);

double avg = sum / 5;
printf("среднее (без приведения): %.2f\n", avg);
printf("среднее (с приведением):  %.2f\n", (double)sum / 5);
```

Переменная `i` пробегает 0, 1, 2, 3, 4 — ровно все индексы. Условие
`i < 5`, а не `i <= 5`: пятого индекса не существует, к нему мы
вернёмся через минуту.

Запускаем:

```text
сумма: 19
среднее (без приведения): 3.00
среднее (с приведением):  3.80
```

Проверь руками: 4 + 5 + 3 + 5 + 2 = 19, делим на 5 — получается 3.8.
Значит, вторая строка вывода врёт, и вот почему.

Обе части выражения `sum / 5` — целые числа. Значит, и деление идёт
**целочисленное**: 19 / 5 = 3, дробная часть выбрасывается **до**
того, как результат попадёт в `double avg`. Тип переменной слева ни
на что не влияет: сначала вычисляется правая часть, по своим
правилам, потом уже результат кладут в переменную.

`(double)sum` — это **приведение типа** (cast). Запись
`(тип)значение` означает «возьми это значение и посчитай его вот
таким типом». Как только одна часть деления стала дробной, вторая
подтягивается автоматически — и `19.0 / 5` даёт честные 3.8. Ошибка
тихая и оттого противная: `3.00` выглядит правдоподобно, и никакого
предупреждения при сборке не будет.

### Выход за границу массива — покажем на живом примере

Теперь специально ошибёмся. Напишем `i <= 5` вместо `i < 5` — самая
частая опечатка новичка. Файл `oob.c` (*out of bounds* — «за
границами»):

```c
#include <stdio.h>

int main(void)
{
    int marks[5] = {4, 5, 3, 5, 2};
    int sum = 0;
    for (int i = 0; i <= 5; i++) {
        printf("marks[%d] = %d\n", i, marks[i]);
        sum = sum + marks[i];
    }
    printf("Сумма: %d\n", sum);
    return 0;
}
```

Собираем как обычно — и первое открытие:

```text
cc -std=c11 -Wall -Wextra -O2 oob.c -o oob
```

Ни одного предупреждения. Компилятор промолчал. Запускаем:

```text
marks[0] = 4
marks[1] = 5
marks[2] = 3
marks[3] = 5
marks[4] = 2
marks[5] = 1165742696
Сумма: 73896
```

Программа не упала. Она просто прочитала **чужой кусок памяти** —
то, что лежало сразу за массивом, — и посчитала его шестой оценкой.
Число `1165742696` у тебя будет другим: там мог оказаться остаток
какой-то служебной переменной, кусок адреса, что угодно. Сумма,
разумеется, тоже испорчена.

Вот главное, что нужно вынести из этого запуска: **Си не проверяет
границы массивов**. Не «иногда не проверяет» — вообще не проверяет.
Проверка стоила бы времени на каждом обращении, а Си выбирает
скорость. Следить за индексами — твоя работа.

Иногда компилятор всё-таки помогает. Если индекс — не переменная, а
записанное прямо в коде число, clang видит ошибку (сообщения
компилятора и санитайзеров бывают длиннее книжной строки, поэтому мы
их переносим; содержимое при этом не меняется):

```c
int marks[5] = {4, 5, 3, 5, 2};
printf("%d\n", marks[5]);
```

```text
oob2.c:5:20: warning: array index 5 is past the end of the array
(that has type 'int[5]') [-Warray-bounds]
    5 |     printf("%d\n", marks[5]);
      |                    ^     ~
oob2.c:4:5: note: array 'marks' declared here
    4 |     int marks[5] = {4, 5, 3, 5, 2};
      |     ^
1 warning generated.
```

Но стоит индексу стать переменной цикла — и компилятор бессилен: во
время компиляции он не знает, какие значения примет `i`.

### Санитайзер — тот, кто ловит такое за руку

Есть инструмент, который всё-таки проверяет каждое обращение к
памяти — **санитайзер адресов** (AddressSanitizer, коротко ASan).
Компилятор по флагу встраивает в программу проверки: перед каждым
чтением и записью смотрит, законен ли адрес. Программа становится
медленнее в несколько раз — зато ошибка находится мгновенно и точно.

Собираем ту же `oob.c` с санитайзером. Флаг `-g` добавляет в
программу отладочную информацию, чтобы в отчёте были номера строк, а
`-O2` при отладке лучше не включать:

```text
cc -std=c11 -Wall -Wextra -g -fsanitize=address oob.c -o oob_asan
./oob_asan
```

Программа печатает первые пять строк как раньше, а потом умирает вот
таким отчётом. Отчёт длинный, приводим его начало — до итоговой
строки `SUMMARY`; дальше идёт ещё карта служебной памяти, которая нам
сейчас ни к чему:

```text
=================================================================
==69592==ERROR: AddressSanitizer: stack-buffer-overflow on address
0x7ff7be25f814 at pc 0x000101c9f91f bp 0x7ff7be25f7d0 sp
0x7ff7be25f7c8
READ of size 4 at 0x7ff7be25f814 thread T0
    #0 0x000101c9f91e in main oob.c:8
    #1 0x7ff804aa4b27 in start+0xca7 (dyld:x86_64+0x12b27)

Address 0x7ff7be25f814 is located in stack of thread T0 at offset 52
in frame
    #0 0x000101c9f7df in main oob.c:4

  This frame has 1 object(s):
    [32, 52) 'marks' (line 5) <== Memory access at offset 52
overflows this variable
HINT: this may be a false positive if your program uses some custom
stack unwind mechanism, swapcontext or vfork
      (longjmp and C++ exceptions *are* supported)
SUMMARY: AddressSanitizer: stack-buffer-overflow oob.c:8 in main
```

Читаем отчёт как текст — он написан по-человечески, просто
по-английски:

- `stack-buffer-overflow` — «выход за границу буфера на стеке».
  **Стек** — область памяти, где живут локальные переменные функции;
  наш `marks` лежит именно там. `READ of size 4` — читали 4 байта,
  то есть `int`.
- `#0 ... in main oob.c:8` — **точное место**: файл `oob.c`, строка
  8. Это наш `printf` с `marks[i]`.
- `This frame has 1 object(s): [32, 52) 'marks' (line 5)` — в кадре
  один объект, массив `marks` со строки 5, и занимает он байты с
  32-го по 52-й (20 байт — пять `int`ов). А обращение было по
  смещению 52 — ровно на один шаг дальше конца.
- `HINT` — оговорка про экзотические случаи, когда санитайзер может
  ошибиться; к нам не относится. `SUMMARY` — та же суть одной
  строкой.

Первое, что делаешь с любым отчётом санитайзера: ищешь строки с
**именем своего файла**. Всё остальное — адреса, номера потоков,
внутренности библиотек — можно пока не разглядывать. Числа в отчёте
у тебя будут другими и поменяются при каждом запуске.

### `sizeof` — откуда взять длину массива

Писать `5` в трёх местах программы плохо: поменяешь массив — забудешь
поменять цикл. Длину можно вычислить. Оператор `sizeof` возвращает
**размер в байтах**:

```c
int marks[5] = {4, 5, 3, 5, 2};
printf("sizeof marks    = %zu байт\n", sizeof marks);
printf("sizeof marks[0] = %zu байт\n", sizeof marks[0]);
printf("элементов       = %zu\n", sizeof marks / sizeof marks[0]);
```

```text
sizeof marks    = 20 байт
sizeof marks[0] = 4 байт
элементов       = 5
```

Весь массив — 20 байт, один элемент — 4 байта, делим одно на другое,
получаем 5. Пояснения:

- `sizeof` — это **оператор**, а не функция, поэтому скобки не
  обязательны: `sizeof marks` и `sizeof(marks)` одинаковы. Для типа
  скобки нужны: `sizeof(int)`.
- `%zu` — спецификатор для типа `size_t`, который возвращает
  `sizeof`. `size_t` — беззнаковый целый тип «размер чего-то в
  байтах». Печатать его через `%d` формально неверно, и компилятор
  поворчит.
- Приём `sizeof массив / sizeof массив[0]` работает **только там, где
  массив объявлен**. Почему — прямо сейчас и увидим.

### Массив «распадается» в указатель

Передадим массив в функцию и попробуем посчитать длину внутри неё.
Файл `decay.c`:

```c
#include <stdio.h>

void print_all(int a[])
{
    int n = sizeof a / sizeof a[0];
    printf("внутри функции: sizeof a = %zu, n = %d\n", sizeof a, n);
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
}

int main(void)
{
    int marks[5] = {4, 5, 3, 5, 2};
    printf("в main: sizeof marks = %zu\n", sizeof marks);
    printf("в main: элементов    = %zu\n",
           sizeof marks / sizeof marks[0]);
    print_all(marks);
    return 0;
}
```

Компилятор сразу поднимает крик — и крик по делу. Всего он выдал три
предупреждения (по одному на каждое `sizeof` от параметра); вот
первое:

```text
decay.c:5:20: warning: sizeof on array function parameter will return
size of 'int *' instead of 'int[]' [-Wsizeof-array-argument]
    5 |     int n = sizeof a / sizeof a[0];
      |                    ^
```

«`sizeof` от параметра-массива вернёт размер `int *`, а не `int[]`».
Запускаем и смотрим, чем это оборачивается:

```text
в main: sizeof marks = 20
в main: элементов    = 5
внутри функции: sizeof a = 8, n = 2
4 5
```

Внутри функции `sizeof a` дал **8**, а не 20. И напечаталось два
элемента вместо пяти.

Вот что произошло. В Си массив **нельзя** передать в функцию
целиком. При передаче имя массива превращается в **адрес его первого
элемента** — это называется «распад массива в указатель» (*array
decay*). Функция получает не 20 байт данных, а один адрес. Адрес на
64-битной машине занимает 8 байт — отсюда и `sizeof a = 8`. Дальше
арифметика честно считает 8 / 4 = 2, и цикл проходит по двум
элементам.

Запись `int a[]` в списке параметров — обман зрения: компилятор
молча переписывает её в `int *a`. Пустые квадратные скобки там
разрешены только ради читаемости, размер в них (даже `int a[5]`)
игнорируется.

Отсюда правило, которое ты увидишь в каждой сишной библиотеке:
**длину массива передают отдельным аргументом**.

```c
int sum(const int a[], int n)
{
    int s = 0;
    for (int i = 0; i < n; i++) {
        s = s + a[i];
    }
    return s;
}
```

- `int n` — длина, которую вызывающий обязан сообщить. Никакого
  способа узнать её изнутри у функции нет.
- `const` перед типом — обещание «эта функция не будет менять
  содержимое массива». Компилятор проследит: попытка написать
  `a[0] = 7` внутри станет ошибкой. Читателю кода тоже полезно: сразу
  видно, что массив только читают.
- А раз функция получила адрес, а не копию, то без `const` она **и
  правда могла бы** менять исходный массив. Этим мы будем
  пользоваться постоянно в сортировках (глава 8).

### Заполняем массив вводом

Пока динамической памяти у нас нет, массив объявляют «с запасом», а
используют столько, сколько попросят:

```c
int a[100];
int n;

printf("Сколько чисел? ");
if (scanf("%d", &n) != 1 || n <= 0 || n > 100) {
    printf("Нужно число от 1 до 100\n");
    return 1;
}
for (int i = 0; i < n; i++) {
    printf("a[%d] = ", i);
    if (scanf("%d", &a[i]) != 1) {
        printf("Не число\n");
        return 1;
    }
}
```

- `int a[100];` — без инициализатора. Значения в таком массиве
  **мусорные**, пока ты сам туда что-нибудь не запишешь.
- `&a[i]` — адрес конкретного элемента, куда `scanf` запишет число.
  Знак `&` тут ровно тот же, что и в `scanf("%d", &n)`.
- Проверка `n > 100` — не формальность. Без неё пользователь введёт
  1000, и цикл вылезет далеко за массив, со всеми последствиями из
  предыдущего раздела.
- `scanf` возвращает число успешно прочитанных значений, поэтому
  `!= 1` ловит и буквы вместо цифр, и конец ввода.

Запуск (числа подаём через конвейер, `printf '3\n10\n20\n30\n' |
./fill`):

```text
Сколько чисел? a[0] = a[1] = a[2] = ввёл: 10 20 30
```

Приглашения слиплись в одну строку — так бывает, когда ввод идёт из
конвейера, а не с клавиатуры: `printf` не переводит строку, а
пользовательских нажатий Enter тут нет. Запусти руками, и диалог
будет нормальный.

### Полная программа `code/03-arrays.c`

```c
#include <stdio.h>

/* Длину массива передаём отдельным аргументом: внутри функции
   имя массива превращается в указатель, и sizeof тут не поможет. */
int sum(const int a[], int n)
{
    int s = 0;
    for (int i = 0; i < n; i++) {
        s = s + a[i];
    }
    return s;
}

int main(void)
{
    int marks[5] = {4, 5, 3, 5, 2};
    int n = (int)(sizeof marks / sizeof marks[0]);

    printf("marks[0] (первая)    = %d\n", marks[0]);
    printf("marks[2] (третья)    = %d\n", marks[2]);
    printf("marks[%d] (последняя) = %d\n", n - 1, marks[n - 1]);

    printf("весь массив:");
    for (int i = 0; i < n; i++) {
        printf(" %d", marks[i]);
    }
    printf("\n");

    printf("sizeof marks    = %zu байт\n", sizeof marks);
    printf("sizeof marks[0] = %zu байт\n", sizeof marks[0]);
    printf("элементов       = %d\n", n);

    int s = sum(marks, n);
    printf("сумма   = %d\n", s);
    printf("среднее = %.2f\n", (double)s / n);
    return 0;
}
```

`(int)(sizeof ... / sizeof ...)` — приведение результата к `int`,
чтобы дальше спокойно печатать его через `%d` и вычитать единицу.

```text
cc -std=c11 -Wall -Wextra -O2 code/03-arrays.c -o arrays
./arrays
```

```text
marks[0] (первая)    = 4
marks[2] (третья)    = 3
marks[4] (последняя) = 2
весь массив: 4 5 3 5 2
sizeof marks    = 20 байт
sizeof marks[0] = 4 байт
элементов       = 5
сумма   = 19
среднее = 3.80
```

## Часть 2. Строки — это массивы символов

В Си **нет** отдельного типа «строка». Строка — это **массив `char`**
(символов), в конце которого стоит специальный символ-метка `'\0'`
(нулевой символ, код 0). Он говорит: «здесь текст закончился».

```c
char name[] = "Anna";
```

- `char name[]` — массив символов. Размер не указали: компилятор
  посчитает его сам по инициализатору.
- `"Anna"` — компилятор разложит текст по буквам и **сам добавит**
  `'\0'`. В памяти окажется пять байт:

```text
        +-----+-----+-----+-----+------+
        | 'A' | 'n' | 'n' | 'a' | '\0' |
        +-----+-----+-----+-----+------+
индекс:    0     1     2     3     4
```

Печатают строку через `%s` (*string*):

```c
printf("Привет, %s!\n", name);
```

`printf` берёт байты от начала и печатает, **пока не встретит**
`'\0'`. Вот зачем нужен нулевой символ: без него `printf` не знает,
где остановиться.

### Что будет без `'\0'` — проверим

Соберём два массива вручную. Один с меткой конца, второй без. Файл
`noterm.c`:

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
    char good[5] = {'A', 'n', 'n', 'a', '\0'};
    char bad[4]  = {'A', 'n', 'n', 'a'};

    printf("good: [%s]\n", good);
    printf("strlen(good) = %zu\n", strlen(good));
    printf("bad:  [%s]\n", bad);
    printf("strlen(bad)  = %zu\n", strlen(bad));
    return 0;
}
```

Одиночные кавычки — это **символьный литерал**: `'A'` — один символ,
`"A"` — уже строка из двух байт (`'A'` и `'\0'`). А `strlen` из
`<string.h>` считает длину строки: идёт от начала и считает байты,
пока не встретит `'\0'` (подробный разбор — чуть ниже). Запускаем:

```text
good: [Anna]
strlen(good) = 4
bad:  [AnnaAnna]
strlen(bad)  = 8
```

`bad` содержит четыре буквы, а напечаталось восемь. `printf` дошёл до
конца массива `bad`, метки не нашёл и поехал дальше по памяти — а там
случайно лежал `good`. Так и вышло `AnnaAnna`. У тебя может
получиться другой мусор: что окажется за массивом, зависит от того,
как компилятор разложил переменные.

Санитайзер, конечно, такое видит. Собери эту программу с
`-fsanitize=address` — получишь знакомый `stack-buffer-overflow` с
указанием на строку 11 (тот самый `printf` с `bad`) и с пояснением,
что `bad` занимает байты `[64, 68)`, а чтение ушло на 68-й.

Вывод простой: **массив `char` без `'\0'` — это не строка**. Если
собираешь текст руками по символам, метку конца ставишь тоже руками.

### `sizeof` против `strlen`

Два разных числа, которые новички постоянно путают:

```c
char name[] = "Anna";
printf("strlen(name) = %zu\n", strlen(name));
printf("sizeof name  = %zu\n", sizeof name);
printf("байт после последней буквы: код %d\n", name[strlen(name)]);
```

```text
strlen(name) = 4
sizeof name  = 5
байт после последней буквы: код 0
```

- `strlen` считает байты **до** `'\0'`, саму метку не считая — 4.
- `sizeof` даёт размер всего массива в байтах, вместе с меткой — 5.
- `name[strlen(name)]` — тот самый байт с кодом 0. Он реально лежит в
  массиве и место занимает.

Правило: для строки-массива `sizeof` ровно на единицу больше
`strlen`. Для указателя на строку (о них — в части 3) `sizeof` даст
размер адреса, 8, и никакой связи с длиной уже не будет.

### Функции из `<string.h>`

Подключив `#include <string.h>`, получаешь готовые инструменты.
Разберём три главные — с сигнатурами.

**`size_t strlen(const char *s)`** — длина строки. Принимает адрес
начала, возвращает число байт до `'\0'`. Подводный камень: работает
за время, пропорциональное длине — она каждый раз считается заново.
Писать `for (i = 0; i < strlen(s); i++)` — значит пересчитывать длину
на каждом шаге цикла. Лучше посчитать один раз в переменную.

**`char *strcpy(char *dst, const char *src)`** — копирует строку
`src` в массив `dst` вместе с `'\0'`. Возвращает `dst` (этим редко
пользуются). Подводный камень **огромный**: `strcpy` не знает, сколько
места в `dst`, и копирует ровно столько, сколько есть в `src`. Не
влезет — затрёт то, что лежит дальше.

```c
char dst[5];
strcpy(dst, "Konstantin");
printf("dst = %s\n", dst);
```

Здесь система защиты в стандартной библиотеке macOS ловит ошибку ещё
при компиляции — длины-то обе известны:

```text
cpy.c:7:5: warning: 'strcpy' will always overflow; destination buffer
has size 5, but the source string has length 11 (including NUL byte)
[-Wfortify-source]
    7 |     strcpy(dst, "Konstantin");
      |     ^
```

(Дальше компилятор показывает, во что разворачивается `strcpy` в
заголовках macOS — эти строки для нас неинтересны.)

А если всё-таки запустить:

```text
bash: line 1: 64142 Illegal instruction: 4  ./cpy
код возврата: 132
```

Программу расстреляли на месте. Но так везёт только с очевидным
случаем: если длина строки станет известна во время работы (пришла от
пользователя), никакой проверки при компиляции уже не будет, и
переполнение произойдёт тихо. Поэтому размер приёмника проверяй сам.

**`int strcmp(const char *a, const char *b)`** — сравнивает две
строки посимвольно. Возвращает:

- `0`, если строки **равны** (да, именно ноль при равенстве — это
  сбивает с толку);
- отрицательное число, если `a` меньше `b` (идёт раньше по алфавиту);
- положительное, если `a` больше.

Стандарт обещает только **знак** результата, не конкретное число: на
одной машине получишь `-1`, на другой — разницу кодов символов.
Поэтому пишут `strcmp(a, b) < 0`, а не `strcmp(a, b) == -1`.

### Почему `==` не сравнивает строки

Самая живучая ошибка новичка. Заведём два разных массива с
одинаковым текстом (файл `eq.c`):

```c
char a[] = "exit";
char b[] = "exit";

printf("адрес a = %p\n", (void *)a);
printf("адрес b = %p\n", (void *)b);
printf("a == b даёт %d\n", a == b);
printf("strcmp(a, b) даёт %d\n", strcmp(a, b));
printf("strcmp(\"abc\", \"abd\") = %d\n", strcmp("abc", "abd"));
printf("strcmp(\"abd\", \"abc\") = %d\n", strcmp("abd", "abc"));
```

Компилятор сразу подсказывает, что дело нечисто:

```text
eq.c:11:38: warning: array comparison always evaluates to false
[-Wtautological-compare]
   11 |     printf("a == b даёт %d\n", a == b);
      |                                  ^
1 warning generated.
```

Запуск:

```text
адрес a = 0x7ff7b3211900
адрес b = 0x7ff7b3211908
a == b даёт 0
strcmp(a, b) даёт 0
strcmp("abc", "abd") = -1
strcmp("abd", "abc") = 1
```

Тексты одинаковые, а `a == b` дало 0, то есть «не равны». Смотри на
первые две строки: адреса разные, 0x…900 и 0x…908. Имя массива в
выражении — это адрес его начала, значит `a == b` сравнило **два
адреса**, а не два текста. Два разных массива лежат в разных местах —
результат всегда «не равны», независимо от содержимого.

А `strcmp(a, b)` дал 0 — «различий нет», то самое равенство. Две
последние строки показывают знаки: `"abc"` идёт раньше `"abd"`, потому
что на третьем символе `c` меньше `d`, — отсюда минус; поменяли
аргументы местами — знак перевернулся.

Правильно так:

```c
if (strcmp(word, "exit") == 0) {
    printf("Пока!\n");
}
```

Читается как «если различий нет». Многие для наглядности заводят
себе привычку писать `if (strcmp(a, b) == 0)` полностью, а не
`if (!strcmp(a, b))` — второе короче, но новичка путает.

### Чтение строки от пользователя

Для одного слова без пробелов годится `%s` в `scanf`:

```c
char word[64];
scanf("%63s", word);
```

- Перед `word` **нет** `&`! Имя массива само по себе уже адрес его
  начала. Это то самое исключение из правила «в `scanf` всегда `&`».
- `%63s` с числом — ограничиваем ввод 63 символами, чтобы влезть в
  массив из 64 (последний байт под `'\0'`). Без ограничения длинный
  ввод затрёт соседнюю память — классическая уязвимость.

Для **целой строки с пробелами** `scanf("%s")` не годится: он читает
до первого пробела. Берём `fgets`.

**`char *fgets(char *s, int size, FILE *stream)`** — читает строку.
Принимает: куда класть, сколько максимум байт (включая `'\0'`),
откуда читать. Возвращает `s` при успехе и `NULL`, если читать больше
нечего (конец файла) или случилась ошибка. Проверять этот `NULL`
нужно — иначе при пустом вводе будешь работать с мусором.

```c
char line[64];
printf("Введи команду: ");
if (fgets(line, sizeof line, stdin) == NULL) {
    printf("\nВвод закончился\n");
    return 1;
}
printf("как есть:   [%s]\n", line);
printf("длина: %zu\n", strlen(line));
```

- `sizeof line` — размер массива в байтах (64). Так `fgets` не
  вылезет за границу, и при изменении размера массива менять код не
  придётся.
- `stdin` — *standard input*, стандартный ввод (клавиатура).

Подаём слово `exit` и смотрим:

```text
Введи команду: как есть:   [exit
]
длина: 5
```

Квадратная скобка уехала на следующую строку, а длина — 5, хотя букв
четыре. `fgets` **оставляет в строке символ перевода строки** `'\n'`
— тот самый, что появился от нажатия Enter. Это фирменная ловушка:
`strcmp(line, "exit")` вернёт «не равно», потому что в `line` лежит
`"exit\n"`.

Чиним — отрезаем последний символ, если это перевод строки:

```c
size_t len = strlen(line);
if (len > 0 && line[len - 1] == '\n') {
    line[len - 1] = '\0';
}
```

Записав `'\0'` на место `'\n'`, мы сдвинули метку конца строки на
один символ влево. Байты дальше никуда не делись, но для всех
строковых функций строка теперь короче. Проверка `len > 0` защищает
от `line[-1]` на пустой строке.

```text
без '\n':   [exit]
длина: 4
Это команда выхода. Пока!
```

Подробнее строковые алгоритмы разберём в главе 10, там эта обрезка
`'\n'` встретится снова.

### Почему `gets` запрещён

Была в Си функция `gets(s)` — читает строку, и всё. Без размера
буфера. Совсем. Сколько пользователь введёт, столько она и запишет,
хоть мегабайт в массив на 10 байт. Через эту дыру взламывали
программы десятилетиями, и в стандарте C11 функцию **удалили из
языка**.

Посмотрим, что скажет компилятор сегодня:

```c
char buf[10];
gets(buf);
```

```text
gets_test.c:6:5: warning: 'gets' is deprecated: This function is
provided for compatibility reasons only.  Due to security concerns
inherent in the design of gets(3), it is highly recommended that you
use fgets(3) instead. [-Wdeprecated-declarations]
    6 |     gets(buf);
      |     ^
```

(Дальше идут строки `note:` с указанием на место в системном
заголовке, где `gets` помечена устаревшей.)

Заголовки macOS всё ещё объявляют `gets` ради совместимости со
старым кодом, но помечают её как устаревшую и прямым текстом
советуют `fgets`. Программа при этом **соберётся** — предупреждение
не ошибка. Именно поэтому его нельзя пропускать мимо глаз: на других
системах `gets` может не найтись вовсе, и там сборка просто упадёт.
Вывод один: **только `fgets`**.

### Полная программа `code/03-strings.c`

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
    char name[] = "Anna";

    printf("Привет, %s!\n", name);
    printf("strlen(name) = %zu\n", strlen(name));
    printf("sizeof name  = %zu\n", sizeof name);
    printf("байт после последней буквы: код %d\n", name[strlen(name)]);

    char copy[16];
    strcpy(copy, name);
    copy[0] = 'J';
    printf("копия после правки: %s, оригинал: %s\n", copy, name);

    /* Два разных массива с одинаковым текстом. */
    char a[] = "exit";
    char b[] = "exit";
    const char *pa = a;              /* через указатели — чтобы  */
    const char *pb = b;              /* компилятор не ругался    */
    printf("адреса равны? %d\n", pa == pb);
    printf("strcmp(a, b)  = %d\n", strcmp(a, b));
    printf("strcmp(\"abc\", \"abd\") = %d\n", strcmp("abc", "abd"));

    char line[64];
    printf("Введи команду: ");
    if (fgets(line, sizeof line, stdin) == NULL) {
        printf("\nВвод закончился\n");
        return 1;
    }
    printf("как есть:   [%s]\n", line);
    printf("длина: %zu\n", strlen(line));

    size_t len = strlen(line);
    if (len > 0 && line[len - 1] == '\n') {
        line[len - 1] = '\0';
    }
    printf("без '\\n':   [%s]\n", line);
    printf("длина: %zu\n", strlen(line));

    if (strcmp(line, "exit") == 0) {
        printf("Это команда выхода. Пока!\n");
    } else {
        printf("Такой команды не знаю\n");
    }
    return 0;
}
```

Пара мелочей из листинга:

- `copy[0] = 'J';` — правим копию и печатаем обе строки. `strcpy`
  делает именно копию, а не второе имя для тех же данных, поэтому
  оригинал не пострадает.
- `const char *pa = a;` — переменная-указатель на символы, в неё
  положили адрес начала массива `a`. Сравнение `pa == pb` — то же
  самое сравнение адресов, что и `a == b`, но записанное так,
  чтобы компилятор не ругался предупреждением на очевидную
  бессмыслицу. Про указатели — прямо в следующей части.
- `"strcmp(\"abc\", \"abd\")"` — обратный слеш перед кавычкой
  говорит: это кавычка внутри текста, а не конец строки.
- `"без '\\n'"` — два обратных слеша дают один настоящий в выводе.

```text
cc -std=c11 -Wall -Wextra -O2 code/03-strings.c -o strings
printf 'exit\n' | ./strings
```

```text

копия после правки: Jnna, оригинал: Anna
адреса равны? 0
strcmp(a, b)  = 0
strcmp("abc", "abd") = -1
Введи команду: как есть:   [exit
]
длина: 5
без '\n':   [exit]
длина: 4
Это команда выхода. Пока!
```

## Часть 3. Указатели — переменные, хранящие адрес

Мы уже встречали `&` в `scanf` и слово «адрес» — раз двадцать.
Пришло время разобраться до конца.

У каждой переменной есть **адрес** — номер ячейки в памяти, где она
лежит. Память компьютера — это длинная лента пронумерованных байт;
адрес переменной и есть её номер на этой ленте. **Указатель** — это
переменная, которая хранит такой номер.

### Адрес и разыменование

```c
int x = 42;
int *p = &x;     /* p хранит адрес x */

printf("значение x:        %d\n", x);
printf("адрес x:           %p\n", (void *)&x);
printf("p хранит адрес:    %p\n", (void *)p);
printf("значение по p:     %d\n", *p);

*p = 100;        /* меняем x через указатель */
printf("теперь x = %d\n", x);
```

Разбор — ключевой момент всей главы:

- `int *p` — объявляем **указатель на int**. Звёздочка в объявлении
  говорит: «`p` — не число, а адрес, по которому лежит число». Тип
  переменной `p` целиком — «указатель на `int`».
- `= &x` — кладём в `p` **адрес** переменной `x`. Оператор `&` —
  «взять адрес».
- `*p` в выражении — оператор **разыменования** (*dereference*):
  «значение, лежащее **по** адресу `p`». Как «открыть коробку, на
  которую указывает стрелка».
- `*p = 100;` — записать 100 туда, куда указывает `p`. Раз `p`
  указывает на `x`, изменится именно `x`.
- `%p` — спецификатор для печати адреса; `(void *)` — приведение,
  которого требует `printf` для адресов. `void *` — «указатель на
  что-то, тип неизвестен».

Часть вывода программы `code/03-pointers.c`:

```text
значение x:        42
адрес x:           0x7ff7b68c2864
p хранит адрес:    0x7ff7b68c2864
значение по p:     42
теперь x = 100
```

Смотри на две средние строки: адрес `x` и содержимое `p` — **одно и
то же число**. Это и значит «указатель хранит адрес». А `*p` вернул
42 — то, что по этому адресу лежит.

Само число (`0x7ff7b68c2864`) у тебя будет другим, и даже при
повторных запусках оно меняется: система каждый раз кладёт программу
в разное место памяти. Запоминать его бессмысленно — важно лишь то,
что оба раза оно совпало. Начальное `0x` означает
шестнадцатеричную запись, в ней адреса печатать удобнее.

### Звёздочка в объявлении и звёздочка в выражении

Один знак, две разные роли — и это главный источник путаницы:

```c
int *p = &x;   /* объявление: p — указатель       */
*p = 100;      /* выражение:  положить 100 по p   */
int y = *p;    /* выражение:  взять значение по p */
```

В объявлении `*` — часть типа, «указатель на». В выражении `*` —
действие «пойти по адресу». Шпаргалка: `&x` — «**адрес** x»,
`int *p` — «p это **указатель**», `*p` — «**значение по** p».

Пишут звёздочку по-разному: `int *p`, `int* p`, `int * p` — для
компилятора одно и то же. В книге держимся `int *p`: такая запись
честнее при объявлении нескольких переменных, ведь в строке
`int *a, b;` указатель только `a`, а `b` — обычный `int`.

### Зачем это нужно: функция, меняющая аргумент

В Си аргументы передаются **по значению** — функция получает копию.
Поэтому такая функция бесполезна:

```c
void bad_swap(int a, int b)
{
    int t = a;
    a = b;
    b = t;
    printf("  внутри bad_swap: a=%d b=%d\n", a, b);
}
```

Чтобы функция поменяла **сами** переменные, передаём их **адреса**:

```c
void swap(int *a, int *b)
{
    int t = *a;             /* запомнили значение по a  */
    *a = *b;                /* в a положили значение по b */
    *b = t;                 /* в b положили запомненное */
}
```

Позовём обе подряд:

```c
int a = 1, b = 2;
bad_swap(a, b);
printf("после bad_swap: a=%d b=%d\n", a, b);
swap(&a, &b);
printf("после swap: a=%d b=%d\n", a, b);
```

```text
  внутри bad_swap: a=2 b=1
после bad_swap: a=1 b=2
после swap: a=2 b=1
```

Три строки, и в них вся суть. Внутри `bad_swap` обмен **произошёл**:
`a=2 b=1`. Но менялись копии, они умерли на выходе из функции, и
снаружи осталось `a=1 b=2`. `swap` получила адреса, полезла по ним в
оригиналы — и вот они действительно поменялись.

Это и есть причина, по которой `scanf` требует `&`: ему нужен адрес,
чтобы записать прочитанное в **твою** переменную, а не в копию,
которая тут же исчезнет.

Приём «вернуть значение через указатель-аргумент» пригодится всюду,
где результатов больше одного: `return` умеет отдать только одно
значение, а указателей можно передать сколько угодно. `swap` мы ещё
раз напишем в главе 19 — это классический вопрос на собеседовании.

### `NULL` — указатель в никуда

Иногда указателю нечего хранить: список пуст, поиск не нашёл
элемента, память не выделилась. Для этого есть `NULL` — специальное
значение «никуда не указываю». Оно определено в `<stdio.h>` и
`<stdlib.h>`.

```c
int *q = NULL;
printf("q = %p\n", (void *)q);
if (q == NULL) {
    printf("q никуда не указывает, *q писать нельзя\n");
}
```

```text
q = 0x0
q никуда не указывает, *q писать нельзя
```

Адрес нулевой. Если запустишь это на Linux, вместо `0x0` увидишь
`(nil)`: как печатать нулевой указатель через `%p`, стандарт не
оговаривает, и библиотека GNU выбрала слово, а не число. Значение от
этого не меняется — указатель пустой в обоих случаях.

А что будет, если всё-таки разыменовать? Файл `nullderef.c`:

```c
#include <stdio.h>

int main(void)
{
    int *p = NULL;
    printf("p = %p\n", (void *)p);
    printf("значение по p: %d\n", *p);
    return 0;
}
```

Собираем без оптимизации (`-O0` — «не оптимизируй») и запускаем:

```text
bash: line 1: 63713 Segmentation fault: 11  ./nullderef0
код возврата: 139
```

**Segmentation fault** — «нарушение сегментации»: операционная
система заметила обращение по запрещённому адресу и убила программу
сигналом номер 11 (`SIGSEGV`). Код возврата 139 = 128 + 11, по этой
арифметике всегда видно, каким сигналом программу прибили. Твоя
оболочка может написать это другими словами (`zsh: segmentation
fault`), суть та же.

Нулевой адрес специально сделан запрещённым — чтобы такая ошибка
падала сразу и громко, а не портила данные.

Сюрприз в том, что «громко» бывает не всегда. Собери ту же программу
с `-O2` — на моей машине она не упала, напечатала `значение по p:
73896` и вышла с кодом 0. Разыменование `NULL` — **неопределённое
поведение** (undefined behavior): стандарт не обещает ничего, и
компилятор вправе считать, что в правильной программе такого не
бывает. Не жди, что ошибка обязательно проявится падением.

Ловит это второй санитайзер, `-fsanitize=undefined`:

```text
nullderef.c:7:45: runtime error: load of null pointer of type 'int'
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior
nullderef.c:7:45
```

Оба санитайзера обычно включают вместе:
`-fsanitize=address,undefined`.

## Часть 4. Динамическая память

`int a[100]` требует знать размер при написании кода. Мало — не
влезет, много — память тратится зря. А если число элементов
выяснится только во время работы? Тогда память просят у системы
**во время выполнения** — это **динамическая память**, она же
**куча** (heap).

Нужен `#include <stdlib.h>` и две функции.

**`void *malloc(size_t size)`** (*memory allocate* — «выделить
память») — просит у системы кусок в `size` **байт**. Возвращает адрес
начала этого куска или `NULL`, если памяти не хватило. Тип `void *`
— «указатель непонятно на что»; в Си он сам приводится к нужному
типу, поэтому писать `(int *)malloc(...)` не требуется.

**`void free(void *ptr)`** — возвращает системе кусок, полученный от
`malloc`. Ничего не возвращает. Сама переменная-указатель после
`free` не меняется — в ней остаётся старый адрес, но пользоваться им
уже нельзя.

```c
int n = 4;
int *a = malloc(n * sizeof(int));
if (a == NULL) {
    printf("Не хватило памяти\n");
    return 1;
}
for (int i = 0; i < n; i++) {
    a[i] = i * i;
}
free(a);
```

- `n * sizeof(int)` — размер в **байтах**, а не в элементах. Четыре
  числа по 4 байта — 16 байт. Забыть про `sizeof` и написать
  `malloc(n)` — классическая ошибка: получишь вчетверо меньше места.
- `if (a == NULL)` — проверка. На настольном компьютере `malloc`
  почти всегда успешен, но привычка проверять стоит одной строки, а
  спасает от падения без объяснений.
- `a[i]` — к динамической памяти обращаются **точно как к массиву**.
  Указатель и массив здесь неотличимы в использовании: `a[i]` для
  компилятора означает «элемент через `i` шагов от адреса `a`».
- `free(a)` — **обязательно**, когда память больше не нужна. Правило:
  на каждый `malloc` однажды должен прийтись ровно один `free`.

### Полная программа `code/03-dynamic.c`

Заодно посмотрим на `realloc` — функцию «мне мало, дай больше».

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int n;
    printf("Сколько чисел? ");
    /* Верхняя граница нужна не для красоты: ниже считается n * 2,
       а переполнение int — это неопределённое поведение. */
    if (scanf("%d", &n) != 1 || n <= 0 || n > 1000000) {
        printf("Нужно число от 1 до 1000000\n");
        return 1;
    }

    int *a = malloc(n * sizeof(int));
    if (a == NULL) {
        printf("Не хватило памяти\n");
        return 1;
    }

    for (int i = 0; i < n; i++) {
        a[i] = i * i;
    }
    printf("квадраты (%d шт.):", n);
    for (int i = 0; i < n; i++) {
        printf(" %d", a[i]);
    }
    printf("\n");

    /* Мало места? Просим ещё — realloc сохраняет то, что уже лежит. */
    int bigger_n = n * 2;
    int *bigger = realloc(a, bigger_n * sizeof(int));
    if (bigger == NULL) {
        printf("Не хватило памяти на расширение\n");
        free(a);
        return 1;
    }
    a = bigger;

    for (int i = n; i < bigger_n; i++) {
        a[i] = i * i;
    }
    printf("после realloc (%d шт.):", bigger_n);
    for (int i = 0; i < bigger_n; i++) {
        printf(" %d", a[i]);
    }
    printf("\n");

    free(a);
    return 0;
}
```

**`void *realloc(void *ptr, size_t new_size)`** — меняет размер
куска, ранее полученного от `malloc`. Возвращает адрес куска нового
размера (возможно, **другой** — если на старом месте не хватило,
система выделит новое место и **сама скопирует** туда старые данные)
или `NULL` при неудаче.

Обрати внимание, что результат кладётся в **новую** переменную
`bigger`, а не сразу в `a`. Если написать `a = realloc(a, ...)` и
получить `NULL`, старый адрес будет потерян навсегда — и память не
освободить, и данные не достать. Через отдельную переменную мы
сохраняем шанс аккуратно всё прибрать. Этот приём — основа растущего
массива, который мы построим в главе 11.

```text
cc -std=c11 -Wall -Wextra -O2 code/03-dynamic.c -o dynamic
printf '4\n' | ./dynamic
```

```text
Сколько чисел? квадраты (4 шт.): 0 1 4 9
после realloc (8 шт.): 0 1 4 9 16 25 36 49
```

Ввели 4 — программа попросила место ровно под четыре числа и
заполнила их квадратами индексов: 0², 1², 2², 3². Потом попросила
вдвое больше, и первые четыре числа остались на месте — их сохранил
`realloc`. Введи 10 — получишь десять и двадцать чисел, и никакого
`int a[100]` «на всякий случай» для этого не понадобилось.

### Три способа испортить кучу

Ошибки с динамической памятью коварны тем, что программа выглядит
работающей и при этом сломана. Разберём три классические, и каждую
покажем санитайзеру.

**Выход за границу выделенного куска.** Тот же `i <= n`, что и с
обычным массивом:

```c
    a[i] = i * i;

free(a);
```

### Утечка памяти

Забыть `free` — значит **утечь**: кусок останется занятым до конца
работы программы. Одна забытая строчка в цикле, который крутится
часами, и программа съедает всю память машины.

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *a = malloc(4 * sizeof(int));
    a[0] = 1;
    printf("a[0] = %d\n", a[0]);
    return 0;              /* free забыли */
}
```

Программа отработает как ни в чём не бывало: `a[0] = 1`, код
возврата 0. Санитайзер адресов утечку тоже не покажет — ищет их
отдельная часть, LeakSanitizer, а **на macOS она не поддерживается**:

```text
ASAN_OPTIONS=detect_leaks=1 ./leak
```

```text
==62643==AddressSanitizer: detect_leaks is not supported on this
platform.
```

На Linux эта же команда напечатала бы отчёт об утечке. На macOS для
того же есть системная утилита `leaks`: `MallocStackLogging=1` просит
систему запоминать, кто и откуда выделял память, а `--atExit`
говорит «проверь в момент выхода».

```text
cc -std=c11 -Wall -Wextra -g leak_demo.c -o leak_demo
MallocStackLogging=1 leaks --atExit -- ./leak_demo
```

Начинается отчёт с полутора десятков строк справки о процессе (путь,
версия macOS, время запуска), а вот его содержательная часть:

```text
leaks Report Version: 4.0, multi-line stacks
Process 70125: 188 nodes malloced for 28 KB
Process 70125: 1 leak for 32 total leaked bytes.

STACK OF 1 INSTANCE OF 'ROOT LEAK: <malloc in main>':
2   dyld                               0x7ff804aa4b28 start + 3240
1   leak_demo                            0x108e4d489 main + 25
leak_demo.c:6
0   libsystem_malloc.dylib             0x7ff804ca8219
_malloc_zone_malloc_instrumented_or_legacy + 115
```

«1 утечка, 32 байта, `malloc` в `main`, файл `leak_demo.c`, строка
6». Стек здесь напечатан снизу вверх: самая нижняя строка — сам
`malloc` в системной библиотеке, над ней — наша строка 6, над ней —
запуск программы. Просили мы 16 байт, а числится 32: `malloc`
округляет размер куска вверх, ему так удобнее управлять кучей.

Хорошая новость: пока `malloc` и `free` стоят парой в одной функции,
утечь трудно. Плохая — как только память начинает жить дольше одной
функции, за парами приходится следить самому. Этим мы вплотную
займёмся в главе 11, когда будем строить списки.

## Замечание про русские буквы

Современные системы хранят текст в кодировке **UTF-8**, где русская
буква занимает **2 байта**, а не 1. Возьми те же четыре буквы, но
русские:

```c
char ru[] = "Анна";
char en[] = "Anna";
printf("ru: strlen = %zu, sizeof = %zu\n", strlen(ru), sizeof ru);
printf("en: strlen = %zu, sizeof = %zu\n", strlen(en), sizeof en);
printf("strlen(\"Привет\") = %zu\n", strlen("Привет"));
```

```text
ru: strlen = 8, sizeof = 9
en: strlen = 4, sizeof = 5
strlen("Привет") = 12
```

Четыре русские буквы дали 8 байт, четыре латинские — 4. `strlen`
считает **байты**, а не буквы. Поэтому в этой книге везде, где важно
считать символы (перевернуть строку, проверить палиндром, посчитать
гласные), мы работаем с латиницей и цифрами — по 1 байту на символ.
Для вывода сообщений русский текст годится полностью: `printf`
печатает байты как есть, и всё выглядит правильно.

контрольный прогон под санитайзерами — он тоже обязан промолчать:

```text
cc -std=c11 -Wall -Wextra -g -fsanitize=address,undefined \
   code/03-dynamic.c -o dyn_san
printf '4\n' | ./dyn_san
```

Санитайзер молчит, а программа печатает то же самое — значит, с
памятью всё в порядке.

## Частые ошибки

**Выход за границы массива.** `for (i = 0; i <= n; i++)` вместо
`i < n`. Си границы не проверяет: программа прочитает или испортит
чужую память и, скорее всего, даже не упадёт. Собирай с
`-fsanitize=address`, когда что-то ведёт себя странно.

**Число элементов от пользователя — без проверки.** Объявил `int
a[100]`, спросил `n` и сразу пошёл циклом до `n`. Пользователь ввёл
1000 — и ты за границей. Проверяй `n` сразу после `scanf` или бери
`malloc`.

**Сравнение строк через `==`.** Сравнивает адреса, а не текст, и для
двух разных массивов всегда даёт «не равны». Нужен `strcmp`, причём
`== 0` означает «равны».

**Забытый `'\0'`.** Собираешь строку вручную по символам — ставь
метку конца сам, иначе `printf("%s")` и `strlen` уедут в чужую
память.

**`fgets` и оставшийся `'\n'`.** Строка `"exit\n"` не равна
`"exit"`. Обрезай перевод строки сразу после чтения.

**`strcpy` в маленький буфер.** Функция не знает размера приёмника.
Проверяй, что влезет, — или бери `snprintf`, который принимает
размер.

**`scanf("%s", ...)` без ограничения длины.** Пиши `%63s` для массива
из 64 байт. И помни, что `&` перед именем массива не нужен.

**`malloc(n)` вместо `malloc(n * sizeof(int))`.** Получишь вчетверо
меньше памяти, чем думаешь, и выход за границу на ровном месте.

**`malloc` без проверки на `NULL`** и **без `free`.** Первое —
возможное падение, второе — утечка.

**`a = realloc(a, ...)` напрямую.** При неудаче потеряешь и память, и
данные. Пиши в отдельную переменную, проверяй, потом присваивай.

**Обращение к памяти после `free`.** Указатель остаётся прежним, но
пользоваться им нельзя. Привычка `a = NULL;` сразу после `free`
превращает тихую порчу данных в честное падение.

**Звёздочка путается в объявлении и в использовании.** В `int *p`
она объявляет указатель, в `*p = 5` — разыменовывает. Разные роли
одного знака.

## Упражнения

1. Заполни массив из 10 чисел вводом и напечатай его в обратном
   порядке. *Подсказка*: второй цикл идёт от `i = 9` вниз до `i >= 0`
   с шагом `i--`.

2. Найди в массиве максимальный элемент. *Подсказка*: заведи `max` и
   положи в него **первый элемент**, а не ноль — иначе на массиве из
   одних отрицательных чисел ответ будет неверным. Проверь на
   `{-5, -2, -9}`.

3. Напиши функцию `void fill(int *a, int n, int value)`, которая
   заполняет первые `n` элементов значением `value`. *Подсказка*:
   `int *a` и `int a[]` в параметрах — одно и то же; функция получает
   адрес, поэтому изменения увидит и вызывающий. Здесь `const`
   ставить нельзя — мы как раз меняем массив.

4. Прочитай строку через `fgets`, обрежь `'\n'` и напечатай длину.
   Потом сравни строку с `"stop"` через `strcmp` и напиши «стоп» или
   «дальше». *Подсказка*: проверь, что программа не падает, если
   ввод пустой (сразу Enter) и если ввод закончился (`fgets` вернёт
   `NULL`).

5. Напиши функцию `void min_max(const int *a, int n, int *mn,
   int *mx)`, которая за один проход находит минимум и максимум и
   возвращает **оба** через указатели. *Подсказка*: внутри пиши
   `*mn = ...`, а вызывай как `min_max(a, n, &lo, &hi)`. Это тот же
   приём, что в `swap`.

6. Через `malloc` выдели массив на введённое число элементов, заполни
   кубами индексов (`i*i*i`), напечатай, потом расширь через
   `realloc` вдвое и заполни хвост. Не забудь `free`. *Подсказка*:
   собери решение с `-fsanitize=address` и убедись, что санитайзер
   молчит; потом специально убери `free` и проверь утечку через
   `leaks --atExit`.

## Что мы получили

Теперь у нас есть всё необходимое для работы с данными: массивы для
наборов значений, строки как массивы символов с меткой `'\0'`,
указатели как адреса (и понимание, зачем `scanf` хочет `&`),
динамическая память с тройкой `malloc`/`realloc`/`free`. И, что не
менее ценно, — умение поймать ошибку памяти инструментом, а не
гаданием: `-Wall -Wextra` при сборке, `-fsanitize=address,undefined`
при отладке, `leaks` для утечек.

числа, факториал и знаменитый FizzBuzz. Заодно встретим переполнение
