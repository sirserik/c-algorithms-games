# Глава 13. Игра «Камень, ножницы, бумага»

В прошлой главе компьютер загадывал число, а ты угадывал. Теперь
поменяем роли местами: ты и компьютер играете на равных в «Камень,
ножницы, бумага». Компьютер делает случайный выбор, ты — свой, и кто-то
выигрывает раунд. Сыграем несколько раундов, посчитаем очки и в конце
объявим победителя матча.

По дороге познакомимся с новой полезной штукой — **перечислением**
(`enum`), научимся аккуратно превращать выбор игрока в число, выпишем
правила игры понятными `if`, заглянем в короткий приём с остатком от
деления и сделаем ввод устойчивым к ерунде вроде `hello` или `5`.

## Что мы сделаем

К концу главы у нас будет программа `code/13-rps.c`, которая:

- предлагает выбрать камень, ножницы или бумагу (или выйти);
- сама случайно выбирает свой ход;
- говорит, кто выиграл раунд;
- ведёт счёт игрока и компьютера;
- играет столько раундов, сколько захочешь, а по команде выхода
  печатает итог матча.

Всё, что нужно, у тебя уже есть из прошлых глав: переменные, `if`,
циклы, функции (глава 2), массивы и строки (глава 3), а также
`rand`/`srand`/`time` для случайных чисел (глава 12). Случайность мы
заново разбирать не будем — просто пользуемся.

## Разбираем задачу руками

Сначала договоримся о правилах. Их три:

- камень бьёт ножницы (тупит лезвие);
- ножницы бьют бумагу (режут);
- бумага бьёт камень (заворачивает).

Если оба выбрали одно и то же — ничья.

Чтобы компьютер мог «думать», выбор нужно превратить в число. Закодируем
ходы так:

- `0` — камень;
- `1` — ножницы;
- `2` — бумага.

Кодировка не случайна. Посмотри, что бьёт что: камень (0) бьёт ножницы
(1), ножницы (1) бьют бумагу (2), бумага (2) бьёт камень (0). Каждый ход
бьёт **следующий по кругу**: 0→1→2→0. Эта закономерность скоро очень нам
пригодится.

Выпишем все девять исходов в таблицу. Слева — ход игрока, сверху — ход
компьютера, в клетке — кто выиграл (И = игрок, К = компьютер, Н =
ничья):

```text
              компьютер
            камень ножницы бумага
игрок   ┌─────────────────────────
камень  │   Н       И        К
ножницы │   К       Н        И
бумага  │   И       К        Н
```

По диагонали — ничьи (выбрали одинаково). Остальные клетки — кто кого
побил по правилам выше. Эту таблицу мы и научим программу заполнять.

## Шаг 1. Один раунд, выбор компьютера

Начнём с самого маленького: компьютер делает случайный ход, мы его
печатаем. Случайное число от 0 до 2 даёт `rand() % 3` — остаток от
деления неотрицательного числа на 3 всегда попадает в диапазон 0..2
(см. главу 12). Честно ли он делит шансы между тремя ходами, проверим
в конце главы.

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

int main(void)
{
    srand((unsigned int)time(NULL));

    int computer = rand() % 3;
    printf("Компьютер выбрал: %d\n", computer);
    return 0;
}
```

Здесь всё знакомо по главе 12:

- `#include <stdlib.h>` — оттуда `rand` и `srand`.
- `#include <time.h>` — оттуда `time`.
- `srand((unsigned int)time(NULL));` — засеваем генератор текущим
  временем, чтобы от запуска к запуску числа были разными.
- `rand() % 3` — случайное число, остаток от деления на 3, то есть 0, 1
  или 2.

Запуск печатает что-то вроде `Компьютер выбрал: 2`. Работает, но
человеку «2» ни о чём не говорит. Нужно показывать слово, а не число.

## Шаг 2. Превращаем число в слово

Можно было бы каждый раз писать `if (computer == 0) printf("камень")`
и так далее. Но это придётся повторять для игрока и для компьютера —
дублирование. Лучше сделать **функцию**, которая по числу возвращает
название хода.

Функция должна вернуть текст. Текст в Си — это массив символов, а доступ
к нему мы передаём через адрес первого символа, то есть через
**указатель на `char`** (см. главу 3). Поэтому тип результата —
`const char *`:

```c
const char *move_name(int move)
{
    if (move == 0) {
        return "камень";
    }
    if (move == 1) {
        return "ножницы";
    }
    return "бумага";
}
```

Разбор того, что здесь нового:

- `const char *` — тип возвращаемого значения: «указатель на символы»,
  то есть строка. Слово `const` означает «только для чтения»: вызывающий
  не должен менять эти буквы. Это разумно, ведь мы возвращаем
  **строковый литерал** — текст `"камень"`, зашитый в программу.
- `return "камень";` — возвращаем адрес начала этой строки. Строковый
  литерал живёт в памяти всё время работы программы, так что возвращать
  на него указатель безопасно.
- Третий вариант (`return "бумага";`) стоит без `if`: если число не 0 и
  не 1, остаётся только 2 — бумага. До него дело доходит, только когда
  оба `return` выше не сработали: `return` сразу выходит из функции.

Теперь вывод понятен человеку:

```c
printf("Компьютер выбрал: %s\n", move_name(computer));
```

`%s` печатает строку по указателю, который вернула функция (см. главу 3).

## Шаг 3. Даём имена числам — `enum`

Числа 0, 1, 2 работают, но в коде `if (move == 1)` непонятно, что
такое «1». Через месяц ты и сам забудешь. В Си для таких случаев есть
**перечисление** — `enum` (от англ. *enumeration*, «перечисление»).

`enum` позволяет дать числам понятные имена:

```c
enum Move { ROCK, SCISSORS, PAPER };
```

Что здесь происходит:

- `enum Move { ... }` — объявляем новый набор именованных целых
  констант под общим названием `Move`.
- `ROCK, SCISSORS, PAPER` — имена. По умолчанию `enum` раздаёт значения
  с нуля по порядку: `ROCK` это 0, `SCISSORS` это 1, `PAPER` это 2.
  Ровно наша кодировка! Можно задать и явно (`enum Move { ROCK = 0,
  SCISSORS = 1, PAPER = 2 };`), но и так сходится.

Само имя `Move` нам в этой главе не понадобится: пользуемся только
константами `ROCK`, `SCISSORS`, `PAPER`, а ходы храним в обычном `int`.
Имена `enum` — это обычные целые числа, просто с человеческим лицом.
Можно писать `ROCK` вместо `0` где угодно: в сравнениях, в присваиваниях,
в арифметике. Компилятор подставит число. Перепишем `move_name`
понятнее:

```c
const char *move_name(int move)
{
    if (move == ROCK) {
        return "камень";
    }
    if (move == SCISSORS) {
        return "ножницы";
    }
    return "бумага";
}
```

Логика та же, но теперь код читается как фраза: «если ход — камень,
верни "камень"». Имена-константы делают программу понятной без
комментариев.

## Шаг 4. Кто победил

Теперь главное: по двум ходам определить победителя. Самый честный путь
— просто перечислить случаи, как в таблице. Сначала ничья, потом три
случая победы игрока, а всё остальное — победа компьютера. Оформим это
функцией: она понадобится и в игре, и в проверке ниже.

```c
/* 0 - ничья, 1 - выиграл игрок, 2 - выиграл компьютер */
int round_winner(int player, int computer)
{
    if (player == computer) {
        return 0;
    }
    if (player == ROCK && computer == SCISSORS) {
        return 1;
    }
    if (player == SCISSORS && computer == PAPER) {
        return 1;
    }
    if (player == PAPER && computer == ROCK) {
        return 1;
    }
    return 2;
}
```

Разбор:

- функция возвращает число-исход: 0, 1 или 2. Что какое число значит,
  написано в комментарии над ней, — без этой строчки через неделю
  придётся вспоминать.
- `player == computer` — выбрали одинаково, значит ничья, возвращаем 0.
- три следующих `if` — три выигрышных для игрока расклада прямо по
  правилам: камень против ножниц, ножницы против бумаги, бумага против
  камня. `&&` — «И» (см. главу 2): нужно, чтобы совпали оба хода.
  Сработал любой из трёх — возвращаем 1.
- `return 2;` в конце ловит всё остальное: раз не ничья и не победа
  игрока, значит выиграл компьютер.

Пробуем на одной паре:

```c
int player = ROCK;        /* пока зашьём вручную, ввод будет позже */
int computer = rand() % 3;
int result = round_winner(player, computer);
printf("Ты: %s. Компьютер: %s. Исход: %d\n",
       move_name(player), move_name(computer), result);
```

Запуск печатает, например, `Ты: камень. Компьютер: бумага. Исход: 2` —
бумага бьёт камень, выиграл компьютер. Сходится с таблицей.

Строк получилось много, зато каждая читается как правило игры, и
ошибиться в них трудно. Именно эту функцию мы и возьмём в итоговую
программу.

## Шаг 5. Для любопытных: то же одной формулой

Этот шаг можно пропустить — игра обойдётся без него. Но в чужом коде
ты наверняка встретишь короткий приём, и полезно его понимать.

Вернёмся к замеченной закономерности: каждый ход бьёт **следующий по
кругу** (0→1→2→0). Посчитаем такое выражение:

```c
int result = (computer - player + 3) % 3;
```

Идея: на сколько шагов по кругу ход компьютера «опережает» ход игрока.

- `computer - player` — разница ходов. Может быть −2, −1, 0, 1 или 2.
- `% 3` — остаток от деления на 3, то есть шаг по кругу 0→1→2→0.
  Встань на 0 и шагни на один назад по кругу — окажешься на 2. А Си на
  `-1 % 3` выдаёт не 2, а −1 (остаток берёт знак делимого, см. главу 2).
- `+ 3` — поэтому заранее прибавляем 3. Это полный круг: он ничего не
  меняет (с какого места ни шагни на три вперёд, вернёшься туда же), зато
  убирает минус. Число от −2 до 2 превращается в число от 1 до 5, и
  `% 3` даёт честный шаг по кругу.

Что означают три возможных значения?

- **0** — ходы равны: ничья.
- **1** — компьютер на один шаг «впереди» игрока по кругу. Например,
  игрок камень (0), компьютер ножницы (1): `(1 - 0 + 3) % 3 = 1`. Камень
  бьёт ножницы — выиграл **игрок**.
- **2** — компьютер на два шага впереди (то же самое, что игрок на один
  шаг впереди компьютера). Например, игрок ножницы (1), компьютер камень
  (0): `(0 - 1 + 3) % 3 = 2`. Камень бьёт ножницы — выиграл
  **компьютер**.

Ровно те же 0, 1 и 2, что возвращает `round_winner`. Одна строка вместо
целой функции.

### Не верь на слово — проверь машиной

Два разобранных примера — это ещё не доказательство. Формулу легко
принять на веру и потом полдня искать, почему игра «странно судит».
Поэтому сделаем то, что вообще стоит делать с любым хитрым приёмом:
**прогоним оба способа по всем девяти парам ходов и сверим ответы**.

Файл — `code/13-rps-check.c`:

```c
/* Проверка к главе 13: сверяем два способа определить победителя
   в «камень, ножницы, бумага» на всех девяти парах ходов.
   Явные if из шага 4 против формулы с остатком из шага 5. */

#include <stdio.h>

enum Move { ROCK, SCISSORS, PAPER };

const char *move_name(int move)
{
    if (move == ROCK) {
        return "камень";
    }
    if (move == SCISSORS) {
        return "ножницы";
    }
    return "бумага";
}

/* 0 - ничья, 1 - выиграл игрок, 2 - выиграл компьютер */
int round_winner(int player, int computer)
{
    if (player == computer) {
        return 0;
    }
    if (player == ROCK && computer == SCISSORS) {
        return 1;
    }
    if (player == SCISSORS && computer == PAPER) {
        return 1;
    }
    if (player == PAPER && computer == ROCK) {
        return 1;
    }
    return 2;
}

/* Тот же ответ одной формулой. */
int winner_mod(int player, int computer)
{
    return (computer - player + 3) % 3;
}

int main(void)
{
    for (int player = 0; player < 3; player++) {
        for (int computer = 0; computer < 3; computer++) {
            int by_if = round_winner(player, computer);
            int by_formula = winner_mod(player, computer);
            printf("%s против %s: if=%d формула=%d",
                   move_name(player), move_name(computer),
                   by_if, by_formula);
            if (by_if != by_formula) {
                printf("   <-- РАСХОЖДЕНИЕ!");
            }
            printf("\n");
        }
    }
    return 0;
}
```

Что тут нового:

- **два вложенных цикла** `for` — внешний перебирает ходы игрока
  (0, 1, 2), внутренний при каждом из них перебирает ходы компьютера.
  Три на три — ровно девять сочетаний, ни одного не пропустим.
- в каждой паре зовём оба способа и печатаем оба ответа. Если они
  разошлись, допечатываем заметное «РАСХОЖДЕНИЕ!» — тогда глазами
  искать не надо, ошибка сама бросится в глаза. Перевод строки `\n`
  печатаем отдельным `printf` в самом конце, чтобы метка встала в ту же
  строку.
- `printf` разбит на три строки кода. Так можно: Си всё равно, где
  кончается строка, пока не закрыта скобка, — команду завершает `;`.

Компилируем и запускаем:

```text
cc -std=c11 -Wall -Wextra -O2 code/13-rps-check.c -o rps-check
./rps-check
```

```text
камень против камень: if=0 формула=0
камень против ножницы: if=1 формула=1
камень против бумага: if=2 формула=2
ножницы против камень: if=2 формула=2
ножницы против ножницы: if=0 формула=0
ножницы против бумага: if=1 формула=1
бумага против камень: if=1 формула=1
бумага против ножницы: if=2 формула=2
бумага против бумага: if=0 формула=0
```

Девять строк, в каждой `if` и `формула` дали одно и то же, ни одного
«РАСХОЖДЕНИЕ!». Сверь заодно исходы с таблицей из начала главы — всё
сходится: по диагонали ничьи, камень бьёт ножницы, ножницы бьют
бумагу, бумага бьёт камень.

Приём работает только потому, что мы заранее **удачно занумеровали**
ходы (каждый бьёт следующего по кругу). Поменяй кодировку — и формула
сломается. Убедись сам: поменяй в `enum Move` местами `SCISSORS` и
`PAPER` и перезапусти проверку — шесть строк из девяти загорятся
«РАСХОЖДЕНИЕ!», и врать будет именно формула. Так же легко сломать её,
забыв `+ 3`. Явные `if` из шага 4 от нумерации не зависят, поэтому в
игре остаются они. А формулу ты теперь узнаешь в чужом коде.

**Короткая запись, которую встретишь в чужом коде.** Метку
«РАСХОЖДЕНИЕ!» можно было напечатать и без отдельного `if`:

```c
printf("%s\n", (by_if == by_formula) ? "" : "   <-- РАСХОЖДЕНИЕ!");
```

Это **тернарный оператор**: `условие ? первое : второе`. Если условие
истинно, всё выражение равно первому значению, иначе — второму. Здесь
он подставил бы пустую строку, когда способы согласны, и метку, когда
нет. Писать так сам не обязан: обычный `if` читается проще. Но в чужом
коде он встречается часто, и теперь ты его прочитаешь.

## Шаг 6. Ввод игрока с проверкой

Игрок должен вводить свой ход. Хочется принимать число (0, 1 или 2) и
букву `q` для выхода, и при этом не падать от мусора вроде `hello` или
`7`.

Через `%d`, как в главе 12, букву `q` не прочитать: `scanf` вернёт 0,
и нам всё равно пришлось бы доставать символы вручную. Проще сразу
прочитать ввод как одно «слово» в массив символов и посмотреть, что
в нём лежит.

```c
char buf[16];

if (scanf("%15s", buf) != 1) {
    break;              /* ввод кончился (Ctrl+D) - выходим */
}

if (buf[0] == 'q' || buf[0] == 'Q') {
    break;
}

int player = -1;        /* -1 - ход пока не распознан */
if (buf[1] == '\0') {   /* введён ровно один символ */
    if (buf[0] == '0') {
        player = ROCK;
    }
    if (buf[0] == '1') {
        player = SCISSORS;
    }
    if (buf[0] == '2') {
        player = PAPER;
    }
}
if (player == -1) {
    printf("Не понял. Введи 0, 1, 2 или q.\n");
    continue;
}
```

`break` и `continue` здесь — команды для цикла раундов, который мы
построим в полной программе.

Разбираем построчно:

- `char buf[16];` — массив символов на 16 байт под введённое слово (см.
  главу 3). С большим запасом.
- `scanf("%15s", buf)` — читаем слово (до пробела) в `buf`. Перед `buf`
  нет `&`: имя массива само по себе — адрес начала (см. главу 3). `%15s`
  ограничивает чтение 15 символами, чтобы не переполнить буфер из 16
  (последний байт — под `'\0'`). `scanf` возвращает, сколько значений он
  успешно прочитал; `!= 1` означает «прочитать не удалось». Для `%s`
  это бывает только в конце ввода (Ctrl+D): «словом» считается любая
  непустая цепочка символов без пробелов, так что буквы, цифры и знаки
  `%s` прочитает всегда, а вернуть 0, как `%d` на буквах, не может.
  Тогда `break` выходит из цикла. Проверять
  результат `scanf` мы научились в главе 12.
- `buf[0] == 'q' || buf[0] == 'Q'` — первый символ буквы выхода, в любом
  регистре. Если это `q` — выходим из цикла через `break`.
- `int player = -1;` — заводим ход со значением −1. Такого хода нет, так
  что −1 значит «пока ничего не распознали».
- `if (buf[1] == '\0')` — после первого символа сразу должен стоять
  конец строки `'\0'` (глава 3). Если там что-то есть, значит ввели
  больше одного символа (например `12` или `5x`) — это не наш одиночный
  ход, и внутрь мы не заходим.
- три внутренних `if` сравнивают символ с `'0'`, `'1'` и `'2'` и
  записывают в `player` нужный ход. Кавычки обязательны: `'1'` — это
  символ цифры, у него свой числовой код (49), а не число 1.
- `if (player == -1)` — ни одна проверка не сработала: ввели `hello`,
  `7` или `12`. Печатаем подсказку и `continue` — переходим к следующему
  витку цикла и заново спрашиваем ход.

В чужом коде символ-цифру часто превращают в число короче: `int player
= buf[0] - '0';`. Коды символов `'0'`, `'1'`, `'2'` идут подряд, поэтому
`'2' - '0'` это 2. Приём стандартный, но проверять, что символ
действительно цифра от 0 до 2, всё равно придётся отдельно. Наши три
`if` делают и то и другое сразу.

Три честных замечания про эту защиту — чтобы ты знал её границы.

Во-первых, на выход мы смотрим только **первый** символ. Значит, `quit`
и даже `qwerty` тоже закончат матч. Для игры это скорее удобно (человек
пишет `quit` — программа его понимает), но помни: это осознанная
поблажка, а не забытая проверка. Захочешь строгости — допиши
`&& buf[1] == '\0'`, как в проверке цифры.

Во-вторых, `%s` читает **слово**, а не строку. Если набрать `0 1` и
нажать Enter, программа сыграет два раунда подряд — сначала камнем,
потом ножницами, не спрашивая второй раз: как хвост `abc` из `50abc`
в первой версии проверки из главы 12, остаток строки просто
дожидается следующего витка. Здесь это
безвредно: каждое слово — законный ход, и каждый раунд честно
засчитан.

В-третьих, `%15s` берёт не больше 15 символов за раз. Если сгоряча
набрать двадцать букв, `scanf` отдаст первые 15, а оставшиеся пять
подхватит **следующий** вызов — и «Не понял» напечатается дважды на
один ввод. Программа не ломается, просто переспрашивает лишний раз.
А вот убрать `15` из формата нельзя ни в коем случае: голый `%s` не
знает, сколько места в приёмнике, и длинное слово уедет за границу
`buf`, затирая соседнюю память (глава 3 предупреждала: следить за
размером приёмника — работа программиста, никто её за тебя не сделает).
Ошибка тихая и крайне неприятная: программа может ещё долго
притворяться рабочей.

## Полная программа

Собираем всё вместе: цикл раундов, счёт, итог матча. Это и есть файл
`code/13-rps.c`.

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

enum Move { ROCK, SCISSORS, PAPER };

const char *move_name(int move)
{
    if (move == ROCK) {
        return "камень";
    }
    if (move == SCISSORS) {
        return "ножницы";
    }
    return "бумага";
}

/* 0 - ничья, 1 - выиграл игрок, 2 - выиграл компьютер */
int round_winner(int player, int computer)
{
    if (player == computer) {
        return 0;
    }
    if (player == ROCK && computer == SCISSORS) {
        return 1;
    }
    if (player == SCISSORS && computer == PAPER) {
        return 1;
    }
    if (player == PAPER && computer == ROCK) {
        return 1;
    }
    return 2;
}

int main(void)
{
    srand((unsigned int)time(NULL));

    int player_score = 0;
    int computer_score = 0;
    int rounds = 0;
    char buf[16];

    printf("Камень, ножницы, бумага!\n");
    printf("Выбор: 0 - камень, 1 - ножницы, 2 - бумага, q - выход.\n");

    while (1) {
        printf("\nТвой ход: ");

        if (scanf("%15s", buf) != 1) {
            break;              /* ввод кончился (Ctrl+D) - выходим */
        }

        if (buf[0] == 'q' || buf[0] == 'Q') {
            break;
        }

        int player = -1;        /* -1 - ход пока не распознан */
        if (buf[1] == '\0') {   /* введён ровно один символ */
            if (buf[0] == '0') {
                player = ROCK;
            }
            if (buf[0] == '1') {
                player = SCISSORS;
            }
            if (buf[0] == '2') {
                player = PAPER;
            }
        }
        if (player == -1) {
            printf("Не понял. Введи 0, 1, 2 или q.\n");
            continue;
        }

        int computer = rand() % 3;

        printf("Ты: %s. Компьютер: %s. ",
               move_name(player), move_name(computer));

        int result = round_winner(player, computer);

        if (result == 0) {
            printf("Ничья.\n");
        } else if (result == 1) {
            printf("Ты выиграл раунд!\n");
            player_score++;
        } else {
            printf("Компьютер выиграл раунд.\n");
            computer_score++;
        }

        rounds++;
    }

    printf("\n=== Итог ===\n");
    printf("Сыграно раундов: %d\n", rounds);
    printf("Ты: %d, компьютер: %d.\n", player_score, computer_score);

    if (player_score > computer_score) {
        printf("Поздравляю, ты победил в матче!\n");
    } else if (player_score < computer_score) {
        printf("Компьютер оказался сильнее. В другой раз!\n");
    } else {
        printf("Ничья по матчу.\n");
    }

    return 0;
}
```

## Как это работает

- В начале `main` заводим три счётчика: `player_score`,
  `computer_score` и `rounds` (сколько раундов сыграно). Все по нулям.
- `while (1)` — **бесконечный цикл**. Условие `1` — это всегда «истина»
  (ложь — 0, истина — любое ненулевое, см. главу 2). Сам по себе такой
  цикл не кончится никогда; выходим из него вручную через `break` —
  когда игрок ввёл `q` или ввод закончился. `break` мгновенно
  прекращает цикл и передаёт управление строкам после него.
- Внутри: спрашиваем ход, проверяем ввод (шаг 6), получаем `player`,
  бросаем кубик за компьютер (`rand() % 3`), печатаем оба хода.
- `result = round_winner(player, computer)` — определяем победителя
  (шаг 4). По числу-исходу печатаем итог раунда и при победе
  увеличиваем нужный счётчик через `++` (см. главу 2).
- `rounds++` в конце витка считает сыгранные раунды (плохой ввод сюда не
  доходит — там был `continue`).
- После цикла печатаем итог: сколько раундов, какой счёт, и кто победил
  в матче — сравнением `player_score` и `computer_score`.

Функции `move_name` и `round_winner` стоят **выше** `main`, потому что
`main` их вызывает, а функцию нужно объявить до вызова (см. главу 2).

## Проверяем

Скомпилируй и запусти:

Сыграем матч из трёх раундов: камень, ножницы, бумага — и `q`. Ходы
компьютера у тебя будут свои, они случайные:

```text

Выбор: 0 - камень, 1 - ножницы, 2 - бумага, q - выход.

Твой ход: 0
Ты: камень. Компьютер: камень. Ничья.

Твой ход: 1
Ты: ножницы. Компьютер: бумага. Ты выиграл раунд!

Твой ход: 2
Ты: бумага. Компьютер: ножницы. Компьютер выиграл раунд.

Твой ход: q

Сыграно раундов: 3
Ты: 1, компьютер: 1.
Ничья по матчу.
```

Все три исхода в одной партии: ничья, победа игрока, победа компьютера.
Сверь их с таблицей — ножницы против бумаги действительно наши, бумага
против ножниц действительно нет.

Теперь защита ввода — подсунем мусор перед нормальным ходом:

```text
Камень, ножницы, бумага!
Выбор: 0 - камень, 1 - ножницы, 2 - бумага, q - выход.

Твой ход: 5
Не понял. Введи 0, 1, 2 или q.

Твой ход: hello
Не понял. Введи 0, 1, 2 или q.

Твой ход: 1

```

`5` и `hello` программа отвергла и переспросила, а `1` приняла и
сыграла раунд. Ни падения, ни зацикливания, и в счёт раундов мусор не
попал: сыгран ровно один.

Осталось проверить края. Что будет, если выйти сразу, не сыграв ни
одного раунда? Или если ввод оборвётся на Ctrl+D? Оба случая дают одно
и то же — и это правильно:

```text
Камень, ножницы, бумага!
Выбор: 0 - камень, 1 - ножницы, 2 - бумага, q - выход.

Твой ход: q

=== Итог ===
Сыграно раундов: 0
Ты: 0, компьютер: 0.
Ничья по матчу.
```

Ноль раундов, ноль очков, «ничья по матчу». Программа не объявляет
победителя из воздуха — просто честно показывает пустой итог. Ctrl+D
вместо `q` даёт тот же результат, оба пути ведут к одному `break`:

```text
Камень, ножницы, бумага!
Выбор: 0 - камень, 1 - ножницы, 2 - бумага, q - выход.

Твой ход: ^D
=== Итог ===
Сыграно раундов: 0
Ты: 0, компьютер: 0.
Ничья по матчу.
```

Разница только в одной пустой строке: после `q` ты нажимаешь Enter, и
терминал переводит строку сам. Ctrl+D перевода строки не даёт — его
делает `\n` в начале `printf("\n=== Итог ===\n")`.

Играть удобно и через конвейер (pipe), не набирая ходы руками:

```text
printf '0\n1\n2\nq\n' | ./rps
```

Только имей в виду: в конвейере строчки «Твой ход:» останутся без
ответа рядом. Эхо набранных символов рисует терминал, а тут никто
ничего не набирает — программа читает ходы из трубы молча. Партия
пройдёт правильно, но выглядеть будет непривычно.

## Честная ли игра: считаем шансы

Против компьютера, который ходит наугад, нет выигрышной стратегии.
Проверим это сначала рассуждением, потом машиной.

**Вероятность** события — это доля случаев, в которых оно происходит,
если повторять опыт очень много раз. Монетка падает орлом с
вероятностью 1/2: примерно в половине бросков из тысячи.

Пусть ты упрямо ставишь камень. Компьютер выбирает один из трёх ходов,
и каждый — с вероятностью 1/3 (три равных варианта, как три грани у
«трёхгранного кубика»). Из этих трёх ровно один (ножницы) проигрывает
твоему камню, один (камень) даёт ничью и один (бумага) бьёт тебя.
Значит, победа, ничья и поражение — по 1/3 каждая. Поставь вместо
камня ножницы или бумагу — картина та же: у каждого твоего хода среди
трёх ответов компьютера один проигрывающий, один равный и один
выигрывающий. Хоть по кругу ходи, хоть наугад — в долгой игре выйдет
примерно поровну.

Рассуждение — ещё не проверка. Сыграем 300 тысяч раундов камнем
против `rand() % 3` и посчитаем исходы той же функцией `round_winner`
(в листинге ниже её тело сокращено до комментария — вставь целиком из
шага 4):

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

enum Move { ROCK, SCISSORS, PAPER };

int round_winner(int player, int computer)
{
    /* ... тело из шага 4 ... */
}

int main(void)
{
    srand((unsigned int)time(NULL));

    int rounds = 300000;
    int count[3] = {0, 0, 0};   /* ничьи, победы игрока, компьютера */

    for (int i = 0; i < rounds; i++) {
        int player = ROCK;              /* упрямо ставим камень */
        int computer = rand() % 3;
        int result = round_winner(player, computer);
        count[result]++;
    }

    printf("ничьих:            %6d (%.4f)\n",
           count[0], (double)count[0] / rounds);
    printf("побед игрока:      %6d (%.4f)\n",
           count[1], (double)count[1] / rounds);
    printf("побед компьютера:  %6d (%.4f)\n",
           count[2], (double)count[2] / rounds);
    return 0;
}
```

Здесь всё знакомо. `round_winner` возвращает номер исхода (0, 1 или 2),
и он же служит индексом в массиве счётчиков: `count[result]++`
прибавляет единицу нужному счётчику. `(double)count[0] / rounds` — доля исхода: без
приведения к `double` деление было бы целочисленным и дало бы 0 (см.
главу 2). `%6d` печатает число в поле шириной 6 символов, `%.4f` —
дробь с четырьмя знаками после запятой.

Два запуска с разницей в секунду:

```text
ничьих:            100291 (0.3343)
побед игрока:       99800 (0.3327)
побед компьютера:   99909 (0.3330)
```

```text
ничьих:             99762 (0.3325)
побед игрока:       99996 (0.3333)
побед компьютера:  100242 (0.3341)
```

Все доли около 1/3 = 0,3333, как и предсказывал расчёт. Ровно по
100000 не выходит, и это нормально: случайность всегда даёт разброс, и
плюс-минус несколько сотен на таком числе раундов — обычное дело, а
не перекос. Перекос от `% 3`, о котором мы говорили в главе 12, тут
того же порядка — меньше одной миллиардной, в счёте его не увидеть.

Из этого есть полезное следствие для отладки: если за тысячи раундов
компьютер выигрывает заметно чаще трети, ищи ошибку в формуле
победителя, а не «невезение». А вот на десятке раундов счёт вроде 5:2 —
обычное дело, по короткому матчу о честности не судят.

## Частые ошибки

**Сверяют символ с числом.** `buf[0] == 1` вместо `buf[0] == '1'` —
тихая ошибка: код символа `'1'` равен 49, а не 1, так что сравнение
никогда не сработает, и программа будет отвечать «Не понял» на любой
ход. Символы цифр — всегда в одинарных кавычках.

**Хитрая формула без проверки.** Если всё же берёшь формулу
`(computer - player + 3) % 3` из шага 5, помни: она верна только при
нумерации «каждый бьёт следующего по кругу» и только с `+ 3`. Переставь
имена в `enum` или забудь тройку — и часть раундов будет засуживаться
неправильно, причём не все, а лишь некоторые, так что в живой игре это
всплывёт не сразу. Любой приём, который работает «магически», проверяй
прогоном по всем случаям, как в `13-rps-check.c`. Девять комбинаций
перебираются за секунду, а пойманная так ошибка не доживёт до игрока.

**Ход через `%d`.** Если читать ход через `scanf("%d", ...)` без
проверки результата, то на `hello` программа зациклится: `scanf` не
сможет прочитать число и не сдвинет ввод (мы видели это в главе 12).
Поэтому мы читаем слово через `%s` и разбираем его сами — так проще
не запутаться.

**Бесконечный цикл без выхода.** В `while (1)` обязательно должен быть
`break` (или другой выход), иначе программа повиснет. У нас выходов
два — по `q` и по концу ввода, — и второй важнее, чем кажется. Забудешь
проверить результат `scanf`, и на Ctrl+D программа закрутится вхолостую:
буфер пуст, читать нечего, а цикл всё равно просит ход.

**`%s` без ограничения длины.** `scanf("%s", buf)` читает столько,
сколько введут, и молча вылезает за границу массива. Всегда указывай
предел — `%15s` для `char buf[16]`. Число в формате на единицу меньше
размера массива: последний байт нужен под `'\0'`.

**Счётчик раундов не там, где надо.** `rounds++` стоит в самом конце
витка, после всех проверок. Поставь его сразу после `printf("Твой
ход: ")` — и в итог попадут «раунды», на которых игрок ввёл `hello`.
Правило то же, что в главе 12: сначала отсеиваем всё, что ходом не
является, и только потом считаем.

## Упражнения

1. **До трёх побед.** Останавливай матч автоматически, как только кто-то
   набрал 3 победы (но не дольше 5 раундов — из-за ничьих до трёх побед
   можно и не дойти). Подскажу: добавь условие выхода из цикла по
   `player_score` и `computer_score`.

   *Решение:* сразу после `rounds++` вставь

   ```c
   if (player_score == 3 || computer_score == 3 || rounds == 5) {
       break;
   }
   ```

   Проверка: на ходах `0 1 2 0 1 2 0` матч заканчивается не позже
   пятого раунда (раньше, если кто-то успел набрать три победы),
   оставшиеся ходы уже не читаются, итог печатается как обычно.

2. **Пять ходов.** Добавь к игре «ящерицу» и «Спока» — есть такой
   известный вариант. Правила: камень бьёт ножницы и ящерицу, ножницы —
   бумагу и ящерицу, ящерица — бумагу и Спока, бумага — камень и Спока,
   Спок — камень и ножницы. У каждого хода две победы и два поражения.
   Можно ли обобщить формулу с остатком — или проще задать таблицу
   исходов массивом? И обязательно переделай `13-rps-check.c` под пять
   ходов: там будет уже 25 сочетаний, руками их не проверишь.

   *Ответ:* можно. Занумеруй ходы так, чтобы каждый бил **два
   следующих** по кругу: 0 — камень, 1 — ножницы, 2 — ящерица, 3 —
   бумага, 4 — Спок. Тогда `d = (computer - player + 5) % 5`: 0 —
   ничья, 1 или 2 — победа игрока, 3 или 4 — победа компьютера. Я
   сверил эту формулу с таблицей `beats[5][5]`, выписанной прямо по
   правилам: 25 пар, расхождений 0. Заметь, почему ходов нечётное
   число. При пяти ходах у каждого четыре соперника: двоих он бьёт,
   двоим проигрывает. При четырёх ходах соперников было бы три —
   поровну не делится.

3. **Статистика.** В конце матча печатай, сколько было ничьих и какой
   ход ты выбирал чаще всего. Заведи счётчики ничьих и трёх ходов
   (можно массивом из трёх элементов, индекс — номер хода).

   *Подсказка к решению:* `int draws = 0; int used[3] = {0};`, в раунде
   — `used[player]++` и `draws++` в ветке ничьей. В конце найди индекс
   максимума в `used` (как в главе 6) и напечатай `move_name` от него.
   Ожидаемо: после ходов `0 0 1 q` — «чаще всего: камень (2 раза)».
   Число ничьих должно совпасть с `rounds - player_score -
   computer_score` — удобная самопроверка.

4. **Усиленная защита ввода.** Принимай не только цифры, но и первые
   буквы ходов. Русская буква в UTF-8 занимает два байта (см. главу 3),
   и `buf[0]` будет лишь первым из них — поэтому проще принимать
   латинские `r` (rock), `s` (scissors), `p` (paper).

   *Подсказка к решению:* схема с `player = -1` из шага 6 расширяется
   почти даром — к каждой цифре добавь её букву через `||`:

   ```c
   int player = -1;                  /* -1 - ход пока не распознан */
   if (buf[1] == '\0') {             /* ровно один символ */
       if (buf[0] == '0' || buf[0] == 'r') {
           player = ROCK;
       }
       if (buf[0] == '1' || buf[0] == 's') {
           player = SCISSORS;
       }
       if (buf[0] == '2' || buf[0] == 'p') {
           player = PAPER;
       }
   }
   if (player == -1) {
       printf("Не понял. Введи 0, 1, 2, r, s, p или q.\n");
       continue;
   }
   ```

   Не забудь, что `q` уже занят выходом, и поправь подсказку в начале
   игры.

5. **Человеческая подсказка.** Если игрок проиграл раунд, печатай, каким
   ходом можно было побить ход компьютера.

   *Решение:* в ветку проигрыша добавь три `if` прямо по правилам:

   ```c
   int better = ROCK;            /* камень бьёт ножницы */
   if (computer == ROCK) {
       better = PAPER;           /* бумага бьёт камень */
   }
   if (computer == PAPER) {
       better = SCISSORS;        /* ножницы бьют бумагу */
   }
   printf("Против хода \"%s\" надо было ставить \"%s\".\n",
          move_name(computer), move_name(better));
   ```

   Проверка: на камень советует бумагу, на ножницы — камень, на
   бумагу — ножницы. Любители формул запишут то же короче:
   `better = (computer + 2) % 3` — в нашей кодировке побеждает ход,
   который стоит по кругу **перед** ходом компьютера.

6. **Серия побед.** Считай и показывай самую длинную серию подряд
   выигранных тобой раундов за матч.

   *Подсказка к решению:* две переменные — `streak` (текущая серия) и
   `best_streak`. Победа: `streak++`, и если `streak > best_streak`,
   обнови рекорд. Ничья или поражение: `streak = 0`. Для раундов
   «победа, победа, ничья, победа» ответ — 2.

## Что мы получили

Мы собрали полноценную интерактивную игру: случайный соперник, проверка
ввода, цикл раундов, счёт и итог матча. Попутно появилось перечисление
`enum` — способ давать числам понятные имена, правила игры легли в
функцию из понятных `if`, а для любопытных — короткий трюк с остатком
от деления, который заменяет ту же функцию одной строкой. А ещё посчитали
шансы: против случайного соперника победа, ничья и поражение — по 1/3
при любой твоей стратегии, и 300 тысяч сыгранных машиной раундов это
подтвердили.

Но главное — не сам трюк, а то, как мы с ним обошлись. Вместо «поверь,
это работает» написали `code/13-rps-check.c`, прогнали оба способа по
всем девяти парам ходов и увидели совпадение своими глазами. Такая
пятиминутная проверка стоит часа отладки: она ловит ошибку до того, как
та превратится в «программа судит как-то странно».

В следующей главе возьмёмся за игру посерьёзнее — **«Виселицу»**. Там
понадобится работать со строкой загаданного слова, отмечать угаданные и
неугаданные буквы, считать ошибки и рисовать состояние игры. Массивы,
строки и `'\0'` из главы 3 наконец развернутся в полную силу.
