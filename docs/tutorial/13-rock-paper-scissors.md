# Глава 13. Игра «Камень, ножницы, бумага»

В прошлой главе компьютер загадывал число, а ты угадывал. Теперь
поменяем роли местами: ты и компьютер играете на равных в «Камень,
ножницы, бумага». Компьютер делает случайный выбор, ты — свой, и кто-то
выигрывает раунд. Сыграем несколько раундов, посчитаем очки и в конце
объявим победителя матча.

По дороге познакомимся с новой полезной штукой — **перечислением**
(`enum`), научимся аккуратно превращать выбор игрока в число, разберём
красивый приём с остатком от деления для определения победителя и
сделаем ввод устойчивым к ерунде вроде `hello` или `5`.

## Что мы сделаем

К концу главы у нас будет программа `code/13-rps.c`, которая:

- предлагает выбрать камень, ножницы или бумагу (или выйти);
- сама случайно выбирает свой ход;
- говорит, кто выиграл раунд;
- ведёт счёт игрока и компьютера;
- играет столько раундов, сколько захочешь, а по команде выхода
  печатает итог матча.

Всё, что нужно, у тебя уже есть из прошлых глав: переменные, `if`,
циклы, функции (главы 2), массивы и строки (глава 3), а также
`rand`/`srand`/`time` для случайных чисел (глава 12). Случайность мы
заново разбирать не будем — просто пользуемся.

## Разбираем задачу руками

Сначала договоримся о правилах. Их три:

- камень бьёт ножницы (тупит лезвие);
- ножницы бьют бумагу (режут);
- бумага бьёт камень (заворачивает).

Если оба выбрали одно и то же — ничья.

Чтобы компьютер мог «думать», выбор нужно превратить в число. Закодируем
ходы так:

- `0` — камень;
- `1` — ножницы;
- `2` — бумага.

Кодировка не случайна. Посмотри, что бьёт что: камень (0) бьёт ножницы
(1), ножницы (1) бьют бумагу (2), бумага (2) бьёт камень (0). Каждый ход
бьёт **следующий по кругу**: 0→1→2→0. Эта закономерность скоро очень нам
пригодится.

Выпишем все девять исходов в таблицу. Слева — ход игрока, сверху — ход
компьютера, в клетке — кто выиграл (И = игрок, К = компьютер, Н =
ничья):

```text
              компьютер
            камень ножницы бумага
игрок   ┌─────────────────────────
камень  │   Н       И        К
ножницы │   К       Н        И
бумага  │   И       К        Н
```

По диагонали — ничьи (выбрали одинаково). Остальные клетки — кто кого
побил по правилам выше. Эту таблицу мы и научим программу заполнять.

## Шаг 1. Один раунд, выбор компьютера

Начнём с самого маленького: компьютер делает случайный ход, мы его
печатаем. Случайное число от 0 до 2 даёт `rand() % 3` — остаток от
деления на 3 всегда попадает в диапазон 0..2 (см. главу 12).

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

int main(void)
{
    srand((unsigned int)time(NULL));

    int computer = rand() % 3;
    printf("Компьютер выбрал: %d\n", computer);
    return 0;
}
```

Здесь всё знакомо по главе 12:

- `#include <stdlib.h>` — оттуда `rand` и `srand`.
- `#include <time.h>` — оттуда `time`.
- `srand((unsigned int)time(NULL));` — «встряхиваем» генератор текущим
  временем, чтобы при каждом запуске числа были разными.
- `rand() % 3` — случайное число, остаток от деления на 3, то есть 0, 1
  или 2.

Запуск печатает что-то вроде `Компьютер выбрал: 2`. Работает, но
человеку «2» ни о чём не говорит. Нужно показывать слово, а не число.

## Шаг 2. Превращаем число в слово

Можно было бы каждый раз писать `if (computer == 0) printf("камень")`
и так далее. Но это придётся повторять для игрока и для компьютера —
дублирование. Лучше сделать **функцию**, которая по числу возвращает
название хода.

Функция должна вернуть текст. Текст в Си — это массив символов, а доступ
к нему мы передаём через адрес первого символа, то есть через
**указатель на `char`** (см. главу 3). Поэтому тип результата —
`const char *`:

```c
const char *move_name(int m)
{
    if (m == 0) return "камень";
    if (m == 1) return "ножницы";
    return "бумага";
}
```

Разбор того, что здесь нового:

- `const char *` — тип возвращаемого значения: «указатель на символы»,
  то есть строка. Слово `const` означает «только для чтения»: вызывающий
  не должен менять эти буквы. Это разумно, ведь мы возвращаем
  **строковый литерал** — текст `"камень"`, зашитый в программу.
- `return "камень";` — возвращаем адрес начала этой строки. Строковый
  литерал живёт в памяти всё время работы программы, так что возвращать
  на него указатель безопасно.
- Третий вариант (`return "бумага";`) стоит без `if`: если число не 0 и
  не 1, остаётся только 2 — бумага.

Теперь вывод понятен человеку:

```c
printf("Компьютер выбрал: %s\n", move_name(computer));
```

`%s` печатает строку по указателю, который вернула функция (см. главу 3).

## Шаг 3. Даём имена числам — `enum`

Числа 0, 1, 2 работают, но в коде `if (m == 1)` непонятно, что такое
«1». Через месяц ты и сам забудешь. В Си для таких случаев есть
**перечисление** — `enum` (от англ. *enumeration*, «перечисление»).

`enum` позволяет дать числам понятные имена:

```c
enum Move { ROCK, SCISSORS, PAPER };
```

Что здесь происходит:

- `enum Move { ... }` — объявляем новый набор именованных целых
  констант под общим названием `Move`.
- `ROCK, SCISSORS, PAPER` — имена. По умолчанию `enum` раздаёт значения
  с нуля по порядку: `ROCK` это 0, `SCISSORS` это 1, `PAPER` это 2.
  Ровно наша кодировка! Можно задать и явно (`enum Move { ROCK = 0,
  SCISSORS = 1, PAPER = 2 };`), но и так сходится.

Имена `enum` — это обычные целые числа, просто с человеческим лицом.
Можно писать `ROCK` вместо `0` где угодно: в сравнениях, в `switch`, в
арифметике. Компилятор подставит число. Перепишем `move_name` понятнее:

```c
const char *move_name(int m)
{
    if (m == ROCK)     return "камень";
    if (m == SCISSORS) return "ножницы";
    return "бумага";
}
```

Логика та же, но теперь код читается как фраза: «если ход — камень,
верни "камень"». Имена-константы делают программу понятной без
комментариев.

## Шаг 4. Кто победил — наивный способ

Теперь главное: по двум ходам определить победителя. Самый честный путь
— просто перечислить все случаи, как в таблице. Сначала ничья, потом три
случая победы игрока, остальное — победа компьютера.

```c
int player = ROCK;        /* пока зашьём вручную, ввод будет позже */
int computer = rand() % 3;

if (player == computer) {
    printf("Ничья.\n");
} else if ((player == ROCK     && computer == SCISSORS) ||
           (player == SCISSORS  && computer == PAPER)    ||
           (player == PAPER     && computer == ROCK)) {
    printf("Ты выиграл раунд!\n");
} else {
    printf("Компьютер выиграл раунд.\n");
}
```

Разбор:

- `player == computer` — выбрали одинаково, значит ничья.
- большое условие через `||` («ИЛИ», см. главу 2) перечисляет три
  выигрышных для игрока расклада прямо по правилам: камень против
  ножниц, ножницы против бумаги, бумага против камня. Если хоть один
  верен — победа игрока.
- `else` ловит всё остальное: раз не ничья и не победа игрока, значит
  выиграл компьютер.

Это абсолютно правильно и понятно. Единственный минус — громоздко: три
строки условий, которые легко набрать с опечаткой. Покажу способ
короче.

## Шаг 5. Красивый приём с остатком

Вернёмся к замеченной закономерности: каждый ход бьёт **следующий по
кругу** (0→1→2→0). Посчитаем такое выражение:

```c
int result = (computer - player + 3) % 3;
```

Идея: насколько ход компьютера «опережает» ход игрока по кругу. Разберём
по кусочкам.

- `computer - player` — разница ходов. Может быть −2, −1, 0, 1 или 2.
- `+ 3` — добавляем 3, чтобы убрать минус. Остаток от деления
  отрицательного числа в Си ведёт себя неудобно, а после `+3` число
  точно неотрицательное.
- `% 3` — берём остаток от деления на 3. Прибавленная тройка на остаток
  не влияет (3 делится на 3 без остатка), зато минусы исчезли. Результат
  всегда 0, 1 или 2.

Что означают эти три значения? Проверим на каждой паре ходов:

- **0** — ходы равны (`computer == player`): ничья.
- **1** — компьютер на один шаг «впереди» игрока по кругу. Например,
  игрок камень (0), компьютер ножницы (1): `(1 - 0 + 3) % 3 = 1`. Камень
  бьёт ножницы — выиграл **игрок**.
- **2** — компьютер на два шага впереди (то же самое, что игрок на один
  шаг впереди компьютера). Например, игрок ножницы (1), компьютер камень
  (0): `(0 - 1 + 3) % 3 = 2`. Камень бьёт ножницы — выиграл
  **компьютер**.

Коротко: `0` — ничья, `1` — победа игрока, `2` — победа компьютера. Одна
строка заменила всю таблицу.

### Не верь на слово — проверь машиной

Два разобранных примера — это ещё не доказательство. Формулу легко
принять на веру и потом полдня искать, почему игра «странно судит».
Поэтому сделаем то, что вообще стоит делать с любым хитрым приёмом:
**прогоним оба способа по всем девяти парам ходов и сверим ответы**.

Файл — `code/13-rps-check.c`:

```c
#include <stdio.h>

enum Move { ROCK, SCISSORS, PAPER };

const char *move_name(int m)
{
    if (m == ROCK)     return "камень";
    if (m == SCISSORS) return "ножницы";
    return "бумага";
}

/* Наивный способ: 0 - ничья, 1 - игрок, 2 - компьютер. */
int winner_if(int player, int computer)
{
    if (player == computer) {
        return 0;
    }
    if ((player == ROCK     && computer == SCISSORS) ||
        (player == SCISSORS && computer == PAPER)    ||
        (player == PAPER    && computer == ROCK)) {
        return 1;
    }
    return 2;
}

/* Тот же ответ одной формулой. */
int winner_mod(int player, int computer)
{
    return (computer - player + 3) % 3;
}

int main(void)
{
    const char *who[3] = { "ничья", "игрок", "компьютер" };

    for (int p = 0; p < 3; p++) {
        for (int c = 0; c < 3; c++) {
            int a = winner_if(p, c);
            int b = winner_mod(p, c);
            printf("игрок %d (%s) против %d (%s): "
                   "if=%d формула=%d -> %s%s\n",
                   p, move_name(p), c, move_name(c), a, b, who[b],
                   (a == b) ? "" : "   <-- РАСХОЖДЕНИЕ!");
        }
    }
    return 0;
}
```

Что тут нового:

- **два вложенных цикла** `for` — внешний перебирает ходы игрока
  (0, 1, 2), внутренний при каждом из них перебирает ходы компьютера.
  Три на три — ровно девять сочетаний, ни одного не пропустим.
- `const char *who[3]` — массив из трёх строк-названий; `who[b]` берёт
  название по номеру исхода. Это тот же приём, что и `move_name`,
  только через массив вместо `if`.
- `(a == b) ? "" : "..."` — **тернарный оператор**: `условие ? одно :
  другое`. Если условие истинно, всё выражение равно первому значению,
  иначе — второму. Здесь он подставляет пустую строку, когда способы
  согласны, и заметное «РАСХОЖДЕНИЕ!», когда нет. Так глазами искать не
  надо: расхождение само бросится в глаза.
- строка формата разбита на две части подряд (`"игрок..." "if=..."`) —
  два строковых литерала рядом Си склеивает в один. Удобно, когда
  строка не влезает в ширину экрана.

Компилируем и запускаем:

```text
cc -std=c11 -Wall -Wextra -O2 code/13-rps-check.c -o rps-check
./rps-check
```

```text
игрок 0 (камень) против 0 (камень): if=0 формула=0 -> ничья
игрок 0 (камень) против 1 (ножницы): if=1 формула=1 -> игрок
игрок 0 (камень) против 2 (бумага): if=2 формула=2 -> компьютер
игрок 1 (ножницы) против 0 (камень): if=2 формула=2 -> компьютер
игрок 1 (ножницы) против 1 (ножницы): if=0 формула=0 -> ничья
игрок 1 (ножницы) против 2 (бумага): if=1 формула=1 -> игрок
игрок 2 (бумага) против 0 (камень): if=1 формула=1 -> игрок
игрок 2 (бумага) против 1 (ножницы): if=2 формула=2 -> компьютер
игрок 2 (бумага) против 2 (бумага): if=0 формула=0 -> ничья
```

Девять строк, в каждой `if` и `формула` дали одно и то же, ни одного
«РАСХОЖДЕНИЕ!». Сверь заодно колонку исходов с таблицей из начала главы
— всё сходится: по диагонали ничьи, камень бьёт ножницы, ножницы бьют
бумагу, бумага бьёт камень.

Приём работает только потому, что мы заранее **удачно занумеровали**
ходы (каждый бьёт следующего по кругу). Поменяй кодировку — и формула
сломается. Убедись сам: поменяй в `enum Move` местами `SCISSORS` и
`PAPER` и перезапусти проверку — шесть строк из девяти загорятся
«РАСХОЖДЕНИЕ!», и врать будет именно формула. Если такой трюк кажется
слишком хитрым, оставь явные `if` из шага 4: они длиннее, но понятнее,
и это нормальный выбор. Мы возьмём короткую формулу — теперь она
подкреплена проверкой, а не обещанием.

## Шаг 6. Ввод игрока с проверкой

Игрок должен вводить свой ход. Хочется принимать число (0, 1 или 2) и
букву `q` для выхода, и при этом не падать от мусора вроде `hello` или
`7`.

Прочитаем ввод как одно «слово» в буфер, а потом разберёмся, что это.
Так мы не запутаемся, цифру ввели или букву.

```c
char buf[16];

if (scanf("%15s", buf) != 1) {
    break;              /* ввод кончился (Ctrl+D) - выходим */
}

if (buf[0] == 'q' || buf[0] == 'Q') {
    break;
}

if (buf[0] < '0' || buf[0] > '2' || buf[1] != '\0') {
    printf("Не понял. Введи 0, 1, 2 или q.\n");
    continue;
}

int player = buf[0] - '0';
```

Разбираем построчно:

- `char buf[16];` — массив символов на 16 байт под введённое слово (см.
  главу 3). С большим запасом.
- `scanf("%15s", buf)` — читаем слово (до пробела) в `buf`. Перед `buf`
  нет `&`: имя массива само по себе — адрес начала (см. главу 3). `%15s`
  ограничивает чтение 15 символами, чтобы не переполнить буфер из 16
  (последний байт — под `'\0'`). `scanf` возвращает, сколько значений он
  успешно прочитал; `!= 1` означает «прочитать не удалось» — обычно это
  конец ввода (Ctrl+D). Тогда `break` выходит из цикла. Проверять
  результат `scanf` мы научились в главе 12.
- `buf[0] == 'q' || buf[0] == 'Q'` — первый символ буквы выхода, в любом
  регистре. Если это `q` — выходим из цикла через `break`.
- большое `if` — проверка корректности. Условие верно (значит ввод
  плохой), если выполнено хоть что-то:
  - `buf[0] < '0' || buf[0] > '2'` — первый символ не цифра из набора
    0,1,2. Символы сравниваем как числа (у `char` есть числовой код, см.
    главу 2), а цифры в таблице символов идут подряд, поэтому такое
    сравнение работает.
  - `buf[1] != '\0'` — после первого символа сразу должен стоять конец
    строки `'\0'`. Если там что-то есть, значит ввели больше одного
    символа (например `12` или `5x`) — это не наш одиночный ход. Про
    `'\0'` как конец строки — глава 3.
  - при плохом вводе печатаем подсказку и `continue` — переходим к
    следующему витку цикла, заново спрашиваем ход.
- `int player = buf[0] - '0';` — превращаем символ-цифру в число.
  Хитрость в том, что коды символов `'0'`, `'1'`, `'2'` идут подряд.
  Значит `'0' - '0'` это 0, `'1' - '0'` это 1, `'2' - '0'` это 2.
  Вычитание кода `'0'` переводит символ цифры в само число. Это
  стандартный приём, запомни его.

Два честных замечания про эту защиту — чтобы ты знал её границы.

Во-первых, на выход мы смотрим только **первый** символ. Значит, `quit`
и даже `qwerty` тоже закончат матч. Для игры это скорее удобно (человек
пишет `quit` — программа его понимает), но помни: это осознанная
поблажка, а не забытая проверка. Захочешь строгости — допиши
`&& buf[1] == '\0'`, как в проверке цифры.

Во-вторых, `%15s` берёт не больше 15 символов за раз. Если сгоряча
набрать двадцать букв, `scanf` отдаст первые 15, а оставшиеся пять
подхватит **следующий** вызов — и «Не понял» напечатается дважды на
один ввод. Программа не ломается, просто переспрашивает лишний раз.
А вот убрать `15` из формата нельзя ни в коем случае: голый `%s` не
знает, сколько места в приёмнике, и длинное слово уедет за границу
`buf`, затирая соседнюю память (глава 3 предупреждала: следить за
размером приёмника — работа программиста, никто её за тебя не сделает).
Ошибка тихая и крайне неприятная: программа может ещё долго
притворяться рабочей.

## Полная программа

Собираем всё вместе: цикл раундов, счёт, итог матча. Это и есть файл
`code/13-rps.c`.

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

enum Move { ROCK, SCISSORS, PAPER };

const char *move_name(int m)
{
    if (m == ROCK)     return "камень";
    if (m == SCISSORS) return "ножницы";
    return "бумага";
}

int main(void)
{
    srand((unsigned int)time(NULL));

    int player_score = 0;
    int computer_score = 0;
    int rounds = 0;
    char buf[16];

    printf("Камень, ножницы, бумага!\n");
    printf("Выбор: 0 - камень, 1 - ножницы, 2 - бумага, q - выход.\n");

    while (1) {
        printf("\nТвой ход: ");

        if (scanf("%15s", buf) != 1) {
            break;              /* ввод кончился (Ctrl+D) - выходим */
        }

        if (buf[0] == 'q' || buf[0] == 'Q') {
            break;
        }

        if (buf[0] < '0' || buf[0] > '2' || buf[1] != '\0') {
            printf("Не понял. Введи 0, 1, 2 или q.\n");
            continue;
        }

        int player = buf[0] - '0';
        int computer = rand() % 3;

        printf("Ты: %s. Компьютер: %s. ",
               move_name(player), move_name(computer));

        int result = (computer - player + 3) % 3;

        if (result == 0) {
            printf("Ничья.\n");
        } else if (result == 1) {
            printf("Ты выиграл раунд!\n");
            player_score++;
        } else {
            printf("Компьютер выиграл раунд.\n");
            computer_score++;
        }

        rounds++;
    }

    printf("\n=== Итог ===\n");
    printf("Сыграно раундов: %d\n", rounds);
    printf("Ты: %d, компьютер: %d.\n", player_score, computer_score);

    if (player_score > computer_score) {
        printf("Поздравляю, ты победил в матче!\n");
    } else if (player_score < computer_score) {
        printf("Компьютер оказался сильнее. В другой раз!\n");
    } else {
        printf("Ничья по матчу.\n");
    }

    return 0;
}
```

## Как это работает

- В начале `main` заводим три счётчика: `player_score`,
  `computer_score` и `rounds` (сколько раундов сыграно). Все по нулям.
- `while (1)` — **бесконечный цикл**. Условие `1` — это всегда «истина»
  (ложь — 0, истина — любое ненулевое, см. главу 2). Сам по себе такой
  цикл не кончится никогда; выходим из него вручную через `break` —
  когда игрок ввёл `q` или ввод закончился. `break` мгновенно
  прекращает цикл и передаёт управление строкам после него.
- Внутри: спрашиваем ход, проверяем ввод (шаг 6), получаем `player`,
  бросаем кубик за компьютер (`rand() % 3`), печатаем оба хода.
- `result = (computer - player + 3) % 3` — определяем победителя одной
  формулой (шаг 5). По её значению печатаем итог раунда и при победе
  увеличиваем нужный счётчик через `++` (см. главу 2).
- `rounds++` в конце витка считает сыгранные раунды (плохой ввод сюда не
  доходит — там был `continue`).
- После цикла печатаем итог: сколько раундов, какой счёт, и кто победил
  в матче — сравнением `player_score` и `computer_score`.

Функция `move_name` стоит **выше** `main`, потому что `main` её
вызывает, а функцию нужно объявить до вызова (см. главу 2).

## Проверяем

Скомпилируй и запусти:

```text
cc -std=c11 -Wall -Wextra -O2 code/13-rps.c -o rps
./rps
```

Сыграем матч из трёх раундов: камень, ножницы, бумага — и `q`. Ходы
компьютера у тебя будут свои, они случайные:

```text
Камень, ножницы, бумага!
Выбор: 0 - камень, 1 - ножницы, 2 - бумага, q - выход.

Твой ход: 0
Ты: камень. Компьютер: камень. Ничья.

Твой ход: 1
Ты: ножницы. Компьютер: бумага. Ты выиграл раунд!

Твой ход: 2
Ты: бумага. Компьютер: ножницы. Компьютер выиграл раунд.

Твой ход: q

=== Итог ===
Сыграно раундов: 3
Ты: 1, компьютер: 1.
Ничья по матчу.
```

Все три исхода в одной партии: ничья, победа игрока, победа компьютера.
Сверь их с таблицей — ножницы против бумаги действительно наши, бумага
против ножниц действительно нет.

Теперь защита ввода — подсунем мусор перед нормальным ходом:

```text
Камень, ножницы, бумага!
Выбор: 0 - камень, 1 - ножницы, 2 - бумага, q - выход.

Твой ход: 5
Не понял. Введи 0, 1, 2 или q.

Твой ход: hello
Не понял. Введи 0, 1, 2 или q.

Твой ход: 1
Ты: ножницы. Компьютер: бумага. Ты выиграл раунд!

Твой ход: q

=== Итог ===
Сыграно раундов: 1
Ты: 1, компьютер: 0.
Поздравляю, ты победил в матче!
```

`5` и `hello` программа отвергла и переспросила, а `1` приняла и
сыграла раунд. Ни падения, ни зацикливания, и в счёт раундов мусор не
попал: сыгран ровно один.

Осталось проверить края. Что будет, если выйти сразу, не сыграв ни
одного раунда? Или если ввод оборвётся на Ctrl+D? Оба случая дают одно
и то же — и это правильно:

```text
Камень, ножницы, бумага!
Выбор: 0 - камень, 1 - ножницы, 2 - бумага, q - выход.

Твой ход: q

=== Итог ===
Сыграно раундов: 0
Ты: 0, компьютер: 0.
Ничья по матчу.
```

Ноль раундов, ноль очков, «ничья по матчу». Программа не объявляет
победителя из воздуха — просто честно показывает пустой итог. Ctrl+D
вместо `q` даёт тот же результат, оба пути ведут к одному `break`:

```text
Камень, ножницы, бумага!
Выбор: 0 - камень, 1 - ножницы, 2 - бумага, q - выход.

Твой ход: ^D
=== Итог ===
Сыграно раундов: 0
Ты: 0, компьютер: 0.
Ничья по матчу.
```

Разница только в одной пустой строке: после `q` ты нажимаешь Enter, и
терминал переводит строку сам, а Ctrl+D никакого перевода не даёт — его
место занимает `\n` из `printf("\n=== Итог ===\n")`.

Играть удобно и через конвейер (pipe), не набирая ходы руками:

```text
printf '0\n1\n2\nq\n' | ./rps
```

Только имей в виду: в конвейере строчки «Твой ход:» останутся без
ответа рядом. Эхо набранных символов рисует терминал, а тут никто
ничего не набирает — программа читает ходы из трубы молча. Партия
пройдёт правильно, но выглядеть будет непривычно.

## Частые ошибки

**Перепутанная кодировка ходов.** Формула `(computer - player + 3) % 3`
работает только при нумерации 0=камень, 1=ножницы, 2=бумага (каждый бьёт
следующего по кругу). Если занумеруешь иначе, формула начнёт врать — мы
это видели, переставив в `enum` два имени. Тогда честнее вернуться к
явным `if` из шага 4. И заведи себе привычку: любой приём, который
работает «магически», проверяй прогоном по всем случаям, как в
`13-rps-check.c`. Девять комбинаций перебираются за секунду, а
пойманная так ошибка не доживёт до игрока.

**Минус в остатке.** Без `+ 3` выражение `(computer - player) % 3` для
отрицательной разницы даст отрицательный остаток, и сравнения с 1 и 2
сломаются. Тройка гарантирует неотрицательное число перед `%`.

**`'1'` это не 1.** Символ цифры и само число — разные вещи: код символа
`'1'` равен 49, а не 1. Чтобы получить число, вычитаем `'0'`:
`buf[0] - '0'`. Забудешь — получишь чушь.

**Ввод одним символом.** Если читать ход через `scanf("%d", ...)`, то на
`hello` программа зациклится: `scanf` не сможет прочитать число и не
сдвинет ввод. Поэтому мы читаем слово через `%s` и разбираем его сами —
так проще не запутаться.

**Бесконечный цикл без выхода.** В `while (1)` обязательно должен быть
`break` (или другой выход), иначе программа повиснет. У нас выходов
два — по `q` и по концу ввода, — и второй важнее, чем кажется. Забудешь
проверить результат `scanf`, и на Ctrl+D программа закрутится вхолостую:
буфер пуст, читать нечего, а цикл всё равно просит ход.

**`%s` без ограничения длины.** `scanf("%s", buf)` читает столько,
сколько введут, и молча вылезает за границу массива. Всегда указывай
предел — `%15s` для `char buf[16]`. Число в формате на единицу меньше
размера массива: последний байт нужен под `'\0'`.

**Счётчик раундов не там, где надо.** `rounds++` стоит в самом конце
витка, после всех проверок. Поставь его сразу после `printf("Твой
ход: ")` — и в итог попадут «раунды», на которых игрок ввёл `hello`.
Правило то же, что в главе 12: сначала отсеиваем всё, что ходом не
является, и только потом считаем.

## Упражнения

1. **Best of 5.** Останавливай матч автоматически, как только кто-то
   набрал 3 победы (или сыграно 5 раундов). Подскажу: добавь условие
   выхода из цикла по `player_score` и `computer_score`.
2. **Колодец (расширенный вариант).** Сделай игру на пять ходов:
   добавь «колодец» и «ящерицу» (или «огонь» и «воду»). Продумай новую
   таблицу побед. Подумай, можно ли обобщить формулу с остатком — или
   проще задать таблицу исходов массивом. И обязательно переделай
   `13-rps-check.c` под пять ходов: там будет уже 25 сочетаний, руками
   их не проверишь.
3. **Статистика.** В конце матча печатай, сколько было ничьих и какой
   ход ты выбирал чаще всего. Заведи счётчики ничьих и трёх ходов
   (можно массивом из трёх элементов, индекс — номер хода).
4. **Усиленная защита ввода.** Принимай не только цифры, но и первые
   буквы: `к` — камень, `н` — ножницы, `б` — бумага. (Помни: русская
   буква в UTF-8 занимает несколько байт, см. главу 3 — проще принимать
   латинские `r`, `s`, `p`.)
5. **Человеческая подсказка.** Если игрок проиграл раунд, печатай, чем
   его можно было побить ход компьютера: «бумага побила бы камень».
6. **Серия побед.** Считай и показывай самую длинную серию подряд
   выигранных тобой раундов за матч.
