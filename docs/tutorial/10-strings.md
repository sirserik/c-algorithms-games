# Глава 10. Строковые алгоритмы: длина, переворот, палиндром, слова, анаграммы

Строка в Си — это массив символов с меткой конца `'\0'` (глава 3). А раз
это массив, над ним можно гонять циклы и считать что угодно: длину,
число слов, симметрию, состав букв. В этой главе мы напишем четыре
маленьких, но настоящих строковых алгоритма — не вызывая готовых
функций, а собирая логику руками.

Заодно познакомимся с `<ctype.h>` — набором функций «а это буква? а
цифра? а пробел?» — и с одной ловушкой, которая ждёт там всех новичков и
половину не-новичков.

## Что мы сделаем

Четыре программы, каждая в своём файле:

- `10-reverse.c` — своя функция длины строки и переворот строки на месте;
- `10-palindrome.c` — читается ли фраза одинаково с двух концов, если
  не обращать внимания на регистр и знаки препинания;
- `10-words.c` — подсчёт слов во фразе и длина самого длинного слова;
- `10-anagram.c` — состоят ли две фразы из одних и тех же букв.

Нового синтаксиса тут почти нет — массивы, циклы, `if` и `char`. Вся
соль в **идеях алгоритмов** и в краевых случаях: пустая строка, строка
из одного символа, три пробела подряд, заглавные буквы.

Сразу предупреждение, к которому мы вернёмся с живым примером: **вводим
только латиницу, цифры, пробелы и знаки препинания**. Почему русские
буквы ломают посимвольные алгоритмы — покажу через пару страниц, когда
у нас будет работающая программа, на которой это видно.

## Часть 1. Длина и переворот строки

### Разбираем задачу руками

Возьмём слово `hello`. Перевернуть его — значит получить `olleh`. Как
это сделать «на бумаге»? Поставим палец слева (на `h`) и палец справа
(на `o`) и **поменяем их местами**:

```text
h e l l o     меняем края: h и o
^       ^

o e l l h     сдвинули пальцы к центру, меняем e и l
  ^   ^

o l l e h     пальцы встретились на середине — готово
    ^
```

Когда пальцы встретились (или перекрестились) — всё, строка перевёрнута.
Средняя буква (если длина нечётная) остаётся на месте, и правильно:
двигать её некуда. Этот приём — **два индекса с концов** — мы будем
использовать постоянно: и здесь, и в палиндроме, и потом в сортировках.

Но прежде чем переворачивать, надо знать **длину** строки: где правый
край. Длину можно взять из `strlen`, но давай напишем свою — так ты раз
и навсегда поймёшь, как Си «видит» конец строки.

### Шаг 1. Своя функция длины

Строка заканчивается невидимым символом `'\0'` (нулевой байт). Значит,
длина — это сколько символов лежит **до** него. Идём циклом, пока не
упрёмся в `'\0'`, и считаем шаги:

```c
int my_strlen(const char *s)
{
    int len = 0;
    while (s[len] != '\0') {
        len++;
    }
    return len;
}
```

Разбор:

- `const char *s` — параметр-строка. `char *` — указатель на символы,
  то есть адрес начала строки (вспомни главу 3: имя массива — это адрес
  его первого элемента). Слово `const` — обещание «я эту строку менять
  не буду, только читаю». Компилятор за этим проследит: попытка
  написать `s[0] = 'x'` внутри такой функции не скомпилируется.
- `s[len]` — `len`-й символ строки. К указателю на символы можно
  обращаться по индексу точно так же, как к массиву.
- `while (s[len] != '\0')` — крутимся, **пока** текущий символ не
  нулевой. `!=` — «не равно». `'\0'` в одинарных кавычках — это один
  символ с кодом 0, метка конца строки.
- На каждом шаге `len++` — продвигаемся дальше. Когда `s[len]` окажется
  `'\0'`, цикл встанет, а в `len` будет ровно число символов до него.
  Его и возвращаем.

Сам `'\0'` в длину **не входит** — мы останавливаемся на нём, не
посчитав. Так же работает и настоящий `strlen` из `<string.h>`. Одно
отличие: `strlen` возвращает не `int`, а `size_t` — беззнаковый целый
тип, специально придуманный под размеры (его печатают через `%zu`, см.
главу 3). Нам в маленьких примерах хватит `int`, но знай, что
«настоящая» подпись такая:

```c
size_t strlen(const char *s);
```

### Шаг 2. Наивный переворот — и сюрприз при запуске

Прочитаем строку через `fgets` и сразу перевернём. Сам приём с двумя
индексами мы уже придумали, так что напишем в лоб и запустим:

```c
#include <stdio.h>

int my_strlen(const char *s)
{
    int len = 0;
    while (s[len] != '\0') {
        len++;
    }
    return len;
}

int main(void)
{
    char line[100];
    printf("Введи строку (латиницей): ");
    fgets(line, sizeof line, stdin);

    int len = my_strlen(line);
    printf("Длина: %d\n", len);

    int i = 0, j = len - 1;
    while (i < j) {
        char tmp = line[i];
        line[i] = line[j];
        line[j] = tmp;
        i++;
        j--;
    }

    printf("Перевёрнутая: %s\n", line);
    return 0;
}
```

- `char line[100]` — буфер под строку: сто ячеек типа `char`.
- `fgets(line, sizeof line, stdin)` — читает строку с клавиатуры. Три
  аргумента: куда класть, сколько байт максимум можно занять, откуда
  читать (`stdin` — стандартный ввод, клавиатура). `sizeof line` — это
  100, размер массива в байтах; так `fgets` физически не сможет вылезти
  за границу. Именно поэтому `fgets`, а не `gets`: у `gets` размера нет,
  и любая длинная строка затирает соседнюю память. `gets` настолько
  плох, что его выкинули из стандарта.
- `char tmp` — временная коробка для обмена. Чтобы поменять два значения
  местами, одно надо где-то придержать, иначе затрёшь (тот же приём
  `swap`, что в главе 3, только для символов).

Собираем и вводим `hello`:

```text
$ cc -std=c11 -Wall -Wextra -O2 naive-reverse.c -o naive-reverse
$ ./naive-reverse
Введи строку (латиницей): hello
Длина: 6
Перевёрнутая: 
olleh
```

Два странных факта разом. Во-первых, длина слова `hello` почему-то
**6**, а не 5. Во-вторых, результат `olleh` уехал на новую строку, а
перед ним пустая.

### Шаг 3. Виноват `'\n'` от fgets — убираем его

Когда ты нажимаешь Enter, в строку попадает символ перевода строки
`'\n'`, и `fgets` его **не выбрасывает**, а честно кладёт в буфер. То
есть в `line` лежит не `hello`, а `hello\n` — шесть символов. Вот и
«Длина: 6».

Дальше понятно: переворот шести символов поставил `'\n'` в самое начало,
получилось `\nolleh`. `printf` напечатал перевод строки, потом `olleh`.
Отсюда и пустая строка.

Лечится это всегда одинаково: после `fgets` смотрим на последний символ,
и если это `'\n'` — затираем его на `'\0'`. Вынесем в функцию, она нам
понадобится во всех четырёх программах:

```c
/* Срезает хвостовой '\n', который оставляет после себя fgets. */
void chomp(char *s)
{
    int len = my_strlen(s);
    if (len > 0 && s[len - 1] == '\n') {
        s[len - 1] = '\0';
    }
}
```

- `void` — функция ничего не возвращает. Она меняет саму строку: ей
  передают адрес, поэтому правки видны снаружи (глава 3).
- `char *s` — здесь без `const`: мы как раз собираемся строку менять.
- `len > 0` — защита от пустой строки. Если в `s` сразу `'\0'`, длина 0,
  и без этой проверки мы полезли бы в `s[-1]` — чтение и запись за левой
  границей массива.
- `s[len - 1]` — последний реальный символ (индексы с нуля, поэтому
  последний — это `len - 1`).
- `s[len - 1] = '\0';` — ставим метку конца на место `'\n'`. Теперь для
  всех функций строка кончается раньше, а `'\n'` как бы исчез. Байт-то
  на месте, просто до него никто уже не дойдёт.

А почему `&&`, а не два вложенных `if`? `&&` — это «и»: условие верно,
только если верны обе половины. И у него есть важное свойство —
**короткое замыкание**: если левая половина ложна, правую Си даже не
считает. Поэтому при `len == 0` выражение `s[len - 1]` вообще не
вычисляется. Порядок половин здесь не случаен, менять их местами нельзя.

Этот кусочек тебе понадобится после **каждого** `fgets`. Запомни его как
рефлекс.

### Полная программа: `10-reverse.c`

```c
#include <stdio.h>

/* Своя длина строки: считаем символы до '\0'. */
int my_strlen(const char *s)
{
    int len = 0;
    while (s[len] != '\0') {
        len++;
    }
    return len;
}

/* Срезает хвостовой '\n', который оставляет после себя fgets. */
void chomp(char *s)
{
    int len = my_strlen(s);
    if (len > 0 && s[len - 1] == '\n') {
        s[len - 1] = '\0';
    }
}

int main(void)
{
    char line[100];

    printf("Введи строку (латиницей): ");
    if (fgets(line, sizeof line, stdin) == NULL) {
        return 0;                       /* ввода не было */
    }
    chomp(line);

    int len = my_strlen(line);

    /* Переворот на месте: меняем местами края, идём к центру. */
    int i = 0;
    int j = len - 1;
    while (i < j) {
        char tmp = line[i];
        line[i] = line[j];
        line[j] = tmp;
        i++;
        j--;
    }

    printf("Длина: %d\n", len);
    printf("Перевёрнутая: %s\n", line);
    return 0;
}
```

Что изменилось против наивной версии:

- `if (fgets(...) == NULL)` — `fgets` возвращает адрес буфера при успехе
  и `NULL`, если читать было нечего: файл кончился или пользователь
  нажал Ctrl+D. Тогда в `line` остаётся мусор, и работать с ним нельзя.
  Проверять результат ввода — хорошая привычка, мы её заводим тут.
- `chomp(line);` сразу после чтения, и только потом считаем длину.
- `while (i < j)` — крутимся, пока левый индекс левее правого. Как
  только они встретились в центре (`i == j`) или разошлись — конец.

### Проверяем

```text
$ cc -std=c11 -Wall -Wextra -O2 10-reverse.c -o 10-reverse
$ ./10-reverse
Введи строку (латиницей): hello
Длина: 5
Перевёрнутая: olleh
```

Длина стала 5, лишнего переноса нет. Теперь краевые случаи — их надо
проверять всегда, а не «когда-нибудь потом».

Пустая строка (просто Enter):

```text
$ ./10-reverse
Введи строку (латиницей): 
Длина: 0
Перевёрнутая: 
```

Один символ:

```text
$ ./10-reverse
Введи строку (латиницей): x
Длина: 1
Перевёрнутая: x
```

Два символа:

```text
$ ./10-reverse
Введи строку (латиницей): ab
Длина: 2
Перевёрнутая: ba
```

При длине 0 у нас `i = 0`, `j = -1`, условие `0 < -1` ложно — цикл не
крутится ни разу, в `line[-1]` мы не лезем. При длине 1: `i = 0`,
`j = 0`, условие `0 < 0` тоже ложно. Оба вырожденных случая обработались
сами, без единого дополнительного `if`, — просто потому, что условие
цикла написано через `<`, а не через `<=`. Напиши мы `while (i <= j)` —
при `i == j` символ поменялся бы сам с собой (не страшно), а вот при
длине 0 мы бы шагнули в `line[-1]`.

### Обещанная демонстрация: почему только латиница

Теперь у нас есть рабочая программа, и на ней видно, что происходит с
русским текстом. Вводим `привет` — шесть букв:

```text
$ ./10-reverse
Введи строку (латиницей): привет
Длина: 12
```

**Длина 12**, а не 6. Дело в кодировке. Современные системы хранят текст
в **UTF-8**, где латинская буква, цифра, пробел и знак препинания
занимают ровно **1 байт**, а русская буква — **2 байта**. Посмотрим на
байты слова `привет`:

```text
$ printf 'привет' | od -An -tx1
           d0  bf  d1  80  d0  b8  d0  b2  d0  b5  d1  82
```

`od` печатает байты числами в шестнадцатеричном виде (`-tx1` — «по
одному байту в шестнадцатеричном»), `-An` убирает столбик со смещениями.
Двенадцать чисел — это шесть пар. `d0 bf` — буква «п», `d1 80` — «р», и
так далее. Для программы на Си строка — просто байты, никаких «букв» она
не знает. `my_strlen` честно насчитал 12.

Посмотрим теперь на байты, которые программа напечатала (берём хвост
вывода — 14 последних байт):

```text
$ printf 'привет\n' | ./10-reverse | tail -c 14 | od -An -tx1
           20  82  d1  b5  d0  b2  d0  b8  d0  80  d1  bf  d0  0a
```

Первый байт `20` — это пробел после двоеточия в «Перевёрнутая: »,
последний `0a` — перевод строки. Между ними наши двенадцать байт, только
в обратном порядке. Пары развалились: было `d0 bf`, стало `bf d0`. Таких
пар в UTF-8 не бывает, поэтому терминал печатает вместо букв
вопросительные знаки и случайные закорючки — то, что в народе зовут
кракозябрами.

Вывод простой: **в этой главе вводим только латиницу**. Русский текст
годится для сообщений (`printf` печатает байты как есть, ничего не
разбирая), но не для посимвольной обработки. Полноценная работа с
Юникодом — отдельная большая тема, она за рамками книги.

## Часть 2. Палиндром

**Палиндром** — фраза, которая читается одинаково слева направо и справа
налево: `level`, `radar`, `noon`. А `world` — не палиндром.

### Наивная версия: сравниваем в лоб

Приём тот же, что в перевороте — два индекса с концов, — только теперь
мы ничего не меняем, а **сравниваем**. Левый символ должен совпадать с
правым, второй слева — со вторым справа, и так до центра. Нашли хоть
одно несовпадение — не палиндром, дальше можно не проверять.

```c
    int i = 0;
    int j = my_strlen(line) - 1;
    int is_palindrome = 1;              /* пока считаем, что да */
    while (i < j) {
        if (line[i] != line[j]) {
            is_palindrome = 0;          /* нашли несовпадение */
            break;
        }
        i++;
        j--;
    }
```

- `int is_palindrome = 1;` — **флаг**: переменная-да/нет. `1` — «истина»,
  `0` — «ложь». Отдельного типа `bool` в Си без `<stdbool.h>` нет,
  поэтому просто берём `int`. Начинаем с оптимизма: считаем фразу
  палиндромом, пока не доказано обратное.
- `break;` — досрочный выход из цикла. Раз нашли несовпадение, дальше
  проверять незачем, ответ уже известен. `break` обрывает ближайший
  цикл, а выполнение продолжается со строки после него.

Собираем и гоняем на четырёх примерах:

```text
$ ./naive-palindrome
Введи строку (латиницей): level
"level" — палиндром
$ ./naive-palindrome
Введи строку (латиницей): Level
"Level" — не палиндром
$ ./naive-palindrome
Введи строку (латиницей): never odd or even
"never odd or even" — не палиндром
$ ./naive-palindrome
Введи строку (латиницей): A man, a plan, a canal: Panama
"A man, a plan, a canal: Panama" — не палиндром
```

Первый ответ верный, остальные три — обидные. `Level` не палиндром
только потому, что `'L'` и `'l'` — **разные символы** с разными кодами
(76 и 108). `never odd or even` спотыкается на пробелах: слева первый
символ `n`, справа последний `n`, но дальше пробелы стоят не
симметрично. А знаменитая фраза про Панаму валится ещё и на запятых с
двоеточием.

Люди-то читают палиндром иначе: они смотрят только на **буквы** и не
различают заглавные со строчными. Значит, и программа должна сначала
выкинуть всё лишнее, а уже потом сравнивать.

### Знакомимся: `<ctype.h>`

Чтобы «выкинуть всё, что не буква», нужно уметь спрашивать: а этот
символ — буква? Написать проверку руками можно:

```c
if ((c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z')) { ... }
```

Но в стандартной библиотеке это уже есть. Заголовок `<ctype.h>`
(*character type* — тип символа) даёт целый набор:

```c
int isalpha(int c);   /* буква?            'a', 'Z' -> не 0 */
int isdigit(int c);   /* цифра?            '0'..'9' -> не 0 */
int isalnum(int c);   /* буква или цифра? */
int isspace(int c);   /* пробельный?       ' ', '\t', '\n', '\r' -> не 0 */
int isupper(int c);   /* заглавная буква? */
int islower(int c);   /* строчная буква? */
int ispunct(int c);   /* знак препинания? */

int tolower(int c);   /* 'A' -> 'a', остальное возвращает как есть */
int toupper(int c);   /* 'a' -> 'A', остальное возвращает как есть */
```

Все они возвращают `int`. Функции семейства `is...` возвращают **не
ноль**, если ответ «да», и ноль, если «нет». Не обязательно 1 — просто
что-то ненулевое, поэтому пиши `if (isalpha(c))`, а не
`if (isalpha(c) == 1)`. `tolower`/`toupper` возвращают уже сам символ
(его код), причём символ, не подходящий под переделку, возвращают
нетронутым: `tolower('5')` — это `'5'`.

### Ловушка: почему `(unsigned char)`

А теперь главное про `<ctype.h>`. Посмотри на подпись: аргумент —
**`int`**, а не `char`. Не случайно. Стандарт требует, чтобы значение
аргумента было либо кодом символа в диапазоне `unsigned char` (0..255),
либо `EOF` (обычно −1). Всё остальное — **неопределённое поведение**.

Где тут подвох? В том, что тип `char` в Си **может быть знаковым**, и на
x86 и на ARM он именно такой: диапазон −128..127. Байт `0xD0` (первый
байт русской «п») в такой `char` попадает как **−48**. Передашь его в
`isalpha` — и передашь отрицательное число, которого там быть не должно.

`isalpha` и `tolower` внутри устроены как таблица: берём код символа,
лезем по этому индексу в массив признаков, читаем ответ. Отрицательный
аргумент — это обращение к массиву **до его начала**. Некоторые
библиотеки специально держат под таблицей запасные ячейки, и у них такой
вызов «прокатывает»; другие — нет. Гадать, повезёт тебе или нет, не
надо: стандарт этого не обещает.

Проверим на своей собственной таблице — ровно такой же, какую держит
библиотека:

```c
#include <stdio.h>
#include <ctype.h>

int main(void)
{
    char word[] = "\xd0\xbf";   /* два байта русской буквы "п" в UTF-8 */
    int count[256] = {0};

    for (int i = 0; word[i] != '\0'; i++) {
        printf("байт %d: char = %d\n", i, word[i]);
        count[word[i]]++;       /* БЕЗ приведения к unsigned char */
    }
    printf("готово\n");
    return 0;
}
```

Компилятор ругается ещё до запуска — и правильно делает:

```text
$ cc -std=c11 -Wall -Wextra -O1 -g -fsanitize=address,undefined \
     badcast.c -o badcast
badcast.c:11:14: warning: array subscript is of type 'char' [-Wchar-subscripts]
   11 |         count[word[i]]++;       /* БЕЗ приведения к unsigned char */
      |              ^~~~~~~~
1 warning generated.
```

`-Wchar-subscripts` — «индекс массива имеет тип `char`». Это ровно наш
случай. Запускаем — и санитайзер ловит промах:

```text
$ ./badcast
байт 0: char = -48
badcast.c:11:9: runtime error: index -48 out of bounds for type 'int[256]'
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior badcast.c:11:9
байт 1: char = -65
готово
```

`index -48 out of bounds` — мы прибавили единицу к памяти, лежащей за
192 байта левее нашего массива. Что там было? Может, другая переменная.
Может, ничего важного. Может, служебные данные функции. Программа не
упала — и это худший вариант: такие ошибки живут годами и всплывают
случайно.

Лечение простое и универсальное: **приводи символ к `unsigned char`**
перед тем, как использовать его как индекс или отдавать в `<ctype.h>`.

```c
unsigned char c = (unsigned char)line[k];
if (isalpha(c)) { ... }
```

`(unsigned char)` — это **приведение типа**: «посмотри на этот байт как
на беззнаковое число». Байт `0xD0` из −48 превращается в 208, и всё
попадает в разрешённый диапазон 0..255.

Запомни правило целиком: **любой `char`, который идёт в `<ctype.h>` или
в индекс массива-таблицы, сначала приводим к `unsigned char`**. Забыть
эту скобку — самая частая необнаруженная ошибка в коде со строками.

### Идея: сначала чистим, потом сравниваем

Раз сравнивать надо только буквы и без учёта регистра, разобьём задачу
на два шага:

1. **Нормализация.** Проходим по строке и переписываем в новый массив
   только буквы, каждую — в нижнем регистре. `A man, a plan, a canal:
   Panama` превращается в `amanaplanacanalpanama`.
2. **Сравнение.** К чистой строке применяем ровно тот же приём двух
   индексов, что и раньше, — теперь ему ничто не мешает.

Так каждый шаг делает одну понятную вещь. И бонусом мы сможем напечатать
промежуточный результат — читателю сразу видно, что программа сравнивала
на самом деле.

Насколько большой нужен второй массив? Мы кладём в него не больше
символов, чем есть в исходной строке, значит, буфера того же размера
хватит с запасом. Возьмём оба по 200.

### Полная программа: `10-palindrome.c`

```c
#include <stdio.h>
#include <ctype.h>

int my_strlen(const char *s)
{
    int len = 0;
    while (s[len] != '\0') {
        len++;
    }
    return len;
}

/* Срезает хвостовой '\n', который оставляет после себя fgets. */
void chomp(char *s)
{
    int len = my_strlen(s);
    if (len > 0 && s[len - 1] == '\n') {
        s[len - 1] = '\0';
    }
}

int main(void)
{
    char line[200];

    printf("Введи строку (латиницей): ");
    if (fgets(line, sizeof line, stdin) == NULL) {
        return 0;
    }
    chomp(line);

    /* Шаг 1: оставляем только буквы, приводя их к нижнему регистру.
     * clean не меньше line, значит переполнить его нечем. */
    char clean[200];
    int m = 0;
    for (int k = 0; line[k] != '\0'; k++) {
        unsigned char c = (unsigned char)line[k];
        if (isalpha(c)) {
            clean[m] = (char)tolower(c);
            m++;
        }
    }
    clean[m] = '\0';

    /* Шаг 2: два индекса идут навстречу друг другу. */
    int i = 0;
    int j = m - 1;
    int is_palindrome = 1;              /* пока считаем, что да */
    while (i < j) {
        if (clean[i] != clean[j]) {
            is_palindrome = 0;          /* нашли несовпадение */
            break;
        }
        i++;
        j--;
    }

    printf("Только буквы: \"%s\" (%d шт.)\n", clean, m);
    if (is_palindrome) {
        printf("\"%s\" — палиндром\n", line);
    } else {
        printf("\"%s\" — не палиндром\n", line);
    }
    return 0;
}
```

Разбор новых мест:

- `for (int k = 0; line[k] != '\0'; k++)` — обход строки без
  предварительного подсчёта длины: идём, пока не встретим `'\0'`. Так в
  Си ходят по строкам чаще всего.
- `unsigned char c = (unsigned char)line[k];` — то самое приведение.
  Дальше `c` можно смело отдавать и в `isalpha`, и в `tolower`.
- `clean[m] = (char)tolower(c);` — `tolower` возвращает `int`, а кладём
  мы в `char`. Приведение `(char)` не обязательно, компилятор сузил бы
  сам, — но оно говорит читателю «да, я знаю, что сужаю тип, это не
  описка». А если добавить к сборке флаг `-Wconversion`, без приведения
  вылезет `warning: implicit conversion loses integer precision: 'int'
  to 'char'`. Лучше сказать явно.
- `m` — счётчик букв в чистой строке. Он же индекс, куда класть
  следующую букву, он же в конце — длина `clean`.
- `clean[m] = '\0';` — **обязательная** строчка. Мы собрали строку
  руками, и метку конца тоже надо поставить руками. Забудешь — `printf`
  с `%s` пойдёт печатать мусор из соседней памяти, пока случайно не
  наткнётся на нулевой байт.
- `\"%s\"` — обратный слэш перед кавычкой говорит `printf`: «это обычная
  кавычка, печатай её», а не конец строки формата. Так фраза в выводе
  берётся в кавычки.

### Проверяем

```text
$ cc -std=c11 -Wall -Wextra -O2 10-palindrome.c -o 10-palindrome
$ ./10-palindrome
Введи строку (латиницей): level
Только буквы: "level" (5 шт.)
"level" — палиндром
```

Те три случая, на которых спотыкалась наивная версия:

```text
$ ./10-palindrome
Введи строку (латиницей): Level
Только буквы: "level" (5 шт.)
"Level" — палиндром
$ ./10-palindrome
Введи строку (латиницей): never odd or even
Только буквы: "neveroddoreven" (14 шт.)
"never odd or even" — палиндром
$ ./10-palindrome
Введи строку (латиницей): A man, a plan, a canal: Panama
Только буквы: "amanaplanacanalpanama" (21 шт.)
"A man, a plan, a canal: Panama" — палиндром
```

Строка «Только буквы» отлично показывает, что именно программа
сравнивала. И контрольный не-палиндром:

```text
$ ./10-palindrome
Введи строку (латиницей): world
Только буквы: "world" (5 шт.)
"world" — не палиндром
```

Краевые случаи. Пустой ввод и один символ:

```text
$ ./10-palindrome
Введи строку (латиницей): 
Только буквы: "" (0 шт.)
"" — палиндром
$ ./10-palindrome
Введи строку (латиницей): x
Только буквы: "x" (1 шт.)
"x" — палиндром
```

И то и другое — палиндромы по определению: читать в обе стороны нечего
или нечему различаться. Программа это учитывает даром: при `m <= 1` цикл
`while (i < j)` не выполняется ни разу, флаг остаётся `1`.

А что со строкой, в которой букв нет вовсе?

```text
$ ./10-palindrome
Введи строку (латиницей): !!!
Только буквы: "" (0 шт.)
"!!!" — палиндром
```

После чистки осталась пустая строка — значит, палиндром. Ответ спорный,
но он хотя бы предсказуемый и объяснимый. Такие решения надо принимать
осознанно и записывать в комментарий к функции, а не оставлять «как
само получилось»: через месяц ты сам не вспомнишь, был это замысел или
недосмотр.

## Часть 3. Подсчёт слов

Посчитаем, сколько слов во фразе.

### Наивная версия: считаем пробелы

Первая мысль почти у всех одна: слов на один больше, чем пробелов.

```c
    int spaces = 0;
    for (int i = 0; line[i] != '\0'; i++) {
        if (line[i] == ' ') {
            spaces++;
        }
    }
    printf("Слов: %d\n", spaces + 1);
```

На аккуратной фразе работает:

```text
$ ./naive-words
Введи фразу (латиницей): the quick brown fox
Слов: 4
```

А теперь то же самое, но с лишними пробелами — по краям и между словами:

```text
$ ./naive-words
Введи фразу (латиницей):   the   quick brown   fox  
Слов: 12
```

Двенадцать слов вместо четырёх. И на пустой строке тоже мимо:

```text
$ ./naive-words
Введи фразу (латиницей): 
Слов: 1
```

Ноль пробелов плюс один — получилось одно слово, хотя фраза пустая.
Идея «пробелов плюс один» верна только для идеально причёсанного текста,
а такой текст пользователь вводит примерно никогда.

### Идея: ловим начало слова

Считать надо не разделители, а **начала слов**. Слово начинается там,
где после разделителя (или в самом начале строки) идёт не-разделитель.

Заведём флаг `in_word` — «мы сейчас внутри слова или нет» — и пройдём по
строке символ за символом:

- встретили пробельный символ → мы вне слова (`in_word = 0`);
- встретили не-пробельный и до этого были вне слова → это **начало
  нового слова**: прибавляем счётчик и ставим `in_word = 1`;
- встретили не-пробельный, но уже были внутри слова → ничего не делаем,
  просто продолжаем то же слово.

Так каждое слово считается ровно один раз — в момент своей первой буквы.
Сколько бы пробелов ни стояло вокруг, лишних единиц не набежит. Пустая
строка даст ноль: цикл просто не выполнится.

Пройдём руками по фразе `  ab  c` (два пробела, `ab`, два пробела, `c`):

```text
символ:   ' ' ' ' 'a' 'b' ' ' ' ' 'c'
in_word:   0   0   1   1   0   0   1
words:     0   0   1   1   1   1   2
```

Счётчик подскочил только на `a` и на `c` — ровно на первых буквах слов.

Что считать разделителем? Пробел — точно. Табуляция `'\t'` — тоже: её
легко вставить, нажав Tab или скопировав текст из таблицы. Ещё бывает
`'\r'` (возврат каретки) — он приезжает в файлах, сделанных на Windows.
Перечислять всё это руками через `||` можно, но именно для этого в
`<ctype.h>` есть `isspace`: она отвечает «да» на пробел, `\t`, `\n`,
`\v`, `\f` и `\r`. Одна проверка вместо шести.

Раз уж мы идём по словам, посчитаем заодно **длину самого длинного
слова** — это почти бесплатно. Держим `current` (длина слова, которое
сейчас идём) и `longest` (рекорд). На каждой букве `current++`, и если
он побил рекорд — обновляем `longest`. На разделителе `current = 0`.

### Полная программа: `10-words.c`

```c
#include <stdio.h>
#include <ctype.h>

int my_strlen(const char *s)
{
    int len = 0;
    while (s[len] != '\0') {
        len++;
    }
    return len;
}

/* Срезает хвостовой '\n', который оставляет после себя fgets. */
void chomp(char *s)
{
    int len = my_strlen(s);
    if (len > 0 && s[len - 1] == '\n') {
        s[len - 1] = '\0';
    }
}

int main(void)
{
    char line[200];

    printf("Введи фразу (латиницей): ");
    if (fgets(line, sizeof line, stdin) == NULL) {
        return 0;
    }
    chomp(line);

    int words = 0;
    int longest = 0;                    /* длина самого длинного слова */
    int current = 0;                    /* длина слова, которое идём */
    int in_word = 0;                    /* сейчас мы внутри слова? */

    for (int i = 0; line[i] != '\0'; i++) {
        unsigned char c = (unsigned char)line[i];
        if (isspace(c)) {
            in_word = 0;                /* пробел — слово кончилось */
            current = 0;
        } else {
            if (in_word == 0) {         /* переход «пробел -> буква» */
                words++;                /* начало нового слова */
                in_word = 1;
            }
            current++;
            if (current > longest) {
                longest = current;
            }
        }
    }

    printf("Слов: %d\n", words);
    printf("Самое длинное слово: %d символов\n", longest);
    return 0;
}
```

Разбор:

- `unsigned char c = (unsigned char)line[i];` — то же правило, что и в
  палиндроме: перед `<ctype.h>` приводим к `unsigned char`.
- `if (isspace(c))` — разделитель ли это. Одна проверка покрывает
  пробел, табуляцию и возврат каретки.
- В ветке-разделителе сбрасываем оба счётчика: `in_word = 0` («мы вышли
  из слова») и `current = 0` («новое слово начнётся с нуля»).
- В другой ветке смотрим `if (in_word == 0)` — если мы только что были
  вне слова, значит это его первая буква. Прибавляем `words++` и ставим
  `in_word = 1`. Пока буквы идут подряд, `in_word` остаётся `1`, и
  счётчик слов не растёт.
- `if (current > longest) longest = current;` — обновление рекорда. Мы
  делаем его на каждой букве, а не в конце слова: так не нужен отдельный
  код «слово кончилось» и не забудется последнее слово строки, если она
  обрывается без пробела в конце. Классическая ошибка «последнее слово
  не посчиталось» тут просто не может случиться.

### Проверяем

```text
$ cc -std=c11 -Wall -Wextra -O2 10-words.c -o 10-words
$ ./10-words
Введи фразу (латиницей): the quick brown fox
Слов: 4
Самое длинное слово: 5 символов
```

Теперь тот же текст, но с двумя пробелами в начале, тремя между словами,
табуляцией вместо пробела перед `brown` и двумя пробелами в конце.
Набрать такое в терминале руками неудобно (Tab там часто перехватывает
оболочка), поэтому подадим ввод через `printf` — `\t` в нём означает
табуляцию, `\n` — Enter:

```text
$ printf '  the   quick\tbrown   fox  \n' | ./10-words
Введи фразу (латиницей): Слов: 4
Самое длинное слово: 5 символов
```

Четыре — как и должно быть. Приглашение и ответ оказались на одной
строке просто потому, что вводить было нечего: `printf` подал текст
сразу, эхо от клавиатуры не появилось.

Пустая строка и строка из одних пробелов:

```text
$ printf '\n' | ./10-words
Введи фразу (латиницей): Слов: 0
Самое длинное слово: 0 символов
$ printf '     \n' | ./10-words
Введи фразу (латиницей): Слов: 0
Самое длинное слово: 0 символов
```

Ноль и ноль. Флаг `in_word` ни разу не включился, цикл честно отработал
вхолостую.

## Часть 4. Анаграммы

**Анаграммы** — две фразы из одних и тех же букв, переставленных в
другом порядке: `listen` и `silent`, `anagram` и `nagaram`. А `hello` и
`world` — нет.

### Идея: считаем частоты букв

Как проверить руками? Можно отсортировать буквы каждого слова и
сравнить: `listen` → `eilnst`, `silent` → `eilnst`, совпало. Но есть
приём проще и быстрее — **подсчёт частот**.

Заведём на каждую возможную букву свой счётчик. Пройдём по первой фразе
и для каждой буквы **прибавим** её счётчик. Потом пройдём по второй и
для каждой буквы **вычтем**. Если фразы — анаграммы, то каждую букву мы
столько же раз прибавили, сколько вычли, и все счётчики в конце окажутся
**нулевыми**. Остался где-то не ноль — состав не совпал.

Пройдём руками по `abc` и `cab`, показывая только ненулевые счётчики:

```text
после "abc":   a: +1   b: +1   c: +1
после "cab":   a:  0   b:  0   c:  0   -> анаграммы
```

А теперь `aab` и `ab`:

```text
после "aab":   a: +2   b: +1
после "ab":    a: +1   b:  0   -> у 'a' остался 1, не анаграммы
```

Заметь приятный побочный эффект: разная длина отсекается сама собой.
Если в первой фразе букв больше, какой-то счётчик обязательно останется
положительным. Отдельная проверка длин не нужна (хотя как быстрая
отсечка она была бы не лишней — см. упражнения).

Под счётчики возьмём массив `int count[256]`. Почему 256? Один байт
принимает значения от 0 до 255, и массив на 256 ячеек даёт отдельный
счётчик под **любой** возможный байт. Сам код символа служит индексом:
для буквы `a` (код 97) растёт `count[97]`.

### Наивная версия и две неудачи

Напишем как есть — считаем все символы подряд, регистр не трогаем:

```c
    int count[256] = {0};
    for (int i = 0; a[i] != '\0'; i++) {
        count[(unsigned char)a[i]]++;   /* в первой фразе — прибавляем */
    }
    for (int i = 0; b[i] != '\0'; i++) {
        count[(unsigned char)b[i]]--;   /* во второй — вычитаем */
    }
```

Проверяем:

```text
$ ./naive-anagram

Вторая фраза (латиницей): silent
"listen" и "silent" — анаграммы
$ ./naive-anagram
Первая фраза (латиницей): Listen
Вторая фраза (латиницей): Silent
"Listen" и "Silent" — не анаграммы
$ ./naive-anagram

Вторая фраза (латиницей): dormitory
"Dirty Room" и "dormitory" — не анаграммы
```

Строчные слова разобраны верно. Стоит появиться заглавным — ломается:
`'L'` (код 76) и `'l'` (код 108) попадают в разные ячейки массива.
А знаменитая пара `Dirty Room` / `dormitory` не проходит ещё и из-за
пробела: в первой фразе он есть, во второй нет, и `count[' ']` остаётся
единицей.

Лечение то же, что и в палиндроме: считать только буквы и только в одном
регистре.

### Выносим подсчёт в функцию

Два цикла отличаются одним знаком: в первом `++`, во втором `--`. Это
просьба вынести общее в функцию и передать разницу параметром:

```c
/* Проходит по строке и меняет счётчики букв на delta:
 * +1 для первой фразы, -1 для второй. Не-буквы пропускает. */
void tally(const char *s, int count[], int delta)
{
    for (int i = 0; s[i] != '\0'; i++) {
        unsigned char c = (unsigned char)s[i];
        if (isalpha(c)) {
            count[tolower(c)] += delta;
        }
    }
}
```

- `int count[]` в параметрах — массив передаётся по адресу, а не
  копируется (глава 3). Значит, изменения внутри функции видны снаружи —
  именно это нам и нужно. Квадратные скобки пустые: длина в параметре
  всё равно не хранится, запись `int count[]` и `int *count` тут
  означают одно и то же.
- `delta` — на сколько менять счётчик: `+1` или `-1`.
- `count[tolower(c)] += delta;` — индекс это уже приведённый к нижнему
  регистру код буквы, так что `A` и `a` попадают в одну ячейку.
  `x += y` — сокращение для `x = x + y`.
- `if (isalpha(c))` — не-буквы (пробелы, запятые, цифры) просто
  пропускаем, они на ответ не влияют.

### Полная программа: `10-anagram.c`

```c
#include <stdio.h>
#include <ctype.h>

int my_strlen(const char *s)
{
    int len = 0;
    while (s[len] != '\0') {
        len++;
    }
    return len;
}

/* Срезает хвостовой '\n', который оставляет после себя fgets. */
void chomp(char *s)
{
    int len = my_strlen(s);
    if (len > 0 && s[len - 1] == '\n') {
        s[len - 1] = '\0';
    }
}

/* Проходит по строке и меняет счётчики букв на delta:
 * +1 для первой фразы, -1 для второй. Не-буквы пропускает. */
void tally(const char *s, int count[], int delta)
{
    for (int i = 0; s[i] != '\0'; i++) {
        unsigned char c = (unsigned char)s[i];
        if (isalpha(c)) {
            count[tolower(c)] += delta;
        }
    }
}

int main(void)
{
    char a[200];
    char b[200];

    printf("Первая фраза (латиницей): ");
    if (fgets(a, sizeof a, stdin) == NULL) {
        return 0;
    }
    printf("Вторая фраза (латиницей): ");
    if (fgets(b, sizeof b, stdin) == NULL) {
        return 0;
    }

    chomp(a);
    chomp(b);

    /* По счётчику на каждый из 256 возможных байтов. */
    int count[256] = {0};
    tally(a, count, +1);        /* в первой фразе — прибавляем */
    tally(b, count, -1);        /* во второй — вычитаем */

    /* Если все счётчики нулевые — буквы совпали по составу. */
    int anagram = 1;
    for (int k = 0; k < 256; k++) {
        if (count[k] != 0) {
            anagram = 0;
            break;
        }
    }

    if (anagram) {
        printf("\"%s\" и \"%s\" — анаграммы\n", a, b);
    } else {
        printf("\"%s\" и \"%s\" — не анаграммы\n", a, b);
    }
    return 0;
}
```

Ещё пара мест, которые стоит проговорить:

- `int count[256] = {0};` — массив из 256 счётчиков. Запись `= {0}`
  заполняет **все** ячейки нулями (не только первую: остальные
  доинициализируются нулями по правилам языка). Без этого в массиве
  лежал бы мусор — что угодно, что осталось в этой памяти от прошлых
  вычислений, — и счёт был бы бессмысленным.
- Финальный цикл проверяет, что **все** счётчики обнулились. Нашли
  ненулевой — `anagram = 0` и `break`.
- Два буфера по 200 и два `fgets` подряд. Тут есть подводный камень:
  если первая фраза длиннее 199 символов, `fgets` возьмёт только начало,
  а хвост останется в потоке ввода и приедет во второй `fgets` вместо
  второй фразы. Об этом — в «Частых ошибках».

## Частые ошибки

**Забыли обрезать `'\n'` после `fgets`.** Главная беда этой главы.
Перевод строки портит и переворот (улетает в начало), и сравнение
(`"level\n"` уже не палиндром), и длину. После каждого `fgets` —
`chomp`. Рефлекс.

**Забыли `(unsigned char)` перед `<ctype.h>` или перед индексом.** Тип
`char` знаковый, байты выше 127 становятся отрицательными, и ты читаешь
память до начала таблицы. Компилятор предупредит только про индекс
массива (`-Wchar-subscripts`), а про `isalpha(c)` промолчит — там
формально всё в порядке по типам. Проверять придётся самому.

**Не поставили `'\0'`, собирая строку вручную.** Скопировал символы в
новый массив — поставь в конце `'\0'` сам. Иначе `printf("%s", ...)`
пойдёт печатать всё подряд, пока не наткнётся на случайный нулевой байт.

**Не обнулили массив-счётчик.** `int count[256];` без `= {0}` содержит
мусор, и подсчёт частот соврёт — причём правдоподобно.

**Сравнение строк через `==`.** `a == b` для двух `char *` сравнивает
**адреса**, а не текст (глава 3). Для содержимого нужен `strcmp` из
`<string.h>`. А вот отдельные символы (`line[i] != line[j]`) сравнивать
через `==`/`!=` можно и нужно: это числа.

**`line[len - 1]` без проверки `len > 0`.** На пустой строке это
`line[-1]` — чтение за левой границей массива. Всегда пиши
`if (len > 0 && ...)`, и именно в таком порядке.

**Строка длиннее буфера.** `fgets` возьмёт `sizeof line - 1` символов, а
остаток оставит в потоке — и следующий `fgets` прочитает **его**, а не
то, что ты наберёшь. Возьмём нарочно крошечные буферы:

```c
#include <stdio.h>

int main(void)
{
    char first[10];
    char second[10];

    printf("Первое слово: ");
    if (fgets(first, sizeof first, stdin) == NULL) {
        return 0;
    }
    printf("Второе слово: ");
    if (fgets(second, sizeof second, stdin) == NULL) {
        return 0;
    }

    printf("first  = [%s]\n", first);
    printf("second = [%s]\n", second);
    return 0;
}
```

Подаём одно длинное слово и одно короткое:

```text
$ cc -std=c11 -Wall -Wextra -O2 trunc.c -o trunc
$ printf 'extraordinary\nsecond\n' | ./trunc
Первое слово: Второе слово: first  = [extraordi]
second = [nary
]
```

Слово `second` не попало никуда: во второй буфер приехал хвост первого
(`nary` вместе с переводом строки). В `first` легло девять символов —
`sizeof first - 1`, десятое место ушло под `'\0'`.

Признак обрезки — в буфере **нет** `'\n'`. Так и проверяй: если `'\n'`
не нашёлся, строка была длиннее буфера, и остаток надо дочитать
`getchar()`-ом до `'\n'` или до `EOF`, иначе он испортит следующий ввод.

**Кириллица в посимвольном алгоритме.** Мы это видели: UTF-8 разложит
русское слово на пары байтов, и переворот с палиндромом дадут
бессмыслицу. В этой главе — только латиница.

## Упражнения

1. Добавь в `10-reverse.c` подсчёт **гласных** (`a, e, i, o, u`) и
   выведи их число. Регистр учитывать не надо — сначала `tolower`.
   Подсказка: одну проверку удобно написать через `strchr("aeiou", c)`
   из `<string.h>`, но можно и просто цепочкой `||`.
2. Напиши свой `int my_tolower(int c)` — без `<ctype.h>`, руками. Буквы
   `'A'..'Z'` идут подряд, и `'a'..'z'` тоже, поэтому разница между
   заглавной и строчной постоянна и равна `'a' - 'A'`. Все остальные
   символы функция должна возвращать нетронутыми. Проверь, что
   `10-palindrome.c` с твоей функцией работает так же.
3. Перепиши палиндром **без второго массива**: два индекса идут
   навстречу прямо по исходной строке, а не-буквы каждый из них
   пропускает сам (`while (i < j && !isalpha(...)) i++;`). Так делают
   на собеседованиях, когда просят «без дополнительной памяти».
   Проверь на тех же четырёх примерах, что и в главе, — ответы должны
   совпасть до буквы.
4. Научи `10-words.c` печатать не только длину самого длинного слова, но
   и само слово. Подсказка: запоминай индекс начала рекордного слова, а
   в конце выведи его через `%.*s` — этот формат печатает ровно столько
   символов, сколько указано: `printf("%.*s\n", len, line + start);`.
5. Напиши программу, которая печатает, **сколько раз** встречается
   каждая латинская буква во введённой фразе. Массив-счётчик из части 4,
   в конце пройдись по `'a'..'z'` и выведи только буквы с ненулевым
   счётчиком.
6. Добавь в `10-anagram.c` быструю отсечку: если число букв в фразах
   разное, ответ «не анаграммы» известен сразу, без подсчёта частот.
   Подсказка: пусть `tally` заодно возвращает число посчитанных букв.
7. Напиши функцию `int my_strcmp(const char *a, const char *b)`, которая
   возвращает 0 при равных строках, отрицательное число, если `a` меньше
   `b` по алфавиту, и положительное иначе, — своими руками, сравнивая
   символы в цикле, без `<string.h>`. Подсказка: иди по обеим строкам
   одновременно, пока символы равны и не кончились; в конце верни
   разность кодов, приведя оба символа к `unsigned char`.

## Что мы получили

Ты умеешь обрабатывать строки **изнутри**, не полагаясь на готовые
функции: считать длину циклом до `'\0'`, ходить двумя индексами с концов
(переворот, палиндром), нормализовать текст перед сравнением, вести флаг
состояния (`in_word` при подсчёте слов) и применять массив-счётчик по
коду символа (анаграммы, частоты).

Заодно ты познакомился с `<ctype.h>` и с правилом `(unsigned char)`,
которое отличает работающий код от кода, который «пока не упал». И ты
знаешь главную бытовую ловушку — хвостовой `'\n'` от `fgets`, — и
срезаешь его на автомате.

Пока все наши данные жили в массивах фиксированного размера:
`char line[100]`, `int count[256]`. Но что, если заранее неизвестно,
сколько элементов понадобится, и они должны то добавляться, то
удаляться? Тогда массива мало. В следующей главе — **динамические
структуры данных**: растущий массив, стек, очередь и связный список, где
элементы связаны указателями и разбросаны по памяти. Там наконец
пригодятся `malloc`/`free` из главы 3 и появится `struct` — способ
склеить несколько значений в один объект.

Итоговые программы главы — `code/10-reverse.c`, `code/10-palindrome.c`,
`code/10-words.c`, `code/10-anagram.c`.
