# Глава 11. Динамические структуры данных: растущий массив, стек, очередь, связный список

До сих пор мы работали с обычным массивом: завёл `int a[100]` — и живи в
этих рамках. Но в настоящих программах данные приходят и уходят: игрок
делает ходы, в очередь встают задачи, в историю добавляются записи.
Заранее размер не угадать.

В этой главе соберём четыре **структуры данных** — четыре способа хранить
набор значений, у каждого свой характер:

- **растущий массив** — обычный массив, который сам увеличивается, когда
  заполнится;
- **стек** — «последним пришёл, первым ушёл»;
- **очередь** — «первым пришёл, первым ушёл»;
- **связный список** — цепочка узлов, разбросанных по памяти.

А заодно познакомимся с `realloc` (расширить уже выделенную память) и с
**структурами** (`struct`) — способом склеить несколько значений в один
объект. Без `struct` ни списка, ни аккуратного стека не построить,
поэтому начнём с него.

Эта глава — про память. Здесь легко наделать ошибок, которые не видны
глазом: выход за границу массива, чтение освобождённого узла, утечка.
Поэтому мы будем регулярно запускать программы под **санитайзерами** —
специальным режимом компилятора, который ловит такие вещи на лету:

```text
cc -std=c11 -Wall -Wextra -O1 -g -fsanitize=address,undefined prog.c -o prog
```

`-fsanitize=address` следит за обращениями к памяти, `undefined` — за
неопределённым поведением вроде выхода индекса за границы. Программа
работает медленнее, зато при первой же ошибке печатает, где именно она
случилась. Правильный код под санитайзерами молчит. Одна оговорка из
главы 3: утечки памяти санитайзер на macOS не ищет (эта его часть,
LeakSanitizer, на маке не работает). Для утечек у нас системная утилита
`leaks`, её мы тоже будем запускать.

## Знакомимся: `struct` — свой составной тип

`int` хранит одно число. Массив — много чисел **одного** типа. А как
описать узел списка, в котором лежит и число, и адрес следующего узла?
Нужен тип, который объединяет **разные** поля под одним именем. Это и
есть **структура** (`struct`, от *structure*).

Представь карточку игрока: имя, очки, уровень. Три разные вещи, но
логически это один объект. Опишем его:

```c
struct Player {
    char name[32];
    int score;
    int level;
};
```

Разбор:

- `struct Player { ... };` — мы **определили** новый тип с именем
  `struct Player`. Само по себе это не создаёт ни одной переменной — это
  чертёж, описание «из чего состоит игрок». Памяти он не занимает.
- внутри фигурных скобок — **поля** (fields): `name`, `score`, `level`.
  Каждое со своим типом, как обычные переменные. Поля идут через `;`.
- после закрывающей `}` обязательно стоит `;` — про неё забывают чаще
  всего, и компилятор выдаёт странную ошибку на следующей строке. Не
  забудь точку с запятой.

Теперь заведём переменную этого типа и заполним поля:

```c
struct Player hero;
hero.score = 0;
hero.level = 1;
```

- `struct Player hero;` — создали **переменную** `hero` типа
  `struct Player`. Вот теперь в памяти лежит реальный игрок: место под
  имя, под очки, под уровень.
- `hero.score = 0;` — обращение к полю через **точку** (`.`): «у объекта
  `hero` поле `score` сделай равным 0».

Полей у структуры может быть сколько угодно, и они лежат в памяти
подряд, одно за другим. Размер структуры узнаётся привычным `sizeof`:
`sizeof(struct Player)`. Он не всегда равен точной сумме размеров полей —
компилятор имеет право вставлять между ними пустые байты для скорости
(это называется выравнивание). Полагаться на конкретное число не надо,
`sizeof` всегда скажет правду.

### Указатель на структуру и стрелка `->`

Часто структуру создают в динамической памяти (`malloc`) или передают в
функцию — и тогда у нас на руках не сама структура, а **указатель** на
неё. К полям через точку уже не обратишься, нужен другой способ.

```c
struct Player *p = &hero;   /* p — адрес нашего игрока */

(*p).score = 50;            /* длинная запись */
p->score = 50;              /* короткая, то же самое */
```

- `struct Player *p` — указатель на структуру (как `int *p`, только тип
  другой).
- `(*p).score` — сначала `*p` разыменовывает указатель («сама структура,
  на которую смотрит `p`»), потом `.score` берёт поле. Скобки нужны:
  без них `*p.score` компилятор поймёт как `*(p.score)`, потому что
  точка «прилипает» сильнее звёздочки.
- `p->score` — **стрелка** `->`. Это просто **сокращение** для
  `(*p).score`. Запомни намертво:

  > `p->field` — это в точности `(*p).field`. Стрелка = «разыменуй и
  > возьми поле».

  Когда у тебя указатель на структуру — пиши через стрелку, так короче и
  так пишут все.

Важное следствие: если функция получает `struct Player *p`, она работает
с **оригиналом**, а не с копией. Изменит `p->score` — изменение увидит и
тот, кто вызвал. Это тот же механизм, что у `swap` из главы 3, просто со
структурой. А если передать структуру по значению (`struct Player p`),
она **скопируется** целиком, вместе с 32-байтным массивом имени. Поэтому
большие структуры почти всегда передают по указателю: копировать один
адрес дешевле, чем сорок байт.

### `typedef` — короткое имя для типа

Писать `struct Player` каждый раз длинно. `typedef` даёт типу псевдоним:

```c
typedef struct Player Player;   /* теперь "Player" = "struct Player" */

Player hero;                    /* можно без слова struct */
```

Часто это совмещают с определением:

```c
typedef struct {
    int value;
} Box;

Box b;          /* удобно */
```

В этой главе я оставлю полную запись `struct Node`, `struct Stack` — так
нагляднее видно, что это структура. Но знай: `typedef` ровно для того,
чтобы избавиться от повторов слова `struct`.

Этого про структуры хватит, чтобы строить дальше.

## Часть 1. Растущий массив

### Разбираем руками

Проблема обычного массива: размер фиксирован. `int a[100]` — а если
понадобится 101? А если выделишь сразу миллион «про запас» — впустую
займёшь память.

Идея растущего массива простая, как у блокнота: начни с маленького, а
когда страницы кончатся — **доклей** ещё. Конкретно:

1. Выделяем место под несколько элементов (пусть под 2).
2. Заводим счётчик `count` — сколько реально занято.
3. Кладём элемент — увеличиваем `count`.
4. Как только `count` упёрся во вместимость — **расширяемся**.

Вопрос на миллион: расширяться **на сколько**? Прибавить одну ячейку?
Удвоить? Разница выглядит мелочью, а на деле это разница между «работает»
и «висит».

### Почему удвоение, а не «плюс один»

Расширить массив — это в худшем случае **переехать**: выделить новый
блок, перенести туда все старые элементы, освободить старый. Перенос
стоит столько, сколько в массиве элементов.

Посчитаем на бумаге для 100 000 вставок.

Стратегия «плюс один»: переезжаем на **каждой** вставке. Первый переезд
копирует 0 элементов, второй — 1, третий — 2, и так до 99 999. Сумма
`0 + 1 + 2 + ... + 99999` — это примерно `100000 * 100000 / 2`, то есть
**пять миллиардов** копирований. Если точно: сумма всех чисел от 0 до
`n − 1` равна `n × (n − 1) / 2`, подставим `n = 100000` и получим
`100000 × 99999 / 2 = 4 999 950 000`.

Стратегия «удвоение»: переезжаем, только когда место кончилось.
Вместимость идёт 1, 2, 4, 8, 16 … 131072 — всего **восемнадцать**
выделений памяти (при самом первом копировать ещё нечего), а
копирований суммарно `0 + 1 + 2 + 4 + ... + 65536 = 131071` — около
**131 тысячи**. Это даже меньше, чем 2 × 100 000: при удвоении на один
элемент приходится меньше двух копирований, сколько бы их ни было.
Почему так при любом числе элементов — разберём чуть ниже. Тот редкий случай, когда «делать реже, но крупнее» выигрывает не
на проценты, а в десятки тысяч раз.

Проверим руками — программа `code/11-growth.c` делает обе стратегии,
копируя элементы явным циклом, и считает копирования:

```text
$ cc -std=c11 -Wall -Wextra -O2 11-growth.c -o 11-growth
$ ./11-growth
вставляем 100000 элементов
рост на +1:   скопировано 4999950000 элементов, 0.850 c
удвоение:     скопировано 131071 элементов, 0.001 c
копирований меньше в 38147 раз
```

Числа копирований — ровно те, что мы насчитали на бумаге. Секунды на
твоей машине будут другие, а вот число копирований — нет, оно чисто
математическое. Поэтому готовые растущие массивы в библиотеках разных
языков увеличивают вместимость **умножением** — кто в 2 раза, кто в 1,5,
кто ещё как, — а не прибавлением.

### Сколько стоит одна вставка: амортизированная O(1)

В главе 8 мы оценивали сортировки через «O большое». Здесь понадобятся
ещё две оценки попроще. **O(1)** — число действий не зависит от `n`:
сколько бы элементов ни лежало, операция укладывается в одно и то же
небольшое число шагов. **O(n)** — число действий растёт не быстрее, чем
пропорционально `n`: вдвое больше элементов — примерно вдвое больше
работы, но не хуже. Напомню, что «O» — это оценка **сверху**: «не хуже, чем».

Теперь честно посмотрим на одну вставку при удвоении. Обычно она дешёвая:
записали число в свободную ячейку, и всё. Но иногда она очень дорогая:
вставка номер 65 537 застаёт массив полным (65 536 из 65 536) и тащит за
собой переезд всех 65 536 элементов. Так что сказать «каждая вставка
стоит O(1)» нельзя — отдельная вставка бывает O(n).

Зато можно посчитать цену **всех** вставок вместе. На `n` вставок уходит
`n` записей новых элементов и копирования при переездах:
`1 + 2 + 4 + ... + 2^(k−1) = 2^k − 1`, где `2^(k−1)` — последняя
вместимость, из которой пришлось переезжать. Переезд случается, только
когда пришёл ещё один элемент, а места нет, значит, эта вместимость
меньше `n`, и копирований меньше `2 × 2^(k−1)`, то есть меньше `2n`.
Проверим на наших числах: последний переезд был из вместимости 65 536,
копирований
131 071 — это меньше, чем `2 × 100000`. Итого на `n` вставок меньше
`3n` действий, то есть меньше трёх действий на вставку, при любом `n`.

Это и называется **амортизированная сложность O(1)**: дорогие вставки
редки, и их цену можно «размазать» по дешёвым, которые были до них. Это
гарантия на всю последовательность операций, а не на каждую отдельную.
Не путай со словами «в среднем» из главы 8 про быструю сортировку: там
усреднение по случайным входным данным, и на неудачных данных можно
проиграть. Здесь никакой случайности нет — оценка верна для **любой**
последовательности вставок.

А у «плюс одного» на `n` вставок уходит `n × (n − 1) / 2` копирований.
Это O(n²) на все вставки, то есть в среднем по O(n) на каждую.

Годится ли другой коэффициент роста? Да, **любое умножение больше
единицы** даёт амортизированную O(1), меняется только константа. Я
посчитал программой для тех же 100 000 вставок: при росте в 2 раза —
131 071 копирование (1,3 на элемент), при росте в 1,5 раза — 276 521
(2,8 на элемент), зато пустующих ячеек в среднем меньше. А вот
**прибавление** постоянного числа — хоть +1, хоть +1000 — даёт квадрат:
при +1000 переездов всё равно около `n / 1000`, и каждый копирует уже
накопленное.

### `realloc` — изменить размер уже выделенной памяти

Расширять память умеет `realloc` (*reallocate* — перевыделить), из
`<stdlib.h>`:

```c
void *realloc(void *ptr, size_t size);
```

Что делает `realloc(старый_указатель, новый_размер_в_байтах)`:

- пытается сделать блок, на который указывает `ptr`, нужного размера;
- **старые данные сохраняются** — если блок пришлось перенести на новое
  место, `realloc` сам их туда скопирует;
- возвращает **адрес** блока нужного размера. Этот адрес может оказаться
  **другим** — поэтому результат обязательно надо куда-то положить.

Иногда `realloc` расширяет блок прямо на месте, ничего не копируя, — но
рассчитывать на это нельзя, это зависит от того, что лежит рядом в
памяти. Считай, что каждый рост — это переезд.

Ловушка, в которую падают почти все:

```c
data = realloc(data, new_size);   /* ОПАСНО */
```

Если `realloc` не сможет выполнить просьбу, он вернёт `NULL`, а **старый
блок оставит нетронутым**. И вот тут запись `data = realloc(data, ...)`
затирает `data` этим `NULL` — единственный адрес старого блока потерян.
Данные недоступны, память не освободить: утечка.

Убедимся, что старый блок правда остаётся целым. Попросим заведомо
невозможный размер:

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *data = malloc(2 * sizeof(int));
    if (data == NULL) {
        return 1;
    }
    data[0] = 42;
    data[1] = 7;

    /* Просим заведомо невозможный размер — половину адресного
     * пространства. Столько памяти нам никто не даст. */
    size_t huge = (size_t)-1 / 2;
    int *bigger = realloc(data, huge);
    if (bigger == NULL) {
        printf("realloc вернул NULL\n");
        printf("а старый блок цел: data[0] = %d, data[1] = %d\n",
               data[0], data[1]);
        free(data);
        return 0;
    }

    data = bigger;
    free(data);
    return 0;
}
```

```text
$ cc -std=c11 -Wall -Wextra -O2 realloc-fail.c -o realloc-fail
$ ./realloc-fail
realloc вернул NULL
а старый блок цел: data[0] = 42, data[1] = 7
```

Числа на месте, и `free(data)` отработал нормально. Кстати, этот пример
нарочно просит невозможное, поэтому запускай его **обычной** сборкой:
санитайзер на такую заявку ругается сам и прерывает программу, не давая
`realloc` вернуть `NULL`.

- `(size_t)-1` — хитрый, но общепринятый способ получить самое большое
  возможное значение типа `size_t`. Тип беззнаковый, поэтому −1 в нём
  «заворачивается» в максимум: беззнаковая арифметика в Си идёт по
  модулю `2^N`. Пополам делим просто для наглядности: это всё ещё
  заведомо невыполнимая просьба (на 64-битном маке — около 8 эксабайт),
  но уже «половина всей памяти», а не странное число-максимум.

Если всё же хочется прогнать этот пример под санитайзером, попроси его
не прерывать программу, а возвращать `NULL`, как обычный `malloc`:
`ASAN_OPTIONS=allocator_may_return_null=1 ./realloc-fail`. Тогда вывод
будет тот же, что выше.

Правильный шаблон, который надо выучить:

```c
int *bigger = realloc(data, new_size);
if (bigger == NULL) {
    /* старый data ещё цел — можно спасти данные или аккуратно выйти */
}
data = bigger;
```

Сначала во **временный** указатель, потом проверка, и только потом
присваивание.

### Полная программа: `11-dynarray.c`

Складываем в растущий массив числа от 1 до 10, начав всего с двух ячеек.

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int capacity = 2;                       /* сколько влезает сейчас */
    int count = 0;                          /* сколько реально лежит */
    int *data = malloc((size_t)capacity * sizeof(int));
    if (data == NULL) {
        printf("Не хватило памяти\n");
        return 1;
    }

    for (int value = 1; value <= 10; value++) {
        if (count == capacity) {            /* заполнили — растём */
            capacity = capacity * 2;
            int *bigger = realloc(data,
                                  (size_t)capacity * sizeof(int));
            if (bigger == NULL) {           /* не дали — старое цело */
                printf("Не хватило памяти при росте\n");
                free(data);
                return 1;
            }
            data = bigger;                  /* теперь работаем с новым */
            printf("[рост: вместимость стала %d]\n", capacity);
        }
        data[count] = value;                /* кладём в свободную ячейку */
        count = count + 1;                  /* занятых стало больше */
    }

    printf("Всего элементов: %d, вместимость: %d\n", count, capacity);
    for (int i = 0; i < count; i++) {
        printf("%d ", data[i]);
    }
    printf("\n");

    free(data);
    return 0;
}
```

Разбор:

- `int capacity = 2;` и `int count = 0;` — два разных числа! `capacity` —
  сколько ячеек **выделено**, `count` — сколько из них **занято**.
  Путать их — типичная ошибка, из-за неё пишут за границу массива.
- `malloc((size_t)capacity * sizeof(int))` — просим память под 2 целых
  (глава 3). Зачем `(size_t)`? `capacity` — это `int`, и на большом
  массиве произведение `capacity * sizeof(int)` могло бы переполнить
  `int` ещё до того, как результат превратится в размер. Приведение к
  `size_t` считает умножение уже в широком беззнаковом типе. На наших
  десяти элементах это неважно, но привычка правильная.
- `if (count == capacity)` — проверка «свободного места не осталось».
  Делаем её **перед** записью, чтобы было куда писать.
- блок с `realloc` — тот самый безопасный шаблон.
- `data[count] = value;` — к памяти от `malloc`/`realloc` обращаемся как
  к обычному массиву, по индексу.
- `free(data);` — один `free` на один блок, в конце. `realloc` не
  требует отдельного `free` для старого блока: он сам его освободил,
  когда переехал.

## Часть 2. Стек (LIFO)

### Аналогия: стопка тарелок

Представь стопку чистых тарелок. Новую кладёшь **сверху**. Берёшь — тоже
**сверху**. До нижней так просто не добраться: сначала снимешь все, что
лежат на ней.

Это и есть **стек** (stack — стопка). Правило работы: **LIFO** — *Last
In, First Out*, «последним пришёл — первым ушёл».

Три операции:

- **push** — положить элемент на вершину;
- **pop** — снять элемент с вершины (и вернуть его);
- **peek** — подсмотреть, что на вершине, **не снимая**.

Где встречается: кнопка «отменить» (Ctrl+Z) — последнее действие
отменяется первым; вызовы функций в программе (тот самый стек вызовов из
главы 9); проверка парности скобок в выражении.

### Строим на массиве

Стек прекрасно ложится на массив плюс одно число — `top` (вершина).
Договоримся: `top` — это **индекс первой свободной ячейки**, он же
заодно равен количеству элементов в стеке.

- push: положить в `data[top]`, потом `top++`;
- pop: сначала `top--`, потом взять `data[top]`;
- стек пуст, если `top == 0`; переполнен, если `top == CAPACITY`.

Порядок в pop строгий: **сначала** `top--`, потом читаем. Наоборот —
прочитаешь свободную ячейку.

### Наивный pop и что бывает на пустом стеке

Напишем pop в лоб, без проверок:

```c
#include <stdio.h>

#define CAPACITY 5

/* Наивный pop: снимает с вершины и возвращает значение. */
int pop(int data[], int *top)
{
    *top = *top - 1;
    return data[*top];
}

int main(void)
{
    int data[CAPACITY];
    int top = 0;                    /* стек пуст */

    int value = pop(data, &top);    /* снимаем из пустого стека */
    printf("сняли %d, top стал %d\n", value, top);
    return 0;
}
```

- `#define CAPACITY 5` — **директива препроцессора**: перед компиляцией
  все слова `CAPACITY` в тексте программы заменяются на `5`. Удобно
  задавать константу в одном месте. Точки с запятой в конце `#define`
  **нет** — это не обычная инструкция, а команда препроцессору.
- `int data[]` и `int *top` в параметрах: массив передаётся по адресу
  сам собой, а вот `top` — обычное число, поэтому его передаём
  указателем, чтобы функция могла его изменить (глава 3).

Запускаем обычной сборкой три раза подряд:

### Как вернуть «стек пуст»: статус плюс указатель на результат

Проверку добавить легко. Сложнее решить, **что вернуть**, если стек
пуст. Первая мысль — какое-нибудь особое число:

```c
int pop(int data[], int *top)
{
    if (*top == 0) {
        return -1;              /* «стек пуст» */
    }
    *top = *top - 1;
    return data[*top];
}
```

Работает ровно до того момента, пока кто-нибудь не положит в стек
`-1`. Тогда честно снятое значение `-1` не отличить от сообщения об
ошибке. И так с любым «особым» числом: стек-то хранит **произвольные**
`int`, свободных значений в нём нет.

Выход — разделить два ответа: «получилось или нет» возвращаем из
функции, а само значение отдаём **через указатель**:

```c
int pop(struct Stack *s, int *out);
```

Функция возвращает `1` (сняли) или `0` (пусто), а снятое число кладёт по
адресу `out`. Такой параметр называют **выходным** (out-parameter). Мы
уже видели этот приём в главе 3, когда `swap` менял значения через
адреса; здесь он же, только с одним значением.

Вызов выглядит так:

```c
int x;
if (pop(&s, &x)) {
    /* тут x — снятое значение */
} else {
    /* стек был пуст, x не тронут */
}
```

Обрати внимание: если `pop` вернул 0, он в `*out` **ничего не писал**, и
`x` остался таким, каким был. Это тоже часть договора, и его надо
соблюдать.

Заодно упакуем массив и `top` в одну структуру — вот и пригодился
`struct`. Так стек становится **одним объектом**, который удобно
передавать в функции: не два параметра, а один указатель.

### Полная программа: `11-stack.c`

```c
#include <stdio.h>

#define CAPACITY 5      /* сколько тарелок влезает в стопку */

struct Stack {
    int data[CAPACITY];
    int top;            /* индекс первой СВОБОДНОЙ ячейки = размер */
};

/* Кладём на вершину. 1 — положили, 0 — стек полон. */
int push(struct Stack *s, int value)
{
    if (s->top == CAPACITY) {
        return 0;
    }
    s->data[s->top] = value;
    s->top++;
    return 1;
}

/* Снимаем с вершины в *out. 1 — сняли, 0 — стек пуст. */
int pop(struct Stack *s, int *out)
{
    if (s->top == 0) {
        return 0;
    }
    s->top--;
    *out = s->data[s->top];
    return 1;
}

/* Подсматриваем вершину, не снимая. 1 — есть что смотреть, 0 — пусто. */
int peek(const struct Stack *s, int *out)
{
    if (s->top == 0) {
        return 0;
    }
    *out = s->data[s->top - 1];
    return 1;
}

int main(void)
{
    struct Stack s;
    s.top = 0;                  /* пустой стек */

    /* Кладём шесть значений в стопку на пять — последнее не влезет. */
    for (int value = 10; value <= 60; value += 10) {
        if (push(&s, value)) {
            printf("push %d (в стеке %d)\n", value, s.top);
        } else {
            printf("push %d: стек полон, не кладу\n", value);
        }
    }

    int x;
    if (peek(&s, &x)) {
        printf("peek: наверху %d (в стеке всё те же %d)\n", x, s.top);
    }

    /* Снимаем, пока pop возвращает 1. */
    while (pop(&s, &x)) {
        printf("pop %d (осталось %d)\n", x, s.top);
    }

    /* Ещё один pop на пустом стеке: не падаем, а честно отказываем. */
    if (pop(&s, &x) == 0) {
        printf("pop на пустом стеке: вернул 0, x не тронут (там %d)\n", x);
    }

    return 0;
}
```

Разбор:

- `struct Stack { int data[CAPACITY]; int top; };` — массив и вершина
  теперь одно целое. Заметь: массив лежит **внутри** структуры, никакого
  `malloc` тут нет, память под него берётся там же, где под саму
  переменную `s`.
- `struct Stack s; s.top = 0;` — создали стек и объявили его пустым.
  Ячейки `data` при этом заполнены мусором, и это нормально: мы никогда
  не читаем выше `top`, а туда всегда сначала пишем.
- `s->top == CAPACITY` в `push` — проверка на переполнение. Без неё
  шестая тарелка легла бы в `data[5]`, а в массиве всего пять ячеек с
  индексами 0..4 — это запись за границу. Санитайзер такое ловит, а без
  него получится тихо испорченная соседняя память: скорее всего, поле
  `top`, которое лежит в структуре сразу за массивом.
- `const struct Stack *s` в `peek` — `const` обещает, что функция стек
  не изменит. Компилятор проследит: попытка написать `s->top = 0` внутри
  `peek` не соберётся. Отличный способ выразить намерение прямо в коде.
- `value += 10` в цикле — шаг 10, чтобы класть 10, 20, …, 60. Шесть
  значений при вместимости пять — специально, чтобы увидеть отказ.
- `while (pop(&s, &x))` — идиома «работаем, пока получается». `pop`
  возвращает 1, пока в стеке что-то есть, и 0, когда опустел, — тогда
  цикл сам и закончится. Никаких отдельных проверок на пустоту.

границу, никакого «волшебного» числа-ошибки.

командой, что и в первой части.

## Часть 3. Очередь (FIFO)

### Аналогия: очередь в магазине

Очередь у кассы работает честно: кто встал раньше, того обслужат раньше.
Новый покупатель встаёт **в хвост**, кассир берёт из **головы**.

Это **очередь** (queue). Правило: **FIFO** — *First In, First Out*,
«первым пришёл — первым ушёл». Полная противоположность стеку.

Операции:

- **enqueue** — встать в хвост;
- **dequeue** — забрать из головы.

Где встречается: задачи на печать (документы печатаются в порядке
отправки), сообщения в мессенджере, обход в ширину по графу.

### Наивная очередь: два индекса, которые ползут только вперёд

Наивно: храним `head` (откуда забираем) и `tail` (куда кладём). enqueue
двигает `tail` вправо, dequeue двигает `head` вправо. Напишем и
посмотрим, где сломается:

```c
#include <stdio.h>

#define CAPACITY 5

int main(void)
{
    int data[CAPACITY];
    int head = 0;           /* откуда забираем */
    int tail = 0;           /* куда кладём */

    for (int value = 1; value <= 5; value++) {
        data[tail] = value;
        tail++;
        printf("enqueue %d (head=%d, tail=%d)\n", value, head, tail);
    }

    for (int k = 0; k < 3; k++) {
        int value = data[head];
        head++;
        printf("dequeue %d (head=%d, tail=%d)\n", value, head, tail);
    }

    /* в массиве заняты только ячейки 3 и 4, свободно три штуки */
    for (int value = 6; value <= 7; value++) {
        if (tail == CAPACITY) {
            printf("enqueue %d: места нет (tail=%d)\n", value, tail);
            continue;
        }
        data[tail] = value;
        tail++;
        printf("enqueue %d (head=%d, tail=%d)\n", value, head, tail);
    }
    return 0;
}
```

Смотри на последние строки. В очереди стоят всего **двое** (значения 4 и
5), ячейки 0, 1, 2 свободны — а программа говорит «места нет». Оба
индекса ползут только вперёд, `tail` упёрся в конец массива и встал.
Массив «кончился», хотя он больше чем наполовину пуст.

Можно было бы после каждого dequeue сдвигать все элементы влево — но это
копирование на каждой выдаче, дорого и глупо.

### Кольцевой буфер

Лечение — **кольцевой буфер**: считаем, что после последней ячейки снова
идёт нулевая, будто массив свёрнут в кольцо. Чтобы индекс «перепрыгивал»
с конца в начало, берём остаток от деления на размер:

```c
tail = (tail + 1) % CAPACITY;
```

Когда `tail` дорастает до `CAPACITY`, остаток делает его снова 0 — мы
вернулись в начало кольца и используем освободившиеся ячейки. Вот зачем
оператор `%` (остаток), который мы разбирали в главе 2.

Но теперь возникает новая беда. Пусть `head == tail`. Что это значит?
Очередь **пуста** (никто не стоит) — или очередь **полна** (мы прошли
полный круг и вернулись в ту же точку)? По двум индексам не различить,
картинка одинаковая. Классические решения — держать одну ячейку всегда
пустой (тогда полная очередь это `(tail + 1) % CAPACITY == head`) или
завести отдельный счётчик.

Мы возьмём счётчик — он проще и не тратит ячейку впустую. Храним `head`
и `count` (сколько элементов сейчас лежит), а хвост **вычисляем**:

```c
tail = (head + count) % CAPACITY;
```

Теперь всё однозначно: пуста при `count == 0`, полна при
`count == CAPACITY`. И `tail` как отдельную переменную хранить не надо —
одной причиной для рассинхронизации меньше.

### Полная программа: `11-queue.c`

```c
#include <stdio.h>

#define CAPACITY 5      /* длина кольцевого буфера */

struct Queue {
    int data[CAPACITY];
    int head;           /* индекс первого в очереди */
    int count;          /* сколько элементов сейчас лежит */
};

/* Индекс первой свободной ячейки — туда встанет следующий. */
int queue_tail(const struct Queue *q)
{
    return (q->head + q->count) % CAPACITY;
}

/* Встаём в хвост. 1 — встали, 0 — очередь полна. */
int enqueue(struct Queue *q, int value)
{
    if (q->count == CAPACITY) {
        return 0;
    }
    q->data[queue_tail(q)] = value;
    q->count++;
    return 1;
}

/* Забираем из головы в *out. 1 — забрали, 0 — очередь пуста. */
int dequeue(struct Queue *q, int *out)
{
    if (q->count == 0) {
        return 0;
    }
    *out = q->data[q->head];
    q->head = (q->head + 1) % CAPACITY;
    q->count--;
    return 1;
}

/* Ставит value в очередь и печатает, что получилось. */
void try_enqueue(struct Queue *q, int value)
{
    int cell = queue_tail(q);           /* куда встанет — до вставки */
    if (enqueue(q, value)) {
        printf("enqueue %d -> ячейка %d (в очереди %d)\n",
               value, cell, q->count);
    } else {
        printf("enqueue %d: очередь полна\n", value);
    }
}

int main(void)
{
    struct Queue q;
    q.head = 0;
    q.count = 0;

    /* Шесть человек на пять мест — последний не влезет. */
    for (int value = 1; value <= 6; value++) {
        try_enqueue(&q, value);
    }

    /* Обслуживаем троих: голова уезжает вправо, слева пусто. */
    int x;
    for (int k = 0; k < 3; k++) {
        if (dequeue(&q, &x)) {
            printf("dequeue %d (осталось %d, head=%d)\n", x, q.count, q.head);
        }
    }

    /* Кольцо в деле: новые встают на освободившиеся ячейки в начале. */
    for (int value = 6; value <= 8; value++) {
        try_enqueue(&q, value);
    }

    while (dequeue(&q, &x)) {
        printf("dequeue %d (осталось %d, head=%d)\n", x, q.count, q.head);
    }

    /* Ещё один dequeue на пустой очереди: отказ, а не падение. */
    if (dequeue(&q, &x) == 0) {
        printf("dequeue на пустой очереди: вернул 0\n");
    }

    return 0;
}
```

Разбор:

- `queue_tail` — вся арифметика кольца в одном месте. Если голова на 3,
  а стоят двое, следующий встанет на `(3 + 2) % 5 = 0`, то есть в самое
  начало массива. Именно это нам и нужно.
- `enqueue` и `dequeue` устроены как `push`/`pop`: статус наружу,
  значение через `*out`.
- `void try_enqueue(...)` — вспомогательная функция ради печати. Она
  спрашивает `queue_tail` **до** вставки: после `enqueue` счётчик уже
  изменится, и ответ будет про следующую ячейку, а не про эту. Мелочь, о
  которую легко споткнуться.
- `q->head = (q->head + 1) % CAPACITY;` — голова тоже умеет
  заворачиваться в начало кольца.

## Часть 4. Связный список

### Зачем он, если есть массив

У массива (даже растущего) есть слабое место: чтобы вставить элемент в
**середину** или в **начало**, надо сдвинуть всё, что правее, — это
копирование, O(n). Связный список вставляет в начало за O(1): за одни и
те же три шага, сколько бы узлов ни было. И не требует непрерывного
куска памяти: узлы могут лежать где угодно, лишь бы каждый знал,
**где следующий**.

Плата за это — потеря быстрого доступа по индексу. В массиве 500-й
элемент `a[499]` достаётся за одно действие. В списке, чтобы добраться
до 500-го узла, придётся начать с головы и пройти по `next` 499 раз.
Каждая структура данных за что-то платит.

**Связный список** (linked list) — цепочка **узлов** (nodes). Каждый узел
хранит своё значение и адрес (указатель) на следующий узел. Последний
узел указывает в `NULL` — «дальше никого».

Картинка цепочки из трёх узлов:

```text
head
 │
 ▼
[3 | ·]──▶[2 | ·]──▶[1 | ·]──▶ NULL
```

В каждой клетке слева значение, справа стрелка `next`. `head` — наш
единственный вход в список: указатель на первый узел. Потеряешь `head` —
потеряешь весь список.

### Описываем узел через `struct`

Вот ради чего мы изучали структуры:

```c
struct Node {
    int value;              /* полезные данные узла */
    struct Node *next;      /* адрес следующего узла (или NULL) */
};
```

- `int value;` — то, что узел хранит.
- `struct Node *next;` — указатель на **такой же** узел. Заметь: внутри
  определения `struct Node` мы уже ссылаемся на `struct Node *`. Так
  можно — это указатель (адрес), его размер компилятору известен заранее,
  даже пока сам тип ещё описывается. А вот поле `struct Node next;` (без
  звёздочки) написать нельзя: получилась бы структура, содержащая саму
  себя, бесконечного размера. Компилятор такое отвергнет.

Узел, ссылающийся на узел того же типа, — и делает цепочку цепочкой.

### Добавление в начало — по шагам

Пусть в списке уже `2 -> 1 -> NULL`, и мы хотим добавить `3`. Три шага:

1. Создаём новый узел через `malloc`, кладём в него `value = 3`.
2. Говорим новому узлу смотреть туда, куда сейчас смотрит `head`:
   `node->next = head;` — то есть на старый первый узел (`2`).
3. Делаем новый узел головой: `head = node;`.

До вставки:

```text
head ──▶ [2|·] ──▶ [1|·] ──▶ NULL
```

Шаг 1–2: создали `[3|·]` и направили его `next` на текущую голову:

```text
        [3|·]
           │ next
           ▼
head ──▶ [2|·] ──▶ [1|·] ──▶ NULL
```

Шаг 3: переставили `head` на новый узел:

```text
head ──▶ [3|·] ──▶ [2|·] ──▶ [1|·] ──▶ NULL
```

Порядок шагов 2 и 3 **нельзя менять**. Если сначала сделать `head = node`,
то адрес старой головы пропадёт: `head` уже указывает на новый узел, а
`node->next` ещё не выставлен. Это называется **потеря головы списка** —
вся остальная цепочка станет недостижимой и утечёт. Сначала
`node->next = head`, потом `head = node`.

Пустой список (`head == NULL`) обрабатывается тем же кодом сам собой:
`node->next` получит `NULL`, и новый узел окажется единственным и
последним. Отдельный `if` не нужен.

### Удаление головы

Убрать первый узел — три строчки, но порядок опять решает всё:

```c
struct Node *pop_front(struct Node *head)
{
    if (head == NULL) {
        return NULL;                    /* удалять нечего */
    }
    struct Node *rest = head->next;     /* СНАЧАЛА запомнили хвост */
    free(head);                         /* потом освободили голову */
    return rest;
}
```

Если сделать наоборот — сначала `free(head)`, потом `head->next` — мы
прочитаем поле из уже уничтоженного узла. Разберём это подробно чуть
ниже, на живом примере.

Функция возвращает новую голову, а вызывающий её запоминает:
`head = pop_front(head);`. Так принято, когда операция может изменить
голову: возвращаем актуальный `head` наружу.

### Удаление последнего

С последним узлом сложнее: чтобы отцепить его, нужен **предпоследний** —
именно у него надо обнулить `next`. А назад по односвязному списку не
пройдёшь, стрелки только вперёд. Значит, идём с головы и ищем узел, у
которого `next->next == NULL`:

```c
struct Node *pop_back(struct Node *head)
{
    if (head == NULL) {
        return NULL;                    /* удалять нечего */
    }
    if (head->next == NULL) {           /* в списке всего один узел */
        free(head);
        return NULL;                    /* список опустел */
    }
    struct Node *cur = head;
    while (cur->next->next != NULL) {   /* ищем ПРЕДпоследний узел */
        cur = cur->next;
    }
    free(cur->next);                    /* убрали последний */
    cur->next = NULL;                   /* предпоследний стал последним */
    return head;
}
```

Три случая, и все три обязательны:

- **список пуст** — делать нечего, возвращаем `NULL`. Без этой проверки
  `head->next` разыменовал бы `NULL` и программа упала бы;
- **ровно один узел** — предпоследнего не существует, поэтому просто
  освобождаем голову и возвращаем `NULL` (список опустел). Без этой
  ветки условие `cur->next->next` полезло бы в `NULL->next`;
- **два и больше** — идём до предпоследнего и отцепляем хвост.

`cur->next->next` читается по стрелкам слева направо: «у узла `cur` поле
`next`; у того узла, в свою очередь, поле `next`». Цикл встаёт, когда эта
двойная стрелка упирается в `NULL`, — значит, `cur->next` и есть
последний узел.

И `cur->next = NULL;` не забудь: иначе предпоследний продолжит указывать
на освобождённую память, и следующий же обход прочитает мёртвый узел.

Заметь цену: чтобы удалить последний узел, пришлось пройти весь список
от головы. Удаление с конца у односвязного списка — O(n), а удаление
головы — O(1).

### Освобождение всего списка и главная ошибка

Обход: заводим «бегунок» `cur`, ставим на `head`, и пока он не `NULL`,
работаем с `cur->value` и прыгаем дальше: `cur = cur->next`.

Освобождение выглядит так же, но есть нюанс. Вот как **нельзя**:

```c
#include <stdio.h>
#include <stdlib.h>

struct Node {
    int value;
    struct Node *next;
};

int main(void)
{
    struct Node *head = malloc(sizeof(struct Node));
    if (head == NULL) {
        return 1;
    }
    head->value = 1;
    head->next = NULL;

    struct Node *cur = head;
    while (cur != NULL) {
        free(cur);              /* сначала освободили... */
        cur = cur->next;        /* ...а потом читаем из мёртвого узла */
    }
    printf("список освобождён\n");

}
```

После `free(cur)` узел больше не наш: система вправе отдать эту память
кому угодно и перезаписать. А мы лезем в него за `next`. Запускаем
обычной сборкой:

void free_list(struct Node *head)

итерацию, и заводить её снаружи незачем.

### Полная программа: `11-list.c`

```c
#include <stdio.h>
#include <stdlib.h>

struct Node {
    int value;              /* полезные данные узла */
    struct Node *next;      /* адрес следующего узла (или NULL) */
};

/* Создаёт узел со значением value, который смотрит на next.
 * Возвращает NULL, если памяти не дали. */
struct Node *make_node(int value, struct Node *next)
{
    struct Node *node = malloc(sizeof(struct Node));
    if (node == NULL) {
        return NULL;
    }
    node->value = value;
    node->next = next;
    return node;
}

/* Печатает список: "список: 3 -> 2 -> 1 -> NULL". */
void print_list(const struct Node *head)
{
    printf("список: ");
    for (const struct Node *cur = head; cur != NULL; cur = cur->next) {
        printf("%d -> ", cur->value);
    }
    printf("NULL\n");
}

/* Удаляет первый узел. Возвращает новую голову. */
struct Node *pop_front(struct Node *head)
{
    if (head == NULL) {
        return NULL;                    /* удалять нечего */
    }
    struct Node *rest = head->next;     /* СНАЧАЛА запомнили хвост */
    free(head);                         /* потом освободили голову */
    return rest;
}

/* Удаляет последний узел. Возвращает голову (возможно, новую). */
struct Node *pop_back(struct Node *head)
{
    if (head == NULL) {
        return NULL;                    /* удалять нечего */
    }
    if (head->next == NULL) {           /* в списке всего один узел */
        free(head);
        return NULL;                    /* список опустел */
    }
    struct Node *cur = head;
    while (cur->next->next != NULL) {   /* ищем ПРЕДпоследний узел */
        cur = cur->next;
    }
    free(cur->next);                    /* убрали последний */
    cur->next = NULL;                   /* предпоследний стал последним */
    return head;
}

/* Освобождает весь список: на каждый malloc свой free. */
void free_list(struct Node *head)
{
    struct Node *cur = head;
    while (cur != NULL) {
        struct Node *next = cur->next;  /* СНАЧАЛА запомнили следующий */
        free(cur);                      /* потом удалили текущий */
        cur = next;                     /* перешли к запомненному */
    }
}

int main(void)
{
    struct Node *head = NULL;           /* пустой список */

    /* Добавляем 1..5 в начало списка. */
    for (int value = 1; value <= 5; value++) {
        struct Node *node = make_node(value, head);
        if (node == NULL) {
            printf("Не хватило памяти\n");
            free_list(head);            /* уже выделенное — вернуть */
            return 1;
        }
        head = node;                    /* новый узел стал головой */
        printf("добавили %d\n", value);
    }
    print_list(head);

    head = pop_front(head);
    printf("удалили голову:\n");
    print_list(head);

    printf("удаляем с конца, пока не опустеет:\n");
    while (head != NULL) {
        head = pop_back(head);
        print_list(head);
    }

    head = pop_back(head);              /* удаление из пустого списка */
    if (head == NULL) {
        printf("pop_back на пустом списке: голова так и осталась NULL\n");
    }

    /* Соберём список заново и освободим его одним махом. */
    for (int value = 10; value <= 30; value += 10) {
        struct Node *node = make_node(value, head);
        if (node == NULL) {
            printf("Не хватило памяти\n");
            free_list(head);
            return 1;
        }
        head = node;
    }
    print_list(head);

    free_list(head);
    head = NULL;                        /* адреса больше не действуют */
    printf("free_list: весь список освобождён\n");
    print_list(head);

    return 0;
}
```

Разбор оставшихся мест:

- `struct Node *head = NULL;` — пустой список. `NULL` здесь значит «узлов
  ещё нет». Всегда инициализируй голову в `NULL`: без этого в ней мусор,
  и первый же обход улетит по случайному адресу.
- `make_node` — вся возня с `malloc` в одном месте. `malloc(sizeof(struct
  Node))` просит память под **один** узел; `sizeof` сам посчитает нужный
  размер. Функция возвращает `NULL`, если памяти не дали, и это
  однозначный сигнал: `NULL` — не узел, тут спутать не с чем (в отличие
  от истории с `pop` и `-1`).
- проверка `if (node == NULL)` в `main` — а перед выходом `free_list`,
  чтобы не бросить уже выделенные узлы. В маленькой программе система и
  так всё вернёт при выходе, но привычка отпускать своё — правильная.
- `const struct Node *head` у `print_list` — печать список не меняет, и
  `const` это фиксирует.
- цикл обхода `for (cur = head; cur != NULL; cur = cur->next)` — пока
  бегунок указывает на узел, печатаем и сдвигаемся по `next`. У
  последнего узла `next` равен `NULL`, условие станет ложным, цикл
  закончится. На пустом списке цикл не выполнится ни разу и напечатается
  просто `список: NULL`.
- `head = NULL;` после `free_list` — сам `free_list` голову обнулить не
  может, она у него копия параметра. Не обнулишь — в `head` останется
  адрес освобождённого узла, и любое обращение по нему будет тем самым
  use-after-free. Такой указатель называют **висячим** (dangling).

### Проверяем

```text
$ cc -std=c11 -Wall -Wextra -O2 11-list.c -o 11-list
$ ./11-list
добавили 1
добавили 2
добавили 3
добавили 4
добавили 5
список: 5 -> 4 -> 3 -> 2 -> 1 -> NULL
удалили голову:
список: 4 -> 3 -> 2 -> 1 -> NULL
удаляем с конца, пока не опустеет:
список: 4 -> 3 -> 2 -> NULL
список: 4 -> 3 -> NULL
список: 4 -> NULL
список: NULL
pop_back на пустом списке: голова так и осталась NULL
список: 30 -> 20 -> 10 -> NULL
free_list: весь список освобождён
список: NULL
```

Разберём по кускам. Добавляли 1, 2, 3, 4, 5, а список вышел
`5 -> 4 -> 3 -> 2 -> 1`. Логично: каждый новый узел вставал **в начало**,
оттесняя предыдущие. Вставка в начало вместе с `pop_front` — это готовый
стек: последним пришёл — первым ушёл.

`pop_front` снял пятёрку — голова сменилась мгновенно, ничего искать не
пришлось. Дальше четыре `pop_back` подряд съели список с конца: 1, 2, 3
и, наконец, одинокая четвёрка — тот самый особый случай «в списке всего
один узел». Пятый `pop_back` уже на пустом списке спокойно вернул `NULL`.

Потом список собрался заново и был убит целиком одним `free_list`.
Финальный `список: NULL` доказывает, что голова обнулена.

Теперь то, ради чего затевалась вся аккуратность, — санитайзеры. Собери и
запусти так:

```text
$ cc -std=c11 -Wall -Wextra -O1 -g -fsanitize=address,undefined \
     11-list.c -o 11-list-san
$ ./11-list-san
```

Вывод будет в точности тот же, что и выше, — ни одной лишней строки, ни
единой жалобы: ни один узел не прочитали после смерти, за границы не
вылезли. А утечки, как договорились, проверяем `leaks`:

```text
$ cc -std=c11 -Wall -Wextra -g 11-list.c -o 11-list-g
$ leaks --atExit -- ./11-list-g | grep "leaks for"
Process 51190: 0 leaks for 0 total leaked bytes.
```

Восемь `malloc` (пять узлов, потом ещё три) и восемь `free`: каждый
выданный узел вернули. Именно так и должна выглядеть программа с ручным
управлением памятью.

## Сколько стоит каждая операция

Сведём вместе, что мы узнали по дороге. `n` — сколько элементов сейчас
лежит в структуре.

```text
растущий массив
  доступ к элементу по индексу       O(1)
  добавить в конец                   O(1) амортизированно,
                                     отдельная вставка до O(n)
  вставить в начало или в середину   O(n): сдвиг всех правее
  найти значение                     O(n): смотрим по очереди

стек на массиве
  push, pop, peek                    O(1)

очередь на кольцевом буфере
  enqueue, dequeue                   O(1)
  (наивная, со сдвигом влево         dequeue O(n))

односвязный список
  вставить в начало, pop_front       O(1)
  pop_back, вставить в конец         O(n): ищем последний узел
  добраться до k-го узла             O(k)
  найти значение                     O(n)
```

Стек и очередь у нас фиксированной вместимости, поэтому переездов у них
нет вовсе и все операции — честные O(1), без оговорок. Вставку в конец
списка можно тоже сделать O(1), если хранить рядом с `head` ещё и
указатель на последний узел, — но его придётся аккуратно обновлять в
каждой операции.

## Частые ошибки

**Забытая `;` после `struct`.** После закрывающей `}` определения
структуры точка с запятой обязательна: `struct Node { ... };`. Забудешь —
clang скажет прямо:

```text
box2.c:5:2: error: expected ';' after struct
    5 | }
      |  ^
      |  ;
```

**Точка вместо стрелки (и наоборот).** Указатель — `p->field`, сама
структура — `s.field`. Тут компилятор тоже помогает и даже подсказывает
замену:

```text
box.c:7:6: error: member reference type 'struct Box *' is a pointer;
           did you mean to use '->'?
    7 |     p.v = 1;
      |     ~^
      |      ->
```

Это тот приятный случай, когда сообщение об ошибке можно просто выполнить
буквально.

**`data = realloc(data, ...)` напрямую.** При неудаче `realloc` вернёт
`NULL`, ты затрёшь единственный адрес старого блока — и потеряешь и
данные, и возможность освободить память. Пиши во временный указатель.

**Путать `count` и `capacity`.** «Сколько лежит» и «сколько влезает» —
разные числа. Записать в `data[capacity]` — выход за границу; печатать
`capacity` элементов вместо `count` — печать мусора.

**Не проверять `malloc` на `NULL`.** `malloc` может отказать. Обращение
`node->value` при `node == NULL` — падение сразу.

**Читать/писать за границей массива.** `data[top]` при `top == CAPACITY`
и `data[top]` при `top == -1` — обе беды из этой главы. Проверки на
пустоту и на переполнение обязательны, и делать их надо **до**
обращения, а не после.

**Возвращать «особое» значение вместо статуса.** `pop`, отдающий `-1`
при пустом стеке, ломается, как только в стеке появится `-1`. Отдавай
успех/неуспех отдельно, а значение — через указатель.

**Потеря головы списка.** Сначала `node->next = head;`, только потом
`head = node;`. Перепутаешь порядок — вся цепочка станет недостижимой.

**`free` перед чтением `next`.** В цикле освобождения сначала запомни
`cur->next` во временную переменную, потом `free(cur)`. Мы видели, чем
это кончается: `heap-use-after-free`.

**Висячий указатель после `free`.** Освободил — обнули: `head = NULL`.
Иначе в переменной остаётся адрес чужой теперь памяти, и однажды по нему
обязательно кто-нибудь пройдётся.

**Утечки памяти.** На каждый `malloc`/`realloc` однажды должен прийтись
`free`. У растущего массива — один `free` в конце; у списка — по одному
`free` на каждый узел. Стек и очередь у нас на массиве внутри структуры,
там `free` не нужен вовсе: память освободится сама, когда переменная
выйдет из области видимости.

**Не запускать под санитайзерами.** Половина ошибок этой главы не
проявляется на маленьких примерах: программа «работает», а память тихо
портится. `-fsanitize=address,undefined` находит их за секунду, а
утечки на маке — `leaks --atExit`. Возьми за правило гонять так любой
код с указателями.

## Упражнения

1. Заведи в растущем массиве счётчик переездов и после ста вставок
   напечатай, сколько раз массив рос и до какой вместимости дорос.
   Проверь себя до запуска: при старте с двух ячеек вместимость идёт
   2, 4, 8, 16… — какая из них первой перевалит за 100 и сколько
   удвоений для этого понадобится?
   Ожидаемый результат: `элементов: 100, переездов: 6, вместимость: 128`
   (2 → 4 → 8 → 16 → 32 → 64 → 128, шесть удвоений).
2. Сделай стек символьным: `char data[CAPACITY]` вместо `int`. Положи в
   него слово по буквам, потом снимай по одной и печатай — на экране
   слово развернётся задом наперёд. Сравни с переворотом из главы 10:
   стек делает то же самое, но без индексов. Не забудь взять
   `CAPACITY` не меньше длины слова, иначе `push` откажет на хвосте.
   Ожидаемый результат: для `hello` — `olleh`.
3. Напиши с помощью стека проверку **парности скобок**: строка вида
   `([]{})` правильная, а `([)]` и `((` — нет. Открывающую скобку кладём
   в стек, на закрывающей снимаем и сверяем пару. В конце стек должен
   оказаться пустым. Если на закрывающей скобке стек уже пуст — строка
   тоже неправильная.
   Ожидаемый результат: `([]{})` — правильная; `([)]` — неправильная
   (к `)` на вершине лежит `[`); `((` — неправильная (стек не опустел);
   `)(` — неправильная (закрывать нечего); пустая строка и `a(b)c` —
   правильные.
4. Добавь в очередь счётчик `total` — сколько элементов прошло через неё
   за всё время. Он только растёт при удачном `enqueue` и никогда не
   уменьшается. Ожидаемый результат: с тем же `main`, что в
   `11-queue.c`, `total` в конце равен 8 — пять первых встали, шестой
   получил отказ, потом встали ещё трое.
5. Напиши для списка функцию `int length(const struct Node *head)`,
   возвращающую число узлов, и `int contains(const struct Node *head,
   int x)`, отвечающую 1, если значение `x` в списке есть. Обе — обычным
   обходом, обе O(n). Ожидаемый результат: для списка
   `5 -> 4 -> 3 -> 2 -> 1` — длина 5, `contains(head, 3)` равно 1,
   `contains(head, 7)` равно 0; для пустого списка длина 0.
6. Добавь в список вставку **в конец**, чтобы порядок сохранялся:
   `1 -> 2 -> 3 -> NULL`. Подсказка: если список пуст, новый узел
   становится головой; иначе дойди обходом до узла, у которого
   `next == NULL`, и подвесь новый к нему. Не забудь проверить
   санитайзером и `leaks`. Ожидаемый результат: после вставок 1, 2, 3 —
   `список: 1 -> 2 -> 3 -> NULL`, санитайзер молчит, `leaks` показывает
   0 утечек. Каждая такая вставка — O(n), потому что идём до конца.
7. (Посложнее.) Напиши `struct Node *reverse(struct Node *head)` —
   разворот списка на месте, без выделения новых узлов. Подсказка: иди
   по списку с тремя указателями (`prev`, `cur`, `next`) и на каждом
   шаге переставляй `cur->next` на `prev`. В конце головой станет `prev`.
   Ожидаемый результат: `5 -> 4 -> 3 -> 2 -> 1 -> NULL` превращается в
   `1 -> 2 -> 3 -> 4 -> 5 -> NULL`; пустой список остаётся пустым,
   список из одного узла — тем же самым.

## Что мы получили

Теперь в твоём арсенале четыре структуры данных и понимание, когда какая
нужна.

**Растущий массив** — когда нужен быстрый доступ по индексу, а размер
заранее неизвестен: `realloc` с удвоением даёт амортизированную O(1) на
вставку, а «плюс один» стоит квадрат от числа вставок. **Стек** — когда важен обратный порядок, LIFO.
**Очередь** — когда важен прямой порядок, FIFO, на кольцевом буфере, где
`count` избавляет от путаницы «пусто или полно». **Связный список** —
гибкая цепочка узлов на `struct` и указателях, с дешёвой вставкой в
начало и ручным управлением памятью.

Плюс мы освоили `struct`, точку, стрелку `->`, `typedef` и приём «статус
из функции, значение через указатель» — без всего этого в Си дальше
никуда. И завели привычку гонять код с указателями под
`-fsanitize=address,undefined`.

На этом часть про базовые алгоритмы и структуры данных закончена. Дальше
начинается самое весёлое — **игры**. В следующей главе напишем первую:
классическую **«Угадай число»**. Компьютер загадает число, ты будешь
гадать, а программа — подсказывать «больше» или «меньше». Там пригодится
почти всё, что мы прошли: ввод, цикл, ветвления, а ещё появятся
случайные числа. Идём играть.

Итоговые программы главы — `code/11-dynarray.c`, `code/11-stack.c`,
`code/11-queue.c`, `code/11-list.c`; замер стратегий роста —
`code/11-growth.c`.
