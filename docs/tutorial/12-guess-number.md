# Глава 12. Игра «Угадай число»

Часть про алгоритмы позади. Теперь начинается самое весёлое — **игры**.
Мы напишем настоящие маленькие программы, в которые можно играть, и
по дороге выучим то, чего ещё не касались.

Первая игра — классика всех времён. Компьютер загадывает число от 1 до
100, а ты пытаешься его угадать. После каждой попытки программа
подсказывает: «больше» или «меньше». В конце она поздравляет тебя и
сообщает, за сколько попыток ты справился.

Звучит просто, но по пути мы разберём важную новую тему — **случайные
числа**. Без них почти ни одна игра не обходится: бросок кубика,
перемешивание колоды, появление врага в неожиданном месте — всё это
случайность.

## Что мы сделаем

К концу главы у тебя будет программа, которая:

- загадывает **случайное** число от 1 до 100 (и каждый запуск — новое);
- в цикле спрашивает твою догадку;
- отвечает «Больше» или «Меньше», подводя тебя к ответу;
- считает попытки;
- поздравляет, когда ты угадал, и не падает, если ввести ерунду.

Новое в этой главе:

- генератор случайных чисел: `rand`, `srand`, `time`;
- как из `rand()` получить число в нужном диапазоне (`% 100 + 1`);
- игровой цикл `while`, который крутится, **пока не угадал**;
- защита от неправильного ввода.

## Разбираем задачу руками

Сыграем партию на бумаге. Пусть компьютер загадал **45** (мы-то этого
не знаем, диапазон 1..100).

Самая глупая стратегия — называть числа подряд: 1, 2, 3… В худшем
случае это 100 попыток. Долго.

Умнее — каждый раз бить в **середину** оставшегося диапазона. Это та
самая идея, что и в бинарном поиске из главы 7, только теперь её
выполняешь ты, а «массив» — это числа от 1 до 100.

```text
диапазон 1..100, говорю 50  → «Меньше» (значит, секрет < 50) → 1..49
диапазон 1..49,  говорю 25  → «Больше» (значит, секрет > 25) → 26..49
диапазон 26..49, говорю 37  → «Больше» → 38..49
диапазон 38..49, говорю 43  → «Больше» → 44..49
диапазон 44..49, говорю 46  → «Меньше» → 44..45
диапазон 44..45, говорю 44  → «Больше» → 45..45
говорю 45 → «Угадал!»
```

Семь попыток вместо сотни. Каждый вопрос делит диапазон пополам,
поэтому даже для 100 чисел хватает максимум семи догадок. Эту
стратегию мы потом подарим компьютеру в упражнениях — пусть он сам
угадывает твоё число.

А пока загадывать будет машина. Значит, сперва надо научить её
придумывать случайное число.

## Шаг 1. Откуда брать случайность

В Си генератор случайных чисел живёт в заголовке `<stdlib.h>`
(*standard library* — «стандартная библиотека»). Главная функция —
`rand` (от *random* — «случайный»). Сигнатура у неё простейшая:

```c
int rand(void);
```

Читается так: «`rand` не принимает аргументов (`void` в скобках) и
возвращает `int`». Возвращённое число лежит в диапазоне от 0 до
константы `RAND_MAX` — она объявлена в том же `<stdlib.h>`. Стандарт
обещает только, что `RAND_MAX` не меньше 32767; на практике обычно
больше. Напечатай `printf("RAND_MAX = %d\n", RAND_MAX);` — у меня
вышло `RAND_MAX = 2147483647`, ровно максимальное значение `int`. У
тебя может быть другое число: `RAND_MAX` зависит от системы, потому
его и не зашивают в код, а берут по имени.

Теперь напечатаем три «случайных» числа:

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    printf("%d\n", rand());
    printf("%d\n", rand());
    printf("%d\n", rand());
    return 0;
}
```

Новое:

- `#include <stdlib.h>` — подключаем библиотеку, где лежит `rand`.
- `rand()` — вызов функции без аргументов (скобки пустые). Возвращает
  целое число, которое мы тут же печатаем через `%d`.

Запустим:

```text
16807
282475249
1622650073
```

Числа и правда выглядят случайными. Но запусти программу **ещё раз**:

```text
16807
282475249
1622650073
```

Те же самые! И в третий раз будут те же. Это и есть проблема.

(Конкретные три числа у тебя могут отличаться: разные системы считают
`rand` по разным формулам. А вот **повторяемость** будет ровно такая
же — в этом и суть.)

## Шаг 2. Почему `rand()` повторяется и что такое «засев»

`rand()` не достаёт числа из воздуха. Внутри он считает их по формуле
из предыдущего числа. Самое первое число он берёт от стартового
значения — **зерна** (англ. *seed*). По умолчанию зерно всегда одно и
то же, поэтому и вся цепочка чисел каждый запуск одинаковая.

Для игры это никуда не годится: компьютер будет загадывать одно и то
же число при каждом старте, и угадать его станет скучно.

Решение — **засеять** генератор разным зерном перед игрой. За это
отвечает функция `srand` (*seed random* — «засеять случайность»), тоже
из `<stdlib.h>`:

```c
void srand(unsigned int seed);
```

Она принимает одно беззнаковое целое — зерно — и ничего не возвращает
(`void`). Пользуются ей так:

```c
srand(42);   /* засеяли зерном 42 */
```

Но если всегда писать `srand(42)`, зерно опять постоянное — толку ноль.
Нам нужно зерно, которое **само меняется** от запуска к запуску.
Идеальный кандидат — текущее время: оно не стоит на месте.

## Шаг 3. Зерно из текущего времени — `time`

Узнать текущее время умеет функция `time` из заголовка `<time.h>`
(*time* — «время»). Вызов `time(NULL)` возвращает число секунд,
прошедших с 1 января 1970 года. Каждую секунду это число другое —
отличный источник свежего зерна.

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

int main(void)
{
    srand((unsigned int)time(NULL));

    printf("%d\n", rand());
    printf("%d\n", rand());
    printf("%d\n", rand());
    return 0;
}
```

Разбор новой строки `srand((unsigned int)time(NULL));`:

- `#include <time.h>` — подключили заголовок ради `time`.
- `time(NULL)` — спрашиваем текущее время. Аргумент `NULL` означает
  «результат никуда дополнительно не записывай, просто верни его»
  (`time` умеет ещё писать ответ по переданному адресу, но нам это не
  нужно).
- `(unsigned int)` — приведение типа (мы видели приведения в главе 3).
  `time` возвращает специальный тип `time_t`, а `srand` ждёт
  `unsigned int` («беззнаковое целое» — целое без минуса). Приводим
  одно к другому, чтобы компилятор не ворчал.
- `srand(...)` — засеваем генератор полученным зерном.

Теперь каждый запуск даёт новую тройку чисел. Случайность настоящая.

### Почему `srand` зовут ровно один раз

Правило звучит так: **`srand` вызывают один раз, в самом начале
программы.** Дальше сколько угодно дёргают `rand()` — он сам
продвигается по цепочке.

Новички часто «чинят» случайность наоборот: раз `srand` даёт свежесть,
надо звать его почаще. Посмотрим, что из этого выходит:

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

int main(void)
{
    for (int i = 0; i < 5; i++) {
        srand((unsigned int)time(NULL));   /* так делать НЕ надо */
        printf("%d\n", rand() % 100 + 1);
    }
    return 0;
}
```

```text
34
34
34
34
34
```

Пять одинаковых чисел. Причина простая: `time(NULL)` меняется раз в
**секунду**, а пять витков цикла компьютер проскакивает за
микросекунды. Значит, все пять раз зерно одно и то же, и `rand()` пять
раз стартует цепочку заново с одного и того же места — выдавая одно и
то же первое число. Запусти программу через пару секунд — получишь
пять `55` вместо пяти `34`: время сменилось, а близнецы никуда не
делись. Так что `srand` — один раз, и только один.

## Шаг 4. Сужаем диапазон до 1..100

`rand()` возвращает огромное число (до миллиардов), а нам нужно
от 1 до 100. Тут на помощь приходит **остаток от деления** `%`,
который мы разбирали в главе 2.

Вспомни: `a % b` — это остаток от деления `a` на `b`. Каким бы большим
ни было `a`, остаток от деления на 100 всегда попадает в диапазон
**0..99** (остаток не может быть равен делителю или больше него).

```c
rand() % 100        // число от 0 до 99
```

Нам нужно 1..100, а не 0..99. Просто прибавим 1 — весь диапазон
сдвинется на единицу вверх:

```c
rand() % 100 + 1    // число от 1 до 100
```

Разберём по шагам на примере. Пусть `rand()` вернул 16807 — то самое
первое число из шага 1.

- `16807 % 100` = 7 (последние две цифры — это и есть остаток от
  деления на 100).
- `7 + 1` = 8.

Получили 8 — годное число из диапазона 1..100. Если бы остаток вышел
0, после `+ 1` стало бы 1 (нижняя граница); если остаток 99 — после
`+ 1` станет 100 (верхняя). Концы диапазона на месте, ни 1, ни 100 не
потеряны.

Общая формула на будущее: чтобы получить число от `min` до `max`
включительно, пиши `rand() % (max - min + 1) + min`. Для 1..100 это
`rand() % 100 + 1`.

Проверим, что числа правда попадают в диапазон:

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

int main(void)
{
    srand((unsigned int)time(NULL));
    for (int i = 0; i < 5; i++) {
        printf("%d\n", rand() % 100 + 1);
    }
    return 0;
}
```

```text
88
83
74
23
14
```

Все пять — в пределах 1..100. Генератор загадок готов.

## Шаг 5. Одна попытка угадать

Сложим первую наивную версию игры: загадываем число, спрашиваем
**одну** догадку, сравниваем.

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

int main(void)
{
    srand((unsigned int)time(NULL));
    int secret = rand() % 100 + 1;

    int guess;
    printf("Угадай число от 1 до 100: ");
    scanf("%d", &guess);

    if (guess < secret) {
        printf("Больше.\n");
    } else if (guess > secret) {
        printf("Меньше.\n");
    } else {
        printf("Угадал!\n");
    }
    return 0;
}
```

Разбор:

- `int secret = rand() % 100 + 1;` — загадали число и положили в
  переменную `secret` («секрет»). Игрок его не видит.
- `scanf("%d", &guess);` — читаем догадку. Не забываем `&` перед
  `guess` (см. главу 2): `scanf` нужен **адрес**, куда записать ввод.
- сравнение в три ветки:
  - `guess < secret` — игрок назвал **меньше**, чем загадано, значит,
    нужное число **больше**. Печатаем «Больше».
  - `guess > secret` — наоборот, «Меньше».
  - иначе числа равны — «Угадал!».

Запуск:

```text
Угадай число от 1 до 100: 50
Меньше.
```

Работает, но играть невозможно: программа задаёт **один** вопрос и
завершается. Чтобы реально угадать, придётся запускать её снова и
снова — и каждый раз будет новое число. Нужен **цикл**, который
повторяет вопрос, пока не угадаешь.

## Шаг 6. Игровой цикл — спрашиваем, пока не угадал

Обернём вопрос и сравнение в цикл `while`. Условие цикла — «пока
догадка не равна секрету»:

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

int main(void)
{
    srand((unsigned int)time(NULL));
    int secret = rand() % 100 + 1;
    int guess = 0;

    printf("Я загадал число от 1 до 100. Угадай!\n");

    while (guess != secret) {
        printf("Твой вариант: ");
        scanf("%d", &guess);

        if (guess < secret) {
            printf("Больше.\n");
        } else if (guess > secret) {
            printf("Меньше.\n");
        } else {
            printf("Угадал!\n");
        }
    }
    return 0;
}
```

Что изменилось:

- `int guess = 0;` — теперь догадку **обязательно** задаём заранее
  значением 0. Почему именно 0? Потому что условие `while` проверяется
  **до** первого ввода, а секрет всегда в диапазоне 1..100. Значит,
  `0 != secret` гарантированно истинно, и цикл точно зайдёт внутрь
  хотя бы раз. Если бы мы оставили `guess` без значения, там лежал бы
  мусор — могло бы случайно совпасть с секретом (маловероятно, но
  оставлять переменную без значения нельзя).
- `while (guess != secret)` — «пока `guess` **не равно** `secret`,
  повторяй тело». Оператор `!=` — «не равно» (см. главу 2). Как только
  игрок введёт число, равное секрету, условие станет ложным, и цикл
  закончится.
- внутри — тот же вопрос и то же сравнение, что и раньше, только
  теперь они повторяются.

Запуск:

```text
Я загадал число от 1 до 100. Угадай!
Твой вариант: 50
Меньше.
Твой вариант: 25
Больше.
Твой вариант: 37
Больше.
Твой вариант: 43
Больше.
Твой вариант: 45
Угадал!
```

Вот это уже игра! Цикл крутится, подсказки ведут к ответу, на верной
догадке всё завершается.

Чего не хватает? Игра не считает попытки. Добавим счётчик.

## Шаг 7. Считаем попытки

Заведём переменную-счётчик и будем увеличивать её на каждой догадке.
Приём знакомый — так мы считали в циклах в главе 2.

```c
int attempts = 0;
```

Внутри цикла, сразу после ввода, добавим:

```c
attempts++;
```

`attempts++` — увеличить `attempts` на 1 (краткая запись `attempts =
attempts + 1`). Ставим её после `scanf`, чтобы каждая введённая
догадка засчитывалась как попытка.

А в ветке «Угадал!» напечатаем итог:

```c
printf("Угадал! Это было число %d.\n", secret);
printf("Тебе понадобилось попыток: %d.\n", attempts);
```

Теперь игра поздравляет и сообщает результат. Осталась одна
неприятность — что будет, если вместо числа ввести буквы?

## Шаг 8. Защита от неправильного ввода

Проверим версию из шага 6 на прочность: вместо числа введём `abc`.
Вот что видно на экране в первые доли секунды:

```text
Я загадал число от 1 до 100. Угадай!
Твой вариант: abc
Больше.
Твой вариант: Больше.
Твой вариант: Больше.
Твой вариант: Больше.
Твой вариант: Больше.
Твой вариант: Больше.
Твой вариант: Больше.
```

Это не обрезанный вывод, а **бесконечный**: «Больше» летит сплошным
потоком, и остановить его можно только через Ctrl+C. Выше — просто то,
что успело напечататься, прежде чем я его нажал. Почему так?

`scanf("%d", &guess)` ждёт **целое число**. Когда на входе буквы, он
не может ничего прочитать: переменную `guess` не меняет (там остаётся
прежний 0), а буквы **оставляет во входном буфере** — они никуда не
делись. На следующем витке `scanf` снова натыкается на те же буквы,
снова ничего не читает, и так бесконечно. Это и есть зацикливание.
Заодно понятно, откуда именно «Больше»: `guess` так и остался нулём, а
0 меньше любого секрета из 1..100.

Такая же беда будет и в конце ввода. Если запустить программу и сразу
нажать Ctrl+D («ввод кончился»), `scanf` тоже ничего не прочитает — и
цикл снова закрутится вхолостую.

Спасает то, что `scanf` **возвращает значение** — сколько значений ему
удалось прочитать. Если он успешно прочёл наше число, вернёт 1. Если
не смог (буквы вместо цифр) — вернёт 0. А если ввод вообще закончился
(пользователь нажал Ctrl+D или ввод идёт из файла, который кончился) —
вернёт особое значение `EOF` (*end of file* — «конец ввода»). `EOF` —
это константа из `<stdio.h>`, обычно равная −1; сравнивать надо именно
с именем `EOF`, а не с −1 вручную.

Проверяем результат `scanf`:

```c
int rc = scanf("%d", &guess);
if (rc == EOF) {
    printf("\nИгра прервана. Я загадывал %d.\n", secret);
    return 0;
}
if (rc != 1) {
    printf("Это не число. Введи целое от 1 до 100.\n");
    int c;
    while ((c = getchar()) != '\n' && c != EOF) {
        /* выбрасываем мусорный ввод до конца строки */
    }
    continue;
}
```

Разбираем по кускам:

- `int rc = scanf(...)` — сохраняем результат `scanf` в переменную `rc`
  (от *return code* — «код возврата»), чтобы проверить его.
- `if (rc == EOF)` — ввод иссяк. Дальше спрашивать некого: вежливо
  прощаемся и выходим через `return 0`. Без этой проверки на конце
  ввода программа тоже зациклилась бы.
- `if (rc != 1)` — `scanf` не смог прочитать число (попались буквы).
  Сообщаем об ошибке и **чистим буфер** от застрявшего мусора:
  - `getchar()` — функция из `<stdio.h>`, читает **один символ** из
    ввода и возвращает его (или `EOF`, если ввод кончился).
  - `while ((c = getchar()) != '\n' && c != EOF)` — крутим, пока не
    дочитаем до конца строки (символ `'\n'` — перевод строки от Enter)
    или до конца ввода. Так мы выбрасываем всё, что осталось от
    неудачной попытки, и следующий `scanf` начнёт с чистого листа.
    Само тело цикла пустое — вся работа в условии.
  - `continue;` — оператор, который **прерывает текущий виток цикла** и
    переходит к проверке условия `while` заново. Мы не считаем такой
    ввод за попытку и не сравниваем мусор с секретом — просто
    спрашиваем заново.

Маленькая деталь: счётчик `attempts++` теперь должен стоять **после**
этих проверок — чтобы неудачный ввод не засчитывался как попытка.

Заодно две мелочи, которые легко проглядеть.

Пустая строка (просто Enter) `scanf("%d")` не смущает: `%d` сам
пропускает пробелы, табы и переводы строки, пока не найдёт цифры.
Лишние Enter'ы программа молча проглотит и продолжит ждать число.

А вот `50abc` похитрее: `scanf` прочитает `50`, вернёт 1, раунд пройдёт
нормально, а хвост `abc` останется в буфере и всплывёт уже на
**следующем** витке, где мы его и отловим:

```text
Я загадал число от 1 до 100. Угадай!
Твой вариант: 50abc
Меньше.
Твой вариант: Это не число. Введи целое от 1 до 100.
Твой вариант: ^D
Игра прервана. Я загадывал 45.
```

Второе приглашение выглядит пустым не потому, что программа сломалась:
ответ на него уже лежал в буфере, набирать ничего не пришлось. А `^D` в
конце — это Ctrl+D, которым я закончил игру.

## Полная программа

Собираем всё вместе. Файл — `code/12-guess.c`.

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

int main(void)
{
    srand((unsigned int)time(NULL));

    int secret = rand() % 100 + 1;
    int guess = 0;
    int attempts = 0;

    printf("Я загадал число от 1 до 100. Угадай!\n");

    while (guess != secret) {
        printf("Твой вариант: ");

        int rc = scanf("%d", &guess);
        if (rc == EOF) {           /* ввод закончился (Ctrl+D) */
            printf("\nИгра прервана. Я загадывал %d.\n", secret);
            return 0;
        }
        if (rc != 1) {             /* ввели не число */
            printf("Это не число. Введи целое от 1 до 100.\n");
            int c;
            while ((c = getchar()) != '\n' && c != EOF) {
                /* выбрасываем мусорный ввод до конца строки */
            }
            continue;
        }

        if (guess < 1 || guess > 100) {   /* мимо правил игры */
            printf("Число должно быть от 1 до 100.\n");
            continue;
        }

        attempts++;

        if (guess < secret) {
            printf("Больше.\n");
        } else if (guess > secret) {
            printf("Меньше.\n");
        } else {
            printf("Угадал! Это было число %d.\n", secret);
            printf("Тебе понадобилось попыток: %d.\n", attempts);
        }
    }

    return 0;
}
```

Единственное, чего мы ещё не обсудили, — проверка
`if (guess < 1 || guess > 100)`. Это вежливость к игроку: если он
ввёл число вне диапазона (например, 200 или −5), мы напоминаем
правила, а не говорим «Меньше». Оператор `||` — «ИЛИ» (см. главу 2):
условие истинно, если число меньше 1 **или** больше 100.

Обрати внимание, где стоит `continue` и где `attempts++`. Число вне
диапазона — такой же «не ход», как и буквы, поэтому бракуем его **до**
счётчика, и попытка не тратится. Правило одно на все проверки: сначала
отсеиваем всё, что ходом не является, и только потом считаем попытку.

И про границы. Секрет `rand() % 100 + 1` может оказаться и 1, и 100 —
оба конца в игре. Проверка `guess < 1 || guess > 100` их пропускает
(`1 < 1` ложно, `100 > 100` тоже ложно), так что назвать их разрешено.
Ошибись мы со знаком (`guess <= 1`), и два числа из ста стали бы
неугадываемыми — игра зависла бы навсегда.

## Как это работает

Пройдём по программе сверху вниз.

1. `srand((unsigned int)time(NULL))` засевает генератор текущим
   временем — один раз на старте. Благодаря этому каждый запуск даёт
   новую загадку.
2. `rand() % 100 + 1` берёт случайное число и ужимает его до
   диапазона 1..100. Результат прячем в `secret`.
3. `guess = 0` гарантирует, что цикл зайдёт внутрь хотя бы раз
   (0 не равно ни одному числу из 1..100).
4. Цикл `while (guess != secret)` крутится, пока игрок не назовёт
   секрет. Каждый виток:
   - печатаем приглашение;
   - читаем ввод и проверяем `scanf`: конец ввода → выходим; не
     число → ругаемся, чистим буфер, начинаем виток заново;
   - число вне 1..100 → напоминаем правила и тоже начинаем виток
     заново, не тратя попытку;
   - засчитываем попытку;
   - сравниваем догадку с секретом и печатаем подсказку;
   - на совпадении печатаем поздравление со счётчиком. Тут же условие
     `guess != secret` становится ложным, и цикл завершается.
5. `return 0` — программа отработала без ошибок.

Почему цикл вообще может закончиться? Потому что единственный способ
сделать `guess` равным `secret` — назвать это число, а секрет всегда
лежит в 1..100, то есть в том самом диапазоне, который мы разрешаем
вводить. Никакой «недостижимой» загадки тут не бывает.

## Частые ошибки

**Забыли `srand`.** Если не засеять генератор, `rand()` каждый запуск
выдаёт одну и ту же последовательность — компьютер будет загадывать
одно и то же число. Всегда зови `srand((unsigned int)time(NULL))` один
раз в начале.

**Зовут `srand` перед каждым `rand()`.** Частая «починка наоборот».
Мы это уже видели в шаге 3: пять витков цикла проходят за доли
секунды, `time(NULL)` за это время не меняется, и все пять чисел
выходят одинаковыми. `srand` — ровно один раз за программу.

**Используют `rand()` без диапазона.** `rand()` сам по себе возвращает
гигантское число. Без `% 100 + 1` секрет окажется где-то в миллиардах,
и угадать его нельзя. Не забывай ужимать диапазон.

**Промахнулись с `% 100` против `% 101`.** `rand() % 100` даёт 0..99.
Чтобы получить 1..100, нужно `+ 1`. Если хочешь 0..100 (101 число),
тогда `% 101`. Считай границы внимательно.

**Забыли `&` в `scanf`.** `scanf("%d", guess)` без `&` — почти
гарантированное падение (см. главу 2). Нужно `scanf("%d", &guess)`.

**Не проверяют результат `scanf`.** Если не ловить случай «введены не
цифры», программа зациклится на мусоре во входном буфере, как мы
видели в шаге 8. И то же самое случится на конце ввода: запусти
наивную версию и сразу нажми Ctrl+D — «Больше» польётся бесконечным
потоком. Поэтому проверок две: `rc == EOF` и `rc != 1`.

**Забыли почистить буфер.** Проверить `scanf` мало. Если поймать `rc
!= 1`, напечатать ругательство и просто уйти на следующий виток, буквы
так и останутся в буфере — и цикл всё равно зависнет, только теперь с
красивым сообщением. Ругательство и `getchar()`-чистка ходят парой.

**Верят `scanf` на слово при огромном числе.** `scanf("%d")` читает
только то, что влезает в `int`; что будет с числом побольше, стандарт
не определяет вовсе. Маленькая программа, которая делает
`scanf("%d", &v)` и печатает результат, показывает вот что:

```text
in=99999999999999999999   -> rc=1 v=-1
in=2147483648             -> rc=1 v=-2147483648
```

`rc` равен единице — «прочитал успешно», — а в переменной чепуха.
Спасает нас та же проверка диапазона: ни −1, ни −2147483648 в 1..100 не
попадают. Мораль: проверить результат `scanf` мало, значение тоже надо
проверять.

**Ждут от `rand() % 100` идеальной честности.** Остаток от деления
чуть-чуть перекашивает вероятности: `rand()` выдаёт 2147483648 разных
значений, на 100 это нацело не делится (в остатке 48), поэтому секреты
1..48 выпадают на один вариант чаще, чем 49..100. Разница — в восьмом
знаке, для игры её не существует. Но там, где равномерность правда
важна, `%` заменяют более аккуратным отбором.

## Упражнения

1. **Другой диапазон.** Сделай, чтобы компьютер загадывал число от 1
   до 1000. Подсказка: меняется только формула `rand() % ... + 1`.
   Сколько попыток теперь нужно при стратегии «бей в середину»?

2. **Ограничь число попыток.** Дай игроку не больше 7 попыток. Если он
   не угадал за 7 ходов — выведи «Ты проиграл, я загадывал N» и
   заверши игру. Подсказка: добавь в условие цикла проверку
   `attempts < 7` через `&&`.

3. **«Горячо/холодно».** Кроме «Больше»/«Меньше» подсказывай, насколько
   игрок близок. Если разница между догадкой и секретом меньше 5 —
   печатай «Горячо!», если меньше 15 — «Тепло», иначе — «Холодно».
   Подсказка: пригодится модуль разности. Своей функции `abs` писать не
   обязательно — можно сравнить `guess - secret` и `secret - guess`.

4. **Сыграй ещё раз.** После завершения партии спроси «Сыграем ещё?
   (1 — да, 0 — нет)» и, если игрок ввёл 1, загадай новое число и
   начни сначала. Подсказка: оберни всю игру во внешний цикл.

5. **Компьютер угадывает.** Поменяй роли: теперь **ты** загадываешь
   число (держишь его в голове), а компьютер угадывает по стратегии
   «бей в середину». Программа называет число, ты отвечаешь буквой:
   `b` — «больше», `m` — «меньше», `t` — «точно, угадал». Компьютер
   ведёт границы `low` и `high`, каждый раз называя `(low + high) / 2`,
   и сужает диапазон по твоему ответу. Это тот самый бинарный поиск из
   главы 7, только вживую. Проверь: за сколько ходов компьютер
   загоняет любое число от 1 до 100?

6. **Счётчик рекордов.** Запоминай лучший результат (наименьшее число
   попыток) за несколько партий и показывай его перед каждой новой
   игрой.

## Что мы получили

Мы написали первую полноценную игру и заодно открыли тему, без которой
дальше никуда, — **случайные числа**. Теперь ты знаешь, как засеять
генератор временем (`srand((unsigned int)time(NULL))`), как получить
случайное число (`rand()`) и как загнать его в нужный диапазон
(`rand() % 100 + 1`). Ты собрал игровой цикл `while`, который крутится,
пока не выполнено условие победы, научился считать попытки и не дал
программе сломаться от неправильного ввода — проверяя результат
`scanf` и подчищая входной буфер.

В следующей главе сделаем ещё одну классику — **«камень, ножницы,
бумага»**. Компьютер будет выбирать ход случайно (`rand` уже в
кармане), а нам предстоит разобрать чуть более хитрую логику сравнения
ходов и аккуратно посчитать счёт за несколько раундов.
