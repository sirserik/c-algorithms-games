# Глава 8. Сортировки: пузырёк, выбором, вставками

Отсортировать — значит расставить числа по порядку: от меньшего к
большему. Звучит просто, но именно на сортировках удобно почувствовать,
что такое **алгоритм**: одну и ту же задачу можно решить по-разному, и
способы отличаются скоростью и идеей.

В этой главе мы напишем три классические сортировки **с нуля**: пузырёк,
выбором и вставками. Для каждой сначала разложим всё руками на маленьком
массиве `[5, 2, 4, 1]`, потом превратим в код, потом запустим. В конце
поговорим, почему эти три — медленные на больших данных, какие есть
быстрые (быстрая сортировка и слияние) и как пользоваться готовой
`qsort` из стандартной библиотеки.

## Что мы сделаем

К концу главы у тебя будут три рабочие программы-сортировки и понимание,
чем они отличаются. Ты научишься:

- расставлять элементы массива по возрастанию;
- видеть, как массив меняется проход за проходом;
- оценивать, быстрый алгоритм или медленный;
- вызывать стандартную `qsort` со своей функцией сравнения.

Всё, что нужно, ты уже знаешь из глав 1–7: массивы, циклы, обмен двух
переменных через временную (swap), функции. Новым будет только устройство
самих алгоритмов.

## Общая заготовка: печать массива

Во всех трёх программах нам надо смотреть на массив до и после. Чтобы не
повторять цикл печати, вынесем его в маленькую функцию:

```c
void print_array(const int a[], int n)
{
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
}
```

Разбор:

- `void` — функция ничего не возвращает, она просто печатает.
- `const int a[]` — принимаем массив целых. `const`, как ты помнишь по
  главе 7, — обещание «массив только читаю, не меняю»; запись в него
  компилятор не пропустит. Печати менять нечего — значит, `const`
  здесь к месту.
- `int n` — сколько элементов печатать. Массив сам не знает свою длину,
  её всегда передают отдельным числом (см. главу 3).
- внутри — обычный перебор и `printf("%d ", a[i])` с пробелом после
  каждого числа, в конце один перевод строки.

Эту функцию мы вставим в каждую из трёх программ.

## Часть 1. Сортировка пузырьком

### Идея руками

Пузырёк сравнивает **соседей** и меняет их местами, если они стоят не по
порядку. Идём слева направо по всему массиву. За один такой проход самый
большой элемент «всплывает» в самый конец — как пузырёк воздуха
поднимается в воде. Отсюда название.

Возьмём `[5, 2, 4, 1]` и сделаем **первый проход**. Сравниваем пары
соседей слева направо:

```text
[5 2 4 1]  5 > 2 ? да  -> меняем -> [2 5 4 1]
[2 5 4 1]  5 > 4 ? да  -> меняем -> [2 4 5 1]
[2 4 5 1]  5 > 1 ? да  -> меняем -> [2 4 1 5]
```

После первого прохода: `[2 4 1 5]`. Заметь — **5 уехала в самый конец** и
больше двигаться не будет. Это и есть всплывший максимум.

**Второй проход** (последний элемент уже на месте, его не трогаем):

```text
[2 4 1 5]  2 > 4 ? нет
[2 4 1 5]  4 > 1 ? да  -> меняем -> [2 1 4 5]
```

После второго прохода: `[2 1 4 5]`. Теперь на местах два хвостовых
элемента — `4` и `5`.

**Третий проход**:

```text
[2 1 4 5]  2 > 1 ? да  -> меняем -> [1 2 4 5]
```

Получили `[1 2 4 5]` — отсортировано. Каждый следующий проход можно
делать чуть короче: хвост уже разобран.

### Шаг 1. Наивная версия

Запишем идею в лоб: внешний цикл повторяет проходы, внутренний идёт по
соседям и меняет их местами.

```c
void bubble_sort(int a[], int n)
{
    for (int pass = 0; pass < n - 1; pass++) {
        for (int i = 0; i < n - 1; i++) {
            if (a[i] > a[i + 1]) {
                int t = a[i];
                a[i] = a[i + 1];
                a[i + 1] = t;
            }
        }
    }
}
```

Разбор:

- `int a[]` — здесь **без** `const`: эту функцию массив именно меняет.
- внешний `for (pass ...)` — счётчик проходов. Проходов хватает `n - 1`:
  за каждый проход как минимум один элемент встаёт на место, а последний
  оставшийся окажется правильным сам собой.
- внутренний `for (i ...)` сравнивает соседей `a[i]` и `a[i + 1]`.
  Условие `i < n - 1`, а не `i < n`: иначе `a[i + 1]` при `i = n - 1`
  залезет за границу массива (см. главу 3, выход за границы — частый
  баг).
- `if (a[i] > a[i + 1])` — соседи стоят «неправильно» (левый больше
  правого), надо поменять.
- три строки с `t` — это **swap** через временную переменную, ровно как в
  главе 6: запомнили левый в `t`, на его место положили правый, а правому
  отдали `t`.

Эта версия уже сортирует правильно. Но в ней есть слабое место.

### Шаг 2. Проблема: лишняя работа

Внутренний цикл всегда доходит до конца (`i < n - 1`), хотя хвост массива
после каждого прохода уже отсортирован. И ещё хуже: даже если массив
**уже** упорядочен, мы всё равно сделаем все `n - 1` проходов впустую.

Дай этой версии почти отсортированный `[1, 2, 3, 5, 4]` — она переставит
`5` и `4` за первый же проход, а потом сделает ещё кучу проходов, ничего
не меняя. Обидно.

### Шаг 3. Фикс: укорачиваем хвост и ставим флаг

Две доработки:

1. Внутренний цикл доводим только до `n - 1 - pass`: всё, что правее, уже
   всплыло на свои места, проверять там нечего.
2. Заводим **флаг** `swapped`. Перед проходом ставим его в 0. Если за
   проход был хоть один обмен — ставим 1. Если после прохода флаг так и
   остался 0, значит, все соседи уже стояли по порядку — массив
   отсортирован, и можно выйти досрочно через `break`.

```c
void bubble_sort(int a[], int n)
{
    for (int pass = 0; pass < n - 1; pass++) {
        int swapped = 0;
        for (int i = 0; i < n - 1 - pass; i++) {
            if (a[i] > a[i + 1]) {
                int t = a[i];
                a[i] = a[i + 1];
                a[i + 1] = t;
                swapped = 1;
            }
        }
        if (swapped == 0) {
            break;
        }
    }
}
```

Разбор добавленного:

- `int swapped = 0;` — флаг «были ли обмены». 0 — «нет», 1 — «да». Это
  обычное использование числа как «да/нет»: помнишь из главы 2, ложь это
  0, истина это любое ненулевое.
- `i < n - 1 - pass` — на проходе номер `pass` последние `pass`
  элементов уже на местах, до них не идём.
- `swapped = 1;` — отмечаем, что обмен случился.
- `if (swapped == 0) break;` — за весь проход ничего не поменяли, значит,
  дальше делать нечего. `break` немедленно прекращает внешний цикл.

На уже отсортированном массиве теперь хватит **одного** прохода: он
пройдёт без обменов, флаг останется 0, и мы выйдем.

### Полная программа

`code/08-bubble.c`:

```c
#include <stdio.h>

/* Печать массива в одну строку — пригодится во всех трёх программах. */
void print_array(const int a[], int n)
{
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
}

/* Сортировка пузырьком по возрастанию.
   За каждый проход самый большой из оставшихся «всплывает» вправо.
   Оптимизация: если за проход не было ни одного обмена — массив
   уже отсортирован, выходим досрочно. */
void bubble_sort(int a[], int n)
{
    for (int pass = 0; pass < n - 1; pass++) {
        int swapped = 0;               /* были ли обмены в этом проходе */

        /* На каждом следующем проходе хвост уже отсортирован,
           поэтому не доходим до конца: -1 за i+1, -pass за хвост. */
        for (int i = 0; i < n - 1 - pass; i++) {
            if (a[i] > a[i + 1]) {     /* соседи стоят не по порядку */
                int t = a[i];          /* классический swap через temp */
                a[i] = a[i + 1];
                a[i + 1] = t;
                swapped = 1;
            }
        }

        if (swapped == 0) {            /* за проход ничего не меняли */
            break;                     /* значит, всё уже на местах */
        }
    }
}

int main(void)
{
    int a[] = {5, 2, 4, 1};
    int n = (int)(sizeof a / sizeof a[0]);

    printf("До:    ");
    print_array(a, n);

    bubble_sort(a, n);

    printf("После: ");
    print_array(a, n);
    return 0;
}
```

Про `int n = (int)(sizeof a / sizeof a[0]);` — это привычный приём из
главы 3: `sizeof a` — размер всего массива в байтах, `sizeof a[0]` —
размер одного элемента; их частное даёт число элементов. Работает только
там, где `a` — настоящий массив, а не пришедший в функцию указатель.

### Проверяем

```text
$ cc -std=c11 -Wall -Wextra -O2 code/08-bubble.c -o bubble
$ ./bubble
До:    5 2 4 1
После: 1 2 4 5
```

Совпадает с тем, что мы получили руками.

## Часть 2. Сортировка выбором

### Идея руками

Здесь логика другая. Мысленно делим массив на две части: слева — уже
**отсортированная** (поначалу пустая), справа — ещё нет. На каждом шаге
находим **минимум** во всей правой части и ставим его в самое её начало,
меняя местами с тем, что там стояло. Отсортированная часть растёт на один
элемент за шаг.

`[5, 2, 4, 1]`, отсортированная часть отмечена `|`:

```text
| 5 2 4 1   минимум справа = 1 (поз. 3), меняем с поз. 0
1 | 2 4 5   минимум справа = 2 (поз. 1), уже на месте
1 2 | 4 5   минимум справа = 4 (поз. 2), уже на месте
1 2 4 | 5   остался один элемент — он на месте
```

Готово: `[1 2 4 5]`. Обрати внимание: обменов делается мало (максимум по
одному на шаг), но сравнений много — каждый раз заново просматриваем весь
остаток.

### Код

Наивной и «починенной» версий тут не будет — алгоритм сразу пишется
понятно. Важно лишь не менять элемент сам с собой, если минимум и так на
месте.

`code/08-selection.c`:

```c
#include <stdio.h>

void print_array(const int a[], int n)
{
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
}

/* Сортировка выбором по возрастанию.
   Делим массив на две части: слева — уже отсортированная,
   справа — ещё нет. На каждом шаге находим минимум в правой части
   и ставим его в начало этой части. */
void selection_sort(int a[], int n)
{
    for (int i = 0; i < n - 1; i++) {
        int min_pos = i;               /* пока считаем минимумом a[i] */

        /* ищем настоящий минимум среди a[i+1 .. n-1] */
        for (int j = i + 1; j < n; j++) {
            if (a[j] < a[min_pos]) {
                min_pos = j;           /* запомнили позицию меньшего */
            }
        }

        if (min_pos != i) {            /* минимум не на своём месте */
            int t = a[i];              /* меняем его с началом части */
            a[i] = a[min_pos];
            a[min_pos] = t;
        }
    }
}

int main(void)
{
    int a[] = {5, 2, 4, 1};
    int n = (int)(sizeof a / sizeof a[0]);

    printf("До:    ");
    print_array(a, n);

    selection_sort(a, n);

    printf("После: ");
    print_array(a, n);
    return 0;
}
```

Разбор `selection_sort`:

- внешний `for (i ...)` — `i` это граница: позиция, куда сейчас поставим
  очередной минимум. Хватает до `n - 1`: последний элемент окажется
  правильным сам.
- `int min_pos = i;` — храним не само минимальное значение, а его
  **позицию** (индекс). Позиция нужна, чтобы потом сделать обмен.
- внутренний `for (j = i + 1; ...)` просматривает неотсортированный
  остаток, начиная сразу за `i`. Если нашли элемент меньше текущего
  минимума — обновляем `min_pos`.
- `if (min_pos != i)` — если минимум уже стоит на позиции `i`, обмен не
  нужен (это не баг, а просто экономия). Иначе — обычный swap через `t`.

### Проверяем

```text
$ cc -std=c11 -Wall -Wextra -O2 code/08-selection.c -o selection
$ ./selection
До:    5 2 4 1
После: 1 2 4 5
```

## Часть 3. Сортировка вставками

### Идея руками

Лучшая аналогия — как ты держишь карты в руке. Берёшь карты по одной из
стопки и **вставляешь** каждую новую на правильное место среди уже
разобранных, сдвигая остальные. Слева у тебя всегда упорядоченный
веер, справа — то, что ещё не разобрал.

В массиве то же самое. Считаем, что первый элемент уже «отсортирован»
(один элемент всегда упорядочен). Берём следующий и продвигаем его влево,
пока слева есть элементы больше него.

`[5, 2, 4, 1]`. Отсортированную левую часть отметим `|`:

```text
5 | 2 4 1   берём 2; 5 > 2 -> сдвигаем 5 вправо, 2 встаёт в начало
2 5 | 4 1   берём 4; 5 > 4 -> сдвигаем 5; 2 < 4 -> стоп, 4 за 2
2 4 5 | 1   берём 1; 5,4,2 все > 1 -> сдвигаем все, 1 в начало
1 2 4 5 |   разобрали все карты
```

Получили `[1 2 4 5]`. Главное действие — **сдвиг**: чтобы освободить место
для вставляемого элемента, большие соседи едут на одну позицию вправо.

### Шаг 1. Наивная мысль и сразу аккуратная версия

Новичок часто пытается «искать место, потом вставлять» в два прохода. Но
сдвиг и поиск места удобно совместить в одном цикле `while`: пока слева
элемент больше вставляемого — двигаем его вправо. Где цикл остановился,
там и место.

Есть тонкость: вставляемый элемент надо **сначала запомнить** в отдельную
переменную (`key`). Если этого не сделать, сдвиг затрёт его первым же
шагом.

`code/08-insertion.c`:

```c
#include <stdio.h>

void print_array(const int a[], int n)
{
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
}

/* Сортировка вставками по возрастанию.
   Слева растёт отсортированная часть. Берём очередной элемент key
   и вставляем его в нужное место этой части, сдвигая большие
   элементы вправо. Так раскладывают карты в руке. */
void insertion_sort(int a[], int n)
{
    for (int i = 1; i < n; i++) {
        int key = a[i];                /* элемент, который вставляем */
        int j = i - 1;                 /* идём по отсортированной части */

        /* сдвигаем вправо всё, что больше key */
        while (j >= 0 && a[j] > key) {
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;                /* нашлось место — кладём key */
    }
}

int main(void)
{
    int a[] = {5, 2, 4, 1};
    int n = (int)(sizeof a / sizeof a[0]);

    printf("До:    ");
    print_array(a, n);

    insertion_sort(a, n);

    printf("После: ");
    print_array(a, n);
    return 0;
}
```

Разбор `insertion_sort`:

- внешний `for (i = 1; ...)` начинается с **1**, а не с 0: элемент с
  индексом 0 считаем уже отсортированной частью из одного элемента.
- `int key = a[i];` — запоминаем вставляемый элемент. Дальше место `a[i]`
  будет затёрто сдвигом, поэтому значение нужно сохранить заранее.
- `int j = i - 1;` — `j` будет двигаться по отсортированной части справа
  налево.
- `while (j >= 0 && a[j] > key)` — два условия через `&&` (логическое
  «И», см. главу 2):
  - `j >= 0` — не вышли за левый край массива;
  - `a[j] > key` — текущий элемент больше вставляемого, значит, его надо
    подвинуть.

  **Порядок важен!** Сначала проверяется `j >= 0`. Если `j` стал −1,
  `&&` дальше не смотрит на `a[j]` (это называется «короткое замыкание»),
  и обращения к `a[-1]` не происходит. Поменяй условия местами — получишь
  выход за границу.
- `a[j + 1] = a[j];` — сдвигаем элемент на одну позицию вправо.
- `j--;` — шаг влево.
- после цикла `a[j + 1] = key;` — `j` указывает на ближайший слева
  элемент, не превышающий `key` (или на −1, если `key` меньше всех в
  отсортированной части). Значит,
  место для `key` — следующая клетка, `j + 1`.

### Проверяем

```text

$ ./insertion
До:    5 2 4 1
После: 1 2 4 5
```

## Как это работает: чем три сортировки отличаются

Все три дают один результат, но «характер» у них разный:

- **Пузырёк** много **меняет** соседей и медленно «протаскивает» большие
  числа в конец. С флагом досрочно ловит уже готовый массив.
- **Выбор** делает мало обменов (по одному на шаг), но всегда честно
  просматривает весь остаток в поисках минимума — даже если массив уже
  отсортирован.
- **Вставки** аккуратно «дораскладывают» массив и особенно хороши, когда
  данные почти упорядочены.

И одно общее свойство. Все три сортируют **на месте** (по-английски
*in-place*): переставляют элементы внутри того же массива и берут
сверху лишь несколько переменных (`t`, `key`, `min_pos`, счётчики
циклов). Сортируешь хоть десять чисел, хоть миллион — дополнительной
памяти нужно одинаково мало. Второй массив под копию данных им не
нужен. Запомни это слово: чуть ниже встретится сортировка, которая на
месте работать не умеет.

## Стабильность: что происходит с одинаковыми элементами

Есть у сортировок ещё одно свойство, о котором новичкам обычно не
рассказывают, а на работе оно всплывает сразу же. Называется
**устойчивость**, или **стабильность** (stability): в русских книгах
встречаются оба слова, значат они одно и то же. Мы будем говорить
«стабильность».

Представь список учеников, уже отсортированный по фамилии. Теперь ты
сортируешь его по оценке. У троих одна и та же пятёрка — в каком порядке
они окажутся между собой? Стабильная сортировка сохранит их прежний
порядок (по фамилии). Нестабильная перемешает как попало.

Определение: сортировка **стабильная**, если элементы с одинаковым
ключом остаются в том же порядке, в каком лежали до сортировки.

Проверим это на наших трёх. Массив из обычных `int` не годится: две
одинаковые пятёрки друг от друга не отличишь, поменялись они местами или
нет — не видно. Поэтому зашьём в каждое число сразу две вещи: **десятки**
— ключ, по которому сортируем, **единицы** — метку исходного места. Число
`42` читается как «ключ 4, метка 2».

Достать половинки помогут две крошечные функции:

```c
static int key_of(int x)
{
    return x / 10;              /* десятки — то, по чему сортируем */
}

static int tag_of(int x)
{
    return x % 10;              /* единицы — откуда элемент пришёл */
}
```

Здесь работают знакомые из главы 4 приёмы: `/ 10` отрезает последнюю
цифру, `% 10` её достаёт. Слово `static` перед функцией означает «эта
функция нужна только внутри своего файла, наружу её не показывать» — для
таких мелких помощников это хороший тон.

Дальше во всех трёх сортировках меняется ровно одно: сравниваем не
`a[i] > a[i + 1]`, а `key_of(a[i]) > key_of(a[i + 1])`. Метки в сравнении
не участвуют вообще — сортировка про них не знает. Полностью программа
лежит в `code/08-stable.c`. Берём массив `41 42 43 24` (три элемента с
ключом 4 и один с ключом 2) и смотрим:

```text
cc -std=c11 -Wall -Wextra -O2 08-stable.c -o 08-stable
./08-stable
до:        4/1  4/2  4/3  2/4
пузырёк:   2/4  4/1  4/2  4/3
вставки:   2/4  4/1  4/2  4/3
выбор:     2/4  4/2  4/3  4/1
```

Ключи везде расставлены правильно: сначала 2, потом три четвёрки. А вот
метки:

- **пузырёк** — `1 2 3`, порядок сохранён. Стабилен;
- **вставки** — `1 2 3`, тоже сохранён. Стабильны;
- **выбор** — `2 3 1`. Порядок сломан. **Нестабилен**.

Откуда взялась разница? У пузырька и вставок сравнение **строгое**:
`a[i] > a[i + 1]` и `a[j] > key`, а не `>=`. Равные элементы не
считаются «стоящими не по порядку», значит, местами их никто не
меняет, а двигаются элементы только к соседу, через головы не прыгают.
Поставь там `>=` — и обе сортировки мгновенно потеряют стабильность.

А выбор ломает порядок самим устройством. Проследи за первым шагом: `i`
= 0, минимум — это `2/4` на позиции 3. Обмен `a[0]` и `a[3]` **швыряет**
`4/1` с начала массива в самый конец, через головы `4/2` и `4/3`. Один
дальний перелёт — и относительный порядок четвёрок сломан навсегда. Так
устроен любой обмен «издалека», и вылечить это, не переписав алгоритм,
нельзя.

Запомни короткий вывод: **пузырёк и вставки стабильны, выбор — нет**.
Пока сортируешь голые числа, это не важно. Как только у элемента
появляются «довески» (фамилия рядом с оценкой, дата рядом с суммой),
стабильность становится настоящим требованием.

## Сложность: почему это медленно и что бывает быстрее

У всех трёх есть общая беда: **два вложенных цикла**. Посчитаем точно,
сколько сравнений это даёт, а не «примерно».

### Считаем сравнения руками

Возьмём пузырёк без флага. На первом проходе он сравнивает `n - 1` пару
соседей, на втором — `n - 2` (хвост уже на месте), и так до последнего
прохода с одной парой. Всего

```text
(n - 1) + (n - 2) + ... + 2 + 1 = n(n - 1) / 2
```

Откуда формула? Запиши эту сумму дважды: один раз как есть, второй —
задом наперёд, одну под другой, и сложи столбиками. В каждом столбике
выходит ровно `n` (`(n - 1) + 1`, `(n - 2) + 2`, ...), столбиков
`n - 1`. Две суммы вместе дают `n(n - 1)`, одна — половину. Проверка на
нашем массиве из четырёх: `3 + 2 + 1 = 6`, и `4 · 3 / 2 = 6`. Для
ста элементов — 4950 сравнений.

Выбор делает столько же: при `i = 0` внутренний цикл сравнивает `n - 1`
раз, при `i = 1` — `n - 2`, и так далее. Вставки в худшем случае (массив
задом наперёд) — тоже: каждый новый элемент протаскивается через всю
левую часть, `1 + 2 + ... + (n - 1)`.

При больших `n` в формуле главное — квадрат:
`n(n - 1) / 2 = n²/2 - n/2`, и вторая часть рядом с первой крошечная.
При `n = 1000` это 500 000 против 500.

### Что значит O(n²)

Для такого «главного в формуле» есть короткая запись — **O-нотация**
(читают «о большое», от английского *order* — порядок). Пишут **O(n²)**
(«о от эн квадрат») и имеют в виду: начиная с какого-то `n`, работа не
превышает `n²`, умноженного на какое-то постоянное число. У наших
сортировок это число — одна вторая: `n(n - 1) / 2` никогда не больше
`n² / 2`.

Три тонкости, о которых часто забывают:

- **O — это потолок**, оценка сверху. Формально про линейный поиск из
  главы 7 тоже верно, что он O(n²): `n` не больше `n²`. Верно, но
  бесполезно. Когда хотят сказать «растёт ровно как `n²`, не быстрее и
  не медленнее», математики пишут `Θ(n²)` (буква «тета»). Программисты в
  разговоре обычно говорят «O», подразумевая именно точный рост, — и мы
  в книге так делаем.
- **Постоянный множитель O не видит.** `n²/2` и `5n²` — оба O(n²), хотя
  второй в десять раз медленнее. Поэтому два O(n²)-алгоритма запросто
  различаются по скорости в разы — скоро увидим это на секундомере.
- **Оценка относится к конкретному случаю** — лучшему, худшему или
  среднему (эти слова мы разобрали в главе 7). У одной и той же
  сортировки они бывают очень разными.

Практический смысл O(n²) такой: увеличишь массив в 10 раз — работы
станет примерно в 100 раз больше; удвоишь — вчетверо.

### Проверяем подсчётом: лучший, средний и худший случай

Формулы — на бумаге. Пусть сортировки сами посчитают свою работу.
Программа `code/08-count.c` — те же три функции, только в каждую
добавлены два счётчика: `cmps` растёт перед каждым сравнением двух
элементов, `moves` — на каждый обмен (у пузырька и выбора) и на каждый
сдвиг (у вставок). Счётчики объявлены вне всех функций, в самом начале
файла (`long cmps = 0;`), поэтому их видят все три сортировки. Такие
переменные называются глобальными, подробнее о них — в главе 9.

Пузырёк и выбор получили по строчке `cmps++;` перед своим `if` и
`moves++;` рядом с обменом. Во вставках сравнение спрятано в условии
`while`, поэтому цикл пришлось разложить на части:

```c
while (j >= 0) {
    cmps++;             /* сравниваем a[j] с key */
    if (a[j] <= key) {
        break;          /* нашли место — дальше не идём */
    }
    a[j + 1] = a[j];
    moves++;            /* один сдвиг вправо */
    j--;
}
```

Это тот же цикл `while (j >= 0 && a[j] > key)`, только вторая половина
условия переехала внутрь: если `a[j]` не больше `key`, место найдено, и
`break` выходит из `while`. Зато теперь каждое сравнение посчитано.

Входов три, по 100 чисел: уже отсортированный (`0 1 2 ... 99`), задом
наперёд (`99 98 ... 0`) и перемешанный. Перемешиваем без `rand`, чтобы
вывод у всех был одинаковым: `a[i] = (i * 37) % 100`. Так получаются все
числа от 0 до 99 по одному разу, но вразброс: 0, 37, 74, 11, 48, ...

```text
cc -std=c11 -Wall -Wextra -O2 08-count.c -o 08-count
./08-count
n = 100, n(n-1)/2 = 4950

сравнений перемещений   сортировка, вход
       99           0   пузырёк, отсортирован
     4950        4950   пузырёк, задом наперёд
     4895        2448   пузырёк, перемешан
     4950           0   выбором, отсортирован
     4950          50   выбором, задом наперёд
     4950          88   выбором, перемешан
       99           0   вставками, отсортирован
     4950        4950   вставками, задом наперёд
     2547        2448   вставками, перемешан
```

Читаем по сортировкам.

- **Пузырёк.** На отсортированном входе — 99 сравнений, то есть
  `n - 1`: один проход без обменов, флаг `swapped` остался нулём,
  `break`. Это **лучший случай**, и он растёт как `n`, а не `n²`. На
  входе задом наперёд — **худший**: ровно 4950 сравнений и 4950 обменов.
  На перемешанном флаг сэкономил совсем немного: 4895 сравнений.
- **Выбор.** 4950 сравнений **на любом входе**, даже на уже
  отсортированном: он не умеет замечать, что всё и так на месте, и
  каждый раз честно ищет минимум в остатке. Зато обменов не больше
  `n - 1`: 0, 50 и 88.
- **Вставки.** Лучший и худший случаи — как у пузырька (99 и 4950), но
  на перемешанном сравнений почти вдвое меньше: 2547.

Почему у пузырька и вставок на перемешанном входе перемещений **ровно
поровну**, 2448 и 2448? Тут помогает ещё одно понятие. **Инверсия** —
это пара элементов, стоящих не по порядку: левый больше правого. В
`[5, 2, 4, 1]` инверсий пять: 5 и 2, 5 и 4, 5 и 1, 2 и 1, 4 и 1.
Обмен двух **соседей**, стоящих не по порядку, убирает ровно одну
инверсию — ту, что между ними, а порядок остальных пар не меняет.
Сортировка кончается, когда инверсий не осталось. Значит, пузырёк
делает ровно столько обменов, сколько инверсий было в массиве. Сдвиг во
вставках — то же самое: `key` перепрыгивает через один больший
элемент, одна инверсия исчезает. Проверь на `[5, 2, 4, 1]`: пять
инверсий — пять обменов у пузырька (мы их делали руками в начале главы:
три, потом один, потом ещё один).

В отсортированном массиве инверсий ноль. В обратном — каждая пара
стоит не по порядку, их `n(n - 1) / 2` = 4950. В случайном массиве
каждая пара с равным шансом стоит так или наоборот, поэтому инверсий в
среднем половина от всех пар: `n(n - 1) / 4`, для ста чисел — 2475. У
нашего перемешанного 2448 — близко. Выходит, и в **среднем** случае
пузырёк и вставки делают порядка `n²` работы.

Итог в одну строку на каждую сортировку:

- **пузырёк с флагом**: лучший случай O(n), средний и худший — O(n²);
- **выбор**: O(n²) сравнений всегда, даже в лучшем случае, но не больше
  `n - 1` обменов;
- **вставки**: лучший случай O(n), средний и худший — O(n²); на
  случайных данных сравнений вдвое меньше, чем у пузырька.

Прикинь масштаб квадратичного роста:

```text
n = 10        ->     ~100 операций      мгновенно
n = 1 000     -> ~1 000 000 операций    ещё терпимо
n = 1 000 000 -> ~10^12 операций        минут двадцать
```

Запись `10^12` значит «десять в двенадцатой степени», то есть единица
с двенадцатью нулями. Откуда «минут двадцать» — сейчас увидим.

### Замеряем по-настоящему

Подсчёт сравнений — это теория, а секундомер — жизнь. Программа
`code/08-bench.c` заполняет массив случайными числами, сортирует его
всеми тремя способами и засекает время `clock()` — тем самым
секундомером из главы 7. Размер каждый раз удваивается:

```text
cc -std=c11 -Wall -Wextra -O2 08-bench.c -o 08-bench
./08-bench
       n   пузырёк   выбором  вставками
    5000     0.010     0.005      0.003
   10000     0.055     0.017      0.010
   20000     0.327     0.069      0.039
   40000     1.654     0.285      0.151

пузырёк по уже отсортированным 40000: 0.000015 c
qsort по 1000000 элементам: 0.1260 c
```

Читаем таблицу столбиком сверху вниз. Удваиваем `n` — и время растёт не
вдвое, а примерно вчетверо: у выбора 0.017 → 0.069 → 0.285, у вставок
0.010 → 0.039 → 0.151. Вот это «в четыре раза при удвоении» и есть
O(n²) вживую: удвоили `n`, значит, `n × n` выросло в `2 × 2 = 4` раза.

У пузырька скачки крупнее: 0.055 → 0.327 → 1.654, в 5–6 раз. Число
сравнений у него растёт ровно вчетверо (это мы только что
посчитали), значит, дороже становится **каждое** сравнение. Скорее
всего, дело в процессоре: он заранее угадывает, куда пойдёт `if`, а на
случайных данных у пузырька эти догадки часто мимо, и каждый промах
стоит времени. O-нотация такие вещи не описывает: она говорит, как
растёт число шагов, а не сколько наносекунд стоит шаг.

Заодно видно, что три «одинаково квадратичных» алгоритма всё же не
равны: на 40 000 элементах вставки примерно в 11 раз быстрее пузырька
на одних и тех же данных. Порядок роста общий, а постоянные множители
разные — ровно та вторая тонкость O-нотации. Сравнений у вставок на
случайных данных вдвое меньше (`n²/4` против почти `n²/2`), каждое
перемещение — одно присваивание вместо трёх в обмене, а остальное,
видимо, добирают промахи процессора у пузырька.

Предпоследняя строка — проверка того самого флага `swapped`. По уже
отсортированным 40 000 элементам пузырёк отработал за 15 микросекунд:
один проход без единого обмена, флаг остался нулём, `break`. Сравни с
1.654 секунды на тех же 40 000 вперемешку — разница примерно в сто
тысяч раз. Это и есть «лучший случай O(n) против среднего O(n²)».

Последняя строка — гвоздь программы. Библиотечная `qsort` разобрала
**миллион** элементов за 0.13 секунды. Это в 25 раз больше данных, чем в
строке про 40 000, — и примерно в 13 раз быстрее по времени. Если бы мы
взялись за тот же миллион пузырьком, по нашей же таблице вышло бы
примерно `1.654 × 25 × 25 ≈ 1030` секунд, то есть около семнадцати
минут (и это оптимистично: мы видели, что у пузырька время растёт даже
быстрее, чем вчетверо). Разница между O(n²) и O(n log n) на глаз.

### Быстрее, чем n²

На миллионе элементов O(n²) уже неприемлемо. К счастью, есть сортировки
посложнее, но куда быстрее — со сложностью **O(n log n)**. Тут `log n` —
это двоичный логарифм из главы 7, `log₂ n`: сколько раз можно поделить
`n` пополам, пока не дойдём до единицы (для миллиона это около 20). То
есть вместо `n × n` получается порядка `n × 20` — огромная разница.
Идею двух главных таких алгоритмов разберём словами, без полного кода.
Обе построены на рекурсии — ей посвящена глава 9, — а целиком, с кодом
и разбором, мы их соберём в приложении В (задачи 1 и 2).

### Быстрая сортировка (quicksort)

Выбираем из массива один элемент — **опорный** (pivot). Переставляем
остальные так, чтобы слева от опорного оказались все меньшие, а справа —
все большие (равные — в любую сторону). Теперь опорный стоит на своём
окончательном месте, а массив разбит на две части. Дальше **точно так
же** сортируем левую часть и правую — каждую как отдельный массив
поменьше. Деление продолжается, пока в частях не останется по одному
элементу или ни одного.

Если опорный каждый раз делит массив примерно пополам, уровней деления
выходит около `log₂ n`, а на каждом уровне все элементы вместе
просматриваются один раз — отсюда `n log n`. На случайных данных так и
бывает в среднем: **средний случай — O(n log n)**. Но если опорный
раз за разом оказывается самым маленьким или самым большим (например,
всегда берём первый элемент, а массив уже отсортирован), части выходят
размером `n - 1` и `0`, и получается тот же `n(n - 1) / 2`: **худший
случай — O(n²)**. Хорошие реализации выбирают опорный хитрее, чтобы
худший случай почти не встречался. Сортирует quicksort на месте, но
стабильным не является: при перестановках элементы прыгают далеко,
через головы равных.

### Сортировка слиянием (merge sort)

Делим массив пополам, каждую половину тоже пополам, и так до кусочков по
одному элементу (один элемент уже «отсортирован»). Потом начинаем
**сливать** кусочки обратно попарно, и при слиянии сразу располагаем
элементы по порядку: берём меньший из первых элементов двух кусков, потом
следующий меньший, и так пока оба не закончатся. Слить два упорядоченных
куска общей длиной `k` можно за `k` шагов, а уровней деления всего около
`log₂ n`. Получаем O(n log n) — **в любом случае**, без неудачных входов,
как у quicksort. Если при равенстве брать элемент из левого куска,
сортировка ещё и **стабильна**. Платим за это памятью: сливать приходится
во временный массив длиной `n`, так что на месте, как наши три,
merge sort не работает.

### Готовое решение: `qsort` из `<stdlib.h>`

В реальном коде свою сортировку обычно не пишут — берут библиотечную
`qsort`. Она универсальная: сортирует массив **чего угодно** (числа,
строки, структуры), потому что не знает заранее, что и как сравнивать. Эти
знания ты даёшь ей сам — через **функцию сравнения** (компаратор).

`code/08-qsort.c`:

```c
#include <stdio.h>
#include <stdlib.h>     /* здесь живёт qsort */

void print_array(const int a[], int n)
{
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
}

/* Компаратор: говорит qsort, какой из двух элементов «раньше».
   Получает адреса двух элементов как const void *.
   Возвращает < 0, если первый меньше; 0, если равны; > 0, если больше. */
int cmp_int(const void *pa, const void *pb)
{
    int a = *(const int *)pa;   /* приводим адрес к int* и разыменовываем */
    int b = *(const int *)pb;
    if (a < b) return -1;
    if (a > b) return 1;
    return 0;
}

int main(void)
{
    int a[] = {5, 2, 4, 1, 9, 3, 7};
    int n = (int)(sizeof a / sizeof a[0]);

    /* qsort(база, число_элементов, размер_элемента, компаратор) */
    qsort(a, (size_t)n, sizeof a[0], cmp_int);

    print_array(a, n);
    return 0;
}
```

Разбор — здесь несколько новых деталей:

- `qsort(a, (size_t)n, sizeof a[0], cmp_int)` — четыре аргумента:
  - `a` — массив (его адрес начала);
  - `(size_t)n` — сколько элементов сортировать. `size_t` — целочисленный
    тип «для размеров и количеств», именно его ждёт `qsort`. Он
    беззнаковый: отрицательных значений в нём не бывает. Без приведения
    программа тоже соберётся, и с нашими флагами молча: `int` сам
    превратится в `size_t`. Пишем `(size_t)n`, чтобы переход был виден
    глазами (строгий флаг `-Wsign-conversion` о таком неявном переходе
    предупреждает);
  - `sizeof a[0]` — размер одного элемента в байтах. По нему `qsort`
    понимает, какими «шагами» ходить по массиву;
  - `cmp_int` — имя нашей функции сравнения. Передаём **саму функцию**
    (без скобок!) — `qsort` будет вызывать её, когда надо сравнить два
    элемента. Передача функции как аргумента — новая для нас вещь.
- `int cmp_int(const void *pa, const void *pb)` — компаратор обязан иметь
  именно такую форму, её требует `qsort`:
  - `const void *` — «адрес чего-то, тип заранее неизвестен». `void *` —
    «указатель на что угодно». `qsort` универсальна и не знает, что
    внутри, поэтому передаёт элементы безликими адресами;
  - `const` — обещаем не менять элементы при сравнении.
- `*(const int *)pa` — два действия сразу:
  - `(const int *)pa` — **приведение** безликого адреса к «адресу на
    `int`»: мы-то знаем, что сравниваем целые;
  - `*` перед этим — **разыменование** (см. главу 3): достаём само число
    по адресу.
- возврат: компаратор должен вернуть **отрицательное** число, если первый
  элемент должен идти раньше второго, **0** — если они равны, и
  **положительное** — если позже. По этим знакам `qsort` и расставляет
  всё по порядку. Хочешь сортировку по убыванию — просто поменяй местами
  `a` и `b` в сравнениях.

Запуск:

```text
$ cc -std=c11 -Wall -Wextra -O2 code/08-qsort.c -o qsort_demo
$ ./qsort_demo
1 2 3 4 5 7 9
```

Одна строка `qsort(...)` — и массив отсортирован быстрым алгоритмом.
Понимать, что у неё внутри, всё равно полезно: иначе компаратор кажется
магией.

### Что `qsort` обещает, а что нет

Три вещи стоит знать заранее, чтобы потом не удивляться.

**Название обманывает.** `qsort` — сокращение от quicksort, но стандарт
Си нигде не требует, чтобы внутри была именно быстрая сортировка.
Библиотека вправе взять что угодно, лишь бы результат был упорядочен.
Разные системы так и делают.

**Стабильность не обещана.** Помнишь предыдущий раздел? Так вот, про
`qsort` стандарт прямо говорит: если два элемента при сравнении
равны, их порядок в результате не уточняется — какой выйдет, такой и
будет.
Нужна стабильность — либо пиши свою сортировку (вставки стабильны), либо
добавляй в компаратор второй ключ: «при равных оценках сравни ещё и
номер в исходном списке».

**Компаратор должен быть честным.** `qsort` строит свою работу на том,
что твоя функция ведёт себя как нормальное сравнение: если `cmp(a, b)`
отрицательное, то `cmp(b, a)` обязано быть положительным; если `a` раньше
`b`, а `b` раньше `c`, то `a` обязан быть раньше `c`; и на одних и тех же
аргументах ответ всегда один. Нарушишь это — по стандарту поведение
`qsort` не определено. Компаратор, который отвечает по настроению
(скажем, зовёт `rand()`), в какой-нибудь библиотеке может завести `qsort`
за границы массива — и это уже не «неверный порядок», а падение.

### Ловушка: `return a - b`

В интернете и в чужом коде ты обязательно встретишь короткий вариант
компаратора:

```c
int cmp_bad(const void *pa, const void *pb)
{
    int a = *(const int *)pa;
    int b = *(const int *)pb;
    return a - b;               /* коротко, красиво и неверно */
}
```

Логика на первый взгляд безупречна: если `a` меньше `b`, разность
отрицательна; если больше — положительна; если равны — ноль. Ровно то,
что просит `qsort`.

Ломается это на больших числах. Разность двух `int` сама должна влезть в
`int`, а она не обязана: `2000000000 - (-2000000000)` — это четыре
миллиарда, потолок `int` (2 147 483 647) почти вдвое ниже. Получаем то
самое переполнение из главы 4 и главы 7 — неопределённое поведение. На
практике разность «заворачивается» и выходит **отрицательной**:
−294 967 296. Компаратор сообщает `qsort`, что два миллиарда **меньше**
минус двух миллиардов, и та ставит их не в том порядке.

Проверим. Программа `code/08-cmp-trap.c` сортирует один и тот же набор
чисел дважды: плохим компаратором и хорошим:

```c
int bad[] = {2000000000, -2000000000, 7, -7};
int n = (int)(sizeof bad / sizeof bad[0]);
int good[4];

for (int i = 0; i < n; i++) {
    good[i] = bad[i];       /* второй экземпляр тех же чисел */
}

qsort(bad,  (size_t)n, sizeof bad[0],  cmp_bad);
qsort(good, (size_t)n, sizeof good[0], cmp_good);
```

Запускаем:

```text
cc -std=c11 -Wall -Wextra -O2 08-cmp-trap.c -o 08-cmp-trap
./08-cmp-trap
до сортировки:    2000000000 -2000000000 7 -7
через a - b:      2000000000 -2000000000 -7 7
через сравнения:  -2000000000 -7 7 2000000000
```

Хороший компаратор дал правильный ответ. Плохой оставил два самых
больших по модулю числа **на своих местах** — то есть двухмиллиардное
положительное стоит перед двухмиллиардным отрицательным. Массив не
отсортирован, а программа об этом даже не намекнула.

Причину покажет санитайзер из главы 4:

```text
cc -std=c11 -Wall -Wextra -g -fsanitize=undefined 08-cmp-trap.c \
   -o 08-cmp-trap-san
./08-cmp-trap-san
08-cmp-trap.c:24:14: runtime error: signed integer overflow: 2000000000
- -2000000000 cannot be represented in type 'int'
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior 08-cmp-trap.c:24:14
до сортировки:    2000000000 -2000000000 7 -7
через a - b:      2000000000 -2000000000 -7 7
через сравнения:  -2000000000 -7 7 2000000000
```

Первая строка отчёта на экране длинная, здесь она перенесена. Строка
24 — это `return a - b;`. Вот и весь фокус. Отчёт появляется один раз,
хотя плохих вычитаний могло быть несколько: санитайзер сообщает о
каждом месте в коде только при первом срабатывании.

Живёт эта ловушка тихо: пока числа маленькие, `a - b` работает годами.
Стрельнет она в тот день, когда в данные попадёт что-нибудь вроде
идентификатора на два миллиарда. Пиши три сравнения — они чуть длиннее,
зато не ломаются никогда. Есть и короткая надёжная запись в одну
строку: `return (a > b) - (a < b);`. Каждое сравнение даёт 1 или 0
(глава 2), и разность этих двух чисел — ровно −1, 0 или 1, без
всякого переполнения.

## Частые ошибки

**Выход за границу в условии цикла.** В пузырьке сравниваем `a[i]` и
`a[i + 1]`, поэтому внутренний цикл идёт до `i < n - 1`, а не `i < n`.
Иначе при `i = n - 1` обратишься к несуществующему `a[n]`.

**Swap без временной переменной.** Если написать `a[i] = a[j]; a[j] =
a[i];`, ты сначала затрёшь `a[i]`, и оба элемента станут одинаковыми.
Нужна третья переменная `t` (см. главу 6).

**В выборе хранят значение вместо позиции.** Для обмена нужен **индекс**
минимума (`min_pos`), а не само минимальное число. По числу непонятно,
какой элемент с каким менять.

**Во вставках забыли сохранить `key`.** Сдвиг `a[j + 1] = a[j]` затрёт
вставляемый элемент, если ты не запомнил его заранее в `key`.

**Перепутан порядок в `&&` у вставок.** Условие должно быть
`j >= 0 && a[j] > key`, а не наоборот. Сначала проверка границы, потом
обращение к `a[j]`, иначе при `j == -1` залезешь за край.

**Компаратор возвращает `a - b`.** Разность двух `int` не обязана влезать
в `int`. Переполнение — неопределённое поведение, на практике знак
выходит неверным, и `qsort` ставит пару элементов не в том порядке — мы
это только что видели своими глазами. Надёжнее три сравнения или
`(a > b) - (a < b)`.

**Ждут от `qsort` стабильности.** Стандарт её не обещает. Если у
элементов есть «довесок» и порядок равных важен — сортируй вставками или
дописывай в компаратор второй ключ.

**Забыли `(size_t)` и `sizeof` в вызове `qsort`.** Второй аргумент —
**число элементов**, третий — **размер одного элемента в байтах**.
Перепутаешь местами или подставишь размер всего массива — `qsort` пойдёт
по памяти неверными шагами. Компилятор здесь не помощник: оба параметра
одного типа `size_t`, любая пара чисел ему подходит.

**Передали компаратор со скобками.** Нужно `cmp_int`, а не `cmp_int()`.
Первое — сама функция, второе — попытка вызвать её прямо здесь. Со
скобками программа не соберётся:

```text
08-qsort.c:30:46: error: too few arguments to function call, expected 2,
have 0
```

**Боятся пустого массива и одного элемента.** Все три наши сортировки
справляются с ними сами, без единой дополнительной проверки. При `n = 0`
и `n = 1` внешний цикл пузырька и выбора (`pass < n - 1`, `i < n - 1`) не
делает ни одного шага, а у вставок цикл начинается с `i = 1` и при
`n <= 1` тоже не запускается. Массив из нуля или одного элемента уже
отсортирован — так и должно быть. Отрицательные числа и массив, где все
элементы равны, тоже проходят нормально: проверь сам под
`-fsanitize=address,undefined`.

**Ставят `>=` вместо `>` в сравнении.** На результат сортировки это не
влияет (числа всё равно встанут по порядку), зато пузырёк и вставки
теряют стабильность и вдобавок делают кучу бессмысленных обменов равных
элементов.

## Упражнения

1. Добавь в `bubble_sort` счётчик обменов (`long swaps`) и печатай его в
   конце. Сравни число обменов для `[5, 2, 4, 1]` и для уже
   отсортированного `[1, 2, 3, 4]`. *Ответ:* 5 и 0 — ровно число
   инверсий в каждом массиве.

2. Сделай так, чтобы все три сортировки печатали массив **после каждого
   прохода** (для пузырька/выбора) или **после каждой вставки**. Понаблюдай,
   как массив приходит в порядок. *Ожидаемо* на `[5, 2, 4, 1]`: пузырёк —
   `2 4 1 5`, `2 1 4 5`, `1 2 4 5`; выбор — `1 2 4 5` уже после первого
   шага (единица поменялась с пятёркой), дальше без изменений; вставки —
   `2 5 4 1`, `2 4 5 1`, `1 2 4 5`. Сверь с раскладками руками из этой
   главы.

3. Переделай `selection_sort` на поиск **максимума** и установку его в
   **конец** неотсортированной части. Результат должен быть тем же.
   *Подсказка:* внешний цикл `for (int end = n - 1; end > 0; end--)`,
   максимум ищем среди `a[0..end]` и меняем с `a[end]`. На массиве из
   `08-qsort.c` получится `1 2 3 4 5 7 9`.

4. Напиши функцию `int is_sorted(const int a[], int n)`, возвращающую 1,
   если массив отсортирован по возрастанию, и 0 иначе. Проверяй ею массив
   до и после сортировки. *Ответ:* для `[5, 2, 4, 1]` до — 0, после — 1.
   Пустой массив и массив из одного элемента — 1: они уже упорядочены.
   Сравнивай соседей `a[i] > a[i + 1]` при `i + 1 < n`, чтобы не выйти
   за край.

5. Заполни массив из 20 чисел вводом (или случайными, если уже умеешь
   `rand`) и отсортируй его любой из трёх сортировок. *Проверка:*
   `is_sorted` из упражнения 4 после сортировки возвращает 1.

6. Возьми `08-qsort.c` и сделай вторую версию компаратора `cmp_desc`,
   сортирующую по **убыванию**. Отсортируй один и тот же массив сначала по
   возрастанию, потом по убыванию. *Ответ:* в `cmp_desc` при `a > b`
   возвращаем −1, при `a < b` — 1. Вывод: `1 2 3 4 5 7 9`, затем
   `9 7 5 4 3 2 1`.

7. **Проверь стабильность руками.** Возьми `08-stable.c`, замени в
   пузырьке и вставках `>` на `>=` и запусти снова. Метки у четвёрок
   встанут в обратном порядке `3 2 1` — обе сортировки перестали быть
   стабильными от одного знака. Объясни себе, почему. *Ответ:* теперь
   равные соседи считаются «стоящими не по порядку» и меняются местами,
   так что каждая следующая четвёрка проталкивается левее предыдущих.

8. **Свой замер.** Добавь в `08-bench.c` строку с `n = 80000` и
   предскажи время **до** запуска: раз при удвоении время растёт вчетверо,
   пузырёк должен уложиться примерно в 7 секунд (`1.65 × 4 ≈ 6.6`).
   Запусти и сравни с предсказанием. *У меня* вышло 7.02 и 7.15 секунды
   на двух запусках — чуть больше прогноза, как и в таблице: пузырёк
   растёт немного быстрее, чем вчетверо. У выбора — около 1.1 секунды,
   у вставок — 0.6–0.7.

9. **Сломай компаратор.** Напиши компаратор, который всегда возвращает
   `0` («все элементы равны»), и посмотри, что `qsort` сделает с
   массивом. Потом такой, что всегда возвращает `1`. Второй нечестен:
   он утверждает, что `a` больше `b` **и** что `b` больше `a`
   одновременно. Результат окажется каким угодно, и полагаться на него
   нельзя, даже если у тебя он выглядит осмысленно. *Что вышло у меня
   на macOS* с массивом `5 2 4 1 9 3 7`: с нулём массив остался как был
   (компаратор честный, просто все равны, а порядок равных `qsort` не
   обещает), с единицей — `7 3 9 1 4 2 5`, то есть задом наперёд. На
   массиве из 40 чисел «единичный» компаратор дал уже полную мешанину.
   В другой библиотеке (например, на Linux) результат может быть другим
   — в этом и смысл упражнения.

## Что мы получили

Ты написал три сортировки с нуля и понял, чем они отличаются: пузырёк
«всплывает» обменами соседей (с флагом для досрочного выхода), выбор ищет
минимум и ставит его в начало, вставки раскладывают элементы как карты в
руке. Все три сортируют на месте и в среднем и худшем случае делают
O(n²) работы: до `n(n - 1) / 2` сравнений. В лучшем случае пузырёк с
флагом и вставки обходятся `n - 1` сравнением, а выбор — нет. И это не
отвлечённые буквы: счётчики в `08-count.c` показали эти числа точно, а
секундомер — как удвоение `n` примерно учетверяет время и как `qsort`
разбирает миллион элементов быстрее, чем пузырёк — сорок тысяч.

Попутно набралось несколько вещей, которые отличают «работает» от
«работает правильно»: пузырёк и вставки **стабильны**, а выбор нет;
`qsort` не обещает ни конкретного алгоритма, ни стабильности; компаратор
`return a - b` тихо ломается на больших числах.

Все программы главы: `08-bubble.c`, `08-selection.c`, `08-insertion.c`,
`08-qsort.c`, а к ним четыре вспомогательные — `08-count.c` (счётчики
сравнений и перемещений), `08-stable.c` (стабильность), `08-cmp-trap.c`
(ловушка компаратора) и `08-bench.c` (замер скорости).
Собираются все одинаково: `cc -std=c11 -Wall -Wextra -O2 файл.c -o имя`.

И quicksort, и merge sort устроены на одном приёме: **разбить задачу на
части поменьше и решить их тем же способом**. Это называется **рекурсия**
— функция, которая вызывает сама себя. Без неё эти быстрые сортировки не
написать красиво. Поэтому следующая глава целиком про рекурсию: разберём
её на простых примерах. А сами quicksort и merge sort, уже с кодом, ждут
тебя в приложении В (задачи 1 и 2).
