# Глава 6. Алгоритмы над массивами: минимум/максимум, сумма, среднее, разворот, сдвиг

Массив у нас уже есть: мы умеем его объявить, заполнить вводом через
цикл и пройтись по элементам. Пора заставить массив работать. В этой
главе мы разберём пять задач, которые встречаются буквально везде —
от обработки оценок до игровой логики:

- найти **минимум** и **максимум**;
- посчитать **сумму** и **среднее**;
- **развернуть** массив задом наперёд, не заводя второй массив;
- **посчитать**, сколько раз встречается заданное число;
- **сдвинуть** массив циклически влево — сначала на одну позицию,
  потом на любое число позиций `k`, в том числе больше длины массива и
  отрицательное.

Все они — про один проход циклом и пару переменных. Никакой новой
тяжёлой теории: только приёмы, которые ты будешь повторять до конца
книги.

## Что мы сделаем

К концу главы у тебя будут три рабочие программы:

- `06-minmax.c` — вводит числа и печатает минимум, максимум, сумму и
  среднее.
- `06-reverse.c` — переворачивает массив **на месте**.
- `06-count-rotate.c` — считает, сколько раз встретилось число, и
  сдвигает массив влево на одну позицию.

Плюс небольшой `rotate-k.c`, который ты наберёшь сам по ходу главы: он
сдвигает массив на `k` позиций за один проход.

И, что важнее, ты поймёшь три вещи, на которых спотыкается почти
каждый новичок: **почему минимум/максимум нельзя начинать с нуля**,
**почему разворот «двумя индексами» останавливается ровно посередине**
и **почему выход за границу массива — самый опасный баг в Си**
(подсказка: потому что программа при этом печатает правильный ответ).

## Часть 1. Минимум, максимум, сумма, среднее

### Разбираем задачу руками

Пусть ввели пять чисел: `7  -3  10  4  10`.

Сумму ты бы считал так: ведёшь «копилку», начинаешь с нуля, идёшь по
числам и каждое добавляешь. `0 → 7 → 4 → 14 → 18 → 28`. Сумма 28.
Среднее (точнее, **среднее арифметическое**) — сумма, делённая на
количество: `28 / 5 = 5.6`. Оно не обязано совпадать ни с одним из
чисел набора и не обязано быть целым.

А как ты ищешь минимум глазами? Смотришь на первое число и держишь его
в голове как «пока самое маленькое». Потом смотришь на каждое
следующее: если оно меньше того, что в голове, — запоминаешь новое.
Дошёл до конца — в голове лежит минимум. Максимум — то же самое, только
«больше».

Главное здесь — **с чего начать**. «В голове» сначала лежит **первое
число массива**, а не ноль. Запомни этот момент, сейчас увидим, почему
он критичен.

### Шаг 1. Наивная версия — и её баг

Сделаем «в лоб»: заведём `min` и `max`, поставим их в 0 (кажется
логичным — «пусто»), сумму тоже в 0, и пройдёмся. Вот весь файл,
назовём его `naive.c`:

```c
#include <stdio.h>

int main(void)
{
    int n;
    printf("Сколько чисел? ");
    if (scanf("%d", &n) != 1 || n <= 0 || n > 100) {
        printf("Нужно от 1 до 100 чисел.\n");
        return 1;
    }

    int a[100];
    for (int i = 0; i < n; i++) {
        printf("a[%d] = ", i);
        if (scanf("%d", &a[i]) != 1) {
            printf("\nЖдал число, получил что-то другое.\n");
            return 1;
        }
    }

    int min = 0;
    int max = 0;
    int sum = 0;
    for (int i = 0; i < n; i++) {
        if (a[i] < min) min = a[i];
        if (a[i] > max) max = a[i];
        sum += a[i];
    }

    printf("Минимум: %d\n", min);
    printf("Максимум: %d\n", max);
    printf("Сумма:    %d\n", sum);
    return 0;
}
```

Разберём то, что тут нового:

- `if (scanf("%d", &n) != 1 || n <= 0 || n > 100)` — три проверки в
  одной. `scanf` возвращает, **сколько значений** он успешно прочитал;
  мы просили одно, значит ждём `1`. Дальше `n <= 0` отсекает пустой и
  отрицательный размер, а `n > 100` — размер больше нашего массива.
  Связка `||` — логическое «ИЛИ»: достаточно, чтобы сработало любое
  из трёх условий (см. главу 2).
- `int a[100];` — массив ровно на 100 чисел. Больше в него не влезет,
  поэтому такую же цифру мы и поставили в проверку выше. (Как
  выделить массив под точное `n`, разберём в упражнениях — там
  понадобится `malloc` из главы 3.)
- `if (scanf("%d", &a[i]) != 1)` — проверяем **каждое** введённое
  число, а не только первое. Пропустишь эту проверку — и на любом
  «плохом» вводе (буквы вместо цифр, конец файла) элемент `a[i]`
  останется **неинициализированным**, то есть в нём будет мусор,
  оставшийся в памяти от прошлых дел. Дальше программа честно посчитает
  минимум и сумму по мусору и уверенно напечатает бессмыслицу.
- `&a[i]` — адрес `i`-го элемента. `scanf` всегда хочет адрес, куда
  писать; для элемента массива он берётся так же, как для обычной
  переменной.
- `sum += a[i];` — короткая запись `sum = sum + a[i]` (видели в
  главе 2). К копилке прибавляем очередной элемент.
- `if (a[i] < min) min = a[i];` — если текущий элемент меньше нашего
  «рекордсмена», обновляем рекорд. Без фигурных скобок: когда в теле
  `if` одна инструкция, скобки можно опустить (но будь аккуратен).

Запускаем на числах `7 -3 10 4 10`:

```text
Сколько чисел? 5
a[0] = 7
a[1] = -3
a[2] = 10
a[3] = 4
a[4] = 10
Минимум: -3
Максимум: 10
Сумма:    28
```

Минимум и максимум совпали с ожиданием. Случайно. Теперь введём числа,
которые **все положительные**: `7 3 10 4 9`.

```text
Сколько чисел? 5
a[0] = 7
a[1] = 3
a[2] = 10
a[3] = 4
a[4] = 9
Минимум: 0
Максимум: 10
Сумма:    33
```

Максимум верный, а минимум — **0**, хотя нуля в данных вообще нет!
Вот он, баг.

### В чём проблема

Мы стартовали `min` с нуля. Дальше условие `if (a[i] < min)` спрашивает
«меньше ли элемент, чем 0?». Все наши числа положительные — значит,
**ни одно** не меньше нуля, `min` так и остаётся 0. Программа уверенно
врёт.

Если бы все числа были, наоборот, **отрицательными**, сломался бы
`max`: он остался бы нулём, потому что ничего не больше нуля. Проверим
на `-7 -3 -10`:

```text
Сколько чисел? 3
a[0] = -7
a[1] = -3
a[2] = -10
Минимум: -10
Максимум: 0
Сумма:    -20
```

Так и есть — максимум 0, хотя самое большое здесь −3.

Ноль — это не «нейтральное пустое значение». Это конкретное число,
которое влезает в сравнение и портит результат. Для суммы ноль
правильный старт (прибавить ноль — ничего не меняет). А для минимума и
максимума нужен старт, который **точно есть среди данных**.

### Шаг 2. Фикс — стартуем с первого элемента

Правильное начало для `min` и `max` — **первый элемент массива**,
`a[0]`. Он гарантированно из наших данных, поэтому ничего не исказит:
в худшем случае минимум так и останется первым элементом, и это будет
правдой.

```c
int min = a[0];
int max = a[0];
int sum = 0;
for (int i = 0; i < n; i++) {
    if (a[i] < min) min = a[i];
    if (a[i] > max) max = a[i];
    sum += a[i];
}
```

Цикл по-прежнему идёт с `i = 0`. Да, на первом шаге мы сравниваем
`a[0]` сам с собой — это не ошибка, просто `min` и `max` не изменятся.
Лишнего тут нет, зато код проще.

Теперь на `7 3 10 4 9`:

```text
Сколько чисел? 5
a[0] = 7
a[1] = 3
a[2] = 10
a[3] = 4
a[4] = 9
Минимум: 3
Максимум: 10
Сумма:    33
```

Минимум правильный. Баг побеждён одной строкой.

### Пустой массив: почему `a[0]` — это не всегда безопасно

У фикса «стартуем с `a[0]`» есть условие: элемент `a[0]` должен
**существовать**. Если `n` равно нулю, никакого `a[0]` в массиве нет, и
строка `int min = a[0];` прочитает из памяти неизвестно что.

Именно поэтому в самом начале мы отсекаем `n <= 0` и выходим с
ошибкой. Строчка `n <= 0` в проверке `scanf` — не формальность, а
защита следующей за ней строки:

```text
Сколько чисел? 0
Нужно от 1 до 100 чисел.
```

Кстати, а что вообще считать минимумом пустого набора? Ответа нет —
минимума пустого множества не существует. Поэтому отказаться считать
здесь честнее, чем выдумать какое-нибудь число.

### Сумма: сто чисел — уже повод задуматься о типе

Мы держим сумму в `int`. Наши пять чисел дают 28, всё хорошо. А если
пользователь введёт сто чисел, каждое около двух миллиардов? Сумма
будет под 2·10^11, а потолок `int` — 2 147 483 647. Знакомое по
главе 4 переполнение, и снова неопределённое поведение.

Проверка простая: **максимум входа × количество**. 100 × 2·10^9 =
2·10^11, в `int` не влезает, в `long long` (до 9·10^18) влезает с
огромным запасом. Значит:

объявляем `long long sum = 0;` вместо `int sum = 0;`, а при печати
берём `%lld` вместо `%d`:

```c
printf("Сумма:    %lld\n", sum);
```

Два слова в объявлении, две буквы в формате — и целый класс багов
закрыт.

А вот `min` и `max` менять не надо: они всегда равны какому-то
элементу массива, а элементы у нас `int`. Тип расширяют там, где
значение **вычисляется**, а не там, где оно просто копируется.

### Среднее: не наступи на целочисленное деление

Количество у нас целое, сумма — тоже (пусть и `long long`). Если
написать `sum / n`, Си поделит **нацело** и отбросит дробную часть —
`28 / 5` даст 5, а не 5.6 (мы разбирали эту ловушку в главе 2). Дробь
отбрасывается **в сторону нуля**: `-28 / 5` даст −5, а не −6. Чтобы
получить дробь, приводим сумму к `double` **до** деления:

```c
double avg = (double)sum / n;
```

Разница не теоретическая, вот три варианта и что каждый печатает при
сумме 28 и `n = 5`:

```text
сумма:            28
sum / n:          5.00
(double)(sum / n): 5.00
(double)sum / n:  5.60
```

Первый вариант неправильный: `sum / n` — деление двух целых, дробь
отброшена ещё до печати. Второй — самая частая ошибка:
кажется, что раз мы приводим к `double`, всё хорошо. Но скобки
поставлены не там: сначала внутри них выполняется **целое** деление
`28 / 5 = 5`, дробная часть уже потеряна, и `double` получает готовую
пятёрку. Приводить нужно **операнд**, а не результат.

Как только один из операндов стал `double`, второй тоже
автоматически превращается в `double` на время операции (это правило
называется «обычные арифметические преобразования»), и деление идёт
дробное. Результат — настоящие 5.6.

`%.2f` в `printf` — печать дробного числа с двумя знаками после
запятой. Просто `%f` дал бы шесть знаков: `5.600000`.

### Полная программа `06-minmax.c`

```c
#include <stdio.h>

#define MAXN 100

int main(void)
{
    int n;
    printf("Сколько чисел? ");
    if (scanf("%d", &n) != 1 || n <= 0 || n > MAXN) {
        printf("Нужно от 1 до %d чисел.\n", MAXN);
        return 1;
    }

    int a[MAXN];
    for (int i = 0; i < n; i++) {
        printf("a[%d] = ", i);
        if (scanf("%d", &a[i]) != 1) {
            printf("\nЖдал число, а получил что-то другое.\n");
            return 1;
        }
    }

    int min = a[0];
    int max = a[0];
    long long sum = 0;   /* сто чисел по два миллиарда int не выдержит */
    for (int i = 0; i < n; i++) {
        if (a[i] < min) {
            min = a[i];
        }
        if (a[i] > max) {
            max = a[i];
        }
        sum += a[i];
    }

    double avg = (double)sum / n;

    printf("Минимум: %d\n", min);
    printf("Максимум: %d\n", max);
    printf("Сумма:    %lld\n", sum);
    printf("Среднее:  %.2f\n", avg);
    return 0;
}
```

Что изменилось по сравнению с наивной версией, кроме старта `min` и
`max` от `a[0]`:

- `#define MAXN 100` — вместимость массива вынесена в **именованную
  константу** (мы завели такую же `N` в решете, глава 5). Теперь число
  100 записано в программе один раз, а не в трёх местах, и поменять
  потолок можно одной строкой. Заглавные буквы в имени — общепринятое
  соглашение для констант.
- `int a[MAXN];` и `n > MAXN` в проверке — обе цифры теперь берутся из
  одного источника и не могут разъехаться.
- `long long sum` и `%lld` — та самая защита от переполнения суммы.
- `return 1;` — выход из `main` с кодом, отличным от нуля. По традиции
  `0` значит «всё хорошо», а ненулевое — «была ошибка».

Заметь ещё, чего здесь **нет**: соблазнительной строки
`if (n > 100) n = 100;` — «попросили больше, молча посчитаем сто».
Это плохая идея. Программа,
которая тихо подменяет то, что у неё попросили, врёт пользователю:
он ввёл 150 чисел, а обработали 100, и никто ему об этом не сказал.
Лучше честный отказ. (Как снять потолок совсем — через `malloc` из
главы 3 — в упражнении 6.)

никто не вводил. В другой раз, на другой машине или с другими флагами
там может оказаться и «Минимум: -1167682112» — предсказать нельзя,
это зависит от того, что лежало в памяти до нас.

## Часть 2. Разворот массива на месте

### Разбираем задачу руками

Есть массив `1 2 3 4 5`, нужно получить `5 4 3 2 1`. Условие — **без
второго массива**: переставляем элементы внутри того же самого. Такой
алгоритм называют работающим **на месте** (по-английски in-place):
кроме самого массива, ему нужна лишь пара переменных, и их число не
растёт с длиной массива — хоть 5 элементов, хоть миллион.

Возьми пять карточек в ряд. Как перевернуть порядок руками? Меняешь
местами **крайние**: первую с последней. Получилось `5 2 3 4 1`. Потом
вторую с предпоследней: `5 4 3 2 1`. Средняя карточка (третья) остаётся
на месте — ей и так быть в центре. Готово за два обмена.

Идея: два «пальца». Левый `i` стоит на первом элементе, правый `j` — на
последнем. Меняем местами то, на что они показывают, и сдвигаем пальцы
навстречу друг другу: `i` вправо, `j` влево. Останавливаемся, когда они
встретились или прошли друг друга.

### Шаг 1. Меняем местами через временную переменную

Обмен двух элементов массива — то же самое, что обмен двух переменных
из главы 3, только теперь это элементы:

```c
int t = a[i];
a[i] = a[j];
a[j] = t;
```

Почему нельзя короче, `a[i] = a[j]; a[j] = a[i];`? Потому что первая
строка **затирает** `a[i]` значением `a[j]`, и старое `a[i]` теряется
навсегда — вторая строка положит обратно то же `a[j]`. Поэтому нужна
временная коробка `t`, куда мы прячем `a[i]` до перезаписи. (В главе 3
мы делали ровно это через указатели в функции `swap`; здесь обмен
прямо на элементах массива.)

### Шаг 2. Сводим индексы навстречу

```c
int i = 0;
int j = n - 1;
while (i < j) {
    int t = a[i];
    a[i] = a[j];
    a[j] = t;
    i++;
    j--;
}
```

- `int j = n - 1;` — правый индекс ставим на **последний** элемент.
  Помни: индексы идут `0 .. n-1`, поэтому последний — `n - 1`, а не
  `n`. Написать `a[n]` значило бы выйти за границу массива.
- `while (i < j)` — повторяем, **пока левый палец левее правого**.
- внутри — обмен через `t`.
- `i++; j--;` — двигаем пальцы навстречу: левый на шаг вправо, правый
  на шаг влево.

### Почему условие именно `i < j`

Это сердце алгоритма, разберём по случаям.

**Почему не `i <= j`?** Когда `i == j`, оба пальца стоят на **одном и
том же** элементе (это центр массива нечётной длины). С `i <= j` цикл
сделает ещё один оборот и поменяет центр сам с собой. Вреда нет, но и
смысла нет — лишняя работа. Сразу после этого `i` станет больше `j`,
и цикл всё равно остановится.

**Почему нельзя идти до конца массива?** Частая ошибка — пройти `i`
по всему массиву, от 0 до `n − 1`, считая пару как `j = n - 1 - i`:

```c
for (int i = 0; i < n; i++) {
    int j = n - 1 - i;
    int t = a[i];
    a[i] = a[j];
    a[j] = t;
}
```

Первая половина оборотов развернёт массив, а вторая пройдётся по тем
же парам ещё раз (`i = 3, j = 1` — та же пара, что `i = 1, j = 3`) и
**развернёт его обратно**. На `1 2 3 4 5` такой цикл печатает
`1 2 3 4 5` — как будто ничего не произошло. Условие `i < j`
останавливает нас ровно посередине.

Посмотрим на `1 2 3 4 5` (нечётная длина, n = 5):

```text
старт:  i=0 j=4   меняем a[0] и a[4] -> 5 2 3 4 1
шаг:    i=1 j=3   меняем a[1] и a[3] -> 5 4 3 2 1
шаг:    i=2 j=2   i < j ложно -> стоп (центр 3 не трогаем)
```

А на `1 2 3 4` (чётная длина, n = 4):

```text
старт:  i=0 j=3   меняем a[0] и a[3] -> 4 2 3 1
шаг:    i=1 j=2   меняем a[1] и a[2] -> 4 3 2 1
шаг:    i=2 j=1   i < j ложно -> стоп
```

В обоих случаях каждый элемент, кроме центрального, переставлен ровно
один раз, а обменов ровно `n / 2` в целочисленном смысле: 5 / 2 = 2,
4 / 2 = 2 — половина длины с отброшенной дробью. Быстро и без лишней
памяти.

### Полная программа `06-reverse.c`

```c
#include <stdio.h>

#define MAXN 100

int main(void)
{
    int n;
    printf("Сколько чисел? ");
    if (scanf("%d", &n) != 1 || n <= 0 || n > MAXN) {
        printf("Нужно от 1 до %d чисел.\n", MAXN);
        return 1;
    }

    int a[MAXN];
    for (int i = 0; i < n; i++) {
        printf("a[%d] = ", i);
        if (scanf("%d", &a[i]) != 1) {
            printf("\nЖдал число, а получил что-то другое.\n");
            return 1;
        }
    }

    int i = 0;
    int j = n - 1;
    while (i < j) {
        int t = a[i];
        a[i] = a[j];
        a[j] = t;
        i++;
        j--;
    }

    printf("Развёрнутый массив:");
    for (int k = 0; k < n; k++) {
        printf(" %d", a[k]);
    }
    printf("\n");
    return 0;
}
```

Ввод здесь ровно такой же, как в `06-minmax.c`: константа `MAXN`,
отказ при `n` вне диапазона, проверка `scanf` на каждом числе. Дальше —
разворот и печать.

При печати мы взяли отдельный счётчик `k`, потому что `i` и `j` после
цикла уже «израсходованы» (они встретились в центре). И обрати внимание
на формат `" %d"` — пробел **перед** числом: так числа красиво
разделяются пробелами, а лишнего пробела в начале строки нет (он идёт
перед первым числом, сразу после двоеточия в `printf` выше).

### Проверяем

Нечётная длина — тот случай, где в центре остаётся неподвижный элемент:

```text
Сколько чисел? 5
a[0] = 1
a[1] = 2
a[2] = 3
a[3] = 4
a[4] = 5
Развёрнутый массив: 5 4 3 2 1
```

Чётная — тут неподвижных нет, все элементы разбились на пары:

```text
Сколько чисел? 4
a[0] = 1
a[1] = 2
a[2] = 3
a[3] = 4
Развёрнутый массив: 4 3 2 1
```

И два вырожденных случая. Два элемента — ровно один обмен:

```text
Сколько чисел? 2
a[0] = 7
a[1] = 8
Развёрнутый массив: 8 7
```

Один элемент — ноль обменов: `i` и `j` сразу равны нулю, `i < j`
ложно, цикл не выполняется:

```text
Сколько чисел? 1
a[0] = 7
Развёрнутый массив: 7
```

Отдельно проверять «а не сломается ли на массиве из одного элемента»
не пришлось — условие `i < j` разобралось само. Хороший признак: если
краевой случай не требует отдельной ветки `if`, алгоритм, скорее
всего, записан правильно.

## Часть 3. Подсчёт значения и сдвиг влево

Две короткие, но полезные задачи в одной программе.

### Задача А. Сколько раз встречается число

Идея простая: заводим счётчик `count = 0`, идём по массиву, и каждый
раз, когда элемент равен искомому, прибавляем 1.

```c
int count = 0;
for (int i = 0; i < n; i++) {
    if (a[i] == target) {
        count++;
    }
}
```

- `target` — то значение, которое ищем (спросим у пользователя).
- `a[i] == target` — сравнение **на равенство**, двойное `==` (один
  `=` был бы присваиванием — классический баг из главы 2).
- `count++` — увеличить счётчик на 1 при каждом совпадении.

Всё. Один проход, одна переменная.

### Задача Б. Циклический сдвиг влево на 1

«Сдвинуть влево на 1» значит: каждый элемент переезжает на одну позицию
левее, а самый первый, которому уже некуда деваться слева, **уходит в
самый конец**. Это и есть «циклический» (по кругу) сдвиг.

Руками на `10 20 30 40`:

```text
было:   10 20 30 40
стало:  20 30 40 10
```

`20` встало на место `10`, `30` на место `20`, `40` на место `30`, а
`10` уехало в хвост.

Как это запрограммировать? Первый элемент мы вот-вот затрём — значит,
сначала **сохраним его** в отдельную переменную. Потом сдвинем все
остальные: на позицию `i` положим то, что было на `i+1`. И в самый
конец вернём сохранённый первый элемент.

### Шаг 1. Наивно — и ловушка с границей

Напрашивается такой цикл:

```c
int first = a[0];
for (int i = 0; i < n; i++) {
    a[i] = a[i + 1];   // опасно на последнем шаге!
}
a[n - 1] = first;
```

Логика «двигаем каждый влево» вроде верная, но посмотри на последний
оборот цикла: при `i = n - 1` строка обращается к `a[i + 1]`, то есть к
`a[n]`. А элемента `a[n]` **не существует** — индексы только до `n - 1`.
Это выход за границу массива: Си не проверяет границы и молча читает
чужой кусок памяти.

Самое неприятное — что программа при этом **выглядит рабочей**.
Проверим на маленьком файле `naive-rotate.c`:

```c
#include <stdio.h>

int main(void)
{
    int a[4] = {10, 20, 30, 40};
    int n = 4;

    int first = a[0];
    for (int i = 0; i < n; i++) {
        a[i] = a[i + 1];
    }
    a[n - 1] = first;

    printf("После сдвига:");
    for (int i = 0; i < n; i++) {
        printf(" %d", a[i]);
    }
    printf("\n");
    return 0;
}
```

```text
cc -std=c11 -Wall -Wextra -O2 naive-rotate.c -o naive-rotate
./naive-rotate
```

```text
После сдвига: 20 30 40 10
```

Ответ **правильный**! Компилятор не сказал ни слова, программа не
упала. Прочитанный за границей мусор попал в `a[3]`, а следующей же
строкой мы этот `a[3]` перезаписали сохранённым `first` — вот баг и не
проявился. Ровно так и живут годами ошибки с границами массива: пока
не повезёт, их не видно.

Позовём адресный санитайзер (AddressSanitizer) — он проверяет каждое
обращение к памяти:

```text
cc -std=c11 -Wall -Wextra -O1 -fsanitize=address,undefined \
   naive-rotate.c -o naive-rotate-san
./naive-rotate-san
```

Первые же строки, которые он печатает:

```text
naive-rotate.c:10:16: runtime error: index 4 out of bounds for type
'int[4]'
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior
naive-rotate.c:10:16
=================================================================
==47818==ERROR: AddressSanitizer: stack-buffer-overflow on address
0x7ff7b1214bb0 at pc 0x00010ecea969 bp 0x7ff7b1214b70 sp 0x7ff7b1214b68
READ of size 4 at 0x7ff7b1214bb0 thread T0
```

(Длинные строки перенесены под ширину страницы.)

Вот и приговор: `index 4 out of bounds for type 'int[4]'` — читаем
элемент номер 4 у массива, где есть только 0, 1, 2, 3. Строка 10 —
это как раз `a[i] = a[i + 1];`. Дальше санитайзер печатает ещё десяток
строк с адресами и картой памяти; там, в частности, написано
`'a' <== Memory access at offset 48 overflows this variable` — мы
полезли ровно за правый край массива `a`.

Номер процесса (`==47818==`) и адреса (`0x7ff7...`) у тебя будут
другие, они меняются от запуска к запуску. Важны строка с
`runtime error` (её печатает санитайзер неопределённого поведения,
`undefined`) и строка с `ERROR: AddressSanitizer` (это уже адресный).
Первый только сообщает и даёт программе идти дальше, второй
останавливает её на месте — поэтому `После сдвига:` в этот раз не
напечатается.

### Шаг 2. Фикс — останавливаем цикл на один шаг раньше

Нам нужно сдвигать только до предпоследнего элемента включительно:
последний (`a[n-1]`) мы всё равно перезапишем сохранённым `first`
вручную. Поэтому условие — `i < n - 1`:

```c
int first = a[0];
for (int i = 0; i < n - 1; i++) {
    a[i] = a[i + 1];
}
a[n - 1] = first;
```

Теперь максимальное `i` равно `n - 2`, и `a[i + 1]` — это `a[n - 1]`,
последний существующий элемент. За границу не вылезаем.

Проследим на `10 20 30 40` (n = 4, `first = 10`):

```text
i=0:  a[0] = a[1]  ->  20 20 30 40
i=1:  a[1] = a[2]  ->  20 30 30 40
i=2:  a[2] = a[3]  ->  20 30 40 40
конец цикла, ставим a[3] = first(10) -> 20 30 40 10
```

Именно то, что мы насчитали руками.

### Полная программа `06-count-rotate.c`

```c
#include <stdio.h>

#define MAXN 100

int main(void)
{
    int n;
    printf("Сколько чисел? ");
    if (scanf("%d", &n) != 1 || n <= 0 || n > MAXN) {
        printf("Нужно от 1 до %d чисел.\n", MAXN);
        return 1;
    }

    int a[MAXN];
    for (int i = 0; i < n; i++) {
        printf("a[%d] = ", i);
        if (scanf("%d", &a[i]) != 1) {
            printf("\nЖдал число, а получил что-то другое.\n");
            return 1;
        }
    }

    int target;
    printf("Какое значение посчитать? ");
    if (scanf("%d", &target) != 1) {
        printf("\nЖдал число, а получил что-то другое.\n");
        return 1;
    }

    int count = 0;
    for (int i = 0; i < n; i++) {
        if (a[i] == target) {
            count++;
        }
    }
    printf("Значение %d встречается %d раз(а)\n", target, count);

    int first = a[0];
    for (int i = 0; i < n - 1; i++) {
        a[i] = a[i + 1];
    }
    a[n - 1] = first;

    printf("После сдвига влево:");
    for (int i = 0; i < n; i++) {
        printf(" %d", a[i]);
    }
    printf("\n");
    return 0;
}
```

Проверку `scanf` мы поставили и на `target` тоже — иначе на оборванном
вводе программа искала бы в массиве случайное число из мусора и
печатала бы что-нибудь вроде «Значение 1167885744 встречается 0 раз(а)».
Правило простое: **любое** значение, пришедшее от пользователя,
проверяется на месте.

### Проверяем

```text
Сколько чисел? 6
a[0] = 10
a[1] = 20
a[2] = 30
a[3] = 20
a[4] = 50
a[5] = 20
Какое значение посчитать? 20
Значение 20 встречается 3 раз(а)
После сдвига влево: 20 30 20 50 20 10
```

Число `20` встретилось 3 раза — верно. И массив сдвинулся: первый `10`
уехал в хвост, остальные сместились влево. Ничего не потерялось: было
шесть чисел, стало шесть тех же самых, просто в другом порядке — в
этом и смысл слова «циклический».

Массив из одного элемента сдвиг тоже переживает. Цикл
`for (int i = 0; i < n - 1; i++)` при `n = 1` не выполняется ни разу
(`0 < 0` ложно), а строка `a[n - 1] = first;` кладёт `a[0]` обратно в
`a[0]`:

```text
Сколько чисел? 1
a[0] = 5
Какое значение посчитать? 5
Значение 5 встречается 1 раз(а)
После сдвига влево: 5
```

Прогоним обе программы главы под санитайзерами — они проверяют и
границы массива, и переполнения:

```text
cc -std=c11 -Wall -Wextra -O1 -fsanitize=address,undefined \
   code/06-count-rotate.c -o rotate-san
printf '6\n10\n20\n30\n20\n50\n20\n20\n' | ./rotate-san
```

Ни одной строчки `runtime error` — в отличие от наивной версии со
сдвигом до `i < n`.

### Сдвиг на `k` позиций

Сдвиг на одну позицию умеем. А если надо на `k`? Руками на
`10 20 30 40 50` при `k = 2`: два первых числа уезжают в хвост, в том
же порядке:

```text
было:   10 20 30 40 50
стало:  30 40 50 10 20
```

**Наивно** — повторить сдвиг на 1 ровно `k` раз. Работать будет, но
посчитаем цену. Один сдвиг на 1 — это `n` присваиваний (`n − 1` в
цикле плюс последнее `a[n - 1] = first`) и ещё одно для `first`.
`k` сдвигов — примерно `k · n` присваиваний. Для массива в миллион
элементов и `k = 500 000` это полтриллиона присваиваний — минуты
работы там, где хватило бы миллиона.

Прежде чем ускорять, разберёмся со странными `k`.

**`k` больше `n`.** Сдвинь массив из 5 элементов на 5 — каждый элемент
обойдёт полный круг и встанет на своё место. Значит, сдвиг на 7 — то
же самое, что сдвиг на 7 − 5 = 2, а вообще важен только остаток
`k % n`. Сдвиг на 1 000 000 007 позиций массива из 5 элементов — это
сдвиг на 2 (1 000 000 007 = 5 · 200 000 001 + 2).

**Отрицательный `k`.** Естественно понимать его как сдвиг **вправо**:
`k = -1` — последний элемент уезжает в начало. А сдвиг вправо на 1 —
то же самое, что сдвиг влево на `n − 1` (проверь на пальцах:
`10 20 30 40 50` → `50 10 20 30 40` в обоих случаях). Осторожно с
остатком: в Си знак `%` такой же, как у делимого (см. главы 2 и 5), так
что `-1 % 5` равно −1, а не 4, и `-6 % 5` тоже −1. Поэтому после
`k % n` отрицательный результат поправляем прибавлением `n`: −1 + 5 = 4.

**`n` равно 0.** Тогда `k % n` — деление на ноль, это неопределённое
поведение (на этом маке программа падает). Массив из нуля или одного
элемента сдвигать нечего, так что такие `n` отсекаем до всякой
арифметики.

**Быстро: три разворота.** Есть красивый приём, который делает сдвиг
на любое `k` за один проход, **на месте** и без всяких повторов.
Разрежем массив на две части: `A` — первые `k` элементов, `B` —
остальные. Сдвиг влево на `k` превращает `A B` в `B A`. И вот как это
получить разворотами из части 2:

```text
было:              10 20 | 30 40 50      (A = 10 20, B = 30 40 50)
развернули A:      20 10 | 30 40 50
развернули B:      20 10 | 50 40 30
развернули всё:    30 40 50 | 10 20      (это B A)
```

Почему работает? Разворот всего массива меняет местами блоки **и**
переворачивает каждый блок внутри. Мы заранее перевернули блоки по
отдельности, и второй разворот вернул их содержимое в правильный
порядок — а сами блоки поменялись местами.

Сколько это стоит? Разворот куска длины `m` делает `m / 2` обменов.
Всего `k / 2 + (n − k) / 2 + n / 2`, то есть не больше `n` обменов при
любом `k`. Для миллиона элементов — миллион обменов вместо
полутриллиона присваиваний.

Собери файл `rotate-k.c`:

```c
#include <stdio.h>

/* Разворачивает кусок массива a[from..to] включительно. */
void reverse_range(int *a, int from, int to)
{
    while (from < to) {
        int t = a[from];
        a[from] = a[to];
        a[to] = t;
        from++;
        to--;
    }
}

/* Циклический сдвиг влево на k позиций за три разворота. */
void rotate_left(int *a, int n, int k)
{
    if (n <= 1) {
        return;                 /* сдвигать нечего */
    }
    k = k % n;                  /* лишние полные круги долой */
    if (k < 0) {
        k = k + n;              /* вправо на 1 = влево на n - 1 */
    }
    reverse_range(a, 0, k - 1);
    reverse_range(a, k, n - 1);
    reverse_range(a, 0, n - 1);
}

int main(void)
{
    int ks[] = {0, 1, 2, 5, 7, -1, -6};
    int count = (int)(sizeof ks / sizeof ks[0]);

    for (int t = 0; t < count; t++) {
        int a[5] = {10, 20, 30, 40, 50};
        rotate_left(a, 5, ks[t]);
        printf("k = %2d:", ks[t]);
        for (int i = 0; i < 5; i++) {
            printf(" %d", a[i]);
        }
        printf("\n");
    }
    return 0;
}
```

Разбор:

- `void reverse_range(int *a, int from, int to)` — тот же разворот
  двумя пальцами, только не всего массива, а куска с `a[from]` по
  `a[to]` включительно. Массив приходит в функцию как адрес начала
  (`int *a`, см. главу 3), поэтому функция меняет настоящий массив
  `main`, а не копию. `void` — функция ничего не возвращает.
- `if (n <= 1) return;` — защита от деления на ноль в `k % n` и от
  бессмысленной работы на одном элементе.
- `k = k % n;` — отбрасываем полные круги. После этого `k` лежит от
  `-(n - 1)` до `n - 1`. (Даже для самого маленького `int`, −2147483648,
  это безопасно: переполнить `%` может только делитель −1, а у нас
  `n` не меньше 2.)
- `if (k < 0) k = k + n;` — отрицательный остаток превращаем в
  равносильный сдвиг влево.
- три вызова `reverse_range` — ровно три разворота из таблички выше.
  При `k = 0` первый вызов получит кусок `a[0..-1]`, где `from > to`,
  и цикл в нём не выполнится ни разу; второй и третий развернут весь
  массив туда и обратно. Лишняя работа, но ответ верный.
- `int ks[] = {0, 1, 2, 5, 7, -1, -6};` — набор проверочных `k`.
  Квадратные скобки без числа: размер компилятор посчитает сам по
  списку.
- `(int)(sizeof ks / sizeof ks[0])` — число элементов массива, приём из
  главы 3.
- `int a[5] = {10, 20, 30, 40, 50};` внутри цикла — на каждом обороте
  массив заводится заново, поэтому каждый `k` сдвигает исходный набор,
  а не результат прошлого сдвига.
- `%2d` — печать числа в поле ширины 2, чтобы столбец выровнялся.

```text
cc -std=c11 -Wall -Wextra -O2 rotate-k.c -o rotate-k
./rotate-k
```

```text
k =  0: 10 20 30 40 50
k =  1: 20 30 40 50 10
k =  2: 30 40 50 10 20
k =  5: 10 20 30 40 50
k =  7: 30 40 50 10 20
k = -1: 50 10 20 30 40
k = -6: 50 10 20 30 40
```

`k = 5` вернул массив на место (полный круг), `k = 7` совпал с
`k = 2`, а `k = -1` и `k = -6` — со сдвигом вправо на 1. Я сверил
`rotate_left` с наивным «`k` раз по одному» на всех `n` от 1 до 9 и
всех `k` от −30 до 30 — расхождений нет, санитайзеры молчат.

## Частые ошибки

**Инициализация min/max нулём.** Самая коварная: на положительных
данных врёт минимум, на отрицательных — максимум, а на смешанных может
случайно «повезти». Всегда стартуй с `a[0]`, а не с 0 (и не с
«огромного числа наугад» — это тоже хрупко).

**Минимум/максимум по пустому массиву.** Если `n` равно 0, то `a[0]`
не существует, и старт `min = a[0]` уже ошибка. Поэтому мы заранее
отсекаем `n <= 0`. У пустого набора минимума просто нет — правильный
ответ тут «отказаться считать», а не выдумать число.

**`scanf` без проверки в цикле ввода.** Проверить первое число и
забыть про остальные — типичная невнимательность. Если ввод оборвётся
на середине, `a[i]` останется неинициализированным, и дальше программа
посчитает минимум, сумму и среднее по случайному мусору из памяти —
причём без единого предупреждения. Проверяй **каждый** `scanf`.

**Молчаливое урезание `n`.** `if (n > 100) n = 100;` выглядит
аккуратно, а на деле подменяет задачу: попросили 150, посчитали 100 и
не сказали. Либо честный отказ, либо `malloc` под точный размер.

**Выход за границу при сдвиге.** `a[i + 1]` в цикле до `i < n` лезет в
`a[n]`. Останавливай цикл на `i < n - 1`. То же правило — при любом
обращении к «соседу справа». И помни: такой баг легко **не
проявляется** — собери программу с `-fsanitize=address`, если есть
хоть малейшее сомнение.

**`a[n]` вместо `a[n - 1]`.** Последний элемент — `n - 1`. Постоянный
источник ошибок и в развороте (`j = n - 1`), и в сдвиге.

**`=` вместо `==` при подсчёте.** `if (a[i] = target)` присвоит элементу
`target` (испортит массив!), а условием станет само присвоенное
значение. Если `target` не ноль, условие истинно на **каждом**
элементе и счётчик выйдет равным `n`; если `target` равен нулю —
ложно всегда, счётчик 0, а массив весь в нулях. Нужно `==`. Компилятор
с `-Wall` предупреждает («using the result of an assignment as a
condition without parentheses») — не игнорируй предупреждения.

**Среднее нацело.** `double avg = sum / n;` посчитает нацело **до**
записи в `double`. `(double)(sum / n)` — та же ошибка в маскировке:
скобки не там. Приводи операнд: `(double)sum / n`.

**Сумма в `int`.** Сами элементы влезают, а их сумма — уже нет. Прикинь
максимум входа, умножь на количество и, если результат за двумя
миллиардами, бери `long long` (и `%lld` в `printf`).

**Обмен без временной переменной.** `a[i] = a[j]; a[j] = a[i];` теряет
одно из значений. Нужна `t`.

**Потеря первого элемента при сдвиге.** Если не сохранить `a[0]` в
`first` до цикла, самый первый шаг его затрёт, и в хвост уезжать будет
уже нечему. Забудешь последнюю строку совсем — на `10 20 30 40`
получишь `20 30 40 40` (последний элемент задвоился). Напишешь в конце
`a[n - 1] = a[0];` вместо `first` — получишь `20 30 40 20`: в `a[0]`
к этому моменту уже лежит 20, а не 10.

**Сдвиг на `k` без `k % n`.** Повторять сдвиг на 1 миллиард раз при
`n = 5` — впустую крутить полные круги. А отрицательный `k` без
поправки `k + n` даст отрицательный индекс. И помни, что при `n = 0`
выражение `k % n` — деление на ноль.

## Упражнения

1. Добавь в `06-minmax.c` вывод **позиции** (индекса) минимума и
   максимума, а не только их значений. Подсказка: заведи `imin`,
   `imax` и обновляй их рядом с `min`, `max`. Отдельно подумай, что
   печатать, если минимум встречается несколько раз, — первую позицию
   или последнюю? Проверь на `3 1 5 1`. Ожидаемо: максимум 5 на
   позиции 2; минимум 1 — на позиции 1, если обновлять по строгому
   `<` (первое вхождение), и на позиции 3, если по `<=` (последнее).
2. Второй по величине элемент. Найди за **один** проход не максимум, а
   второй по величине (для `7 3 10 4 9` это 9). Подсказка: держи две
   переменные, `max` и `second`, и обновляй их аккуратно. Сначала
   договорись об определении: «второе по величине **различное**
   значение» или «второй элемент, если отсортировать по убыванию»? Для
   `10 10 3` первое определение даёт 3, второе — 10. А на `5 5 5` по
   первому определению ответа нет вовсе — программа должна так и
   сказать, а не печатать мусор или `max`.
3. Сделай разворот **функцией** `void reverse(int *a, int n)` и вызови
   её из `main`. Вспомни из главы 3: имя массива — это адрес начала,
   поэтому функция изменит настоящий массив. Проверь, что она
   корректна при `n = 0` и `n = 1`. Ожидаемо: при `n = 0` будет
   `j = -1`, условие `0 < -1` ложно, и функция ничего не трогает; при
   `n = 1` — тоже ноль обменов.
4. Циклический сдвиг **вправо** на 1: последний элемент уходит в начало,
   остальные сдвигаются вправо. Подумай, в какую сторону теперь должен
   идти цикл, чтобы не затереть нужное значение раньше времени.
   Подсказка: сохранить надо `a[n - 1]`, а цикл пойдёт с конца
   (`a[i] = a[i - 1]` для `i` от `n - 1` вниз до 1). Ожидаемо:
   `10 20 30 40` → `40 10 20 30`. Сверь с `rotate_left(a, n, -1)` из
   `rotate-k.c`.
5. Сдвиг влево на `k` «в лоб»: повтори сдвиг на 1 ровно `k % n` раз
   (с поправкой для отрицательного `k`) и сверь результат с
   `rotate_left` для всех `k` от −20 до 20 на массиве из 5 элементов.
   Ожидаемо: ни одного расхождения. Потом добавь счётчик присваиваний
   в обе версии и сравни их для `n = 1000`, `k = 500`: у наивной выйдет
   около полумиллиона (500 сдвигов по ~1000), у трёх разворотов —
   1000 обменов по 3 присваивания, то есть 3000.
6. Перепиши любую из программ так, чтобы массив выделялся через
   `malloc(n * sizeof(int))` (глава 3) под точное `n`, без потолка в
   100 элементов. Не забудь `free` в конце и проверку `malloc` на
   `NULL`. `n` по-прежнему проверяй: хотя бы `n >= 1` (иначе снова нет
   `a[0]`) и разумный потолок сверху, чтобы `n * sizeof(int)` не
   попросил невозможного. Прогони результат под `-fsanitize=address` —
   он поймает выход за границу кучи. А вот утечки на macOS он не ловит
   (см. главу 3): их проверяй `leaks --atExit -- ./программа`. Забыл
   `free` — увидишь строку вида `1 leak for 416 total leaked bytes`
   (так выходит для 100 `int`: 400 байт, округлённые менеджером памяти
   до 416); не забыл — `0 leaks for 0 total leaked bytes`.

## Что мы получили

Теперь ты умеешь главные «однопроходные» приёмы над массивом: накопить
сумму, удержать рекорд (мин/макс) с правильным стартом от `a[0]`,
переставить элементы на месте двумя индексами навстречу и аккуратно
сдвинуть массив, не вылезая за его границу, — а тремя разворотами
сдвинуть и на любое `k`, хоть больше длины, хоть отрицательное, за
`n` обменов вместо `k · n` присваиваний. Это не просто упражнения —
накопление и «бегунок навстречу» лежат в основе сортировок и поиска,
которыми мы займёмся дальше.

И три привычки, которые теперь стоит носить с собой: проверять
**каждый** `scanf`, а не только первый; отдельно думать про пустой
массив и массив из одного элемента; и при любом сомнении в границах
пересобирать программу с `-fsanitize=address,undefined`. Наивный сдвиг
из части 3 напечатал абсолютно правильный ответ и всё равно был
сломан — глазами такое не ловится.

В следующей главе возьмёмся за **поиск**: как найти нужный элемент в
массиве. Сначала линейный поиск (тот же проход циклом, что и здесь),
потом — двоичный, который находит число в отсортированном массиве за
считанные шаги даже среди миллионов элементов.

Итоговые программы главы — `code/06-minmax.c`, `code/06-reverse.c` и
`code/06-count-rotate.c`; `rotate-k.c` целиком напечатан в части 3.
