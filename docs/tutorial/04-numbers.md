# Глава 4. Числа: чётность, сумма цифр, переворот числа, факториал, FizzBuzz

Хватит теории — займёмся первыми настоящими алгоритмами. Все они про
числа, и все опираются на один скромный, но мощный инструмент:
**остаток от деления** `%` и **целочисленное деление** `/`. С их помощью
мы научимся разбирать число на цифры, считать их сумму, переворачивать
число задом наперёд, вычислять факториал (и заодно наткнёмся на
переполнение `int` — важнейшую ловушку Си) и напишем знаменитую
задачку с собеседований — FizzBuzz.

Всё, что нужно из прошлых глав, у тебя уже есть: переменные и типы,
`printf`/`scanf` с `&`, арифметика и `%`, `if`/`else`, циклы `while` и
`for`, функции (см. главы 2 и 3). Новое тут — только пара приёмов и тип
`long long`. Их разберём подробно.

## Что мы сделаем

К концу главы у тебя будут четыре рабочие программы:

- `04-digits.c` — вводит число, печатает сумму его цифр и само число
  задом наперёд;
- `04-factorial.c` — считает факториал, корректно справляясь с
  переполнением и отрицательным вводом;
- `04-overflow.c` — маленькая демонстрация: таблица, из которой видно,
  на каком именно `n` факториал перестаёт влезать в `int` и в
  `long long`;
- `04-fizzbuzz.c` — печатает числа от 1 до 100, заменяя кратные 3 на
  `Fizz`, кратные 5 — на `Buzz`, кратные 15 — на `FizzBuzz`.

А главное — ты прочувствуешь два оператора, `%` и `/`, на которых
держится половина числовых алгоритмов.

## Мостик: чётность через остаток

Вспомним из главы 2: `%` — это **остаток от деления**. `7 % 2` равно 1,
потому что 7 = 2·3 + **1**. А `8 % 2` равно 0, потому что 8 делится на
2 без остатка.

Отсюда главный трюк:

> `n % 2 == 0` — число чётное; `n % 2 != 0` — нечётное.

И шире: `n % k == 0` означает «`n` делится на `k` нацело». Это правило
мы будем гонять всю главу. Кратно 3? `n % 3 == 0`. Кратно 10? `n % 10
== 0`. Запомни эту формулу — она ключ ко всему дальнейшему.

## Часть 1. Сумма цифр и переворот числа

### Разбираем задачу руками

Возьмём число 12345. Как достать из него отдельные цифры, не зная
заранее, сколько их? Тут и пригодятся `%` и `/`.

Посмотри, что делает остаток от деления на 10:

```text
12345 % 10 = 5   ← последняя цифра!
```

Деление на 10 нацело отбрасывает эту последнюю цифру:

```text
12345 / 10 = 1234   ← число без последней цифры
```

Дальше повторяем то же самое с 1234, потом с 123, и так пока число не
станет нулём. Распишем по шагам:

```text
n = 12345   n % 10 = 5   n / 10 = 1234
n = 1234    n % 10 = 4   n / 10 = 123
n = 123     n % 10 = 3   n / 10 = 12
n = 12      n % 10 = 2   n / 10 = 1
n = 1       n % 10 = 1   n / 10 = 0   ← стоп, n стал 0
```

Мы «откусили» цифры по одной с конца: 5, 4, 3, 2, 1. Сложи их — вот и
сумма цифр (15). А если приклеивать их в новое число в том порядке, в
каком достаём, — получится перевёрнутое число (54321). Осталось
оформить это кодом.

### Шаг 1. Наивная версия — считаем сумму

Начнём с малого: только сумма цифр.

```c
#include <stdio.h>

int main(void)
{
    int n;
    printf("Введи целое число: ");
    scanf("%d", &n);

    int sum = 0;
    while (n > 0) {
        sum = sum + n % 10;   /* добавили последнюю цифру */
        n = n / 10;           /* отбросили её */
    }

    printf("Сумма цифр: %d\n", sum);
    return 0;
}
```

Разбор новых для главы мест (всё остальное — из глав 2–3):

- `int sum = 0;` — заводим «копилку» и обнуляем её. Очень важно
  стартовать с нуля: если оставить `sum` без значения, в ней будет
  мусор и сумма получится бессмысленной.
- `while (n > 0)` — крутим цикл, пока в числе ещё остались цифры. Как
  только `n` дошёл до 0 (все цифры откусили), условие станет ложным и
  цикл закончится.
- `sum = sum + n % 10;` — здесь важен **порядок операций**. `%` и `+`:
  сначала считается `n % 10` (последняя цифра), потом она прибавляется
  к `sum`. Скобки не нужны — `%` «сильнее» `+`, как умножение сильнее
  сложения в обычной математике.
- `n = n / 10;` — целочисленное деление (см. главу 2): дробная часть
  отбрасывается, число «укорачивается» на одну цифру справа.

Запустим с числом 12345:

```text
Введи целое число: 12345
Сумма цифр: 15
```

Работает. 1+2+3+4+5 = 15 — верно.

### Шаг 2. Проблема — где взять перевёрнутое число?

Нам нужна ещё и вторая величина — число задом наперёд. Заведём
переменную `reversed` и будем «пристраивать» к ней цифры по мере того,
как достаём.

Главный приём — вот эта строка:

```c
reversed = reversed * 10 + digit;
```

Как она собирает число? Каждый шаг мы сдвигаем то, что уже накопили,
на разряд влево (умножение на 10 дописывает справа ноль), а на
освободившееся место ставим новую цифру. Распишем для 12345:

```text
старт:           reversed = 0
цифра 5:  0*10 + 5  = 5
цифра 4:  5*10 + 4  = 54
цифра 3: 54*10 + 3  = 543
цифра 2: 543*10 + 2 = 5432
цифра 1: 5432*10 + 1 = 54321
```

Так из 0 постепенно вырастает 54321. Тот же приём (накопить число,
дописывая цифры справа) встретится тебе ещё много раз.

### Шаг 3. Проблема — последняя цифра тратится дважды

В наивной версии я писал `n % 10` дважды: один раз для суммы, другой
раз понадобится для переворота. Но между ними нельзя менять `n`!
Аккуратнее — посчитать `n % 10` **один раз**, положить в отдельную
переменную `digit`, и пользоваться ею:

```c
int digit = n % 10;          /* последняя цифра — один раз */
sum = sum + digit;
reversed = reversed * 10 + digit;
n = n / 10;                  /* и только теперь укорачиваем n */
```

Это и понятнее, и надёжнее: видно, что обе операции работают с одной и
той же цифрой, а укорачивание `n` происходит **после** них.

### Шаг 4. Краевые случаи — ноль и минус

Наивный цикл `while (n > 0)` спотыкается на двух входах.

**Ноль.** Если ввести 0, условие `n > 0` ложно сразу, цикл не сделает
ни шагу, и `sum`/`reversed` останутся нулями. Для нуля это как раз
правильный ответ (сумма цифр нуля — 0, переворот — 0), так что нам
повезло. Но держать этот случай в голове полезно.

**Отрицательное число.** Введи −90 — и `n > 0` тоже ложно сразу,
программа выдаст нули. Неверно: у −90 сумма цифр 9. Напрашивается
простой фикс — в начале взять модуль (отбросить знак):

```c
if (n < 0) {
    n = -n;   /* унарный минус: меняет знак на противоположный */
}
```

`-n` — это **унарный минус**: один операнд, меняет знак. Для −90 он
даст 90, и дальше всё работает как обычно. Знак мы при этом теряем — но
для суммы цифр и переворота он и не нужен.

И ещё мелочь: в цикле `n` испортится (мы же его делим), а напечатать
хочется исходное число. Поэтому до цикла сохраним копию в отдельную
переменную `original`.

### Шаг 5. Собираем наивную версию целиком и пробуем её сломать

Соберём всё, что придумали, в один файл. Назови его `naive.c` — этот
вариант мы сейчас будем ломать, поэтому в `code/` он не пойдёт:

```c
#include <stdio.h>

int main(void)
{
    int n;
    printf("Введи целое число: ");
    if (scanf("%d", &n) != 1) {
        printf("Это не число.\n");
        return 1;
    }

    if (n < 0) {
        n = -n;
    }
    int original = n;

    int sum = 0;
    int reversed = 0;
    while (n > 0) {
        int digit = n % 10;
        sum = sum + digit;
        reversed = reversed * 10 + digit;
        n = n / 10;
    }

    printf("Число:           %d\n", original);
    printf("Сумма цифр:      %d\n", sum);
    printf("Задом наперёд:   %d\n", reversed);
    return 0;
}
```

На 12345, 100 и 0 она отвечает верно, на −90 печатает сумму 9 и
переворот 9 (в строке «Число» показывает уже модуль, 90 — мелкая
неаккуратность, её мы тоже поправим). А теперь два злых входа, и оба
ломают именно `int`.

**Злой вход первый: 1000000009.** Само число в `int` влезает (меньше
2 147 483 647). А вот перевёрнутое — 9 000 000 001 — уже нет:

```text
Введи целое число: 1000000009
Число:           1000000009
Сумма цифр:      10
Задом наперёд:   410065409
```

Сумма цифр верная, а переворот — чушь. Вход помещался, результат уже
нет: перевёрнутое число бывает **больше** исходного, про это легко
забыть.

**Злой вход второй: −2147483648.** Это самое маленькое значение `int`.
У него внутри `int` нет модуля: 2147483648 там уже не помещается,
потолок — 2147483647. Значит, строка `n = -n;` физически не может дать
правильный ответ:

```text
Введи целое число: -2147483648
Число:           -2147483648
Сумма цифр:      47
Задом наперёд:   -126087180
```

Программа даже не напечатала модуль — «Число» осталось отрицательным,
хотя знак мы вроде бы поменяли.

Обе поломки — это **неопределённое поведение** (undefined behaviour,
сокращённо UB): по стандарту Си переполнение знакового целого не имеет
никакого предписанного результата. Компилятор вправе делать что угодно,
и с разной оптимизацией результат разный. Убедимся: соберём тот же
`naive.c` без оптимизации (`-O0`) и с ней (`-O2`) и сравним на входе
−2147483648:

```text
cc -std=c11 -Wall -Wextra -O0 naive.c -o naive-O0
cc -std=c11 -Wall -Wextra -O2 naive.c -o naive-O2
```

```text
-O0:  Сумма цифр: 0    Задом наперёд: 0
-O2:  Сумма цифр: 47   Задом наперёд: -126087180
```

Один и тот же исходник, один и тот же компилятор — два разных ответа.
Вот чем UB хуже обычного бага: он не воспроизводится стабильно, и на
твоей машине программа может «работать» ровно до того дня, когда её
пересоберут с другими флагами.

Ловить такие места глазами тяжело, поэтому есть инструмент —
**санитайзер неопределённого поведения** (UndefinedBehaviorSanitizer).
Он встроен в clang и gcc, включается одним флагом и во время работы
пишет в терминал, если программа сделала что-то запрещённое:

```text
cc -std=c11 -Wall -Wextra -O1 -fsanitize=undefined naive.c -o naive-ub
```

Запускаем на 1000000009 — и он не молчит:

```text
naive.c:22:29: runtime error: signed integer overflow: 900000000 * 10
cannot be represented in type 'int'
```

А на −2147483648:

```text
naive.c:13:13: runtime error: negation of -2147483648 cannot be
represented in type 'int'; cast to an unsigned type to negate this
value to itself
```

Санитайзер назвал файл, строку, столбец и суть проблемы: строка 22 —
это `reversed = reversed * 10 + digit;`, строка 13 — `n = -n;`. Возьми
за привычку: сомневаешься в программе — пересобери её с
`-fsanitize=undefined` и прогони ещё раз. Замедление в разы, зато
находятся вещи, которых не видно вообще никак.

### Шаг 6. Фикс — считаем в `long long`

Обе беды лечит одна и та же мысль: **считать в коробке побольше**.
Тип `long long` (мы подробно разберём его во второй части главы) — это
целое на 8 байт, оно вмещает примерно до 9·10^18. В нём и 2147483648, и
9000000001 помещаются свободно.

План такой:

- само введённое `n` не трогаем — оно нам нужно, чтобы честно
  напечатать, что ввёл пользователь;
- заводим рабочую копию `long long m = n;` и модуль берём уже у неё;
- `reversed` тоже делаем `long long`;
- а если перевёрнутое всё-таки не влезло бы в `int` — прямо говорим об
  этом читателю, а не делаем вид, что всё хорошо.

Чтобы сравнить с границей `int`, нам нужна сама эта граница. Она уже
записана в стандартном заголовке `<limits.h>` под именем `INT_MAX`.
Подключаем заголовок строкой `#include <limits.h>` рядом с
`<stdio.h>`, и дальше можно писать:

```c
if (reversed > INT_MAX) {
    printf("  (в int уже не влезает!)");
}
```

`INT_MAX` — константа «самое большое значение типа `int`», на
типичной машине 2147483647. Рядом живут `INT_MIN`, `LLONG_MAX` и
прочие. Пользоваться ими лучше, чем вбивать 2147483647 руками: на
другой машине размер типа может отличаться, а `INT_MAX` подстроится.

### Полная программа `04-digits.c`

```c
#include <stdio.h>
#include <limits.h>

int main(void)
{
    int n;
    printf("Введи целое число: ");
    if (scanf("%d", &n) != 1) {
        printf("Это не число.\n");
        return 1;
    }

    /* Работаем не с самим n, а с копией в long long. Две причины:
       1) -n для INT_MIN не влезает в int, а в long long влезает;
       2) перевёрнутое число бывает больше исходного и int переполняет. */
    long long m = n;
    if (m < 0) {
        m = -m;   /* берём модуль: знак цифрам не нужен */
    }

    int sum = 0;             /* сюда копим сумму цифр */
    long long reversed = 0;  /* сюда собираем перевёрнутое число */

    while (m > 0) {
        int digit = (int)(m % 10);         /* последняя цифра */
        sum = sum + digit;                 /* добавили к сумме */
        reversed = reversed * 10 + digit;  /* приклеили справа */
        m = m / 10;                        /* отбросили цифру */
    }

    printf("Число:           %d\n", n);
    printf("Сумма цифр:      %d\n", sum);
    printf("Задом наперёд:   %lld", reversed);
    if (reversed > INT_MAX) {
        printf("  (в int уже не влезает!)");
    }
    printf("\n");
    return 0;
}
```

Что тут стоит разобрать построчно:

- `if (scanf("%d", &n) != 1)` — `scanf` возвращает **число успешно
  прочитанных значений**. Мы просили одно (`%d`), значит при успехе он
  вернёт 1. Если пользователь ввёл буквы вместо цифр, вернётся не 1 — и
  мы вежливо выходим с `return 1`. По соглашению `return 0` из `main`
  значит «всё хорошо», а ненулевое — «была ошибка».
- `long long m = n;` — копируем `int` в `long long`. Такое присваивание
  всегда безопасно: маленькая коробка целиком влезает в большую.
- `int digit = (int)(m % 10);` — `m % 10` имеет тип `long long`, а нам
  нужна одна цифра, для неё `int` за глаза. Запись `(int)` — это
  **приведение типа** (cast): «возьми это значение и считай его `int`».
  Скобки обязательны. Без приведения компилятор с `-Wall -Wextra`
  промолчал бы, но написать явно — честнее: видно, что сужение
  осознанное и безопасное (цифра от 0 до 9).
- `%lld` в `printf` — спецификатор для `long long` (буквы `ll` от
  *long long*, `d` — десятичное). Для `int` был `%d`; перепутаешь —
  получишь мусор.
- последний `printf("\n")` отдельной строкой: мы печатаем перевод
  строки уже после того, как решили, добавлять примечание про `int` или
  нет.

Ноль отдельным `if` не обрабатываем: при `n = 0` цикл просто не
выполнится ни разу, `sum` и `reversed` останутся нулями — а это и есть
верный ответ.

### Проверяем

```text
cc -std=c11 -Wall -Wextra -O2 code/04-digits.c -o digits
./digits
```

Прогоним на всех входах, что нам встретились:

```text

Число:           12345
Сумма цифр:      15
Задом наперёд:   54321
```

```text

Число:           100
Сумма цифр:      1
Задом наперёд:   1
```

Обрати внимание на 100: задом наперёд получилось `1`, а не `001`.
Ведущие нули в числе не хранятся — `001` это просто `1`. Так и должно
быть, когда мы переворачиваем именно **число**, а не строку.

```text
Введи целое число: -90
Число:           -90
Сумма цифр:      9
Задом наперёд:   9
```

Введённое число печатаем как есть, со знаком, а цифры считаем по
модулю.

```text
Введи целое число: 1000000009
Число:           1000000009
Сумма цифр:      10
Задом наперёд:   9000000001  (в int уже не влезает!)
```

Вот теперь честно: 9000000001 — настоящий переворот, и программа сама
предупредила, что в `int` этот ответ не поместился бы.

```text
Введи целое число: -2147483648
Число:           -2147483648
Сумма цифр:      47
Задом наперёд:   8463847412  (в int уже не влезает!)
```

Самый злой вход тоже посчитан правильно (2+1+4+7+4+8+3+6+4+8 = 47).
И санитайзер на всех этих запусках теперь молчит — проверь сам:

```text
cc -std=c11 -Wall -Wextra -O1 -fsanitize=address,undefined \
   code/04-digits.c -o digits-san
echo 1000000009 | ./digits-san
```

Ни одной строчки `runtime error` — значит, запрещённых операций не
осталось.

## Часть 2. Факториал и ловушка переполнения

### Разбираем задачу руками

**Факториал** числа `n` (пишут `n!`) — это произведение всех целых от 1
до `n`:

```text
5! = 1 · 2 · 3 · 4 · 5 = 120
```

Отдельно: `0! = 1` (так договорились математики, и это удобно). А для
отрицательных факториал не определён вовсе.

Считать будем циклом: завести накопитель `fact = 1` и домножать его на
2, 3, …, `n`. Стартуем именно с 1, а не с 0 — ведь умножение на 0 всё
обнулит.

### Шаг 1. Наивная версия на `int`

```c
#include <stdio.h>

int main(void)
{
    int n;
    printf("Факториал какого числа? ");
    scanf("%d", &n);

    int fact = 1;
    for (int i = 2; i <= n; i++) {
        fact = fact * i;
    }

    printf("%d! = %d\n", n, fact);
    return 0;
}
```

Разбор:

- `int fact = 1;` — накопитель произведения, стартует с 1.
- `for (int i = 2; i <= n; i++)` — идём от 2 до `n` включительно
  (`<=`). С 2, а не с 1: умножать на 1 бессмысленно, результат не
  меняется. Если `n` равно 0 или 1, цикл не выполнится ни разу, и
  `fact` останется 1 — как раз правильный ответ для `0!` и `1!`.
- `fact = fact * i;` — домножаем накопитель на очередное число.

Проверим на 5 и 12:

```text
Факториал какого числа? 5
5! = 120
```

```text
Факториал какого числа? 12
12! = 479001600
```

Отлично. А теперь введём 13:

```text
Факториал какого числа? 13
13! = 1932053504
```

### Шаг 2. Проблема — это неправильный ответ!

13! на самом деле равно **6 227 020 800**, а программа выдала
1 932 053 504. Откуда мусор?

Вспомни из главы 2: `int` вмещает примерно от −2 до +2 миллиардов
(точнее, до 2 147 483 647). А 13! — больше шести миллиардов. Число **не
помещается** в коробку `int`. Это и есть **переполнение целого**
(integer overflow) — одна из самых коварных ошибок: программа выглядит
рабочей, а считает чушь.

Формально, как мы уже видели в первой части главы, переполнение
знакового целого — неопределённое поведение: стандарт не обещает
никакого конкретного числа. 1 932 053 504 — это то, что выдал вот этот
компилятор при вот этих флагах, а не «правило Си». На практике чаще
всего получается «обрезок» — младшие 32 бита настоящего произведения, —
но полагаться на это нельзя.

Доведём до абсурда — попросим 20!:

```text
Факториал какого числа? 20
20! = -2102132736
```

Факториал стал **отрицательным**! Произведение положительных чисел —
отрицательное. Так бывает, когда переполнение задевает знаковый бит.
Верный признак, что `int` лопнул.

### Шаг 3. Фикс — берём `long long`

Нужна коробка побольше. В Си для этого есть тип `long long` —
**целое увеличенной разрядности**, обычно 8 байт. Он вмещает примерно
до 9.2·10^18 (девять квинтиллионов) — на порядки больше, чем `int`.

```c
long long fact = 1;
```

Печатать `long long` нужно специальным спецификатором — `%lld`
(буквы `ll` — *long long*, `d` — десятичное). Если оставить `%d`,
компилятор с `-Wall` тут же на это укажет. Проверим на трёх строчках
(файл `lld.c`):

```c
#include <stdio.h>
int main(void)
{
    long long fact = 6227020800;
    printf("%d\n", fact);
    return 0;
}
```

```text
lld.c:5:20: warning: format specifies type 'int' but the argument has
type 'long long' [-Wformat]
    5 |     printf("%d\n", fact);
      |             ~~     ^~~~
      |             %lld
1 warning generated.
```

Компилятор даже подсказал внизу, чем `%d` заменить. И это не
придирка: если предупреждение проигнорировать, программа напечатает
`1932053504` вместо `6227020800` — те же младшие биты. Пишем как надо:

```c
printf("%d! = %lld\n", n, fact);
```

С `long long` 13! и 20! считаются правильно:

```text
Факториал какого числа? 13
13! = 6227020800
```

```text
Факториал какого числа? 20
20! = 2432902008176640000
```

### Шаг 4. Где именно ломается каждый тип

«13 много для `int`, 21 много для `long long`» — откуда эти числа?
Давай не поверим на слово, а посмотрим таблицу. Программа
`code/04-overflow.c` считает факториал в обоих типах, но перед каждым
умножением спрашивает себя: «а результат-то влезет?»

```c
if (int_ok && fact_int > INT_MAX / i) {
    int_ok = 0;   /* дальше в int считать нельзя */
}
```

Приём стоит запомнить. Мы хотим узнать, влезет ли `fact_int * i`, но
**не имеем права** это произведение вычислить: оно и будет тем самым
UB. Поэтому переносим `i` в другую часть неравенства: `fact * i` больше
`INT_MAX` ровно тогда, когда `fact` больше `INT_MAX / i`. Деление
целых никогда не переполняется, так что проверка безопасна. Так
проверяют переполнение всегда — **до** операции, а не после.

Запускаем:

```text
cc -std=c11 -Wall -Wextra -O2 code/04-overflow.c -o overflow
./overflow
```

### Шаг 5. Честная программа отказывается врать

Бесконечно растить тип не выйдет (для совсем больших чисел нужна
«длинная арифметика», это отдельная большая тема). Раз мы теперь знаем
границу точно — 20, — программа должна **сама** отказаться считать
дальше:

```c
if (n > 20) {
    printf("Слишком большое: даже long long переполнится при n > 20.\n");
    return 1;
}
```

И заодно отсечём отрицательный ввод, для которого факториал не
определён:

```c
if (n < 0) {
    printf("Факториал определён только для n >= 0.\n");
    return 1;
}
```

### Полная программа `04-factorial.c`

```c
#include <stdio.h>

int main(void)
{
    int n;
    printf("Факториал какого числа? ");
    if (scanf("%d", &n) != 1) {
        printf("Это не число.\n");
        return 1;
    }

    if (n < 0) {
        printf("Факториал определён только для n >= 0.\n");
        return 1;
    }

    if (n > 20) {
        printf("Слишком большое: даже long long переполнится при n > 20.\n");
        return 1;
    }

    long long fact = 1;   /* 1! = 1, и 0! = 1 — стартуем с единицы */
    for (int i = 2; i <= n; i++) {
        fact = fact * i;
    }

    printf("%d! = %lld\n", n, fact);
    return 0;
}
```

```text

```


```text

```


Запомни вывод из этой части: **прежде чем выбрать тип, прикинь, какие
числа в нём окажутся.** Маленький `int` для счётчика — нормально. Для
факториала, суммы больших величин, произведений — сразу думай про
`long long`.

## Часть 3. FizzBuzz

### Разбираем задачу руками

Классическая задачка с собеседований. Печатаем числа от 1 до 100, но:

- если число кратно 3 — вместо него пишем `Fizz`;
- если кратно 5 — пишем `Buzz`;
- если кратно **и** 3, и 5 (то есть кратно 15) — пишем `FizzBuzz`;
- иначе — само число.

Кратность мы уже умеем проверять: `i % 3 == 0`, `i % 5 == 0`. Вся
хитрость — в **порядке** проверок.

### Шаг 1. Наивная версия — и её баг

Напишем «в лоб», как читается условие:

```c
for (int i = 1; i <= 100; i++) {
    if (i % 3 == 0) {
        printf("Fizz\n");
    } else if (i % 5 == 0) {
        printf("Buzz\n");
    } else {
        printf("%d\n", i);
    }
}
```

Что выведет для 15? 15 кратно 3, значит сработает **первая** ветка —
напечатается `Fizz`. А мы хотели `FizzBuzz`! Случай «кратно и 3, и 5»
мы вообще не предусмотрели. Это и есть главная ловушка FizzBuzz, на
которой спотыкаются на собеседованиях.

### Шаг 2. Фикс — самую строгую проверку ставим первой

В цепочке `if / else if` ветки проверяются **сверху вниз**, и
срабатывает **первая** подходящая, остальные пропускаются. Значит самое
частное условие — «кратно 15» — должно идти **раньше** более общих
«кратно 3» и «кратно 5». Тогда 15 поймается до того, как дойдёт до них:

```c
if (i % 15 == 0) {
    printf("FizzBuzz\n");
} else if (i % 3 == 0) {
    printf("Fizz\n");
} else if (i % 5 == 0) {
    printf("Buzz\n");
} else {
    printf("%d\n", i);
}
```

Почему `i % 15`, а не `i % 3 == 0 && i % 5 == 0`? Это одно и то же:
число делится и на 3, и на 5 ровно тогда, когда делится на их
произведение 15. Можно писать любой из вариантов — `% 15` просто
короче.

### Полная программа `04-fizzbuzz.c`

```c
#include <stdio.h>

int main(void)
{
    for (int i = 1; i <= 100; i++) {
        if (i % 15 == 0) {
            printf("FizzBuzz\n");
        } else if (i % 3 == 0) {
            printf("Fizz\n");
        } else if (i % 5 == 0) {
            printf("Buzz\n");
        } else {
            printf("%d\n", i);
        }
    }
    return 0;
}
```

Эта программа ничего не вводит — поэтому `scanf` тут не нужен.

### Проверяем

```text

./fizzbuzz
```

Первые 16 строк:

```text

```

Видишь: 3, 6, 9, 12 → `Fizz`; 5, 10 → `Buzz`; а 15 → `FizzBuzz`, как и
задумано. Порядок проверок решил всё.

## Частые ошибки

**Накопитель не обнулён/не выставлен в 1.** Для суммы стартуй с
`sum = 0`, для произведения — с `fact = 1`. Перепутаешь — получишь
мусор или вечный ноль.

**`while (n > 0)` и отрицательный ввод.** Цикл откусывания цифр не
работает с минусом — сначала возьми модуль.

**`n = -n` для самого маленького `int`.** У `INT_MIN` (−2147483648)
модуля внутри `int` не существует, и унарный минус тут — неопределённое
поведение. Либо считай модуль в `long long`, как мы, либо явно
отсекай этот вход. Ловушка редкая, но именно из-за редкости она и
доживает до продакшена.

**Переполнение `int`.** Факториалы, произведения, суммы больших чисел
легко вылетают за 2 миллиарда. Признак — внезапно отрицательный или
явно неправильный результат. Лечится переходом на `long long` (и не
забудь `%lld` в `printf`).

**Результат больше входа.** Перевёрнутое число, произведение, сумма —
всё это может не влезть в тип, в который прекрасно влезали исходные
данные. Прикидывай размер **результата**, а не аргументов.

**Проверка переполнения «постфактум».** Написать `if (fact * i < 0)`
после умножения — плохая идея: само умножение уже совершило UB, и
компилятор вправе выкинуть проверку целиком (он ведь «знает», что
произведение положительных не бывает отрицательным). Проверяй до:
`if (fact > INT_MAX / i)`.

**`%d` вместо `%lld` для `long long`.** Спецификатор и тип должны
совпадать, иначе мусор. Компилятор с `-Wall` предупредит — не игнорируй.

**Неверный порядок в FizzBuzz.** Если «кратно 3» проверяется раньше
«кратно 15», числа вроде 15 и 30 получат `Fizz` вместо `FizzBuzz`.
Самое строгое условие — первым.

**Деление и остаток от нуля.** `n % 0` и `n / 0` — это ошибка времени
выполнения (программа упадёт). В наших программах делитель всегда 10,
3, 5, 15 — не ноль, так что мы в безопасности. Но если делитель
приходит от пользователя — проверяй его на ноль.

## Упражнения

1. Подсчёт цифр. Измени `04-digits.c` так, чтобы он ещё печатал,
   **сколько** цифр в числе (заведи счётчик и увеличивай его на каждом
   шаге цикла). Подсказка: у нуля цикл не крутится ни разу, а цифра в
   нём одна — не забудь про этот случай.
2. Палиндром. Число-палиндром читается одинаково в обе стороны
   (121, 1331). Используя готовый переворот, проверь: если `reversed`
   равен модулю введённого числа, печатай «палиндром». Подсказка:
   сравнивать надо `long long` с `long long`, поэтому модуль тоже
   придётся где-то сохранить.
3. Сумма от 1 до n. Напиши функцию `long long sum_to(int n)`,
   возвращающую сумму всех чисел от 1 до `n` циклом. Прогони её на
   `n = 100000` и посчитай ту же сумму формулой `n * (n + 1) / 2` в
   `int` — сравни результаты и объясни разницу.
4. Степень. Напиши `long long power(int base, int exp)`, считающую
   `base` в степени `exp` циклом (накопитель стартует с 1, домножаем
   `exp` раз). Добавь проверку «до умножения» из шага 4 и найди, при
   каком `exp` ломается `power(2, exp)` и при каком — `power(3, exp)`.
5. FizzBuzz по-своему. Спроси у пользователя два делителя (вместо
   жёстких 3 и 5) и два слова, и сделай настраиваемый FizzBuzz от 1 до
   100. Не забудь проверить, что делители не равны нулю.
6. Сумма чётных цифр. Переделай сумму цифр так, чтобы она складывала
   только **чётные** цифры числа (подсказка: внутри цикла добавь
   `if (digit % 2 == 0)`).
7. Санитайзер в деле. Возьми `naive.c` из шага 5, собери его с
   `-fsanitize=undefined` и подбери ещё один вход, на котором
   санитайзер ругнётся. Подсказка: любое число, у которого переворот
   переваливает за 2 147 483 647, — например, начинающееся с
   единицы и заканчивающееся большой цифрой.

## Что мы получили

Четыре рабочие программы — и, что важнее, чувство двух операторов, `%`
и `/`, которыми разбирают числа на части. Ты увидел, как «откусывать»
цифры с конца (`n % 10` и `n / 10`), как собирать число обратно
(`r = r*10 + digit`), как копить сумму и произведение, и как порядок
веток `if / else if` меняет результат (FizzBuzz).

А ещё ты трижды столкнулся с переполнением вживую — в перевороте, в
модуле `INT_MIN` и в факториале — и получил к нему три инструмента:
таблицу границ (`04-overflow.c`), проверку «до операции»
(`fact > INT_MAX / i`) и санитайзер `-fsanitize=undefined`, который
находит то, что глазами не видно. Этот урок будет возвращаться всю
книгу.

В следующей главе останемся в мире чисел, но копнём в теорию чисел:
найдём **наибольший общий делитель** двух чисел алгоритмом Евклида (тем
самым `%`, только хитрее) и научимся проверять, **простое** ли число.
Это первые алгоритмы, у которых есть имя и история.

Итоговые программы главы — `code/04-digits.c`, `code/04-factorial.c`,
`code/04-overflow.c` и `code/04-fizzbuzz.c`.
