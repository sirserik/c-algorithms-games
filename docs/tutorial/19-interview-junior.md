# Приложение A. Задачи с собеседований: Junior

Книга закончилась, а собеседования только начинаются. Это приложение —
сборник задач, которые реально дают на собеседовании C-разработчику
уровня **Junior** (младший, начинающий). Здесь нет ничего, чего ты не
проходил: всё опирается на главы 1–18 — числа, массивы, строки,
указатели, циклы, функции. Новой теории не будет. Будет другое — взгляд
на знакомые приёмы глазами интервьюера.

Зачем это нужно. На собесе мало написать работающий код. Спрашивающий
смотрит, **как ты думаешь**: учёл ли краевые случаи, помнишь ли про
переполнение, понимаешь ли, что делает каждая строка. Поэтому к каждой
задаче я добавил блок «что спросят дальше» — те самые уточняющие
вопросы, которыми тебя будут «дожимать».

## Как пользоваться

Каждая задача оформлена так:

- **Условие** — как её формулируют вслух на собесе.
- **Идея** — как к ней подступиться, без кода.
- **Решение** — рабочий код.
- **Разбор** — почему так, а не иначе.
- **Что спросят дальше** — продолжения и подвохи.

Главный совет: **сначала реши сам**, на бумаге или в редакторе, и только
потом смотри решение. Подсмотренное решение забывается к утру.
Решённое самому — остаётся. Даже если решил криво — сравни с моим
вариантом, и разница тебе многое объяснит.

Раздел делится на две части. Сначала **задачи на код** — где надо
что-то написать. Потом блок **каверз** «что выведет / в чём ошибка» —
короткие фрагменты, на которых проверяют, насколько ты внимателен к
деталям языка.

Рабочие решения лежат в `code/19-XX-*.c` — их можно собрать и запустить.
Каверзы намеренно содержат ошибки или неопределённое поведение, поэтому
в файлы они не вынесены: разбираем их прямо здесь.

# Часть 1. Задачи на код

## Задача 1. Поменять местами две переменные

**Условие.** Есть две переменные `a` и `b`. Поменяй их значения
местами. После обмена в `a` должно лежать то, что было в `b`, и наоборот.

**Идея.** Наивная попытка «в лоб» не работает:

```c
a = b;   /* старое значение a потеряно навсегда */
b = a;   /* сюда попадёт b, а не старое a */
```

Первая же строка затирает `a`. Нужна **временная переменная**, чтобы
запомнить значение перед затиранием.

**Решение** (`code/19-01-swap.c`):

```c
#include <stdio.h>

int main(void)
{
    int a = 5;
    int b = 9;

    printf("До:    a = %d, b = %d\n", a, b);

    int temp = a;   /* запомнили a */
    a = b;          /* в a положили b */
    b = temp;       /* в b положили старое a */

    printf("После: a = %d, b = %d\n", a, b);
    return 0;
}
```

Запуск:

```text
До:    a = 5, b = 9
После: a = 9, b = 5
```

**Разбор.** `temp` хранит копию `a`, пока мы перезаписываем `a`
значением `b`. Потом достаём из `temp` старое `a` и кладём в `b`. Три
строки, всё прозрачно.

**Что спросят дальше.** «А можно без временной переменной?» Да, два
способа.

Через арифметику:

```c
a = a + b;
b = a - b;   /* = старое a */
a = a - b;   /* = старое b */
```

Через XOR (исключающее «или», оператор `^`):

```c
a = a ^ b;
b = a ^ b;
a = a ^ b;
```

Оба выглядят эффектно, и интервьюер любит про них спросить. Но честный
ответ — **в реальном коде так делать не надо**. Почему:

- Арифметический способ **переполняется**: если `a + b` вылезет за
  пределы `int`, получишь мусор (см. главу 4 про переполнение).
- XOR-своп ломается, если `a` и `b` — **одна и та же переменная** (один
  адрес): `x ^ x` даёт 0, и значение теряется. Для `swap(&x, &x)` это
  реальная ловушка.
- Оба варианта **нечитаемы** и не быстрее: современный компилятор и так
  оптимально реализует обмен через `temp`.

Правильный вывод, который хочет услышать грамотный интервьюер: «знаю про
XOR-трюк, но в продакшене пишу через `temp` — понятнее и без подвохов».

## Задача 2. Проверить чётность числа

**Условие.** Дано целое число. Определи, чётное оно или нечётное.

**Идея.** Школьный способ — остаток от деления: `n % 2 == 0` (см. главу
4). Но на собесе часто хотят увидеть **битовый** приём: у чётного числа
младший бит равен 0, у нечётного — 1. Проверить младший бит можно
операцией `&` (побитовое «И») с единицей.

**Решение:**

```c
#include <stdio.h>

int main(void)
{
    int n = 7;

    if (n & 1) {
        printf("%d — нечётное\n", n);
    } else {
        printf("%d — чётное\n", n);
    }
    return 0;
}
```

**Разбор.** `n & 1` сравнивает биты `n` и числа 1 по позициям. У единицы
выставлен только самый младший бит. Поэтому `n & 1` оставляет от `n`
ровно этот младший бит: 1 у нечётных, 0 у чётных. В `if` ненулевое — это
истина (см. главу 2), так что `if (n & 1)` срабатывает на нечётных.

**Что спросят дальше.** «Чем `n & 1` лучше `n % 2`?» Для положительных
чисел — ничем существенным, оба корректны и одинаково быстры. Но есть
тонкость с **отрицательными**: в C `-7 % 2` даёт `-1` (мы это проверим в
каверзах), поэтому проверка `n % 2 == 1` для отрицательных нечётных
**не сработает** — там получится `-1`, а не `1`. Безопаснее писать
`n % 2 != 0`. А `n & 1` на типичной машине даёт правильный младший бит и
для отрицательных. Это хороший момент показать, что ты знаешь про знак.

## Задача 3. Максимум и минимум массива

**Условие.** Дан массив целых. Найди наибольший и наименьший элементы за
один проход.

**Идея.** Заводим `max` и `min`, инициализируем их **первым элементом**
массива (не нулём! см. подвох ниже) и идём по остальным, обновляя.

**Решение:**

```c
#include <stdio.h>

int main(void)
{
    int a[] = {4, -2, 9, 1, 7, -8, 3};
    int n = (int)(sizeof(a) / sizeof(a[0]));

    int max = a[0];
    int min = a[0];
    for (int i = 1; i < n; i++) {
        if (a[i] > max) {
            max = a[i];
        }
        if (a[i] < min) {
            min = a[i];
        }
    }

    printf("min = %d, max = %d\n", min, max);
    return 0;
}
```

**Разбор.** `sizeof(a) / sizeof(a[0])` — это размер всего массива в
байтах, делённый на размер одного элемента, то есть **число элементов**.
Приём работает только пока `a` — настоящий массив, а не указатель (см.
ниже). Цикл стартует с `i = 1`, потому что нулевой элемент уже лежит в
`max` и `min`.

**Что спросят дальше.**

- «Почему инициализируешь первым элементом, а не нулём?» Если поставить
  `max = 0`, а все числа в массиве отрицательные — максимумом ошибочно
  останется 0, которого в массиве нет. То же с `min` и положительными.
  Безопасно стартовать значением **из самого массива**.
- «А если передать массив в функцию и там взять `sizeof`?» Не сработает!
  В функции параметр-массив превращается в **указатель**, и `sizeof`
  вернёт размер указателя (8 байт), а не массива. Поэтому длину всегда
  передают **отдельным параметром**: `void f(int *a, int n)`. Это
  классический подвох (см. главу 3 про указатели и каверзу про `sizeof`
  ниже).

## Задача 4. Развернуть строку на месте

**Условие.** Дана строка. Переверни её **на месте** — без создания
второго массива.

**Идея.** Два указателя-индекса: один на начало (`left`), другой на
конец (`right`). Меняем символы местами и идём навстречу, пока они не
встретятся посередине.

**Решение** (`code/19-02-reverse-string.c`):

```c
#include <stdio.h>
#include <string.h>

/* Переворачивает строку на месте, без второго массива. */
void reverse(char *s)
{
    int left = 0;
    int right = (int)strlen(s) - 1;
    while (left < right) {
        char tmp = s[left];
        s[left] = s[right];
        s[right] = tmp;
        left++;
        right--;
    }
}

int main(void)
{
    char text[] = "Hello, world";
    reverse(text);
    printf("%s\n", text);
    return 0;
}
```

Запуск:

```text
dlrow ,olleH
```

**Разбор.** `strlen(s)` — длина строки без учёта завершающего нуля
`'\0'` (см. главу 10). Последний символ имеет индекс `strlen(s) - 1`.
Внутри цикла — обычный обмен через `tmp` (как в задаче 1). Условие
`left < right` останавливает нас на середине: средний символ при
нечётной длине трогать не нужно.

**Что спросят дальше.**

- «Почему `char text[] = "..."`, а не `char *text = "..."`?» Строковый
  литерал через указатель (`char *`) — это, как правило,
  **read-only** память; попытка её менять — неопределённое поведение и
  падение. Массив `char text[]` — это твоя изменяемая копия. Менять
  можно только её. Это важная деталь (см. каверзу про литералы ниже).
- «Сложность?» O(n) по времени, O(1) по дополнительной памяти — мы не
  выделяли новый буфер, переставляли на месте.

## Задача 5. Проверка палиндрома

**Условие.** Палиндром читается одинаково слева направо и справа налево
(`level`, `radar`). Проверь, палиндром ли данная строка.

**Идея.** Та же пара указателей с краёв, но теперь не меняем символы, а
**сравниваем**. Нашли несовпадение — сразу не палиндром.

**Решение** (`code/19-03-palindrome.c`):

```c
#include <stdio.h>
#include <string.h>

/* Возвращает 1, если строка — палиндром, иначе 0. */
int is_palindrome(const char *s)
{
    int left = 0;
    int right = (int)strlen(s) - 1;
    while (left < right) {
        if (s[left] != s[right]) {
            return 0;   /* нашли несовпадение — это не палиндром */
        }
        left++;
        right--;
    }
    return 1;
}

int main(void)
{
    const char *words[] = {"level", "radar", "hello", "noon"};
    for (int i = 0; i < 4; i++) {
        if (is_palindrome(words[i])) {
            printf("%s — палиндром\n", words[i]);
        } else {
            printf("%s — нет\n", words[i]);
        }
    }
    return 0;
}
```

Запуск:

```text
level — палиндром
radar — палиндром
hello — нет
noon — палиндром
```

**Разбор.** Параметр `const char *s` — обещание «эту строку я менять не
буду», только читаю. Поэтому функция спокойно принимает строковые
литералы. Выход `return 0` при первом же несовпадении — это
**ранний выход**: нет смысла проверять дальше, ответ уже ясен.

**Что спросят дальше.**

- «Сделай регистронезависимо: `Level` тоже палиндром.» Сравнивай не
  `s[left]` и `s[right]`, а их версии в одном регистре (приём приведения
  к нижнему регистру — в задаче 8 про гласные).
- «А если игнорировать пробелы и знаки: `A man a plan a canal Panama`?»
  Тогда указатели нужно «перепрыгивать» через не-буквы. Часто это и есть
  настоящая задача за вывеской простого палиндрома.

## Задача 6. Сколько цифр в числе

**Условие.** Дано целое число. Посчитай, сколько в нём цифр (123 → 3).

**Идея.** Делим число на 10 нацело, пока оно не станет нулём, и считаем
число шагов (см. главу 4 — «откусывание» цифр).

**Решение.** Подсчёт цифр объединён с суммой цифр в одном файле
`code/19-08-digits.c` — см. задачу 7. Ядро подсчёта:

```c
int count = 0;
if (n == 0) {
    count = 1;   /* у нуля одна цифра */
}
while (n > 0) {
    count++;
    n /= 10;     /* то же, что n = n / 10 */
}
```

**Разбор.** Каждое деление на 10 убирает одну цифру справа, и так до
нуля. Отдельный случай — само число **0**: цикл `while (n > 0)` для него
не выполнится ни разу, а ответ должен быть 1 (одна цифра). Поэтому ноль
обрабатываем вручную.

**Что спросят дальше.** «А отрицательные?» У −123 три цифры, минус не
считается. Возьми модуль в начале: `if (n < 0) n = -n;`. И сразу
подвох: `-n` для самого маленького `int` (`INT_MIN`) переполнится —
у него нет положительной пары. На Junior это редко спрашивают, но
упомянуть — большой плюс.

## Задача 7. Сумма цифр числа

**Условие.** Посчитай сумму цифр числа (456 → 4+5+6 = 15).

**Идея.** То же «откусывание», но вместо счётчика копим сумму остатков
`n % 10`.

**Решение** (`code/19-08-digits.c` — считает и количество, и сумму):

```c
#include <stdio.h>

int main(void)
{
    int n;
    printf("Введи целое число: ");
    if (scanf("%d", &n) != 1) {
        printf("Это не число.\n");
        return 1;
    }

    if (n < 0) {
        n = -n;   /* знак на количество и сумму цифр не влияет */
    }

    int count = 0;   /* сколько цифр */
    int sum = 0;     /* сумма цифр */

    if (n == 0) {
        count = 1;   /* у нуля одна цифра */
    }
    while (n > 0) {
        int digit = n % 10;
        sum += digit;
        count++;
        n /= 10;
    }

    printf("Цифр: %d, сумма цифр: %d\n", count, sum);
    return 0;
}
```

Запуск:

```text
Введи целое число: 90834
Цифр: 5, сумма цифр: 24
```

**Разбор.** `n % 10` — последняя цифра, `n /= 10` — отбрасываем её.
`digit` вычисляем **один раз** и используем для суммы, чтобы не
повторять `n % 10` (см. главу 4, шаг 3). `count` и `sum` стартуют с 0:
сумма копится с нуля, как и положено накопителю.

**Что спросят дальше.** «Цифровой корень: складывай сумму цифр, пока не
останется одна цифра (9875 → 29 → 11 → 2).» Это сумма цифр в цикле
поверх цикла — частое продолжение.

## Задача 8. Подсчёт гласных в строке

**Условие.** Посчитай, сколько гласных букв в строке (английские
a, e, i, o, u в любом регистре).

**Идея.** Идём по строке посимвольно до `'\0'`. Для каждого символа
проверяем, не гласная ли он. Чтобы не плодить проверки для верхнего и
нижнего регистра, приводим символ к нижнему.

**Решение** (`code/19-06-vowels.c`):

```c
#include <stdio.h>
#include <string.h>

/* Возвращает 1, если c — английская гласная (любого регистра). */
int is_vowel(char c)
{
    char lower = c;
    if (c >= 'A' && c <= 'Z') {
        lower = (char)(c - 'A' + 'a');   /* привели к нижнему регистру */
    }
    return lower == 'a' || lower == 'e' || lower == 'i'
        || lower == 'o' || lower == 'u';
}

int main(void)
{
    const char *s = "Programming In C";
    int count = 0;
    for (int i = 0; s[i] != '\0'; i++) {
        if (is_vowel(s[i])) {
            count++;
        }
    }
    printf("В строке \"%s\" гласных: %d\n", s, count);
    return 0;
}
```

Запуск:

```text
В строке "Programming In C" гласных: 4
```

**Разбор.** Трюк `c - 'A' + 'a'` переводит заглавную букву в строчную.
Символы в C — это коды (см. главу 2): буквы `A..Z` идут подряд, и `a..z`
тоже. Разница между заглавной и строчной одной буквы постоянна
(`'a' - 'A'`), поэтому сдвиг работает. Условие цикла `s[i] != '\0'` —
канонический способ пройти строку до завершающего нуля.

**Что спросят дальше.**

- «А `<ctype.h>`?» В стандартной библиотеке есть `tolower()` — он делает
  ровно наш сдвиг и работает с любой локалью. На собесе ценят, когда ты
  знаешь про готовое, но умеешь и руками.
- «Учитывай 'y' / русские гласные» — расширение списка, проверка
  внимательности.

## Задача 9. Факториал итеративно

**Условие.** Посчитай факториал числа `n` циклом (без рекурсии).
`n! = 1·2·…·n`, при этом `0! = 1`.

**Идея.** Накопитель `fact = 1`, домножаем на 2, 3, …, n. Стартовое
значение — **единица**, а не ноль (умножение на 0 всё обнулит). И сразу
помним про переполнение из главы 4.

**Решение** (`code/19-04-factorial.c`):

```c
#include <stdio.h>

int main(void)
{
    int n;
    printf("Факториал какого числа? ");
    if (scanf("%d", &n) != 1) {
        printf("Это не число.\n");
        return 1;
    }

    if (n < 0) {
        printf("Факториал определён только для n >= 0.\n");
        return 1;
    }
    if (n > 20) {
        printf("Слишком большое: long long переполнится при n > 20.\n");
        return 1;
    }

    long long fact = 1;   /* 0! = 1 и 1! = 1 — стартуем с единицы */
    for (int i = 2; i <= n; i++) {
        fact = fact * i;
    }

    printf("%d! = %lld\n", n, fact);
    return 0;
}
```

Запуск:

```text
Факториал какого числа? 13
13! = 6227020800
```

**Разбор.** Тип накопителя — `long long` (8 байт), потому что `int`
лопается уже на 13! (см. главу 4). Печатаем через `%lld`. Цикл идёт с 2
(умножать на 1 бессмысленно); для `n = 0` и `n = 1` он не выполнится, и
`fact` останется 1 — верный ответ.

**Что спросят дальше.**

- «До какого `n` это корректно?» До 20: 20! ≈ 2.4·10^18 ещё помещается в
  `long long`, а 21! — уже нет. Поэтому мы заранее отсекаем `n > 20`.
  Грамотный кандидат **сам** проговаривает границу типа.
- «А рекурсией?» Можно (см. главу 9), но итеративно — без риска
  переполнить стек вызовов на больших `n` и обычно быстрее.

## Задача 10. FizzBuzz

**Условие.** Числа от 1 до 100. Кратные 3 заменяй на `Fizz`, кратные 5 —
на `Buzz`, кратные и 3, и 5 — на `FizzBuzz`, остальные печатай как есть.

**Идея.** Вся соль — в **порядке** проверок. Самое строгое условие
(кратно 15) должно идти первым, иначе число 15 поймается веткой «кратно
3» и выдаст `Fizz` вместо `FizzBuzz` (полный разбор — в главе 4).

**Решение** (готовый файл — `code/04-fizzbuzz.c` из главы 4):

```c
#include <stdio.h>

int main(void)
{
    for (int i = 1; i <= 100; i++) {
        if (i % 15 == 0) {
            printf("FizzBuzz\n");
        } else if (i % 3 == 0) {
            printf("Fizz\n");
        } else if (i % 5 == 0) {
            printf("Buzz\n");
        } else {
            printf("%d\n", i);
        }
    }
    return 0;
}
```

**Разбор.** В цепочке `if / else if` срабатывает **первая** подходящая
ветка. Поэтому «кратно 15» (то же, что «кратно и 3, и 5») ставим раньше
«кратно 3» и «кратно 5».

**Что спросят дальше.** «Сделай без `% 15`, только через `% 3` и `% 5`.»
Собери строку из флагов:

```c
int by3 = (i % 3 == 0);
int by5 = (i % 5 == 0);
if (by3) printf("Fizz");
if (by5) printf("Buzz");
if (!by3 && !by5) printf("%d", i);
printf("\n");
```

Этот вариант легко расширяется (добавить «кратно 7 → Bazz»), и
интервьюер часто просит именно его — проверить, что ты не зубрил, а
понимаешь структуру.

## Задача 11. Второй по величине элемент массива

**Условие.** Найди второй по величине элемент массива за **один** проход
(не сортируя).

**Идея.** Держим две переменные: `max` (наибольший) и `second`
(второй). Для каждого числа: если оно больше `max` — старый `max`
становится `second`, а само число — новым `max`. Иначе, если оно меньше
`max`, но больше `second` — обновляем `second`. Дубликаты максимума
вторым считать не должны.

**Решение** (`code/19-05-secondmax.c`):

```c
#include <stdio.h>
#include <limits.h>

int main(void)
{
    int a[] = {3, 9, 9, 1, 7, 9, 4};
    int n = (int)(sizeof(a) / sizeof(a[0]));

    int max = INT_MIN;     /* самое большое */
    int second = INT_MIN;  /* второе по величине */

    for (int i = 0; i < n; i++) {
        if (a[i] > max) {
            second = max;  /* бывший максимум становится вторым */
            max = a[i];
        } else if (a[i] > second && a[i] < max) {
            second = a[i]; /* не максимум, но больше второго */
        }
    }

    if (second == INT_MIN) {
        printf("Второго по величине нет.\n");
    } else {
        printf("Максимум: %d, второй: %d\n", max, second);
    }
    return 0;
}
```

Запуск:

```text
Максимум: 9, второй: 7
```

**Разбор.** `INT_MIN` из `<limits.h>` — самое маленькое значение `int`.
Стартуем с него, чтобы любой реальный элемент оказался больше. Массив
`{3, 9, 9, 1, 7, 9, 4}` содержит максимум 9 трижды, но вторым выводится
7, а не 9 — условие `a[i] < max` отсекает дубликаты максимума. Это
именно тот случай, который любят подсунуть.

**Что спросят дальше.**

- «Что если в массиве все элементы одинаковы (`{5,5,5}`)?» Тогда второго
  по величине нет — наш код напечатает «Второго нет», потому что
  `second` так и остался `INT_MIN`. Уточни у интервьюера, считать ли
  дубликат вторым: трактовки бывают разные, и важно проговорить выбор.
- «А k-й по величине?» Обобщение — там уже нужна частичная сортировка
  или куча (heap). Это уже уровень Middle.

## Задача 12. Проверка на простое число

**Условие.** Дано число `n`. Определи, простое ли оно (делится только на
1 и на себя; 0, 1 и отрицательные — не простые).

**Идея.** Перебираем возможные делители от 2. Нашли хоть один — число
составное. Ключевая оптимизация: проверять делители только **до корня**
из `n`, потому что делители идут парами (`n = d · (n/d)`), и меньший из
пары всегда не больше √n.

**Решение** (`code/19-07-prime.c`):

```c
#include <stdio.h>

/* Возвращает 1, если n — простое число, иначе 0. */
int is_prime(int n)
{
    if (n < 2) {
        return 0;             /* 0, 1 и отрицательные — не простые */
    }
    for (int d = 2; d * d <= n; d++) {
        if (n % d == 0) {
            return 0;         /* нашли делитель — составное */
        }
    }
    return 1;
}

int main(void)
{
    int n;
    printf("Введи число: ");
    if (scanf("%d", &n) != 1) {
        printf("Это не число.\n");
        return 1;
    }

    if (is_prime(n)) {
        printf("%d — простое\n", n);
    } else {
        printf("%d — не простое\n", n);
    }
    return 0;
}
```

Запуск:

```text
Введи число: 17
17 — простое
```

**Разбор.** Условие цикла `d * d <= n` вместо `d <= n` — это и есть
«до корня»: вместо `sqrt()` сравниваем квадрат делителя с числом, без
дробной арифметики. Для n = 1 000 000 это ~1000 проверок вместо
миллиона. Случаи `n < 2` отсекаем сразу — иначе единица ошибочно сошла
бы за простую.

**Что спросят дальше.**

- «Почему `d * d <= n`, а не `d <= sqrt(n)`?» Чтобы не звать `sqrt`
  (дробная функция, возможны погрешности на границе) и не подключать
  `<math.h>`. Целочисленное сравнение точнее и быстрее. Осторожно: для
  очень больших `n` `d * d` само может переполниться — тогда берут
  `long long` или сравнивают `d <= n / d`.
- «Ускорь ещё.» Проверять 2 отдельно, а дальше только нечётные делители
  (`d += 2`) — вдвое меньше итераций.
- «Все простые до N?» Это уже **решето Эратосфена** (см. главу 5) —
  частый следующий шаг.

# Часть 2. Каверзы: «что выведет / в чём ошибка»

Здесь короткие фрагменты. На собесе их показывают и спрашивают: «что
напечатает?» или «найди ошибку». Цель — не код написать, а проверить,
насколько хорошо ты знаешь язык в деталях. Сначала подумай сам, потом
читай ответ.

## Каверза 1. `sizeof('a')` — сколько это?

```c
printf("%zu %zu\n", sizeof(int), sizeof('a'));
```

**Вопрос.** Что выведет? Подсказка-ловушка: `'a'` — это же один символ,
значит 1 байт?

**Ответ.** Выведет `4 4` (на типичной системе). Сюрприз в том, что в
языке **C** символьный литерал `'a'` имеет тип не `char`, а **`int`**!
Поэтому `sizeof('a')` равен `sizeof(int)`, то есть 4, а не 1.

Важно: это особенность именно C. В C++ `'a'` — это `char`, и там
`sizeof('a')` равно 1. На собесе по C правильный ответ — 4.

А вот `sizeof(char)` по стандарту **всегда** равен 1 — это и есть тот
самый «единица измерения» для `sizeof`.

`%zu` — спецификатор для типа `size_t`, который возвращает `sizeof`
(беззнаковый размер). Печатать его через `%d` формально неверно.

## Каверза 2. Целочисленное деление `5 / 2`

```c
printf("%d\n", 5 / 2);
double x = 5 / 2;
printf("%f\n", x);
```

**Вопрос.** Что в обеих строках?

**Ответ.** Первая печатает `2` — деление двух **целых** идёт нацело,
дробная часть отбрасывается (см. главу 2), не округляется. `5 / 2` это
2, а не 2.5 и не 3.

Вторая печатает `2.000000`, а **не** 2.5, и это главный подвох. Хотя
`x` объявлен как `double`, выражение `5 / 2` считается **до** записи в
`x`: оба операнда целые → целочисленное деление → 2 → и уже 2
превращается в `2.0`. Тип переменной слева не влияет на то, как
вычисляется правая часть.

Чтобы получить 2.5, дробным должен быть хотя бы один операнд:
`5.0 / 2`, или `(double)5 / 2`, или `5 / 2.0`.

## Каверза 3. `printf("%d", c)` для `char`

```c
char c = 'A';
printf("%d\n", c);
```

**Вопрос.** Что выведет?

**Ответ.** Выведет `65`. Символ в C — это маленькое целое, его **код**.
Код буквы `A` в таблице ASCII равен 65. Спецификатор `%d` просит напечатать
число, поэтому печатается не сама буква, а её код. Если хочешь увидеть
букву `A` — используй `%c`.

И наоборот полезно помнить: `printf("%c\n", 66)` напечатает `B` — число
истолкуется как код символа. На этой двойственности (символ = число)
держатся трюки вроде перевода регистра из задачи 8.

## Каверза 4. `=` вместо `==` в условии

```c
int n = 5;
if (n = 0) {
    printf("ноль\n");
} else {
    printf("не ноль\n");
}
```

**Вопрос.** Что выведет?

**Ответ.** Выведет `не ноль`, и при этом **испортит** `n`. Здесь стоит
один `=` (присваивание), а не `==` (сравнение). Поэтому `n = 0` сначала
**кладёт** 0 в `n`, а потом результатом всего выражения становится само
присвоенное значение — 0. Ноль в условии — это «ложь», поэтому
срабатывает ветка `else`. Заодно `n` теперь равно 0, хотя мы вроде бы
только «проверяли».

Если бы было `if (n = 5)`, условие стало бы истинным (5 — ненулевое), и
такие баги особенно коварны: код «как будто работает». Спасает
компилятор с `-Wall` — он предупреждает о присваивании внутри `if`.
Защитный приём — «йода-условие»: писать `if (0 == n)`; тогда опечатку
`0 = n` компилятор отвергнет как ошибку (нельзя присвоить константе).

## Каверза 5. Лишняя `;` после `for(...)`

```c
int sum = 0;
for (int i = 1; i <= 5; i++);
{
    sum += i;
}
printf("%d\n", sum);
```

**Вопрос.** Найди ошибку. Что не так?

**Ответ.** Лишняя точка с запятой сразу после `for(...)`. Эта `;` —
**пустое тело цикла**. То есть цикл крутится 5 раз и ничего не делает.
А блок в фигурных скобках ниже — это уже **обычный блок**, не связанный
с циклом; он выполнится **один раз**.

Хуже того: этот фрагмент вообще не скомпилируется — `i` объявлена внутри
`for` и за его пределами не видна, так что `sum += i;` обратится к
неизвестному имени. Но даже если бы `i` была видна, логика была бы
сломана. Мораль: точка с запятой сразу после `for`, `while` или `if` —
почти всегда ошибка. Компилятор с `-Wall` предупреждает об «empty body».

## Каверза 6. `printf("%d %d", i++, ++i)`

```c
int i = 1;
printf("%d %d\n", i++, ++i);
```

**Вопрос.** Что выведет?

**Ответ.** Честный ответ: **неизвестно**. Это **неопределённое поведение**
(undefined behavior, UB). В одном выражении переменная `i` и читается, и
дважды меняется (`i++` и `++i`) без гарантированного порядка между этими
изменениями. Стандарт C не определяет, в каком порядке вычисляются
аргументы `printf` и когда применяются `++`. Разные компиляторы выдадут
разные числа, и **полагаться нельзя ни на одно из них**.

Если на собесе спрашивают «что выведет» — правильный ответ не «2 3» и не
«1 3», а именно: «это UB, результат не определён, так писать нельзя».
Интервьюер проверяет, узнаёшь ли ты опасную конструкцию, а не считаешь
ли в уме «как у меня на ноутбуке».

Лечится разнесением по строкам:

```c
int a = i++;   /* теперь порядок однозначен */
int b = ++i;
printf("%d %d\n", a, b);
```

## Каверза 7. Неинициализированная переменная

```c
int sum;
for (int i = 1; i <= 5; i++) {
    sum += i;
}
printf("%d\n", sum);
```

**Вопрос.** Что выведет?

**Ответ.** Заранее **неизвестно**. `sum` объявлена, но не инициализирована
— в локальной переменной лежит **мусор** (что осталось в этой ячейке
памяти). К мусору прибавляется 1+2+3+4+5 = 15, и печатается
«мусор + 15». Может вывестись и 15 (если повезло и там был 0), и любое
другое число, и значение может меняться от запуска к запуску.

Чтение неинициализированной локальной переменной — тоже неопределённое
поведение. Фикс — один символ: `int sum = 0;`. Любой накопитель перед
циклом обнуляй (сумма — в 0, произведение — в 1). Компилятор с `-Wall`
часто предупреждает «may be used uninitialized» — не игнорируй.

## Каверза 8. Остаток от отрицательного числа

```c
printf("%d %d\n", -7 / 2, -7 % 2);
```

**Вопрос.** Что выведет?

**Ответ.** Выведет `-3 -1`. В современном C (стандарт C99 и новее)
деление округляется **к нулю**: `-7 / 2` это −3 (а не −4). А остаток
подчиняется правилу `(a / b) * b + a % b == a`, поэтому `-7 % 2` равен
−1, а не +1.

Практический вывод: проверять нечётность через `n % 2 == 1` **опасно** —
для отрицательных нечётных получится −1, и проверка провалится. Пиши
`n % 2 != 0`. Это прямая связь с задачей 2 про чётность.

# Мини-резюме

Что стоит унести из этого приложения — не сами решения (их в интернете
тысячи), а привычки, которые отличают подготовленного кандидата:

- **Краевые случаи проговаривай вслух**: пустой массив, один элемент,
  ноль, отрицательное, дубликаты, переполнение. Интервьюер часто ставит
  плюс именно за то, что ты сам про них вспомнил.
- **Помни про типы и переполнение.** `int` лопается на ~2 млрд; символ —
  это `int` в C; деление целых идёт нацело. Эти три факта спрашивают
  чаще всего.
- **Знай про опасные приёмы, но не используй их без нужды.** XOR-своп,
  арифметический обмен — рассказать можешь, в код кладёшь `temp`.
- **UB называй своим именем.** Увидел `i++` и `++i` в одном выражении,
  неинициализированную переменную, изменение строкового литерала —
  отвечай «это неопределённое поведение», а не угадывай результат.
- **Компилируй с `-Wall -Wextra`.** Половину каверз из второй части
  компилятор ловит сам.

Все рабочие решения собираются и запускаются:

```text
cc -std=c11 -Wall -Wextra -O2 code/19-07-prime.c -o prime
./prime
```
