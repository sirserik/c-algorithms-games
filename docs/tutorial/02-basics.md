# Глава 2. Минимум Си: переменные, ввод, ветвления, циклы, функции

В первой главе программа умела ровно одно: напечатать заранее
заготовленную строчку. Она ничего не помнила, ни о чём не спрашивала и
всегда вела себя одинаково. Пора это исправить.

Здесь мы разберём всё, без чего не написать ни одного алгоритма:
**переменные и типы**, **вывод чисел**, **ввод с клавиатуры**,
**арифметику** с её ловушками, **ветвления** (`if`/`else`), **циклы**
(`while`, `for`, `do-while`) и **свои функции**.

Глава длинная — это единственный такой теоретический кусок в книге.
Не пытайся заучить: набирай и запускай каждый пример руками, тогда
уляжется само.

## Что мы сделаем

К концу главы у нас будет маленькая интерактивная программа: она
спрашивает число и печатает его таблицу умножения ровным столбиком,
помечая чётные результаты:

```text
Таблица умножения для какого числа? 3
 3 x  1 =   3
 3 x  2 =   6  (чётное)
 3 x  3 =   9
 3 x  4 =  12  (чётное)
 3 x  5 =  15
 3 x  6 =  18  (чётное)
 3 x  7 =  21
 3 x  8 =  24  (чётное)
 3 x  9 =  27
 3 x 10 =  30  (чётное)
```

Программка крошечная, но в ней уже есть переменная, ввод с проверкой,
цикл, ветвление и собственная функция — весь минимум Си.

## Разбираем задачу руками

Прежде чем писать код, сделай то же самое на бумаге. Пусть `n` равно
3. Что нужно напечатать?

```text
3 x 1 = 3
3 x 2 = 6
3 x 3 = 9
...и так до 10
```

Видно повторение: меняется только второй множитель — 1, 2, 3, …, 10.
Значит, нужна «коробка» под сам `n` (его вводит человек) и вторая
коробка под текущий множитель, который мы увеличиваем на единицу
десять раз подряд. Первая коробка — переменная, «увеличиваем десять
раз» — цикл. С коробок и начнём.

## Шаг 1. Переменная — коробка для значения

Переменная — это **именованная коробочка в памяти**, в которой лежит
значение. У коробочки есть имя (чтобы к ней обращаться) и тип (чтобы
знать, что в ней лежит и сколько места занимает).

```c
#include <stdio.h>

int main(void)
{
    int age = 25;
    printf("Возраст: %d\n", age);
    return 0;
}
```

Разбор новых вещей:

- `int age = 25;` — мы **объявили** переменную. По частям:
  - `int` — тип: целое число (мы его уже видели у `main`).
  - `age` — имя. Имена пишем латиницей: буквы, цифры (не первой) и
    `_`. Регистр важен, `age` и `Age` — разные переменные. Пробелов и
    дефисов быть не может, поэтому длинные имена пишут `max_value`
    или `maxValue`.
  - `=` — оператор **присваивания**: «положи в коробку `age`
    значение справа». Это **не** «равно» из математики, это команда
    «запиши». Запомни сразу: один `=` присваивает, два `==`
    сравнивают.
  - `25` — само значение.
  - `;` — конец инструкции.
- `printf("Возраст: %d\n", age);` — тут новое:
  - `%d` внутри строки — **спецификатор формата**: «сюда подставь
    целое число в десятичной записи» (`d` — *decimal*).
  - после строки, через запятую, мы передали `age`. Его значение и
    встанет на место `%d`.

Компилируем и запускаем — как в главе 1:

```text
Возраст: 25
```

Значение можно менять сколько угодно раз: `age = 30;` затрёт старое
содержимое коробки новым. Можно объявить переменную и без значения —
`int age;` — но тогда до первой записи в ней лежит **мусор**: то, что
случайно осталось в этом месте памяти. Читать такую переменную нельзя,
сначала надо в неё что-то положить.

## Шаг 2. Типы: сколько места и что туда влезает

Тип нужен компилятору, чтобы понять, сколько байт выделить под коробку
и как трактовать лежащие там биты. Пока хватит четырёх типов:

- `int` — целое число (−7, 0, 42), спецификатор `%d`;
- `double` — дробное (3.14, −0.5), «двойная точность», `%f`;
- `char` — один символ (`'A'`, `'?'`), `%c`;
- `long long` — целое побольше, когда `int` мал, `%lld`.

```c
double y = 3.14159;
printf("%f\n", y);      // дробное как есть
printf("%.2f\n", y);    // два знака после точки
```

```text
3.141590
3.14
```

`%f` печатает шесть знаков после точки — отсюда лишние нули. Точность
задаётся через точку: `%.2f`. И заодно: `//` — это **комментарий**,
всё от `//` до конца строки компилятор игнорирует. Есть и
многострочный вид: `/* ... */`.

### Смотрим размеры своими глазами

Сколько байт занимает `int`? В книгах пишут «обычно 4», но проверять
надо на своей машине. Для этого есть оператор `sizeof`:

```c
#include <stdio.h>
#include <limits.h>

int main(void)
{
    printf("char      %zu байт\n", sizeof(char));
    printf("int       %zu байта\n", sizeof(int));
    printf("long long %zu байт\n", sizeof(long long));
    printf("double    %zu байт\n", sizeof(double));
    printf("int вмещает от %d до %d\n", INT_MIN, INT_MAX);
    return 0;
}
```

- `sizeof(int)` — размер типа в байтах. Это не функция, а оператор:
  считается **на этапе компиляции**, программа ничего не измеряет.
- `%zu` — спецификатор для того типа, который возвращает `sizeof`
  (он называется `size_t`). Через `%d` его печатать неправильно.
- `#include <limits.h>` — ещё один заголовочный файл. Он не приносит
  функций, только готовые константы: `INT_MIN` и `INT_MAX` — самое
  маленькое и самое большое целое, влезающее в `int`.

Запуск на моей машине (Apple clang, 64-битный Mac):

```text
char      1 байт
int       4 байта
long long 8 байт
double    8 байт
int вмещает от -2147483648 до 2147483647
```

Вот и ответ: `int` — четыре байта, примерно от минус двух до плюс двух
миллиардов. Стандарт Си именно этих чисел не обещает (на
микроконтроллере `int` вполне бывает двухбайтным), поэтому аккуратные
программы пишут `sizeof` и `INT_MAX`, а не «4» и «2 миллиарда».

### Что будет, если число не влезло

Коробка конечного размера. Положим в неё число на единицу больше
максимума:

```c
int big = INT_MAX;
printf("big     = %d\n", big);
big = big + 1;
printf("big + 1 = %d\n", big);
```

```text
big     = 2147483647
big + 1 = -2147483648
```

Прибавили единицу к самому большому числу — получили самое маленькое.
Это **переполнение** (overflow): результат не влез, старшие биты
потерялись, а бит, отвечающий за знак, включился. Программа при этом
не падает и ничего не сообщает — молча считает чушь дальше.

Формально прибавлять единицу к `INT_MAX` в Си вообще запрещено, это
«неопределённое поведение», и компилятор вправе сделать что угодно. На
практике почти всегда получается вот такой перескок через край.
Запомни признак: сумма или произведение положительных чисел вдруг
стала отрицательной — значит, `int` лопнул. Лечится переходом на
`long long`; подробно займёмся этим в главе 4 на факториале.

### `char` — это маленькое целое

Тип `char` называют символьным, но внутри там обычное целое число —
код символа. Никакой отдельной «буквы» в памяти нет. Убедимся:
напечатаем одну переменную двумя разными спецификаторами.

```c
char c = 'A';
printf("символ %c — это число %d\n", c, c);
printf("а %c — это %d\n", c + 1, c + 1);
```

```text
символ A — это число 65
а B — это 66
```

- `'A'` в одинарных кавычках — символьная константа, ровно один знак.
  Не путай с `"A"` в двойных: это строка (о строках — глава 3).
- `%c` говорит `printf`: «трактуй число как код символа и напечатай
  сам символ». `%d` говорит: «напечатай число».
- `c + 1` — к символу можно прибавить единицу, потому что это число.
  65 + 1 = 66, а 66 — это код `'B'`. Латинские буквы идут в таблице
  подряд, поэтому такой арифметикой удобно пользоваться: `'a' + 3`
  даст `'d'`.

Эти три опыта собраны в готовый файл `code/02-types.c`.

## Шаг 3. `printf` — разбираем как функцию

Мы зовём `printf` с первой главы, но ни разу не посмотрели на неё как
на функцию. Итак:

- **Живёт** в `<stdio.h>` (*standard input/output*). Без этого
  `#include` компилятор про неё не знает.
- **Принимает** первым аргументом строку формата, а дальше — сколько
  угодно аргументов, по одному на каждый спецификатор. Функции с
  переменным числом аргументов называют вариадическими; их в Си
  немного, и `printf` — главная.
- **Возвращает** `int` — сколько байт напечатала.
- **Подводный камень**: она не проверяет, что тип аргумента совпал со
  спецификатором.

Проверим, что возвращаемое значение не выдумка:

```c
#include <stdio.h>

int main(void)
{
    int n = printf("Привет, мир!\n");
    printf("printf напечатал %d байт\n", n);
    int m = printf("ABC\n");
    printf("а тут %d\n", m);
    return 0;
}
```

```text
Привет, мир!
printf напечатал 22 байт
ABC
а тут 4
```

С `ABC\n` всё сходится: три буквы плюс перевод строки. А почему у
`«Привет, мир!\n»` вышло 22, если знаков там 13? Потому что считаются
**байты**: в кодировке UTF-8 каждая русская буква занимает два. Как
раз поэтому все посимвольные алгоритмы в книге мы будем писать на
латинице — с ней «один символ = один байт».

### Если спецификатор не совпал с типом

Напишем заведомо неправильно: напечатаем `double` через `%d`.

```c
#include <stdio.h>

int main(void)
{
    double price = 19.99;
    printf("Цена: %d\n", price);
    return 0;
}
```

Компилятор с `-Wall` ругается сразу:

```text
bad.c:6:30: warning: format specifies type 'int' but the argument has
      type 'double' [-Wformat]
    6 |     printf("Цена: %d\n", price);
      |                   ~~     ^~~~~
      |                   %f
1 warning generated.
```

«Формат обещает тип `int`, а аргумент имеет тип `double`», и внизу
подсказка — надо `%f`. Но warning не ошибка, программа собралась.
Запускаем:

```text
Цена: -1112010808
```

Мусор. `printf` честно взял четыре байта оттуда, где обычно лежит
целочисленный аргумент, — а `double` туда не клали, он передаётся
иначе. У тебя число будет другим, это и означает «мусор».

Отсюда правило: **собирай всегда с `-Wall -Wextra` и не оставляй ни
одного предупреждения**. Компилятор ловит такое бесплатно, а без него
ты будешь искать это глазами.

### Ширина поля

Спецификатор умеет не только «какой тип», но и «сколько места занять».
`%3d` значит «напечатай целое, заняв не меньше трёх позиций, слева
добей пробелами». Числа выравниваются по правому краю — ровно то, что
нужно для таблиц. Скоро пригодится.

## Шаг 4. `scanf` — спрашиваем у пользователя

Считать число с клавиатуры умеет `scanf` (*scan formatted*), тоже из
`<stdio.h>`.

```c
#include <stdio.h>

int main(void)
{
    int age;
    printf("Сколько тебе лет? ");
    scanf("%d", &age);
    printf("Через год будет %d\n", age + 1);
    return 0;
}
```

Запуск (после вопроса показано то, что ты набрал):

```text
Сколько тебе лет? 25
Через год будет 26
```

Что нового:

- `int age;` — объявили переменную **без** значения, сейчас заполним
  её вводом.
- `"%d"` — формат: «ожидаю целое число». `scanf` пропустит пробелы и
  переводы строк, потом прочитает подряд идущие цифры.
- `&age` — знак `&` означает «**адрес** переменной `age`», то есть
  «где в памяти лежит коробка `age`». Разница принципиальная: `age` —
  это значение (25), `&age` — это место. `scanf` должна не прочитать
  переменную, а **записать** в неё, поэтому ей нужно место.
- `age + 1` — арифметика прямо в аргументе `printf`: сначала
  посчитается сумма, потом подставится в `%d`.

### Что будет, если забыть `&`

Ошибка номер один у новичков, посмотрим на неё вживую. Пишем
`scanf("%d", age)` — компилятор выдаёт два предупреждения:

```text
noamp.c:6:17: warning: format specifies type 'int *' but the argument
      has type 'int' [-Wformat]
    6 |     scanf("%d", age);
      |            ~~   ^~~
noamp.c:6:17: warning: variable 'age' is uninitialized when used here
      [-Wuninitialized]
    6 |     scanf("%d", age);
      |                 ^~~
noamp.c:5:12: note: initialize the variable 'age' to silence this
      warning
    5 |     int age;
      |            ^
      |             = 0
2 warnings generated.
```

Первое: «формат обещает `int *` (адрес целого), а аргумент — `int`».
Второе: «переменная `age` используется неинициализированной» — мы
скормили `scanf` тот самый мусор, который в ней лежал, и она приняла
его за адрес.

Дальше как повезёт. У меня программа не упала, а напечатала `73896`:
`scanf` записала число по случайному адресу и поехала дальше. На
другой машине то же самое даст `Segmentation fault` — падение. Второй
вариант, честно говоря, лучше: молчаливая порча чужой памяти опаснее
честного падения.

Правило: **в `scanf` перед обычной переменной всегда стоит `&`**.

### `scanf` возвращает число, и его надо проверять

`scanf` возвращает, **сколько значений успешно прочитала**. Один `%d`
в формате — при удаче вернёт 1. А если удачи нет?

```c
#include <stdio.h>

int main(void)
{
    int age;
    printf("Сколько тебе лет? ");
    int ok = scanf("%d", &age);
    printf("scanf вернул %d, age = %d\n", ok, age);
    return 0;
}
```

Три запуска: с числом, с буквами и вообще без ввода (ввод закрывается
клавишами Ctrl+D).

```text
Сколько тебе лет? 25
scanf вернул 1, age = 25
```

```text
Сколько тебе лет? abc
scanf вернул 0, age = 32760
```

```text
Сколько тебе лет? scanf вернул -1, age = 32760
```

- `1` — прочитано одно значение, всё хорошо.
- `0` — «данные на входе есть, но это не то, что я просила». `age`
  осталась нетронутой, там мусор (у тебя будет другое число).
- `-1` — это константа `EOF` (*end of file*): читать больше нечего.

Главное здесь: при `0` и `-1` переменная **не заполнилась**. Если
программа не проверит результат, она пойдёт считать по мусору. Поэтому
в книге ты всюду будешь видеть такую форму:

```c
if (scanf("%d", &n) != 1) {
    printf("Это не число.\n");
    return 1;
}
```

`return 1;` из `main` означает «завершились с ошибкой»: ноль — успех,
любое другое число — код ошибки, так принято во всех командах
терминала.

### Буква вместо числа: почему программа зависает

Логично попросить ввод заново, если он оказался плохим:

```c
int n;
printf("Введи число: ");
while (scanf("%d", &n) != 1) {
    printf("Это не число. Ещё раз: \n");
}
printf("Принято: %d\n", n);
```

Выглядит разумно. Запускаем, вводим `abc`:

```text
Введи число: Это не число. Ещё раз: 
Это не число. Ещё раз: 
Это не число. Ещё раз: 
Это не число. Ещё раз: 
Это не число. Ещё раз: 
Это не число. Ещё раз: 
```

И так до бесконечности, пока не нажмёшь Ctrl+C.

Причина вот в чём: наткнувшись на букву, `scanf` **не забирает** её из
входного потока. Она возвращает 0 и оставляет `abc` лежать там же. На
следующем витке цикла она видит те же самые буквы, снова возвращает
0 — и по кругу. Значит, плохой ввод надо выбросить самим.

### Настоящий фикс

```c
#include <stdio.h>

int main(void)
{
    int n;

    printf("Введи целое число: ");
    while (scanf("%d", &n) != 1) {
        int c;
        while ((c = getchar()) != '\n' && c != EOF) {
        }
        if (c == EOF) {
            printf("Ввод кончился, выхожу.\n");
            return 1;
        }
        printf("Это не число. Попробуй ещё раз: ");
    }

    printf("Принято: %d\n", n);
    printf("Удвоенное: %d\n", n * 2);
    return 0;
}
```

Новое здесь — `getchar`:

- **Живёт** в `<stdio.h>`, **принимает** ничего.
- **Возвращает** `int` — код очередного символа со входа либо `EOF`.
  Именно `int`, а не `char`: `EOF` равен −1 и в `char` мог бы
  совпасть с нормальным кодом символа.
- **Подводный камень**: результат `getchar` всегда кладут в `int`.

Разбираем строку `while ((c = getchar()) != '\n' && c != EOF) { }`:

- `c = getchar()` — прочитали символ и **положили в `c`**. В Си
  присваивание само является выражением со значением — тем, которое
  присвоили. Поэтому его можно сравнивать прямо на месте.
- Внешние скобки вокруг `(c = getchar())` обязательны: без них
  сравнение `!=` сработало бы раньше присваивания.
- Тело цикла пустое: `{ }`. Делать с этими символами ничего не надо,
  их надо просто проглотить.
- После цикла — `if (c == EOF)`. Без этой проверки при закрытом вводе
  получился бы новый вечный цикл: `scanf` вечно возвращает −1, а
  чистить уже нечего.

Запускаем и вводим по очереди `abc`, `hex`, `7`:

```text
Введи целое число: abc
Это не число. Попробуй ещё раз: hex
Это не число. Попробуй ещё раз: 7
Принято: 7
Удвоенное: 14
```

Программа лежит в `code/02-input.c`. Приём «проверил результат
`scanf` → вычистил строку → спросил заново» встретится ещё много раз,
особенно в играх из второй половины книги.

## Шаг 5. Арифметика и её ловушки

Операторы почти как в математике: `+`, `-`, `*`, `/` и `%` — остаток
от деления. Но три вещи ведут себя не так, как ждёт человек, впервые
увидевший Си.

```c
#include <stdio.h>

int main(void)
{
    printf("7 / 2   = %d\n", 7 / 2);
    printf("7 %% 2   = %d\n", 7 % 2);
    printf("7.0 / 2 = %f\n", 7.0 / 2);
    printf("-7 / 2  = %d\n", -7 / 2);
    printf("-7 %% 2  = %d\n", -7 % 2);
    printf("7 %% -2  = %d\n", 7 % -2);
    printf("2 + 3 * 4   = %d\n", 2 + 3 * 4);
    printf("(2 + 3) * 4 = %d\n", (2 + 3) * 4);
    printf("10 - 4 - 3  = %d\n", 10 - 4 - 3);
    return 0;
}
```

Сразу мелочь, которая смущает: `%%`. Знак процента для `printf`
служебный, поэтому, чтобы напечатать сам процент, его удваивают — на
экране получится один `%`.

```text
7 / 2   = 3
7 % 2   = 1
7.0 / 2 = 3.500000
-7 / 2  = -3
-7 % 2  = -1
7 % -2  = 1
2 + 3 * 4   = 14
(2 + 3) * 4 = 20
10 - 4 - 3  = 3
```

**Целочисленное деление.** `7 / 2` дало **3**, а не 3.5. Если оба
операнда целые, деление тоже целое: дробная часть отбрасывается. Чтобы
получить 3.5, хотя бы одно число должно быть дробным — `7.0 / 2`.
Отсюда классический баг:

```c
int sum = 7, count = 2;
double avg = sum / count;      // avg станет 3.0, а не 3.5!
```

Деление произошло **до** записи в `double`, спасать уже нечего.
Лечится приведением типа: `double avg = (double)sum / count;`. Запись
`(double)x` называется **приведением типа** (cast) и означает «считай
это значение дробным». Достаточно привести один операнд, второй
подтянется сам.

**Знак остатка.** `%` даёт остаток: `7 % 2` равно 1. Штука
невероятно полезная — `n % 2` равно нулю ровно для чётных, `n % 10`
даёт последнюю цифру, `i % 3` крутится по кругу 0, 1, 2, 0, 1, 2… Но с
минусами внимательно: `-7 % 2` дало **−1**, а не 1. Знак остатка
совпадает со знаком **делимого**, а знак делителя не влияет вообще
(`7 % -2` дало 1).

Практический вывод: проверка на нечётность через `n % 2 == 1`
**сломается** на отрицательных числах:

```c
int n = -7;
printf("n %% 2       = %d\n", n % 2);
printf("n %% 2 == 1  -> %d\n", n % 2 == 1);
printf("n %% 2 != 0  -> %d\n", n % 2 != 0);
```

```text
n % 2       = -1
n % 2 == 1  -> 0
n % 2 != 0  -> 1
```

Число −7 нечётное, но `n % 2 == 1` ответило «нет». Правильная проверка
на нечётность — `n % 2 != 0`. А на чётность годится и `n % 2 == 0`:
у нуля знака нет.

**Приоритет.** `2 + 3 * 4` дало 14: умножение и деление выполняются
раньше сложения и вычитания, как в школе. Скобки этот порядок
переопределяют. Операторы одного уровня считаются слева направо:
`10 - 4 - 3` — это `(10 - 4) - 3 = 3`. Остаток `%` стоит на одном
уровне с `*` и `/`, поэтому `1 + n % 2` — это `1 + (n % 2)`. Всю
таблицу приоритетов заучивать не надо, надёжнее правило: сложнее двух
операций — ставь скобки.

### `i++` и `++i` — не одно и то же

`i = i + 1` пишут короче: `i++` или `++i`. Обе записи увеличивают `i`
на единицу, но **значение самого выражения** у них разное. `i++`
(постфиксный инкремент) возвращает старое значение и потом
увеличивает; `++i` (префиксный) сначала увеличивает и возвращает уже
новое. Разница видна, только если результат куда-то используется:

```c
#include <stdio.h>

int main(void)
{
    int i = 5;
    int a = i++;
    printf("после a = i++:  a = %d, i = %d\n", a, i);

    int j = 5;
    int b = ++j;
    printf("после b = ++j:  b = %d, j = %d\n", b, j);
    return 0;
}
```

```text
после a = i++:  a = 5, i = 6
после b = ++j:  b = 6, j = 6
```

`i` и `j` обе стали шестёрками — тут разницы нет. А `a` получила
старую пятёрку, `b` — новую шестёрку.

Когда инкремент стоит отдельной строкой (`i++;`) или в третьей части
`for`, разницы никакой, и пишут обычно `i++`. Не пихай `i++` внутрь
сложных выражений: это верный способ получить код, который никто не
может прочитать. Похожие сокращения: `i--`, `i += 3`, `i -= 2`,
`i *= 2`, `i /= 2` — краткая запись `i = i + 3` и так далее.

## Шаг 6. Принимаем решения — `if` и `else`

Программа должна уметь выбирать путь: «если число чётное — сделай так,
иначе — эдак». Для этого есть `if`.

```c
#include <stdio.h>

int main(void)
{
    int n;

    printf("Введи число: ");
    if (scanf("%d", &n) != 1) {
        printf("Это не число.\n");
        return 1;
    }

    if (n % 2 == 0) {
        printf("%d — чётное\n", n);
    } else {
        printf("%d — нечётное\n", n);
    }
    return 0;
}
```

Два запуска:

```text
Введи число: 7
7 — нечётное
```

```text
Введи число: 10
10 — чётное
```

Разбор:

- `if (условие) { ... }` — если условие истинно, выполняется блок в
  фигурных скобках. Условие пишут в круглых скобках, и после `)`
  точка с запятой **не ставится**.
- `n % 2 == 0` — тут два оператора: `%` даёт остаток, а `==`
  **сравнивает**. Ещё раз: `==` сравнивает, `=` присваивает.
- `else { ... }` — «иначе», выполняется, если условие оказалось
  ложным. Не обязателен.
- `return 1;` в середине `main` мгновенно завершает программу — до
  второго `if` дело не дойдёт.

### `=` вместо `==` — классический баг

Что будет, если в условии написать один знак равенства?

```c
int n = 3;
if (n = 5) {
    printf("n равно 5? n = %d\n", n);
}
```

Компилятор с `-Wall` предупреждает, и очень подробно:

```text
asg.c:6:11: warning: using the result of an assignment as a condition
      without parentheses [-Wparentheses]
    6 |     if (n = 5) {
      |         ~~^~~
asg.c:6:11: note: place parentheses around the assignment to silence
      this warning
    6 |     if (n = 5) {
      |           ^  
      |         (    )
asg.c:6:11: note: use '==' to turn this assignment into an equality
      comparison
    6 |     if (n = 5) {
      |           ^
      |           ==
1 warning generated.
```

А программа печатает:

```text
n равно 5? n = 5
```

Условие оказалось истинным, да ещё и `n` испортилась: было 3, стало 5.
Оба зла сразу. Компилятор прямым текстом советует `==` — слушайся.

### Сравнения и логика

Сравнения: `==` равно, `!=` не равно, `<`, `>`, `<=`, `>=`.

Отдельного логического типа в привычном виде в Си нет: **ложь — это 0,
истина — любое ненулевое число**. Сравнение возвращает ровно 1 или 0,
это обычный `int`, его можно печатать через `%d` — мы так и делали,
когда проверяли `n % 2 != 0`. Отсюда и коварство `if (n = 5)`: пятёрка
не ноль, значит истина.

Условия соединяют:

- `&&` — «И», истина, когда истинны оба: `if (age >= 18 && age < 65)`;
- `||` — «ИЛИ», истина, когда истинно хотя бы одно:
  `if (c == 'y' || c == 'Y')`;
- `!` — «НЕ», переворачивает: `if (!found)` — «если не найдено».

Полезная деталь: `&&` и `||` **ленивые**. В `a && b` правая часть
вообще не вычисляется, если левая ложна. Этим пользуются постоянно:
`if (i < n && a[i] > 0)` сначала убедится, что индекс не вылез за
границу, и только потом полезет в массив (массивы — глава 3).

Если веток несколько, их сцепляют через `else if`:

```c
if (n > 0) {
    printf("положительное\n");
} else if (n < 0) {
    printf("отрицательное\n");
} else {
    printf("ноль\n");
}
```

Проверки идут сверху вниз, и как только одна сработала, остальные
пропускаются. Последний `else` ловит всё, что не подошло.

## Шаг 7. Повторяем — циклы

### `while`

Самый понятный цикл — `while` («пока»): пока условие истинно,
повторяй тело. Напечатаем числа от 1 до 5:

```c
int i = 1;
while (i <= 5) {
    printf("%d ", i);
    i++;
}
printf("\n");
```

```text
1 2 3 4 5 
```

- `int i = 1;` — заводим **счётчик**.
- `while (i <= 5)` — условие проверяется **перед** каждым проходом.
- в `%d ` после `d` стоит пробел, поэтому числа не слипаются.
- `i++;` — увеличиваем счётчик. **Без этой строки условие никогда не
  станет ложным и программа зациклится навсегда.** Случилось —
  Ctrl+C.
- отдельный `printf("\n")` после цикла переводит строку, чтобы
  приглашение терминала не приклеилось к нашим числам.

### `for`

Когда у цикла есть счётчик с понятным началом, концом и шагом, удобнее
`for`. Тот же вывод 1..5:

```c
for (int i = 1; i <= 5; i++) {
    printf("%d ", i);
}
printf("\n");
```

```text
1 2 3 4 5 
```

В скобках `for` — три части через `;`:

1. `int i = 1` — **инициализация**, выполняется один раз в начале.
2. `i <= 5` — **условие**, проверяется перед каждым повтором.
3. `i++` — **шаг**, выполняется в конце каждого повтора, перед
   следующей проверкой условия.

Это ровно тот же `while`, только всё про счётчик собрано в одном месте
и его не забудешь. Переменная `i`, объявленная прямо в `for`, живёт
только внутри цикла — снаружи её нет.

Как выбирать: знаешь заранее, **сколько раз** повторять (десять строк
таблицы, все элементы массива) — бери `for`. Повторяешь, **пока
что-то не случится** (пока не введут ноль, пока не угадали число) —
бери `while`. Технически они взаимозаменяемы, но по такому коду сразу
видно намерение автора.

### `break` и `continue`

Два слова, вмешивающиеся в ход цикла: `break;` немедленно **выходит**
из цикла целиком, `continue;` бросает текущий проход и переходит к
следующему (шаг `i++` при этом всё равно выполнится).

```c
for (int i = 1; i <= 10; i++) {
    if (i % 3 == 0) {
        continue;
    }
    if (i == 8) {
        break;
    }
    printf("%d ", i);
}
printf("\n");
```

```text
1 2 4 5 7 
```

3 и 6 пропущены — на них сработал `continue`. На восьмёрке сработал
`break` и вышиб нас из цикла, поэтому 8, 9 и 10 не напечатались вовсе.

### `do-while`

Третий цикл проверяет условие **после** тела, поэтому тело выполняется
хотя бы один раз. Разница видна на условии, ложном с самого начала:

```c
int i = 10;
while (i <= 5) {
    printf("while: %d\n", i);
    i++;
}

int j = 10;
do {
    printf("do-while: %d\n", j);
    j++;
} while (j <= 5);
```

```text
do-while: 10
```

`while` не напечатал ничего: условие `10 <= 5` ложно, тело ни разу не
запустилось. `do-while` напечатал строку — он сначала выполнил тело и
только потом проверил. Заметь точку с запятой после `while (j <= 5);`:
в `do-while` она обязательна.

## Шаг 8. Свои функции

`printf`, `scanf`, `getchar` — чужие функции. Пишем свои: чтобы не
повторять код и дать кускам логики понятные имена.

```c
#include <stdio.h>

int square(int x)
{
    return x * x;
}

int main(void)
{
    int n = 6;
    printf("%d в квадрате = %d\n", n, square(n));
    return 0;
}
```

Разбор `int square(int x)`:

- `int` (первый) — тип того, что функция **вернёт**.
- `square` — имя, придумали сами.
- `(int x)` — **параметр**: функция принимает одно целое и внутри
  называет его `x`. Параметров может быть несколько через запятую, у
  каждого свой тип: `int max2(int a, int b)`.
- `return x * x;` — посчитать и **вернуть** наружу. `return` заодно
  завершает функцию: код после него не выполнится.

В `main` запись `square(n)` — это **вызов**: передаём `n`, получаем
результат, который тут же подставляется в `printf`.

### Прототип: функция должна быть объявлена до вызова

Компилятор читает файл сверху вниз. Переставим `square` вниз, под
`main`:

```text
noproto.c:5:20: error: call to undeclared function 'square'; ISO C99
      and later do not support implicit function declarations
      [-Wimplicit-function-declaration]
    5 |     printf("%d\n", square(6));
      |                    ^
1 error generated.
```

Это уже не warning, а **error** — сборки не будет. «Вызов
необъявленной функции». Первый способ починить — держать функции выше
`main`, как мы и делали. Второй, более гибкий, — **прототип**:
объявление без тела, обещающее компилятору «такая функция есть, вот её
вход и выход, тело будет ниже».

```c
#include <stdio.h>

int square(int x);          /* прототип: обещание компилятору */

int main(void)
{
    printf("square(6) = %d\n", square(6));
    return 0;
}

int square(int x)           /* тело — ниже */
{
    return x * x;
}
```

```text
square(6) = 36
```

Прототип — это первая строка функции плюс точка с запятой вместо тела.
Имя параметра в нём можно опустить (`int square(int);`), но с именем
понятнее. Так устроены и заголовочные файлы: в `<stdio.h>` лежат
прототипы `printf` и `scanf`, а тела — в готовой библиотеке. Потому
`#include <stdio.h>` и обязателен.

### Локальные переменные и область видимости

Переменные, объявленные внутри функции, называются **локальными**: они
рождаются при входе в функцию и исчезают при выходе. Снаружи их не
существует, и одноимённые переменные в разных функциях никак не
связаны.

```c
#include <stdio.h>

int square(int x)
{
    int result = x * x;
    return result;
}

int main(void)
{
    int result = 100;
    printf("square(6) = %d\n", square(6));
    printf("result в main = %d\n", result);
    return 0;
}
```

```text
square(6) = 36
result в main = 100
```

Две разные переменные с именем `result`, и они не мешают друг другу.
Правило шире: переменная видна от места объявления до закрывающей
фигурной скобки того блока, где объявлена. Поэтому `int i` внутри
`for` не виден после цикла.

### Аргументы передаются по значению

Главный факт про функции в Си: **функция получает копию аргумента, а
не сам аргумент**. Что бы она с ним ни делала, снаружи ничего не
изменится.

```c
#include <stdio.h>

void add_ten(int x)
{
    x = x + 10;
    printf("внутри функции x = %d\n", x);
}

int main(void)
{
    int n = 5;
    printf("до вызова   n = %d\n", n);
    add_ten(n);
    printf("после вызова n = %d\n", n);
    return 0;
}
```

```text
до вызова   n = 5
внутри функции x = 15
после вызова n = 5
```

Внутри `x` честно стал пятнадцатью, а `n` в `main` как был пятёркой,
так и остался: при вызове значение `n` скопировалось в новую коробочку
`x`, и функция всю дорогу возилась с копией.

Отсюда два следствия. Если функция должна что-то сообщить наружу — она
это **возвращает** через `return`. А если нужно изменить саму
переменную вызывающего, придётся передать её **адрес** — тот самый
`&`, который мы уже видели у `scanf`. Это указатели, ими займёмся в
главе 3. Запомни этот запуск, мы к нему вернёмся.

### `void` — функция, которая ничего не возвращает

У `add_ten` вместо типа результата стоит `void`:

```c
void hello(void)
{
    printf("Привет!\n");
}
```

`void` как тип результата означает «ничего не возвращаю». Внутри такой
функции можно написать `return;` без значения, чтобы выйти досрочно, а
можно не писать вовсе. `void` в скобках, как в `main(void)`, означает
другое — «не принимаю аргументов».

## Полная программа: таблица умножения

Начнём с наивной версии — без ввода, без функций, только цикл и
`printf`:

```c
#include <stdio.h>

int main(void)
{
    int n = 7;

    for (int i = 1; i <= 10; i++) {
        printf("%d x %d = %d\n", n, i, n * i);
    }
    return 0;
}
```

```text
7 x 1 = 7
7 x 2 = 14
7 x 3 = 21
7 x 4 = 28
7 x 5 = 35
7 x 6 = 42
7 x 7 = 49
7 x 8 = 56
7 x 9 = 63
7 x 10 = 70
```

Считает верно, но столбик съехал: в последней строке множитель
двузначный, и знак `=` уехал вправо. Лечится шириной поля — той самой,
про которую был разговор в шаге 3. Множителю дадим две позиции,
результату три:

```c
printf("%2d x %2d = %3d\n", n, i, n * i);
```

```text
 7 x  1 =   7
 7 x  2 =  14
 7 x  3 =  21
 7 x  4 =  28
 7 x  5 =  35
 7 x  6 =  42
 7 x  7 =  49
 7 x  8 =  56
 7 x  9 =  63
 7 x 10 =  70
```

Всё выровнено по правому краю. Осталось спросить число у пользователя
(с проверкой!) и пометить чётные результаты — для этого заведём свою
функцию `is_even`.

```c
#include <stdio.h>

int is_even(int x)
{
    return x % 2 == 0;
}

int main(void)
{
    int n;

    printf("Таблица умножения для какого числа? ");
    if (scanf("%d", &n) != 1) {
        printf("Это не число.\n");
        return 1;
    }

    for (int i = 1; i <= 10; i++) {
        int result = n * i;
        if (is_even(result)) {
            printf("%2d x %2d = %3d  (чётное)\n", n, i, result);
        } else {
            printf("%2d x %2d = %3d\n", n, i, result);
        }
    }

    return 0;
}
```

Сохрани её как `code/02-multiplication.c`.

## Как это работает

Пройдём программу глазами, как будто мы компьютер, для ввода `3`.

1. `int n;` — заводим коробку под число, пока в ней мусор.
2. `printf(...)` — печатаем вопрос. Перевода строки в конце нет, и
   курсор остаётся на той же строке: приглашение и ответ окажутся
   рядом.
3. `scanf("%d", &n)` — программа замирает и ждёт Enter. Ты набрал
   `3`, `scanf` разобрала это как целое, положила в `n` тройку и
   вернула 1. Значит, `!= 1` ложно, в `if` мы не заходим.
4. `for (int i = 1; i <= 10; i++)` — заводим `i = 1`, проверка
   `1 <= 10` истинна, входим в тело.
5. `int result = n * i;` — **новая** переменная, объявленная внутри
   тела цикла: на каждом витке создаётся заново. `3 * 1 = 3`.
6. `if (is_even(result))` — вызываем свою функцию. Внутри `x` — копия
   тройки, считается `3 % 2 == 0`, то есть `1 == 0`, то есть ложь,
   то есть 0. `if` видит ноль и идёт в `else`.
7. Печатается ` 3 x  1 =   3`.
8. Выполняется шаг `i++`, `i` становится 2, снова проверка условия.
   `3 * 2 = 6`, `6 % 2 == 0` истинно, `is_even` возвращает 1 — и
   работает ветка `if`, со словом «(чётное)».
9. Так десять раз. Когда `i` станет 11, условие `11 <= 10` ложно,
   цикл заканчивается, `return 0;` завершает программу.

Отдельно про `is_even`: она возвращает результат сравнения
`x % 2 == 0`, а сравнение даёт 1 или 0. Значит, `is_even` возвращает 1
для чётных и 0 для нечётных, и `if (is_even(result))` срабатывает
ровно на чётных. Писать `if (is_even(result) == 1)` не нужно — то же
самое, только длиннее.

## Частые ошибки

**`=` вместо `==` в условии.** `if (n == 5)` сравнивает, `if (n = 5)`
присваивает и всегда даёт истину, попутно портя `n`. Компилятор с
`-Wall` предупреждает — мы видели это предупреждение выше.

**Забытый `&` в `scanf`.** `scanf("%d", n)` — либо падение, либо
молчаливая порча памяти. Правильно `scanf("%d", &n)`.

**Непроверенный `scanf`.** Если ввод не подошёл, переменная останется
с мусором, а программа пойдёт считать как ни в чём не бывало. Всегда
`if (scanf(...) != 1) { ... }`.

**Вечный цикл на плохом вводе.** Плохие символы `scanf` не забирает из
потока. Просто повторить `scanf` в цикле мало — надо вычистить строку
через `getchar` и не забыть проверить `EOF`.

**Неверный спецификатор.** `double` через `%d` — мусор на экране,
`int` через `%f` — тоже. Тип и спецификатор обязаны совпадать, `-Wall`
это ловит.

**Точка с запятой после `if` или `for`.** `if (n > 0);` — пустое тело,
и следующий блок выполнится всегда. `for (int i = 0; i < 10; i++);` —
цикл, крутящийся вхолостую.

**Целочисленное деление врасплох.** `double avg = sum / count;`, где
`sum` и `count` целые, делит нацело **до** записи в `double`. Приводи:
`(double)sum / count`.

**Проверка на нечётность через `% 2 == 1`.** На отрицательных не
работает: `-7 % 2` равно −1. Пиши `n % 2 != 0`.

**Бесконечный цикл.** Забыл менять счётчик в `while` — программа
висит. Ctrl+C, и добавь `i++`.

**Переполнение `int`.** Результат больше двух миллиардов молча
превращается в отрицательный. Числа могут вырасти — бери `long long`.

**Переменная объявлена, но не заполнена.** `int sum;` и сразу
`sum += x;` — прибавление к мусору. Счётчики и накопители всегда
инициализируй: `int sum = 0;`.

## Упражнения

1. Программа спрашивает два числа и печатает их сумму, разность,
   произведение и частное. Частное — дробное, через `%.2f`.
   *Подсказка*: `scanf("%d %d", &a, &b)` читает сразу два числа и при
   удаче возвращает 2; частное считай как `(double)a / b`, и не
   забудь, что делить на ноль нельзя — проверь `b` заранее.
2. Программа спрашивает число и говорит, положительное оно,
   отрицательное или ноль. *Подсказка*: цепочка `if` / `else if` /
   `else`, три ветки, ни одной лишней проверки.
3. С помощью `for` напечатай все чётные числа от 2 до 20 в одну
   строку. *Подсказка*: можно идти с шагом 2 (`i += 2`), а можно идти
   по всем и пропускать нечётные через `continue`. Сделай обоими
   способами и реши, какой понятнее.
4. Напиши функцию `int max2(int a, int b)`, возвращающую большее из
   двух чисел, и проверь её в `main` на трёх парах, включая пару
   равных чисел. *Подсказка*: тело — один `if` с `return` в каждой
   ветке; при равных числах любой ответ верен, но функция обязана
   что-то вернуть, а не провалиться до конца тела.
5. Цикл `while`: спрашивай числа, пока пользователь не введёт 0, и в
   конце напечатай их сумму и количество. *Подсказка*: накопитель
   `int sum = 0;` заведи **до** цикла; выходить удобно через `break`,
   когда прочитан ноль; проверяй результат `scanf` — на `EOF` тоже
   надо выйти, иначе получишь вечный цикл.
6. Возьми `code/02-multiplication.c` и сделай так, чтобы программа
   спрашивала ещё и до скольки печатать таблицу (`3` до `5` даёт пять
   строк). *Подсказка*: вторая переменная и второй `scanf` с
   проверкой, а в условии `for` вместо `10` подставь её. Посмотри, что
   выйдет при вводе `0` и при отрицательном числе — и добавь проверку,
   если результат тебе не понравится.
