# Глава 17. Игра «Змейка»

Вот мы и добрались до финала. «Змейка» — та самая игра из старых
телефонов: по полю ползёт змейка, ест еду, растёт и не должна
врезаться ни в стену, ни в саму себя. Игра простая на вид, но в ней
сходится всё, что мы прошли: поле из клеток, массивы координат,
глобальное состояние игры, случайная еда, цикл и проверки
столкновений.

И тут появляется по-настоящему новое. Раньше наши программы ждали,
пока ты нажмёшь клавишу и Enter. Змейка так не умеет: она ползёт
**сама**, а клавишу должна ловить **мгновенно**, без Enter и без
эха на экране. За это отвечает «сырой» режим терминала через
`termios` — главная новая тема главы. Разберём её спокойно и по
частям.

## Что мы сделаем

К концу главы у тебя будет настоящая игра в терминале:

- поле с рамкой из символов `#`;
- змейка (`O` — голова, `o` — тело), которая ползёт сама;
- управление клавишами W A S D или стрелками **без нажатия Enter**;
- еда `*`, которая появляется в случайном месте; съел — змейка растёт
  и счёт увеличивается;
- проигрыш при столкновении со стеной или с собственным телом;
- победа, если змейка заняла всё поле целиком;
- выход по клавише `q` — и терминал, который остаётся рабочим при
  любом способе закончить игру.

Строить будем как всегда: от простого к сложному. Сначала просто
нарисуем поле и неподвижную змейку. Потом заставим её двигаться. Потом
научимся ловить клавиши. Потом добавим еду и рост. И в конце —
столкновения и проигрыш.

## Разбираем задачу руками

Прежде чем писать код, поймём две вещи: как хранить змейку и почему
обычного ввода тут не хватит.

### Как хранить змейку

Змейка — это цепочка клеток на поле. Каждая клетка — пара чисел:
номер столбца `x` и номер строки `y`. Заведём два массива:

```text
snake_x:  9  8  7
snake_y:  5  5  5
```

Это змейка из трёх сегментов на одной строке. Элемент с индексом `0`
— **голова** (`x=9, y=5`), дальше идёт тело. Длину храним отдельно в
переменной `snake_len`.

Можно было бы завести структуру с полями `x` и `y` и один массив таких
структур (глава 11) — это хорошее упражнение. Два отдельных массива
берём, чтобы в коде было поменьше значков: `snake_x[i]` вместо
`snake[i].x`.

Как змейка делает шаг? Представь гусеницу: каждый сегмент
переползает на место предыдущего, а голова делает шаг в новую
клетку. Сдвинули тело — поставили новую голову. Всё.

```text
было:   голова(9,5)  тело(8,5)  тело(7,5)
сдвиг:  ?(9,5)        (9,5)      (8,5)      <- каждый занял место соседа
голова: (10,5)        (9,5)      (8,5)      <- голова шагнула вправо
```

Направление движения тоже храним парой чисел `dir_x, dir_y`:
вправо — это `(1, 0)`, влево — `(-1, 0)`, вверх — `(0, -1)`, вниз —
`(0, 1)`. Обрати внимание: вверх — это **минус** по `y`, потому что
строки нумеруются сверху вниз (нулевая строка — самая верхняя).

### Почему обычный ввод не подходит

По умолчанию терминал работает в **каноническом режиме** (canonical
mode, его ещё зовут «строчным»). Это значит две вещи:

1. Терминал **ждёт Enter**. Что бы ты ни печатал, программа ничего не
   получит, пока ты не нажмёшь Enter. Вся строка копится в буфере.
2. Терминал **печатает эхо** — показывает на экране каждый набранный
   символ.

Для обычной программы это удобно: можно стереть опечатку до Enter. Но
для игры — катастрофа. Змейка должна реагировать на `d` сразу, а не
ждать Enter. И буквы `wasd` не должны замусоривать наше поле.

Значит, нам нужно временно выключить два этих поведения: ожидание
Enter и эхо. А ещё сделать чтение **неблокирующим**. Обычное чтение
блокирующее: программа стоит и ждёт, пока ты нажмёшь клавишу, — так
работают `scanf` и `getchar`. Змейке так нельзя: она ползёт и без
ввода, а клавишу только иногда проверяет.

Всё это делается через `termios` — набор настроек терминала из POSIX.
POSIX — общий стандарт, которого держатся macOS и Linux: он добавляет к
языку Си функции для работы с терминалом, файлами, процессами. На Windows механизм другой (там для той
же задачи берут `_getch` из `<conio.h>`), но мы пишем под
macOS/Linux.

## Шаг 1. Поле и неподвижная змейка

Начнём с самого простого: нарисуем рамку, змейку и еду — пока без
всякого движения. Цель шага — увидеть картинку.

```c
#include <stdio.h>

#define WIDTH   20
#define HEIGHT  10

int main(void)
{
    int snake_x[3] = {9, 8, 7};
    int snake_y[3] = {5, 5, 5};
    int snake_len = 3;

    /* верхняя рамка */
    for (int x = 0; x < WIDTH + 2; x++) {
        putchar('#');
    }
    putchar('\n');

    for (int y = 0; y < HEIGHT; y++) {
        putchar('#');                       /* левая стенка */
        for (int x = 0; x < WIDTH; x++) {
            char ch = ' ';
            for (int i = 0; i < snake_len; i++) {
                if (snake_x[i] == x && snake_y[i] == y) {
                    ch = (i == 0) ? 'O' : 'o';
                    break;
                }
            }
            putchar(ch);
        }
        putchar('#');                       /* правая стенка */
        putchar('\n');
    }

    /* нижняя рамка */
    for (int x = 0; x < WIDTH + 2; x++) {
        putchar('#');
    }
    putchar('\n');
    return 0;
}
```

Разбор нового:

- `#define WIDTH 20` — именованная константа, как `H` и `W` в сапёре
  (см. главу 16): препроцессор перед компиляцией заменит везде в тексте
  `WIDTH` на `20`. Захочешь поле побольше — поменяешь одну строку.
- `WIDTH` и `HEIGHT` — ширина и высота **внутренней** части поля, без
  рамки. Рамка добавляет по одному символу слева и справа, поэтому в
  цикле рамки идёт `WIDTH + 2`.
- `putchar('#')` — функция из `stdio.h`, печатает **один символ**.
  Это как `printf("%c", '#')`, только короче: не нужна строка формата.
  Аргумент — символ в одинарных кавычках (точнее, его код, тип `int`).
- Внешний цикл по `y` идёт по строкам поля (0..HEIGHT−1), внутренний
  по `x` — по столбцам (0..WIDTH−1). Для каждой клетки `(x, y)`
  решаем, что в ней напечатать.
- `char ch = ' ';` — по умолчанию клетка пустая (пробел).
- Внутренний цикл `for (int i = 0; ...)` проверяет: не стоит ли в этой
  клетке сегмент змейки? Если координаты сегмента `i` совпали с `(x,
  y)`, рисуем символ.
- `ch = (i == 0) ? 'O' : 'o';` — тернарный оператор из главы 13.
  Читается так: «если `i == 0`, то значение `'O'`, иначе `'o'`».
  Голова (индекс 0) — заглавная `O`, тело — строчная `o`.
- `break;` — как только нашли сегмент в клетке, выходим из
  внутреннего цикла: дальше проверять нет смысла.

Скомпилируй и запусти:

```text
######################
#                    #
#                    #
#                    #
#                    #
#                    #
#       ooO          #
#                    #
#                    #
#                    #
#                    #
######################
```

Поле есть, змейка на месте (голова `O` справа, тело `oo` слева). Но
она не двигается. Чиним.

## Шаг 2. Заставляем змейку ползти

Чтобы змейка двигалась, нужен **игровой цикл**: бесконечно повторяем
«сдвинули змейку → перерисовали поле → подождали чуть-чуть». А чтобы
картинка не уезжала вниз простынёй, перед каждой отрисовкой будем
**очищать экран**.

Очистка делается специальной командой для терминала —
**управляющей последовательностью** (escape sequence):

```c
printf("\033[H\033[2J");
```

Разберём по кускам:

- `\033` — это символ Escape (его код 27). Запись `\033` — способ
  записать символ по его номеру; номер тут в восьмеричной записи:
  3 · 8 + 3 = 27. Просто запомни: `\033` — это Escape. С него
  начинаются почти все команды управления терминалом. Терминал,
  увидев Escape и `[`, понимает: дальше не текст для печати, а
  команда.
- `\033[H` — команда «переместить курсор в левый верхний угол»
  (Home). Следующая печать пойдёт с самого верха.
- `\033[2J` — команда «стереть весь экран» (J — erase, 2 — целиком).

Вместе `\033[H\033[2J` — «очисти экран и поставь курсор в угол». Это
работает в любом нормальном терминале macOS/Linux.

Теперь сдвиг змейки. Как договорились, тело переползает по цепочке, а
голова шагает в направлении `dir`:

```c
/* сдвигаем тело: каждый сегмент встаёт на место предыдущего */
for (int i = snake_len - 1; i > 0; i--) {
    snake_x[i] = snake_x[i - 1];
    snake_y[i] = snake_y[i - 1];
}
/* голова делает шаг */
snake_x[0] += dir_x;
snake_y[0] += dir_y;
```

Идти надо **с хвоста к голове** (`i` от конца к 1). Если бы мы шли с
головы, то затёрли бы координаты, которые ещё нужны соседнему
сегменту.

Чтобы между кадрами была видимая пауза, нужна функция `usleep`
(*microsecond sleep* — «спать микросекунды») из `<unistd.h>`. Она
считается устаревшей (на замену есть `nanosleep`), но и macOS, и Linux
её по-прежнему поддерживают, а для игры она проще всех:

```c
usleep(150000);   /* 150 000 микросекунд = 0,15 секунды */
```

В одной секунде миллион микросекунд, так что `150000` — это примерно
0,15 секунды между кадрами. Чем меньше число, тем быстрее змейка.

Маленькая деталь сборки. `usleep` — не из стандарта Си, а из POSIX. На
Linux строгий флаг `-std=c11` прячет её объявление, и без подсказки
сборка там ругнётся. Подсказка — строка в самом начале файла, **до всех
`#include`**:

```c
#define _DEFAULT_SOURCE
```

Она просит заголовки показать и POSIX-функции тоже. На маке она ничего
не меняет (там `usleep` видна и так), но и не мешает, а файл
соберётся одинаково на обеих системах. `#define` без значения просто
«включает» имя, само число тут ни при чём.

Соберём шаг 2 целиком — змейка ползёт вправо сама:

```c
#define _DEFAULT_SOURCE
#include <stdio.h>
#include <unistd.h>

#define WIDTH   20
#define HEIGHT  10

int main(void)
{
    int snake_x[3] = {9, 8, 7};
    int snake_y[3] = {5, 5, 5};
    int snake_len = 3;
    int dir_x = 1;              /* ползём вправо */
    int dir_y = 0;

    for (int step = 0; step < 8; step++) {   /* пока 8 шагов для пробы */
        printf("\033[H\033[2J");

        /* рисуем поле */
        for (int x = 0; x < WIDTH + 2; x++) {
            putchar('#');
        }
        putchar('\n');
        for (int y = 0; y < HEIGHT; y++) {
            putchar('#');
            for (int x = 0; x < WIDTH; x++) {
                char ch = ' ';
                for (int i = 0; i < snake_len; i++) {
                    if (snake_x[i] == x && snake_y[i] == y) {
                        ch = (i == 0) ? 'O' : 'o';
                        break;
                    }
                }
                putchar(ch);
            }
            putchar('#');
            putchar('\n');
        }
        for (int x = 0; x < WIDTH + 2; x++) {
            putchar('#');
        }
        putchar('\n');

        /* двигаем змейку */
        for (int i = snake_len - 1; i > 0; i--) {
            snake_x[i] = snake_x[i - 1];
            snake_y[i] = snake_y[i - 1];
        }
        snake_x[0] += dir_x;
        snake_y[0] += dir_y;

        usleep(150000);
    }
    return 0;
}
```

Запусти — увидишь, как змейка проползает вправо восемь шагов и
программа завершается. Уже живая картинка! Но управлять ей мы пока не
можем, а на стену она просто уедет. Добавим управление.

## Шаг 3. Ловим клавиши без Enter — сырой режим

Это сердце главы. Нам нужно:

1. выключить ожидание Enter и эхо (сырой режим);
2. читать клавишу **не блокируясь** — нет нажатия, идём дальше;
3. в конце игры **вернуть** терминал в обычное состояние.

Но сначала наведём порядок в самой программе, иначе всё новое просто
некуда будет положить.

### Раскладываем программу по функциям

В шаге 2 весь код живёт в `main`, и это уже сорок строк. Дальше
добавятся клавиши, еда, рост, столкновения — `main` разрастётся в
простыню, в которой ничего не найти. Поэтому разложим её по
функциям: `draw()` рисует кадр, `update()` делает один шаг змейки. В
`main` останется только игровой цикл.

Тут же всплывает загвоздка. Массивы `snake_x`, `snake_y` и направление
нужны и `draw`, и `update`, а локальные переменные `main` другим
функциям не видны. Передавать всё аргументами — по пять-шесть штук в
каждую функцию. Проще вынести состояние игры **из** `main`, выше всех
функций, — в глобальные переменные (они встречались в главе 5): их
видят все функции файла.

```c
#define WIDTH   20
#define HEIGHT  10
#define MAX_LEN (WIDTH * HEIGHT)   /* змейка не длиннее всех клеток */

int snake_x[MAX_LEN];   /* координаты сегментов: [0] — голова */
int snake_y[MAX_LEN];
int snake_len;          /* сколько сегментов сейчас */
int dir_x;              /* куда голова поедет в следующем кадре */
int dir_y;
int game_over;          /* 0 — играем, 1 — конец */
```

- `MAX_LEN` — сколько сегментов вообще может быть у змейки. Скоро она
  начнёт расти, и массивы на три элемента уже не годятся. Длиннее, чем
  клеток на поле (20 · 10 = 200), змейка не станет, поэтому массивы
  берём ровно на 200.
- Скобки в `(WIDTH * HEIGHT)` нужны потому, что препроцессор
  подставляет текст, а не число. Без скобок `MAX_LEN - 1` превратилось
  бы в `20 * 10 - 1` — тут повезло, это 199. А вот `100 / MAX_LEN`
  стало бы `100 / 20 * 10`, то есть 50, хотя 100 / 200 в целых числах
  даёт 0. Макрос с выражением всегда бери в скобки.
- Глобальные переменные Си обнуляет сам при старте программы (глава 9),
  так что `game_over` с самого начала равен 0.

Функция шага — это кусок «двигаем змейку» из шага 2, просто
переехавший в отдельную функцию:

```c
void update(void)
{
    for (int i = snake_len - 1; i > 0; i--) {
        snake_x[i] = snake_x[i - 1];
        snake_y[i] = snake_y[i - 1];
    }
    snake_x[0] += dir_x;
    snake_y[0] += dir_y;
}
```

`draw()` точно так же забирает себе весь код рисования рамки и змейки.
А главный цикл теперь крутится не восемь шагов, а пока игра не
кончилась:

```c
while (!game_over) {
    /* ...здесь будем читать клавиши... */
    update();
    draw();
    usleep(150000);
}
```

Целиком программа шага 3 будет чуть ниже, когда к ней добавятся
клавиши. Сначала разберёмся с терминалом.

### Включаем сырой режим

Подключаем заголовки:

```c
#include <termios.h>   /* настройки терминала */
#include <unistd.h>    /* read, STDIN_FILENO, usleep, _exit */
#include <signal.h>    /* signal — перехват Ctrl+C */
```

`<termios.h>` даёт структуру `struct termios` (набор флагов
терминала) и функции `tcgetattr`/`tcsetattr` (прочитать и записать
эти настройки). `STDIN_FILENO` из `<unistd.h>` — имя для числа 0. Дело
в том, что система нумерует открытые у программы каналы: 0 — ввод с
клавиатуры, 1 — вывод на экран, 2 — вывод ошибок. Функциям терминала
мы будем говорить «настрой канал 0», а `STDIN_FILENO` читается
понятнее голого нуля. `<signal.h>` понадобится чуть ниже, когда будем
страховаться от Ctrl+C.

```c
struct termios orig_termios;   /* сюда сохраним исходные настройки */
int raw_saved;                 /* 1 — orig_termios заполнен */

/* Вернуть терминал в нормальный режим. */
void disable_raw_mode(void)
{
    if (raw_saved) {
        tcsetattr(STDIN_FILENO, TCSANOW, &orig_termios);
    }
}

/* Применить игровой режим поверх сохранённых настроек. */
void apply_raw_mode(void)
{
    struct termios raw = orig_termios;          /* копия для правки */

    raw.c_lflag = raw.c_lflag & ~(ICANON | ECHO); /* без Enter и эха */
    raw.c_cc[VMIN] = 0;                         /* read не ждёт символов */
    raw.c_cc[VTIME] = 0;                        /* и не ждёт по таймеру */

    tcsetattr(STDIN_FILENO, TCSANOW, &raw);     /* применить сейчас же */
}

/* Включить «сырой» неблокирующий ввод: без ожидания Enter и без эха.
   Возвращает 1 при успехе, 0 — если ввод не терминал (пайп, файл). */
int enable_raw_mode(void)
{
    if (tcgetattr(STDIN_FILENO, &orig_termios) == -1) {
        return 0;                               /* это не терминал */
    }
    raw_saved = 1;                              /* запомнили как было */
    apply_raw_mode();
    return 1;
}
```

Разбираем по строчкам:

- `struct termios orig_termios;` — глобальная переменная под исходные
  настройки. `struct termios` — структура с настройками терминала (про
  структуры мы говорили в главе 11).
- `tcgetattr(STDIN_FILENO, &orig_termios)` — **прочитать** текущие
  настройки терминала и сложить в `orig_termios`. `&` — адрес: функция
  запишет настройки в нашу переменную (как `scanf` пишет по адресу).
  Возвращает `0` при успехе и `-1` при ошибке — и вот это возвращаемое
  значение проверять надо. Если стандартный ввод не терминал, у него
  просто нет настроек терминала. Так бывает, когда программу запускают
  как `./snake < file.txt` или через пайп — это когда вывод одной
  команды подают на вход другой знаком `|`. Тогда `tcgetattr` отдаст
  `-1`, и ничего полезного в `orig_termios` не окажется.
- `raw_saved` — флажок «в `orig_termios` лежит что-то настоящее».
  `disable_raw_mode` смотрит на него и не пытается ничего чинить, если
  чинить нечего.
- `struct termios raw = orig_termios;` — делаем **копию**. Исходник
  `orig_termios` бережём нетронутым, чтобы в конце восстановить.
- `raw.c_cc[VMIN] = 0;` и `raw.c_cc[VTIME] = 0;` — массив `c_cc` хранит
  «спецсимволы» и параметры чтения. Два нуля вместе означают: «чтение
  возвращает управление **сразу**, даже если ничего не нажато». Это и
  есть неблокирующее чтение. Обычное, блокирующее, ведёт себя как
  `scanf`: программа стоит и ждёт клавишу. Нам так нельзя — змейка
  должна ползти и без нажатий.
- `tcsetattr(STDIN_FILENO, TCSANOW, &raw)` — **записать** новые
  настройки. `TCSANOW` — «применить немедленно».
- `disable_raw_mode` делает обратное: возвращает сохранённый
  `orig_termios`. Её **обязательно** вызвать в конце, иначе после игры
  терминал останется без эха и будет вести себя странно.

Осталась строка `raw.c_lflag = raw.c_lflag & ~(ICANON | ECHO);` —
самая важная и самая непривычная. В ней три значка, которых в книге
ещё не было: `|`, `~` и одиночный `&`. Разберём на картинке.

`c_lflag` — одно число, но работает оно как ряд лампочек: каждый его
бит (двоичная цифра) отвечает за свой режим терминала. Бит равен 1 —
режим включён, 0 — выключен. `ICANON` (ожидание Enter) и `ECHO` (эхо)
— это числа, в которых горит ровно одна лампочка, каждая своя. Возьмём
для наглядности восемь бит (в настоящем `c_lflag` их больше, но
работает так же):

```text
c_lflag было:      0101 1010   какие-то режимы включены
ICANON | ECHO:     0000 1010   две лампочки, которые хотим погасить
~(ICANON | ECHO):  1111 0101   маска «всё, кроме этих двух»
было & маска:      0101 0000   эти две погасли, остальные как были
```

- `|` — побитовое ИЛИ: бит результата равен 1, если он равен 1 **хотя
  бы в одном** из чисел. Так из двух флагов собирается одно число, где
  горят обе лампочки.
- `~` — побитовое НЕ: переворачивает каждый бит, 0 в 1 и 1 в 0.
  Получается маска, где горит всё, **кроме** наших двух флагов.
- `&` (одиночный, между двумя числами) — побитовое И: бит результата
  равен 1, только если он равен 1 **в обоих** числах. Там, где в маске
  нули, результат обязательно гаснет; там, где единицы, бит остаётся
  каким был.

Итог: все прочие режимы терминала не тронуты, а ожидание Enter и эхо
выключены. В чужом коде ты почти всегда увидишь ту же строку короче:
`raw.c_lflag &= ~(ICANON | ECHO);`. Запись `x &= y` значит `x = x & y`
— так же, как `x += y` значит `x = x + y`.

Зачем включение разбито на две функции — `apply_raw_mode` и
`enable_raw_mode`? Сохранять исходные настройки надо ровно **один
раз**, при старте. А вот включать игровой режим придётся ещё и потом:
когда игру усыпят по Ctrl+Z и разбудят обратно, терминал надо будет
забрать снова. Если бы обе задачи жили в одной функции, второй вызов
затёр бы `orig_termios` уже сырыми настройками — и восстанавливать
стало бы нечего.

В `main` проверяем результат и честно отказываемся играть, если
клавиатуры нет:

```c
if (!enable_raw_mode()) {
    fprintf(stderr, "Змейке нужен настоящий терминал: "
                    "запусти ./snake без пайпа и без < файла.\n");
    return 1;
}
```

Без этой проверки игра пошла бы дальше вслепую: `read` за первый же
кадр выгребет всё, что пришло по пайпу, а потом змейка поедет сама, и
управлять ею будет нечем.

`fprintf(stderr, ...)` — тот же `printf`, но пишет в **поток ошибок**
`stderr` (тот самый канал номер 2), а не в обычный вывод. Сообщения о
проблемах принято отправлять туда: их видно на экране, но они не
попадут в файл, если вывод программы куда-то перенаправили. Проверить
это легко:

```text
printf 'dddd' | ./snake
```

```text
Змейке нужен настоящий терминал: запусти ./snake без пайпа и без < файла.
```

### Страховка: терминал надо вернуть в любом случае

«Вызвать в конце» звучит просто, но конец бывает разный. Игра может
закончиться нормально — тогда мы дойдём до `disable_raw_mode` сами.
А может и не дойти: ты нажмёшь Ctrl+C, программа упадёт, ты закроешь
её из другого окна. Терминал при этом останется в сыром режиме, и сама
программа его уже не починит.

Насколько это заметно, зависит от оболочки (оболочка, она же шелл, —
программа, которая показывает приглашение и запускает твои команды; на
маке по умолчанию это zsh). Я проверил на этом маке. zsh после конца
каждой программы сам возвращает терминалу свои настройки, и там
поломку можно не заметить вовсе. bash чинит терминал, если программу
убил сигнал или она уснула. Если же она завершилась сама и режим не
вернула, набранных букв не видно, команды выполняются вслепую, а `cat` и другие
программы, читающие ввод, ведут себя странно. Проверь сам: набери
`bash`, а в нём запусти змейку, в которой забыт `disable_raw_mode`, и
выйди по `q` (спасает команда `reset`, набранная вслепую). Рассчитывать
на заботливую оболочку программа не должна: её могут запустить из
скрипта, который ничего чинить не станет.

Первая подпорка — `atexit`:

```c
atexit(disable_raw_mode);      /* вернуть режим при любом выходе */
```

`atexit(функция)` из `<stdlib.h>` регистрирует функцию, которую система
вызовет **при нормальном завершении программы** — хоть через `return`
из `main`, хоть через `exit()` откуда угодно. Функцию мы тут передаём
в другую функцию — тот же приём, что с функцией сравнения для `qsort`
в главе 8. Имя пишется **без скобок**:

- `atexit(disable_raw_mode)` — «вот функция, вызови её потом, при
  выходе». Так правильно.
- `atexit(disable_raw_mode())` — ошибка: скобки вызывают функцию прямо
  сейчас, и в `atexit` пошёл бы её результат. А результата у функции
  `void` нет, так что компилятор такое не соберёт: `passing 'void' to
  parameter of incompatible type`.

Но `atexit` не спасает от **сигналов**. Сигнал — короткое уведомление,
которое ядро (сердцевина операционной системы) посылает процессу, то
есть запущенной программе. Самый знакомый пример: ты жмёшь Ctrl+C, и
ядро посылает игре сигнал `SIGINT`. Что делать с сигналом, решает
программа, а если она ничего не решила, срабатывает поведение по
умолчанию: умереть немедленно. Мимо `atexit`, мимо всего. Терминал
остаётся в сыром режиме.

Поэтому перехватим `SIGINT` своей функцией — **обработчиком**:

```c
/* Ctrl+C, kill, закрытие окна: чиним терминал и выходим сами. */
void on_fatal_signal(int sig)
{
    disable_raw_mode();
    _exit(128 + sig);    /* 128 + номер сигнала — так принято в шеллах */
}
```

И скажем системе, что звать её надо именно на `SIGINT`:

```c
signal(SIGINT, on_fatal_signal);    /* Ctrl+C */
```

- `signal(НОМЕР, функция)` из `<signal.h>` говорит: «когда придёт вот
  этот сигнал, вызови вот эту функцию вместо поведения по умолчанию».
  Функция снова передаётся без скобок, как в `atexit`.
- `int sig` — номер пришедшего сигнала; такова обязательная подпись
  обработчика. Здесь он даже пригодился: подставляем его в код выхода.
- Зачем обработчику завершать программу самому? Если из него просто
  вернуться, программа продолжит играть, как будто Ctrl+C никто не
  нажимал. Поэтому, починив терминал, выходим сами.
- `_exit(...)` из `<unistd.h>` завершает процесс **немедленно**. Не
  обычный `exit`, потому что сигнал может прилететь в любой момент,
  хоть посреди работы `printf`, и звать из обработчика можно далеко не
  всё. `_exit` и `tcsetattr` — из короткого списка того, что можно.
  Обратная сторона: `_exit` не допечатывает то, что `printf` ещё держал
  в памяти, и последняя строка на экране может оборваться. Для
  аварийного выхода это нормальная цена.
- `128 + sig` — подражаем правилу шеллов: если программу убил сигнал
  номер `N`, шелл показывает её код завершения (переменная `$?`) как
  `128 + N`. У `SIGINT` номер 2, значит, после Ctrl+C `echo $?`
  напечатает 130.

Тем же обработчиком закрываем ещё три способа убить программу:

- `SIGTERM` — кто-то сделал `kill НОМЕР` из другого окна (код выхода
  128 + 15 = 143);
- `SIGQUIT` — ты нажал Ctrl+`\` (код 131);
- `SIGHUP` — закрыли окно терминала (код 129).

```c
signal(SIGINT, on_fatal_signal);    /* Ctrl+C */
signal(SIGTERM, on_fatal_signal);   /* kill */
signal(SIGQUIT, on_fatal_signal);   /* Ctrl+\ */
signal(SIGHUP, on_fatal_signal);    /* окно закрыли */
```

Все четыре кода я проверил запуском: Ctrl+C даёт 130, Ctrl+`\` — 131,
`kill` — 143, закрытие окна (`SIGHUP`) — 129.

### Ctrl+Z и команда fg

Ctrl+Z тоже присылает сигнал, но он программу не убивает, а
**усыпляет**: игра замирает, и ты снова в командной строке. Разбудить
её можно командой `fg`. Пока игра спит, терминал должен быть обычным —
и тут нам делать ничего не надо: bash и zsh сами возвращают ему
нормальный режим, когда программа засыпает (я проверил обе).

Беда на пробуждении. После `fg` bash отдаёт игре терминал в обычном,
каноническом режиме. Я проверил: без нашей помощи змейка в bash после
`fg` замирает — `read` снова ждёт Enter, — а нажатые буквы печатаются
прямо на поле. zsh возвращает игровой режим сам, но рассчитывать на
это, как мы уже договорились, нельзя.

Пробуждение тоже приходит сигналом, он называется `SIGCONT`. Ловим его
и просто включаем игровой режим заново:

```c
/* Нас разбудили командой fg — снова включаем игровой режим. */
void on_sigcont(int sig)
{
    (void)sig;
    apply_raw_mode();
}
```

```c
signal(SIGCONT, on_sigcont);        /* fg после Ctrl+Z */
```

- `(void)sig;` — номер сигнала тут не нужен, но параметр убрать нельзя,
  а `-Wextra` ругнётся на неиспользованный. Эта строка — общепринятый
  способ сказать компилятору «я знаю про параметр и намеренно его не
  трогаю».
- Вот где пригодилось разделение на две функции: зовём
  `apply_raw_mode`, а не `enable_raw_mode`. Тот бы перезаписал
  `orig_termios` текущими настройками, и настоящие исходные пропали бы.

Полностью герметично это всё равно не получится. Есть сигнал `SIGKILL`
(`kill -9`) — его перехватить нельзя в принципе, такова его роль. Если
кто-то прибьёт игру через `kill -9`, сама программа терминал уже не
вернёт: остаётся надежда на оболочку (bash и zsh в этом случае его
восстанавливают), а если и она не помогла — на `reset`. Это не повод не
ставить остальные подпорки: они закрывают все случаи, которые случаются
в жизни.

### Читаем клавишу

```c
/* Прочитать одну клавишу. Если её нет — вернуть -1 (не ждём ввода). */
int read_key(void)
{
    unsigned char c;                        /* байт 0..255 */
    if (read(STDIN_FILENO, &c, 1) == 1) {   /* прочитали ровно 1 байт */
        return c;
    }
    return -1;                              /* клавиши нет */
}
```

- `read(STDIN_FILENO, &c, 1)` — функция чтения из POSIX (это общий
  стандарт для macOS и Linux, о нём ниже): «прочитать из канала 0 в
  переменную `c` не больше 1 байта». Возвращает, сколько байт реально
  прочла.
- Прочла ровно один — клавишу нажали, отдаём её код. `c` объявлена как
  `unsigned char`: так код байта всегда от 0 до 255 и никогда не
  получится отрицательным, а значит, не спутается с нашим `-1`.
- Нажатия не было — `read` вернёт 0 (мы же сделали неблокирующее
  чтение), и функция вернёт `-1`: «клавиши нет».

### Стрелки и русская раскладка

Первое, что сделает почти любой игрок, — нажмёт стрелки. А стрелка —
это не один байт, а **три**: Escape (код 27), потом `[`, потом буква.
Стрелка вверх приходит как `27 [ A`, вниз — `27 [ B`, вправо — `27 [ C`,
влево — `27 [ D`. Escape — тот же символ, с которого начинается
очистка экрана `\033[H` из шага 2: терминал говорит программе на том
же языке команд.

Если стрелки никак не разбирать, `read_key` отдаст эти байты по
одному, и последняя буква попадёт в обычную проверку клавиш. А там
`A` — это заглавная `a`, то есть «влево»! Я проверил на версии без
разбора стрелок: змейка ползёт вниз, жмёшь стрелку вверх — она
поворачивает влево. Стрелка влево, наоборот, поворачивает вправо.

Поэтому разбор нажатия соберём в одну функцию, и стрелки она сначала
переводит в буквы WASD:

```c
/* Разобрать одно нажатие: WASD, стрелки или q. */
void handle_key(int key)
{
    if (key == 27) {          /* Escape: так начинается стрелка */
        read_key();           /* второй байт '[' просто пропускаем */
        key = read_key();     /* третий байт — буква стрелки */
        if (key == 'A') {
            key = 'w';        /* стрелка вверх — то же, что W */
        } else if (key == 'B') {
            key = 's';        /* вниз */
        } else if (key == 'C') {
            key = 'd';        /* вправо */
        } else if (key == 'D') {
            key = 'a';        /* влево */
        } else {
            return;           /* какая-то другая клавиша — пропускаем */
        }
    }

    if (key == 'w' || key == 'W') {
        set_dir(0, -1);
    } else if (key == 's' || key == 'S') {
        set_dir(0, 1);
    } else if (key == 'a' || key == 'A') {
        set_dir(-1, 0);
    } else if (key == 'd' || key == 'D') {
        set_dir(1, 0);
    } else if (key == 'q' || key == 'Q') {
        game_over = 1;
    }
}
```

- `key == 27` — пришёл Escape, значит, следом лежат ещё два байта той
  же стрелки. Все три байта терминал присылает разом, так что они уже
  ждут в буфере.
- Первый `read_key()` забирает `[` — он нам не нужен, результат просто
  не сохраняем. Второй забирает букву.
- Букву стрелки заменяем на нужную из WASD и идём дальше, в обычную
  проверку. Так каждое направление задано в программе ровно в одном
  месте.
- Если после Escape пришло что-то другое (или ничего: ты нажал сам
  Escape), выходим из функции, ничего не меняя.
- Вторая половина — обычный разбор: WASD меняют направление (учитываем
  и заглавные на случай Caps Lock), `q` — выход.

Теперь про раскладку. Если у тебя включена русская, клавиши W, A, S, D
печатают «ц», «ф», «ы», «в». Это совсем другие коды — каждая русская
буква к тому же занимает два байта, — и ни одна наша проверка на них не
сработает: змейка не слушается, даже `q` не выходит (на его месте
«й»). Перед игрой **переключи раскладку на английскую**. Стрелки от
раскладки не зависят и работают при любой.

### Поворачиваем змейку

Реверс (резкий разворот на 180°) запрещаем — иначе змейка мгновенно
врежется в себя:

```c
void set_dir(int nx, int ny)
{
    if (nx == -dir_x && ny == -dir_y) {
        return;   /* противоположное текущему — игнорируем */
    }
    dir_x = nx;
    dir_y = ny;
}
```

`set_dir` меняет направление, но если новое — точная
противоположность текущему (`nx == -dir_x` и `ny == -dir_y`), просто
выходит, ничего не меняя.

В игровом цикле читаем **все** накопившиеся нажатия за кадр (вдруг ты
нажал несколько раз) и разбираем каждое:

```c
int key;
while ((key = read_key()) != -1) {
    handle_key(key);
}
```

`while ((key = read_key()) != -1)` — присваиваем результат
`read_key()` переменной `key` **и тут же** сравниваем с `-1`. Пока
клавиши есть, крутимся. Опустошили буфер — `read_key` вернёт `-1`,
цикл закончится. Скобки вокруг `key = read_key()` обязательны.

### Собираем шаг 3 целиком

Вот программа шага 3 целиком: поле, движение, WASD, стрелки и `q`.
Еды и столкновений пока нет.

```c
#define _DEFAULT_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <termios.h>
#include <unistd.h>

#define WIDTH   20
#define HEIGHT  10
#define MAX_LEN (WIDTH * HEIGHT)

int snake_x[MAX_LEN];
int snake_y[MAX_LEN];
int snake_len;
int dir_x;
int dir_y;
int game_over;

struct termios orig_termios;
int raw_saved;

void disable_raw_mode(void)
{
    if (raw_saved) {
        tcsetattr(STDIN_FILENO, TCSANOW, &orig_termios);
    }
}

void apply_raw_mode(void)
{
    struct termios raw = orig_termios;
    raw.c_lflag = raw.c_lflag & ~(ICANON | ECHO);
    raw.c_cc[VMIN] = 0;
    raw.c_cc[VTIME] = 0;
    tcsetattr(STDIN_FILENO, TCSANOW, &raw);
}

int enable_raw_mode(void)
{
    if (tcgetattr(STDIN_FILENO, &orig_termios) == -1) {
        return 0;
    }
    raw_saved = 1;
    apply_raw_mode();
    return 1;
}

void on_fatal_signal(int sig)
{
    disable_raw_mode();
    _exit(128 + sig);
}

void on_sigcont(int sig)
{
    (void)sig;
    apply_raw_mode();
}

int read_key(void)
{
    unsigned char c;
    if (read(STDIN_FILENO, &c, 1) == 1) {
        return c;
    }
    return -1;
}

void draw(void)
{
    printf("\033[H\033[2J");
    for (int x = 0; x < WIDTH + 2; x++) {
        putchar('#');
    }
    putchar('\n');
    for (int y = 0; y < HEIGHT; y++) {
        putchar('#');
        for (int x = 0; x < WIDTH; x++) {
            char ch = ' ';
            for (int i = 0; i < snake_len; i++) {
                if (snake_x[i] == x && snake_y[i] == y) {
                    ch = (i == 0) ? 'O' : 'o';
                    break;
                }
            }
            putchar(ch);
        }
        putchar('#');
        putchar('\n');
    }
    for (int x = 0; x < WIDTH + 2; x++) {
        putchar('#');
    }
    putchar('\n');
    printf("WASD или стрелки, q — выход\n");
}

void set_dir(int nx, int ny)
{
    if (nx == -dir_x && ny == -dir_y) {
        return;   /* противоположное текущему — игнорируем */
    }
    dir_x = nx;
    dir_y = ny;
}

void handle_key(int key)
{
    if (key == 27) {
        read_key();
        key = read_key();
        if (key == 'A') {
            key = 'w';
        } else if (key == 'B') {
            key = 's';
        } else if (key == 'C') {
            key = 'd';
        } else if (key == 'D') {
            key = 'a';
        } else {
            return;
        }
    }

    if (key == 'w' || key == 'W') {
        set_dir(0, -1);
    } else if (key == 's' || key == 'S') {
        set_dir(0, 1);
    } else if (key == 'a' || key == 'A') {
        set_dir(-1, 0);
    } else if (key == 'd' || key == 'D') {
        set_dir(1, 0);
    } else if (key == 'q' || key == 'Q') {
        game_over = 1;
    }
}

void update(void)
{
    for (int i = snake_len - 1; i > 0; i--) {
        snake_x[i] = snake_x[i - 1];
        snake_y[i] = snake_y[i - 1];
    }
    snake_x[0] += dir_x;
    snake_y[0] += dir_y;
}

int main(void)
{
    if (!enable_raw_mode()) {
        fprintf(stderr, "Змейке нужен настоящий терминал: "
                        "запусти ./snake без пайпа и без < файла.\n");
        return 1;
    }
    atexit(disable_raw_mode);
    signal(SIGINT, on_fatal_signal);
    signal(SIGTERM, on_fatal_signal);
    signal(SIGQUIT, on_fatal_signal);
    signal(SIGHUP, on_fatal_signal);
    signal(SIGCONT, on_sigcont);

    snake_len = 3;
    snake_x[0] = 10;
    snake_y[0] = 5;
    snake_x[1] = 9;
    snake_y[1] = 5;
    snake_x[2] = 8;
    snake_y[2] = 5;
    dir_x = 1;
    dir_y = 0;

    draw();
    while (!game_over) {
        int key;
        while ((key = read_key()) != -1) {
            handle_key(key);
        }
        if (game_over) {
            break;
        }
        update();
        draw();
        usleep(150000);
    }

    disable_raw_mode();
    printf("Пока!\n");
    return 0;
}
```

Почти всё здесь ты уже видел по кускам. Новое только в `main`:

- Голову ставим в `(10, 5)` — в середину поля шириной 20.
- `if (game_over) { break; }` сразу после чтения клавиш: если нажали
  `q`, выходим из цикла, не делая лишнего шага и не рисуя лишний кадр.
- `disable_raw_mode();` перед прощальным `printf` возвращает терминал
  в нормальный режим, чтобы прощание печаталось уже в нём. Тот же вызов
  потом сделает и `atexit` — это безвредно: функция просто ещё раз
  поставит те же настройки. `atexit` — страховка на случай, если
  программа выйдет из другого места.

Собери и запусти в обычном окне терминала. Змейка ползёт вправо,
стрелки и WASD её поворачивают сразу, без Enter, нажатые буквы на поле
не появляются, `q` выходит, и терминал после этого в порядке. Одно
«но»: стен ещё нет. Уедешь за край — змейка просто пропадёт с экрана и
будет ползти где-то за рамкой. Жми `q`, стены будут в шаге 5.

### Где ломается защита от разворота

Выглядит убедительно. И всё-таки защита от разворота ломается. Цикл
выгребает за кадр **все** нажатия подряд, а `set_dir` сравнивает новое
направление с `dir_x/dir_y` — то есть с результатом предыдущего
нажатия, а не с тем, куда змейка реально ползёт.

Змейка едет вправо, `dir = (1, 0)`. Ты нервно тыкаешь W, а следом A
(обе клавиши успевают попасть в один кадр):

1. `set_dir(0, -1)` — вверх. Проверка: `(0,-1)` против `-(1,0) =
   (-1,0)`. Не совпало, разрешено. Теперь `dir = (0, -1)`.
2. `set_dir(-1, 0)` — влево. Проверка: `(-1,0)` против `-(0,-1) =
   (0,1)`. Не совпало — тоже разрешено! `dir = (-1, 0)`.

Итог: за один кадр направление перевернулось с «вправо» на «влево»
через промежуточное «вверх», и следующий шаг поведёт голову прямо в
собственное тело. Когда в шаге 5 появятся столкновения, это будет
мгновенный проигрыш, причём из-за нажатия, которое игрок считает
законным.

Проверить это можно, не играя: два нажатия за один кадр руками не
поймать, а программой — легко. Возьми программу шага 3 и замени её
`main` на такой:

```c
int main(void)
{
    snake_len = 3;               /* голова в (10,5), тело левее */
    snake_x[0] = 10;
    snake_y[0] = 5;
    snake_x[1] = 9;
    snake_y[1] = 5;
    snake_x[2] = 8;
    snake_y[2] = 5;
    dir_x = 1;                   /* ползём вправо */
    dir_y = 0;

    /* два нажатия за один кадр: W, потом A */
    handle_key('w');
    handle_key('a');
    printf("направление после двух нажатий: (%d,%d)\n", dir_x, dir_y);
    update();
    for (int i = 0; i < snake_len; i++) {
        printf("(%d,%d) ", snake_x[i], snake_y[i]);
    }
    printf("\n");
    return 0;
}
```

Терминал тут не нужен: мы не играем, а просто зовём функции по очереди
и печатаем, что получилось. Запуск:

```text
направление после двух нажатий: (-1,0)
(9,5) (10,5) (9,5)
```

Направление стало «влево». Голова шагнула в `(9,5)` — а там же стоит
последний сегмент тела. Змейка наехала сама на себя.

Чинится это одной идеей: сравнивать надо не с «накопленным»
направлением, а с тем, **куда змейка реально поехала в прошлом
кадре**. Заводим для этого ещё пару глобальных переменных и сравниваем
с ними:

```c
int moved_x;   /* куда змейка реально поехала в прошлом кадре */
int moved_y;

void set_dir(int nx, int ny)
{
    if (nx == -moved_x && ny == -moved_y) {
        return;   /* противоположное реальному движению — игнорируем */
    }
    dir_x = nx;
    dir_y = ny;
}
```

А `update` в самом начале запоминает, с каким направлением работает
этот кадр:

```c
void update(void)
{
    moved_x = dir_x;
    moved_y = dir_y;
    /* ... дальше сдвиг тела и шаг головы, как было ... */
}
```

И в `main` вместе с начальным направлением задаём `moved_x = dir_x;`
и `moved_y = dir_y;` — иначе первый же `set_dir` сравнится с парой
нулей и пропустит что угодно.

Теперь второе нажатие в том же кадре меряется от `moved = (1,0)`, и
`A` отсекается. Тот же опыт после правки (в его `main` тоже добавь две
строки с `moved_x` и `moved_y`):

```text
направление после двух нажатий: (0,-1)
(10,4) (10,5) (9,5)
```

Змейка ушла вверх — ровно то, чего игрок и хотел.

Теперь змейкой можно рулить. Осталась еда, рост и проигрыш.

## Шаг 4. Еда, рост и счёт

Еда `*` лежит в случайной клетке. Съел — змейка прибавляет сегмент, а
счёт растёт. Добавь к глобальным переменным ещё четыре:

```c
int food_x;     /* где лежит еда */
int food_y;
int score;      /* счёт */
int game_won;   /* 1 — змейка заняла всё поле */
```

Случайные числа — `rand` из `<stdlib.h>` (глава 12), так что в начале
`main` нужен `srand((unsigned int)time(NULL));` и `#include <time.h>`.
Кладём еду в свободную клетку:

```c
void place_food(void)
{
    int ok = 0;
    while (!ok) {
        food_x = rand() % WIDTH;
        food_y = rand() % HEIGHT;
        ok = 1;
        for (int i = 0; i < snake_len; i++) {
            if (snake_x[i] == food_x && snake_y[i] == food_y) {
                ok = 0;   /* попали в тело — выбираем заново */
                break;
            }
        }
    }
}
```

- `rand() % WIDTH` — остаток от деления случайного числа на ширину
  даёт число в диапазоне 0..WIDTH−1, то есть допустимый столбец.
  Аналогично для строки.
- Цикл `while (!ok)` повторяет выбор, пока еда не окажется в пустой
  клетке: если случайно попали в тело змейки, ставим `ok = 0` и
  бросаем кубик заново.

Почему «бросай, пока не попадёшь», а не «составь список свободных
клеток и выбери из него»? Потому что так проще, а бросков почти всегда
хватает одного-двух. Свободна половина поля — в среднем хватит двух
бросков. Свободна одна клетка из 200 — понадобится около двухсот. Даже
это компьютер сделает мгновенно, игрок разницы не увидит.

Но здесь спрятана мина замедленного действия, и её стоит увидеть
заранее. А что, если свободных клеток **не осталось вовсе** — змейка
выросла и заняла всё поле до последней клетки? Тогда `ok` никогда не
станет единицей, и программа зависнет навсегда: экран замрёт, а
процессор будет крутить пустой цикл на все сто процентов.

Случай редкий: чтобы до него дожить, надо съесть 197 порций еды подряд,
ни разу не врезавшись. Но «редкий» и «невозможный» — разные вещи, а
зависшая программа — худший из возможных исходов. Проверить нехватку
места нетрудно: если сегментов уже столько же, сколько клеток на поле
(`MAX_LEN`), класть еду некуда.

```c
int place_food(void)
{
    if (snake_len >= MAX_LEN) {
        food_x = -1;              /* свободных клеток нет: убираем еду */
        food_y = -1;              /* с поля, чтобы не закрыла голову */
        return 0;
    }
    int ok = 0;
    while (!ok) {
        food_x = rand() % WIDTH;
        food_y = rand() % HEIGHT;
        ok = 1;
        for (int i = 0; i < snake_len; i++) {
            if (snake_x[i] == food_x && snake_y[i] == food_y) {
                ok = 0;   /* попали в тело — выбираем заново */
                break;
            }
        }
    }
    return 1;
}
```

Функция стала возвращать `int`: `1` — еду положили, `0` — класть
некуда. Тот, кто её зовёт, теперь может отличить одно от другого — и
превратить безвыходную ситуацию в победу, а не в зависание. Ниже, в
`update`, мы так и сделаем.

Строчки `food_x = -1; food_y = -1;` убирают еду с поля: клеток с
координатой −1 нет, и `draw` её нигде не нарисует. Без них на
последнем, победном кадре еда осталась бы там, где её только что
съели, — то есть под головой. А `draw` проверяет еду раньше змейки и
нарисовал бы вместо головы `*`. Эту мелочь я поймал, когда прогнал
логику змейки до полной победы на маленьком поле 6×4: без этих строк
голова и еда на последнем кадре совпадали.

Теперь рост. Хитрость в том, что при сдвиге тела последний сегмент
(хвост) «теряется» — его координаты затираются. Если змейка съела
еду, мы вернём этот хвост обратно, и она станет на сегмент длиннее.
Поэтому в `update` **перед** сдвигом тела запоминаем хвост, а **после**
шага головы проверяем еду:

```c
int tail_x = snake_x[snake_len - 1];
int tail_y = snake_y[snake_len - 1];

/* ...сдвиг тела и шаг головы как раньше... */

if (snake_x[0] == food_x && snake_y[0] == food_y) {
    if (snake_len < MAX_LEN) {
        snake_x[snake_len] = tail_x;   /* отрастили хвост обратно */
        snake_y[snake_len] = tail_y;
        snake_len++;
    }
    score += 10;
    if (!place_food()) {
        game_won = 1;                  /* поле заполнено целиком */
        game_over = 1;
    }
}
```

- `snake_len - 1` — индекс последнего сегмента (помни: нумерация с 0,
  поэтому последний — не `snake_len`, а на единицу меньше).
- Если голова попала на еду, добавляем новый сегмент в позицию
  бывшего хвоста: `snake_x[snake_len] = tail_x`, и увеличиваем длину.
- `if (snake_len < MAX_LEN)` — защита от выхода за границы массива:
  не даём длине превысить размер.
- `score += 10` — за каждую еду 10 очков.
- `if (!place_food())` — а вот и обещанная развязка. Если положить еду
  некуда, значит, змейка заняла всё поле. Это не ошибка и не зависание,
  а самый настоящий выигрыш: поднимаем флаг `game_won` и заканчиваем
  партию. В конце `main` он превратится в отдельную поздравительную
  строчку.

Порядок здесь важен: сначала растим змейку, и только потом зовём
`place_food`. Тогда новая еда точно не окажется под свежим сегментом —
функция проверяет все `snake_len` клеток, включая только что добавленную.

Не дорого ли каждый кадр сдвигать всё тело? В змейке максимум 200
сегментов, сдвиг — 200 пар присваиваний за кадр, компьютер этого не
заметит. Поэтому берём самый понятный способ. Есть и способ без сдвига
— кольцевой буфер из главы 11: двигают не
сегменты, а номер ячейки, где сейчас голова. Для поля в 200 клеток
такая хитрость не нужна.

В `draw` добавляем еду перед проверкой змейки:

```c
if (x == food_x && y == food_y) {
    ch = '*';
} else {
    /* ...поиск сегмента змейки, как раньше... */
}
```

А строка под полем теперь показывает счёт:

```c
printf("Счёт: %d   (WASD или стрелки, q — выход)\n", score);
```

В `main` перед циклом остаётся позвать `place_food();` — чтобы еда
лежала на поле с первого кадра.

## Шаг 5. Столкновения и конец игры

Последний штрих — проигрыш. Игра кончается, если голова вышла за
стену или наехала на собственное тело. Напрашивается: в `update`
сделать шаг, а потом посмотреть, куда попали.

```c
/* сначала шагнули... */
snake_x[0] += dir_x;
snake_y[0] += dir_y;

/* ...потом проверяем стену */
if (snake_x[0] < 0 || snake_x[0] >= WIDTH ||
    snake_y[0] < 0 || snake_y[0] >= HEIGHT) {
    game_over = 1;
    return;
}
```

Логика верная, игра действительно заканчивается. Но запусти, не трогай
клавиши и дай змейке доехать до правой стены — вот последний кадр,
который останется на экране:

```text
######################
#                    #
#                    #
#              *     #
#                    #
#                    #
#                  oo#
#                    #
#                    #
#                    #
#                    #
######################
Счёт: 0   (WASD или стрелки, q — выход)

Игра окончена! Итоговый счёт: 0
```

Тело на месте, а головы нет. И понятно почему: `update` уже сдвинул
голову в клетку `x = 20`, которой на поле не существует, а `draw`
рисует только клетки `0..19` — голову просто некуда поставить. Игрок
видит обезглавленную змейку и недоумевает, обо что он вообще ударился.
Порчи памяти тут нет (в массив мы записали своё же поле `snake_x[0]`),
но картинка врёт.

Чинится сменой порядка: сначала посчитаем, **куда голова собирается**,
проверим это место — и только если оно хорошее, сделаем шаг.

```c
/* куда голова СОБИРАЕТСЯ шагнуть */
int nx = snake_x[0] + dir_x;
int ny = snake_y[0] + dir_y;

/* столкновение со стеной — проверяем ДО шага */
if (nx < 0 || nx >= WIDTH || ny < 0 || ny >= HEIGHT) {
    game_over = 1;
    return;
}

/* столкновение с собственным телом */
for (int i = 1; i < snake_len - 1; i++) {
    if (snake_x[i] == nx && snake_y[i] == ny) {
        game_over = 1;
        return;
    }
}
```

- `nx`, `ny` — «новая x», «новая y». Обычные локальные переменные:
  посчитали будущую клетку, но в змейку её пока не записали.
- Первое условие: будущая клетка левее 0, правее поля, выше 0 или ниже
  поля — это удар о стену. Раз шага не было, змейка осталась на поле
  целиком, и тот же прогон выглядит уже понятно — голова уткнулась в
  стенку:

```text
######################
#                    #
# *                  #
#                    #
#                    #
#                    #
#                 ooO#
#                    #
#                    #
#                    #
#                    #
######################
Счёт: 0   (WASD или стрелки, q — выход)

Игра окончена! Итоговый счёт: 0
```

(Еда лежит в разных местах просто потому, что это два разных запуска —
`srand` каждый раз даёт новое поле.)

- Цикл по телу начинается с `i = 1`: нулевой сегмент — сама голова,
  сравнивать её будущую клетку с её же текущей бессмысленно.
- А вот верхняя граница `i < snake_len - 1` — тонкость, которую легко
  проглядеть. Последний сегмент — хвост, и в этом же кадре он **уползёт**
  со своей клетки: тело вот-вот сдвинется по цепочке. Значит, наехать
  на него нельзя — к моменту, когда голова там окажется, клетка уже
  освободится. Если хвост учитывать, змейка будет ни за что проигрывать
  в тесных поворотах.
- `game_over = 1` поднимает флаг, `return` обрывает шаг: дальше ни тело
  двигать, ни еду проверять незачем.

После проверок идёт то, что мы уже разобрали: запомнили хвост, сдвинули
тело, поставили голову в `(nx, ny)`, посмотрели на еду.

Главный цикл крутится, пока `!game_over`. Как только флаг поднят (или
нажали `q`), выходим, **возвращаем терминал** и печатаем счёт. Собираем
всё вместе.

## Полная программа

Сохрани это как `code/17-snake.c`.

```c
/* Глава 17. Игра «Змейка» в терминале.
 *
 * Управление: W A S D или стрелки, q — выход.
 * Компиляция (macOS/Linux):
 *   cc -std=c11 -Wall -Wextra -O2 17-snake.c -o snake
 *
 * Программа интерактивная: запускать в обычном терминале, не в пайпе.
 */

/* usleep не из стандарта Си, а из POSIX. На Linux строгий -std=c11
   прячет её объявление, и эта строка просит его показать. На macOS
   она ничего не меняет, но и не мешает. Ставить ДО #include. */
#define _DEFAULT_SOURCE

#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <time.h>
#include <termios.h>
#include <unistd.h>

/* ---- Размеры игрового поля (без учёта рамки) ---- */
#define WIDTH   20
#define HEIGHT  10
#define MAX_LEN (WIDTH * HEIGHT)   /* змейка не длиннее всех клеток поля */

/* ---- Состояние игры ---- */
int snake_x[MAX_LEN];   /* координаты сегментов: [0] — голова */
int snake_y[MAX_LEN];
int snake_len;          /* сколько сегментов сейчас */
int dir_x;              /* куда голова поедет в следующем кадре */
int dir_y;
int moved_x;            /* куда она реально поехала в прошлом кадре */
int moved_y;
int food_x;             /* где лежит еда */
int food_y;
int score;              /* счёт */
int game_over;          /* 0 — играем, 1 — конец */
int game_won;           /* 1 — змейка заняла всё поле */

/* ---- Сырой режим терминала ---- */
struct termios orig_termios;   /* сюда сохраним исходные настройки */
int raw_saved;                 /* 1 — orig_termios заполнен */

/* Вернуть терминал в нормальный режим. */
void disable_raw_mode(void)
{
    if (raw_saved) {
        tcsetattr(STDIN_FILENO, TCSANOW, &orig_termios);
    }
}

/* Применить игровой режим поверх сохранённых настроек. */
void apply_raw_mode(void)
{
    struct termios raw = orig_termios;          /* копия для правки */

    raw.c_lflag = raw.c_lflag & ~(ICANON | ECHO); /* без Enter и эха */
    raw.c_cc[VMIN] = 0;                         /* read не ждёт символов */
    raw.c_cc[VTIME] = 0;                        /* и не ждёт по таймеру */

    tcsetattr(STDIN_FILENO, TCSANOW, &raw);     /* применить сейчас же */
}

/* Включить «сырой» неблокирующий ввод: без ожидания Enter и без эха.
   Возвращает 1 при успехе, 0 — если ввод не терминал (пайп, файл). */
int enable_raw_mode(void)
{
    if (tcgetattr(STDIN_FILENO, &orig_termios) == -1) {
        return 0;                               /* это не терминал */
    }
    raw_saved = 1;                              /* запомнили как было */
    apply_raw_mode();
    return 1;
}

/* Ctrl+C, kill, закрытие окна: чиним терминал и выходим сами. */
void on_fatal_signal(int sig)
{
    disable_raw_mode();
    _exit(128 + sig);    /* 128 + номер сигнала — так принято в шеллах */
}

/* Нас разбудили командой fg — снова включаем игровой режим. */
void on_sigcont(int sig)
{
    (void)sig;
    apply_raw_mode();
}

/* Прочитать одну клавишу. Если её нет — вернуть -1 (не ждём ввода). */
int read_key(void)
{
    unsigned char c;                        /* байт 0..255 */
    if (read(STDIN_FILENO, &c, 1) == 1) {   /* прочитали ровно 1 байт */
        return c;
    }
    return -1;                              /* клавиши нет */
}

/* Положить еду в случайную свободную клетку.
   Возвращает 0, если свободных клеток не осталось: змейка заняла всё
   поле. Без этой проверки цикл ниже крутился бы вечно. */
int place_food(void)
{
    if (snake_len >= MAX_LEN) {
        food_x = -1;              /* свободных клеток нет: убираем еду */
        food_y = -1;              /* с поля, чтобы не закрыла голову */
        return 0;
    }
    int ok = 0;
    while (!ok) {
        food_x = rand() % WIDTH;
        food_y = rand() % HEIGHT;
        ok = 1;
        for (int i = 0; i < snake_len; i++) {
            if (snake_x[i] == food_x && snake_y[i] == food_y) {
                ok = 0;   /* попали в тело — выбираем заново */
                break;
            }
        }
    }
    return 1;
}

/* Нарисовать поле, змейку, еду и счёт. */
void draw(void)
{
    printf("\033[H\033[2J");   /* курсор в угол + очистка экрана */

    /* верхняя рамка */
    for (int x = 0; x < WIDTH + 2; x++) {
        putchar('#');
    }
    putchar('\n');

    for (int y = 0; y < HEIGHT; y++) {
        putchar('#');                       /* левая стенка */
        for (int x = 0; x < WIDTH; x++) {
            char ch = ' ';
            if (x == food_x && y == food_y) {
                ch = '*';                   /* еда */
            } else {
                for (int i = 0; i < snake_len; i++) {
                    if (snake_x[i] == x && snake_y[i] == y) {
                        ch = (i == 0) ? 'O' : 'o';   /* голова / тело */
                        break;
                    }
                }
            }
            putchar(ch);
        }
        putchar('#');                       /* правая стенка */
        putchar('\n');
    }

    /* нижняя рамка */
    for (int x = 0; x < WIDTH + 2; x++) {
        putchar('#');
    }
    putchar('\n');

    printf("Счёт: %d   (WASD или стрелки, q — выход)\n", score);
}

/* Сменить направление, не разрешая разворот на 180 градусов.
   Сравниваем с тем, куда змейка ПОЕХАЛА в прошлом кадре (moved_x/moved_y),
   а не с уже накопленным dir_x/dir_y: иначе два нажатия за один кадр
   (вверх, потом влево, пока ползём вправо) сложились бы в разворот. */
void set_dir(int nx, int ny)
{
    if (nx == -moved_x && ny == -moved_y) {
        return;   /* противоположное реальному движению — игнорируем */
    }
    dir_x = nx;
    dir_y = ny;
}

/* Разобрать одно нажатие: WASD, стрелки или q. */
void handle_key(int key)
{
    if (key == 27) {          /* Escape: так начинается стрелка */
        read_key();           /* второй байт '[' просто пропускаем */
        key = read_key();     /* третий байт — буква стрелки */
        if (key == 'A') {
            key = 'w';        /* стрелка вверх — то же, что W */
        } else if (key == 'B') {
            key = 's';        /* вниз */
        } else if (key == 'C') {
            key = 'd';        /* вправо */
        } else if (key == 'D') {
            key = 'a';        /* влево */
        } else {
            return;           /* какая-то другая клавиша — пропускаем */
        }
    }

    if (key == 'w' || key == 'W') {
        set_dir(0, -1);
    } else if (key == 's' || key == 'S') {
        set_dir(0, 1);
    } else if (key == 'a' || key == 'A') {
        set_dir(-1, 0);
    } else if (key == 'd' || key == 'D') {
        set_dir(1, 0);
    } else if (key == 'q' || key == 'Q') {
        game_over = 1;
    }
}

/* Один шаг змейки: сдвиг тела, новая голова, столкновения, еда. */
void update(void)
{
    /* фиксируем направление этого кадра — на него будет смотреть set_dir */
    moved_x = dir_x;
    moved_y = dir_y;

    /* куда голова СОБИРАЕТСЯ шагнуть */
    int nx = snake_x[0] + dir_x;
    int ny = snake_y[0] + dir_y;

    /* столкновение со стеной — проверяем ДО шага, чтобы на последнем
       кадре змейка осталась нарисованной целиком, а не без головы */
    if (nx < 0 || nx >= WIDTH || ny < 0 || ny >= HEIGHT) {
        game_over = 1;
        return;
    }

    /* столкновение с собственным телом. Хвост (последний сегмент) в этом
       кадре уползёт, поэтому его не считаем — вот почему i < snake_len-1. */
    for (int i = 1; i < snake_len - 1; i++) {
        if (snake_x[i] == nx && snake_y[i] == ny) {
            game_over = 1;
            return;
        }
    }

    /* запомним хвост — он пригодится, если змейка вырастет */
    int tail_x = snake_x[snake_len - 1];
    int tail_y = snake_y[snake_len - 1];

    /* сдвигаем тело: каждый сегмент встаёт на место предыдущего */
    for (int i = snake_len - 1; i > 0; i--) {
        snake_x[i] = snake_x[i - 1];
        snake_y[i] = snake_y[i - 1];
    }

    /* голова делает шаг в текущем направлении */
    snake_x[0] = nx;
    snake_y[0] = ny;

    /* съели еду? */
    if (nx == food_x && ny == food_y) {
        if (snake_len < MAX_LEN) {
            snake_x[snake_len] = tail_x;   /* отрастили хвост обратно */
            snake_y[snake_len] = tail_y;
            snake_len++;
        }
        score += 10;
        if (!place_food()) {
            game_won = 1;                  /* поле заполнено целиком */
            game_over = 1;
        }
    }
}

int main(void)
{
    srand((unsigned int)time(NULL));   /* новый «случай» при каждом запуске */

    if (!enable_raw_mode()) {      /* переключаем терминал в игровой режим */
        fprintf(stderr, "Змейке нужен настоящий терминал: "
                        "запусти ./snake без пайпа и без < файла.\n");
        return 1;
    }
    atexit(disable_raw_mode);           /* вернуть режим при любом выходе */
    signal(SIGINT, on_fatal_signal);    /* Ctrl+C */
    signal(SIGTERM, on_fatal_signal);   /* kill */
    signal(SIGQUIT, on_fatal_signal);   /* Ctrl+\ */
    signal(SIGHUP, on_fatal_signal);    /* окно закрыли */
    signal(SIGCONT, on_sigcont);        /* fg после Ctrl+Z */

    /* начальная змейка из 3 сегментов в центре, ползёт вправо */
    snake_len = 3;
    int cx = WIDTH / 2;
    int cy = HEIGHT / 2;
    snake_x[0] = cx;
    snake_y[0] = cy;
    snake_x[1] = cx - 1;
    snake_y[1] = cy;
    snake_x[2] = cx - 2;
    snake_y[2] = cy;
    dir_x = 1;
    dir_y = 0;
    moved_x = dir_x;
    moved_y = dir_y;
    score = 0;
    game_over = 0;
    game_won = 0;

    place_food();
    draw();                        /* показываем стартовое поле сразу */

    while (!game_over) {
        /* разбираем все нажатия, накопившиеся за кадр */
        int key;
        while ((key = read_key()) != -1) {
            handle_key(key);
        }

        if (game_over) {
            break;             /* нажали q */
        }

        update();
        draw();

        usleep(150000);        /* пауза 0,15 с между кадрами */
    }

    disable_raw_mode();        /* счёт печатаем уже в нормальном режиме */

    if (game_won) {
        printf("\nПоле заполнено целиком — ты прошёл игру!\n");
    }
    printf("\nИгра окончена! Итоговый счёт: %d\n", score);
    return 0;
}
```

## Как это работает

Проследим один оборот игрового цикла, пока `game_over` равен 0:

1. **Ввод.** Внутренний `while` вытягивает из буфера все нажатые
   клавиши и отдаёт каждую в `handle_key`. Стрелки там превращаются в
   буквы, WASD меняют `dir_x/dir_y` через `set_dir` (он сверяется с
   `moved_x/moved_y` — направлением прошлого кадра — и не пускает
   разворот), `q` поднимает `game_over`. Нет нажатий — `read_key`
   сразу отдаёт `-1`, и мы не зависаем.
2. **Шаг.** `update` фиксирует `moved_x/moved_y`, считает будущую
   клетку головы `(nx, ny)` и проверяет её на стену и на тело — при
   ударе ставит `game_over` и выходит, ничего не сдвинув. Если клетка
   хорошая, запоминает хвост, сдвигает тело по цепочке и переносит
   голову в `(nx, ny)`. Если там лежала еда — отращивает хвост обратно,
   плюсует счёт и кладёт новую еду.
3. **Отрисовка.** `draw` чистит экран `\033[H\033[2J` и заново рисует
   рамку, еду `*`, голову `O`, тело `o` и строку счёта.
4. **Пауза.** `usleep(150000)` ждёт 0,15 секунды — иначе кадры
   мелькали бы слишком быстро, чтобы что-то разглядеть.

Цикл повторяется, и из быстрой смены кадров рождается плавное
движение. Как закончили — `disable_raw_mode` возвращает терминал в
нормальный вид, и печатается итоговый счёт.

Глобальные переменные (`snake_x`, `dir_x` и прочие) мы вынесли наружу
ещё в шаге 3, чтобы все функции (`update`, `draw`, `place_food`)
работали с одним и тем же состоянием, не передавая кучу аргументов.
Для маленькой игры в один файл это нормально.

## Проверяем

Скомпилируй и запусти:

```text
cc -std=c11 -Wall -Wextra -O2 17-snake.c -o snake
./snake
```

Флаг `-std=c11` задаёт стандарт языка, `-Wall -Wextra` включают
основные предупреждения (их быть не должно), `-O2` — оптимизацию. На
маке файл собирается чисто и без `#define _DEFAULT_SOURCE`; эта строка
нужна, чтобы так же чисто он собрался и на Linux.

Запусти `./snake` **в обычном окне терминала**. Через пайп змейка
играться не будет и честно об этом скажет — мы это специально
предусмотрели. Увидишь поле, змейку в центре и еду. Управляй клавишами
W, A, S, D или стрелками — Enter нажимать **не надо**, змейка
поворачивает сразу. Для WASD раскладка должна быть английской: на
русской эти клавиши печатают «ц ф ы в», и змейка их не узнает.
Наводи голову на `*`: змейка растёт, счёт растёт на 10. Врежешься в
стену или в себя — игра закончится и покажет счёт. Выйти в любой момент
— клавиша `q`.

Вот настоящий кадр из партии: одна еда уже съедена, змейка ползёт
влево (голова `O` слева), следующая порция лежит в правом верхнем углу.

```text
######################
#                   *#
#          Oooo      #
#                    #
#                    #
#                    #
#                    #
#                    #
#                    #
#                    #
#                    #
######################
Счёт: 10   (WASD или стрелки, q — выход)
```

Кстати, полезная проверка на внимательность: по картинке всегда можно
пересчитать счёт. Стартовая змейка — 3 сегмента, каждая еда даёт `+1`
сегмент и `+10` очков. Здесь сегментов четыре (`Oooo`), значит, съедена
ровно одна порция, значит, счёт — 10. Если у тебя в игре числа
разошлись, ищи ошибку в `update`: скорее всего, счёт растёт не там, где
растёт длина.

### Проверяем, что терминал возвращается

Самое неприятное в этой главе — испорченный терминал, поэтому проверь
все выходы явно, один за другим. После каждого пункта просто набери в
терминале любую команду: если буквы видно и Enter работает — всё
хорошо.

1. Обычный конец: врежься в стену. Или нажми `q`.
2. Ctrl+C прямо во время игры.
3. Ctrl+Z во время игры — игра замрёт и вернёт тебя в командную
   строку в нормальном режиме. Набери `fg` — игра проснётся и
   продолжится ровно с того места, снова забрав терминал под себя.
4. Из **другого** окна терминала: `kill НОМЕР` (номер процесса покажет
   `ps` или `pgrep snake`). Игра умрёт, терминал останется рабочим.

Учти, что bash и zsh часть поломок чинят сами, поэтому рабочий
терминал после пунктов 2 и 4 ещё не доказывает, что сработал именно
наш обработчик. Отличить можно по сообщению оболочки. Если процесс
убил сам `SIGTERM`, zsh напечатает `zsh: terminated  ./snake` (bash —
`Terminated: 15`). Если сигнал поймал наш обработчик и вышел через
`_exit`, оболочка промолчит, а `echo $?` покажет 143. Самая наглядная
проверка — пункт 3: после `fg` змейка должна снова слушаться клавиш
без Enter.

Единственный случай, который программа сама не чинит, — `kill -9`:
этот сигнал перехватить нельзя. bash и zsh после него терминал
восстанавливают; если же буквы всё-таки перестали отображаться,
набери вслепую `reset` и нажми Enter.

## Частые ошибки

**Забыл вернуть режим терминала.** Если программа завершится (или
упадёт) до `disable_raw_mode`, терминал останется в сыром режиме. Если
программа вышла сама, в bash ты потом печатаешь, а букв не видно (zsh
починит терминал сам, но рассчитывать на это нельзя). Это не поломка
навсегда — набери вслепую команду `reset` и нажми Enter, терминал
починится. Чтобы такого
не было, зови `disable_raw_mode` перед выходом и подстрахуйся `atexit`
плюс обработчиками сигналов: одного явного вызова в конце `main` мало,
потому что до конца `main` можно и не добраться.

**Подстраховались только от Ctrl+C.** Самая частая половинчатая
починка: повесили обработчик на `SIGINT` и успокоились. А программу
гасят не только с клавиатуры. Запусти игру, найди её номер
(`pgrep snake`) и из другого окна сделай `kill НОМЕР`: если `SIGTERM`
не перехвачен, программа умрёт, не вернув терминал, и вся надежда на
оболочку (zsh скажет об этом строкой `zsh: terminated`). С Ctrl+Z
отдельная беда: без обработчика `SIGCONT` игра в bash после `fg`
получит терминал в обычном режиме, станет ждать Enter и печатать
нажатые буквы прямо на поле. Закрывай все выходы сразу: `SIGINT`,
`SIGTERM`, `SIGQUIT`, `SIGHUP` — на общий обработчик, `SIGCONT` — на
повторное включение игрового режима.

**Не проверил, что ввод вообще терминал.** `tcgetattr` на пайпе или
файле возвращает `-1`, и в структуре не оказывается ничего полезного.
Если результат не проверить, игра запустится с вводом, которым нельзя
управлять: всё, что пришло по пайпу, прочитается в первом кадре, и
змейка уедет в стену сама. Проверяй возвращаемое значение и выходи с
понятным сообщением.

**Змейка на последнем кадре осталась без головы.** Значит, проверка
стены стоит **после** шага головы: голова уже уехала за поле, а `draw`
рисует только клетки внутри рамки. Считай будущую клетку в отдельные
`nx`, `ny`, проверяй их — и шагай только если проверка прошла.

**Картинка мерцает или «лесенкой» уезжает вниз.** Значит, ты не
очищаешь экран перед отрисовкой. Каждый кадр должен начинаться с
`printf("\033[H\033[2J")`. Если мерцание сильное, проверь, что не
печатаешь лишних пустых строк между кадрами.

**Выход за границу массива сегментов.** Если растить змейку без
проверки `if (snake_len < MAX_LEN)`, при заполнении всего поля длина
вылезет за размер массивов `snake_x/snake_y` — порча памяти. Граница
обязательна.

**Поиск свободной клетки крутится вечно.** `place_food` бросает кубик,
пока не попадёт в пустую клетку. Когда пустых клеток не осталось, этот
цикл уже не закончится никогда: программа замирает, а процессор уходит
в потолок. Любой цикл «бросай кубик, пока не повезёт» надо
сопровождать вопросом: «а бывает ли, что не повезёт никогда?» Если
бывает — проверь это условие до цикла и верни отдельный ответ.

**Змейка проигрывает в тесном повороте.** Если в проверке на укус
самой себя дойти циклом до последнего сегмента (`i < snake_len`, а не
`i < snake_len - 1`), змейка будет «врезаться» в собственный хвост,
который в этом же кадре и так уползёт. Хвост — единственный сегмент,
на место которого шагнуть можно.

**Змейка мгновенно проигрывает при развороте.** Без защиты в
`set_dir` нажатие в обратную сторону вгоняет голову в свой второй
сегмент — и сразу «конец игры». Поэтому развороты на 180° запрещены.
И сверяться при этом надо с `moved_x/moved_y` — направлением, в
котором змейка реально сделала прошлый шаг. Если сравнивать с
`dir_x/dir_y`, два быстрых нажатия за один кадр (W, потом A на
движении вправо) проскочат проверку по очереди и всё равно сложатся
в разворот.

**Цикл сдвига тела «съедает» змейку.** Если сдвигать сегменты от
головы к хвосту (а не от хвоста к голове), координаты затрутся раньше
времени, и тело схлопнется. Иди в цикле от `snake_len - 1` к `1`.

**`implicit declaration of function 'usleep'` при `-std=c11`.** Это
сообщение ты увидишь на Linux с glibc: там объявление `usleep` спрятано
от строгого `-std=c11`. Добавь `#define _DEFAULT_SOURCE` в самом начале
файла (до всех `#include`) или собирай с флагом `-D_DEFAULT_SOURCE`. На
macOS такого предупреждения не будет даже без макроса. Не удивляйся,
если у тебя и товарища на разных системах поведение разное: это не
магия, а разные заголовки.

**Змейка не слушается WASD.** Почти всегда это русская раскладка:
клавиши шлют «ц ф ы в», а программа ждёт латинские буквы. Даже `q` не
выходит — на его месте «й». Переключи раскладку на английскую или
рули стрелками: они от раскладки не зависят. Выйти, не меняя
раскладку, можно и по Ctrl+C — терминал наш обработчик всё равно
починит.

**Стрелка вверх поворачивает змейку влево.** Значит, стрелки не
разобраны как три байта `27 [ A`: последняя буква `A` попадает в
проверку `key == 'A'` и читается как заглавная «a», то есть «влево».
Лови Escape (код 27) первым и забирай за ним ещё два байта, как в
`handle_key`.

## Упражнения

1. **Ускорение.** Сделай так, чтобы с каждой съеденной едой игра шла
   быстрее: заведи переменную задержки (например, начать с `150000`) и
   уменьшай её на немного при росте, но не ниже какого-то минимума,
   чтобы змейка не стала неуправляемой. Передавай это значение в
   `usleep`.
   *Что должно получиться:* если начать со `150000` и отнимать `5000`
   за каждую еду до минимума `60000`, то после 18-й порции
   ((150 000 − 60 000) / 5000 = 18) скорость перестанет расти: кадр
   будет идти 0,06 секунды вместо 0,15, то есть в 2,5 раза быстрее.

2. **Пауза.** Добавь клавишу `p` — пауза. По нажатию игра замирает
   (цикл крутится, но `update` не вызывается и рисуется надпись
   «ПАУЗА»), повторное нажатие `p` продолжает.
   *Что должно получиться:* пока пауза, змейка стоит, счёт не
   меняется, клавиши WASD не должны менять направление (иначе на
   паузе можно «накопить» разворот). После второго `p` змейка
   продолжает с той же клетки в прежнюю сторону. Флажок паузы удобно
   переключать так: `paused = !paused;`.

3. **Стены-телепорты.** Сделай режим, где змейка не разбивается о
   стену, а появляется с противоположной стороны. Подсказка: вместо
   проверки на проигрыш заверни будущие координаты по модулю —
   `nx = (nx + WIDTH) % WIDTH; ny = (ny + HEIGHT) % HEIGHT;`. Прибавка
   `+ WIDTH` тут не для красоты: в Си остаток от отрицательного числа
   не бывает положительным (`-1 % 20` даёт `-1`, а не `19`), и без неё змейка
   уедет в индекс `-1`. Проверь на всех четырёх стенах.
   *Что должно получиться:* решение ниже.

4. **Рекорд.** Запоминай лучший счёт за сессию и показывай его рядом с
   текущим. Усложнение: сохраняй рекорд в файл (`fopen`, `fprintf`,
   `fscanf`) и читай при старте, чтобы он жил между запусками.
   *Что должно получиться:* сыграй на 30 очков и выйди — в файле
   (например, `snake-record.txt`) лежит `30`. Следующий запуск
   показывает «Рекорд: 30», партия на 20 очков его не трогает, на 40 —
   переписывает. Если файла ещё нет, `fopen(..., "r")` вернёт `NULL` —
   это не ошибка, рекорд просто равен нулю.

5. **Две еды.** Добавь второй вид еды, которая даёт больше очков, но
   живёт на поле ограниченное число кадров и потом исчезает.
   *Что должно получиться:* например, `$` на 30 очков, живёт 40 кадров
   (40 · 0,15 = 6 секунд). Она не должна появляться ни на теле змейки,
   ни на обычной еде, а съеденная `$` тоже удлиняет змейку. Проверка
   на победу при этом не меняется: сегментов всё так же не больше
   `WIDTH * HEIGHT`.

6. **Размер поля.** Вынеси `WIDTH` и `HEIGHT` в аргументы командной
   строки (`int main(int argc, char *argv[])`), чтобы запускать
   `./snake 30 15`. Подумай, как тогда задать размеры массивов
   (подсказка: `malloc`).
   *Что должно получиться:* `./snake 30 15` рисует рамку шириной
   32 символа и высотой 17 строк (поле плюс по клетке рамки с каждой
   стороны), массивы сегментов — на 30 · 15 = 450 элементов.
   Слишком маленькое поле (скажем, `./snake 2 2`) программа должна
   отклонить: стартовая змейка из трёх клеток в ряд туда не влезет.
   Не забудь `free` перед выходом.

### Решение упражнения 3

В `update` вместо расчёта `nx`, `ny` и проверки стены пишем:

```c
/* стены-телепорты: вышли за край — появились с другой стороны */
int nx = (snake_x[0] + dir_x + WIDTH) % WIDTH;
int ny = (snake_y[0] + dir_y + HEIGHT) % HEIGHT;
```

Проверка на укус самой себя остаётся как была. Разберём числа.
Голова в `x = 19` (последний столбец) едет вправо:
`(19 + 1 + 20) % 20 = 40 % 20 = 0` — вынырнула в столбце 0. Голова в
`x = 0` едет влево: `(0 - 1 + 20) % 20 = 19 % 20 = 19` — последний
столбец. Без `+ 20` получилось бы `-1 % 20 = -1`: в Си знак остатка
совпадает со знаком делимого, и `%` здесь не математический остаток
от деления (тот всегда от 0 до 19), а просто то, что осталось после
деления с отбрасыванием дробной части.

Я проверил все четыре стены, подставив голову к краю и сделав один
шаг `update`:

```text
-1 % 20 = -1, (-1 + 20) % 20 = 19
(19,5) шаг (1,0) -> (0,5), game_over=0
(0,5) шаг (-1,0) -> (19,5), game_over=0
(10,0) шаг (0,-1) -> (10,9), game_over=0
(10,9) шаг (0,1) -> (10,0), game_over=0
```

## Что мы получили

Ты собрал полноценную аркадную игру: поле, самодвижущаяся змейка,
мгновенное управление без Enter, случайная еда, рост, счёт и честный
проигрыш. По дороге разобрал по-настоящему важную тему — **управление
терминалом**: сырой и неблокирующий ввод через `termios`, очистку
экрана управляющими последовательностями и игровой цикл с паузой
`usleep`.

И отдельно — о том, чему научила именно эта глава: **программа
отвечает за то, что она оставит после себя**. Змейка меняет настройки
чужого терминала — значит, обязана вернуть их назад, чем бы дело ни
кончилось: обычным выходом, Ctrl+C, `kill` или Ctrl+Z. Отсюда и
`atexit`, и обработчики сигналов, и проверка `tcgetattr`. Тот же
принцип действует всюду, где программа берёт что-то общее: открытый
файл, выделенную память, запись в базе.

Это тот самый набор, на котором держатся все текстовые
игры — от «Тетриса» до рогаликов.
