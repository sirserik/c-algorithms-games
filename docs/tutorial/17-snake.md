# Глава 17. Игра «Змейка»

Вот мы и добрались до финала. «Змейка» — та самая игра из старых
телефонов: по полю ползёт змейка, ест еду, растёт и не должна
врезаться ни в стену, ни в саму себя. Игра простая на вид, но в ней
сходится всё, что мы прошли: двумерное поле, массивы координат,
структура состояния, случайная еда, цикл и проверки столкновений.

И тут появляется по-настоящему новое. Раньше наши программы ждали,
пока ты нажмёшь клавишу и Enter. Змейка так не умеет: она ползёт
**сама**, а клавишу должна ловить **мгновенно**, без Enter и без
эха на экране. За это отвечает «сырой» режим терминала через
`termios` — главная новая тема главы. Разберём её спокойно и по
частям.

## Что мы сделаем

К концу главы у тебя будет настоящая игра в терминале:

- поле с рамкой из символов `#`;
- змейка (`O` — голова, `o` — тело), которая ползёт сама;
- управление клавишами W A S D **без нажатия Enter**;
- еда `*`, которая появляется в случайном месте; съел — змейка растёт
  и счёт увеличивается;
- проигрыш при столкновении со стеной или с собственным телом;
- победа, если змейка заняла всё поле целиком;
- выход по клавише `q` — и терминал, который остаётся рабочим при
  любом способе закончить игру.

Строить будем как всегда: от простого к сложному. Сначала просто
нарисуем поле и неподвижную змейку. Потом заставим её двигаться. Потом
научимся ловить клавиши. Потом добавим еду и рост. И в конце —
столкновения и проигрыш.

## Разбираем задачу руками

Прежде чем писать код, поймём две вещи: как хранить змейку и почему
обычного ввода тут не хватит.

### Как хранить змейку

Змейка — это цепочка клеток на поле. Каждая клетка — пара чисел:
номер столбца `x` и номер строки `y`. Заведём два массива:

```text
snake_x:  9  8  7
snake_y:  5  5  5
```

Это змейка из трёх сегментов на одной строке. Элемент с индексом `0`
— **голова** (`x=9, y=5`), дальше идёт тело. Длину храним отдельно в
переменной `snake_len`.

Как змейка делает шаг? Представь гусеницу: каждый сегмент
переползает на место предыдущего, а голова делает шаг в новую
клетку. Сдвинули тело — поставили новую голову. Всё.

```text
было:   голова(9,5)  тело(8,5)  тело(7,5)
сдвиг:  ?(9,5)        (9,5)      (8,5)      <- каждый занял место соседа
голова: (10,5)        (9,5)      (8,5)      <- голова шагнула вправо
```

Направление движения тоже храним парой чисел `dir_x, dir_y`:
вправо — это `(1, 0)`, влево — `(-1, 0)`, вверх — `(0, -1)`, вниз —
`(0, 1)`. Обрати внимание: вверх — это **минус** по `y`, потому что
строки нумеруются сверху вниз (нулевая строка — самая верхняя).

### Почему обычный ввод не подходит

По умолчанию терминал работает в **каноническом режиме** (canonical
mode, его ещё зовут «строчным»). Это значит две вещи:

1. Терминал **ждёт Enter**. Что бы ты ни печатал, программа ничего не
   получит, пока ты не нажмёшь Enter. Вся строка копится в буфере.
2. Терминал **печатает эхо** — показывает на экране каждый набранный
   символ.

Для обычной программы это удобно: можно стереть опечатку до Enter. Но
для игры — катастрофа. Змейка должна реагировать на `d` сразу, а не
ждать Enter. И буквы `wasd` не должны замусоривать наше поле.

Значит, нам нужно временно выключить два этих поведения: ожидание
Enter и эхо. А ещё сделать чтение **неблокирующим** — чтобы программа
не зависала, ожидая клавишу, когда её не нажали. Змейка ведь ползёт и
без ввода.

Всё это делается через `termios` — набор настроек терминала в POSIX
(стандарт для macOS и Linux). На Windows механизм другой (там для той
же задачи берут `_getch` из `<conio.h>`), но мы пишем под
macOS/Linux.

## Шаг 1. Поле и неподвижная змейка

Начнём с самого простого: нарисуем рамку, змейку и еду — пока без
всякого движения. Цель шага — увидеть картинку.

```c
#include <stdio.h>

#define WIDTH   20
#define HEIGHT  10

int main(void)
{
    int snake_x[3] = {9, 8, 7};
    int snake_y[3] = {5, 5, 5};
    int snake_len = 3;

    /* верхняя рамка */
    for (int x = 0; x < WIDTH + 2; x++) {
        putchar('#');
    }
    putchar('\n');

    for (int y = 0; y < HEIGHT; y++) {
        putchar('#');                       /* левая стенка */
        for (int x = 0; x < WIDTH; x++) {
            char ch = ' ';
            for (int i = 0; i < snake_len; i++) {
                if (snake_x[i] == x && snake_y[i] == y) {
                    ch = (i == 0) ? 'O' : 'o';
                    break;
                }
            }
            putchar(ch);
        }
        putchar('#');                       /* правая стенка */
        putchar('\n');
    }

    /* нижняя рамка */
    for (int x = 0; x < WIDTH + 2; x++) {
        putchar('#');
    }
    putchar('\n');
    return 0;
}
```

Разбор нового:

- `#define WIDTH 20` — именованная константа, как `H` и `W` в сапёре
  (см. главу 16): препроцессор перед компиляцией заменит везде в тексте
  `WIDTH` на `20`. Захочешь поле побольше — поменяешь одну строку.
- `WIDTH` и `HEIGHT` — ширина и высота **внутренней** части поля, без
  рамки. Рамка добавляет по одному символу слева и справа, поэтому в
  цикле рамки идёт `WIDTH + 2`.
- `putchar('#')` — функция из `stdio.h`, печатает **один символ**.
  Это как `printf("%c", '#')`, только короче: не нужна строка формата.
  Аргумент — символ в одинарных кавычках (точнее, его код, тип `int`).
- Внешний цикл по `y` идёт по строкам поля (0..HEIGHT−1), внутренний
  по `x` — по столбцам (0..WIDTH−1). Для каждой клетки `(x, y)`
  решаем, что в ней напечатать.
- `char ch = ' ';` — по умолчанию клетка пустая (пробел).
- Внутренний цикл `for (int i = 0; ...)` проверяет: не стоит ли в этой
  клетке сегмент змейки? Если координаты сегмента `i` совпали с `(x,
  y)`, рисуем символ.
- `ch = (i == 0) ? 'O' : 'o';` — тернарный оператор из главы 13.
  Читается так: «если `i == 0`, то значение `'O'`, иначе `'o'`».
  Голова (индекс 0) — заглавная `O`, тело — строчная `o`.
- `break;` — как только нашли сегмент в клетке, выходим из
  внутреннего цикла: дальше проверять нет смысла.

Скомпилируй и запусти:

```text
######################
#                    #
#                    #
#                    #
#                    #
#                    #
#       ooO          #
#                    #
#                    #
#                    #
#                    #
######################
```

Поле есть, змейка на месте (голова `O` справа, тело `oo` слева). Но
она не двигается. Чиним.

## Шаг 2. Заставляем змейку ползти

Чтобы змейка двигалась, нужен **игровой цикл**: бесконечно повторяем
«сдвинули змейку → перерисовали поле → подождали чуть-чуть». А чтобы
картинка не уезжала вниз простынёй, перед каждой отрисовкой будем
**очищать экран**.

Очистка делается специальной командой для терминала —
**управляющей последовательностью** (escape sequence):

```c
printf("\033[H\033[2J");
```

Разберём по кускам:

- `\033` — это символ Escape (его код 27). Запись `\033` — код в
  восьмеричной системе. С него начинаются почти все команды
  управления терминалом. Терминал, увидев Escape и `[`, понимает:
  дальше не текст для печати, а команда.
- `\033[H` — команда «переместить курсор в левый верхний угол»
  (Home). Следующая печать пойдёт с самого верха.
- `\033[2J` — команда «стереть весь экран» (J — erase, 2 — целиком).

Вместе `\033[H\033[2J` — «очисти экран и поставь курсор в угол». Это
работает в любом нормальном терминале macOS/Linux.

Теперь сдвиг змейки. Как договорились, тело переползает по цепочке, а
голова шагает в направлении `dir`:

```c
/* сдвигаем тело: каждый сегмент встаёт на место предыдущего */
for (int i = snake_len - 1; i > 0; i--) {
    snake_x[i] = snake_x[i - 1];
    snake_y[i] = snake_y[i - 1];
}
/* голова делает шаг */
snake_x[0] += dir_x;
snake_y[0] += dir_y;
```

Идти надо **с хвоста к голове** (`i` от конца к 1). Если бы мы шли с
головы, то затёрли бы координаты, которые ещё нужны соседнему
сегменту.

Чтобы между кадрами была видимая пауза, нужна функция `usleep`
(*microsecond sleep* — «спать микросекунды») из `<unistd.h>`. Её
придумали в BSD-Unix, потом она попала в стандарт POSIX, а в 2008 году
её оттуда убрали как устаревшую (на замену есть `nanosleep`). Но и
macOS, и Linux её по-прежнему поддерживают, а для игры она проще всех:

```c
usleep(150000);   /* 150 000 микросекунд = 0,15 секунды */
```

В одной секунде миллион микросекунд, так что `150000` — это примерно
0,15 секунды между кадрами. Чем меньше число, тем быстрее змейка.

Маленькая деталь сборки. Мы пишем со стандартом `-std=c11`, а `usleep`
— функция POSIX, не из чистого C11. Флаг `-std=c11` просит компилятор
быть строгим, и часть POSIX-объявлений в заголовках может оказаться
спрятана. Поэтому в самом начале файла, **до всех `#include`**, ставим
строку:

```c
#define _DEFAULT_SOURCE
```

Это «фича-макрос» (feature test macro) — переключатель, которым ты
говоришь заголовкам, какой набор объявлений тебе нужен. `#define` без
значения просто «включает» имя, само число тут ни при чём.

Разберём точно, что этот макрос делает, потому что в интернете на
этот счёт много путаницы:

- На **Linux с glibc** он нужен по-настоящему. Там объявление `usleep`
  в `<unistd.h>` закрыто условием `#if defined __USE_MISC ...`, а
  `__USE_MISC` включается как раз через `_DEFAULT_SOURCE`. Без макроса
  строгий `-std=c11` даст `implicit declaration of function 'usleep'`
  — предупреждение, а в gcc 14 и новее уже ошибку сборки.
- На **macOS** он не меняет ничего. В тамошнем `<unistd.h>` объявление
  `usleep` стоит под условием `#if __DARWIN_C_LEVEL >= 199506L`, а оно
  при обычной сборке истинно, и `-std=c11` его не выключает. Проверить
  это можно за десять секунд — убери `#define` и собери файл: на маке
  соберётся молча.

Так зачем оставлять? Чтобы один и тот же файл собирался без
предупреждений и на маке, и на Linux. Лишний макрос ничего не ломает, а
его отсутствие ломает сборку у половины читателей. Если не хочешь
трогать исходник — тот же эффект даёт флаг `-D_DEFAULT_SOURCE` в
командной строке.

Соберём шаг 2 целиком — змейка ползёт вправо сама:

```c
#define _DEFAULT_SOURCE
#include <stdio.h>
#include <unistd.h>

#define WIDTH   20
#define HEIGHT  10

int main(void)
{
    int snake_x[3] = {9, 8, 7};
    int snake_y[3] = {5, 5, 5};
    int snake_len = 3;
    int dir_x = 1, dir_y = 0;   /* ползём вправо */

    for (int step = 0; step < 8; step++) {   /* пока 8 шагов для пробы */
        printf("\033[H\033[2J");

        /* рисуем поле */
        for (int x = 0; x < WIDTH + 2; x++) putchar('#');
        putchar('\n');
        for (int y = 0; y < HEIGHT; y++) {
            putchar('#');
            for (int x = 0; x < WIDTH; x++) {
                char ch = ' ';
                for (int i = 0; i < snake_len; i++) {
                    if (snake_x[i] == x && snake_y[i] == y) {
                        ch = (i == 0) ? 'O' : 'o';
                        break;
                    }
                }
                putchar(ch);
            }
            putchar('#');
            putchar('\n');
        }
        for (int x = 0; x < WIDTH + 2; x++) putchar('#');
        putchar('\n');

        /* двигаем змейку */
        for (int i = snake_len - 1; i > 0; i--) {
            snake_x[i] = snake_x[i - 1];
            snake_y[i] = snake_y[i - 1];
        }
        snake_x[0] += dir_x;
        snake_y[0] += dir_y;

        usleep(150000);
    }
    return 0;
}
```

Запусти — увидишь, как змейка проползает вправо восемь шагов и
программа завершается. Уже живая картинка! Но управлять ей мы пока не
можем, а на стену она просто уедет. Добавим управление.

## Шаг 3. Ловим клавиши без Enter — сырой режим

Это сердце главы. Нам нужно:

1. выключить ожидание Enter и эхо (сырой режим);
2. читать клавишу **не блокируясь** — нет нажатия, идём дальше;
3. в конце игры **вернуть** терминал в обычное состояние.

Сначала подключаем заголовки:

```c
#include <termios.h>   /* настройки терминала */
#include <unistd.h>    /* read, STDIN_FILENO, usleep, _exit */
#include <signal.h>    /* signal, raise — перехват Ctrl+C и Ctrl+Z */
```

`<termios.h>` даёт структуру `struct termios` (набор флагов
терминала) и функции `tcgetattr`/`tcsetattr` (прочитать и записать
эти настройки). `STDIN_FILENO` из `<unistd.h>` — это номер
стандартного ввода (клавиатуры), равен 0. `<signal.h>` понадобится
чуть ниже, когда будем страховаться от Ctrl+C.

### Включаем сырой режим

```c
static struct termios orig_termios;   /* сюда сохраним исходные настройки */
static int raw_saved;                 /* 1 — orig_termios заполнен */

/* Вернуть терминал в нормальный режим. */
static void disable_raw_mode(void)
{
    if (raw_saved) {
        tcsetattr(STDIN_FILENO, TCSANOW, &orig_termios);
    }
}

/* Применить игровой режим поверх сохранённых настроек. */
static void apply_raw_mode(void)
{
    struct termios raw = orig_termios;         /* копия для правки */

    raw.c_lflag &= ~(ICANON | ECHO);           /* снять канонику и эхо */
    raw.c_cc[VMIN]  = 0;                       /* read не ждёт символов */
    raw.c_cc[VTIME] = 0;                       /* и не ждёт по таймеру */

    tcsetattr(STDIN_FILENO, TCSANOW, &raw);    /* применить сейчас же */
}

/* Смертельный сигнал (Ctrl+C, kill, закрытие окна): чиним терминал и
   только потом умираем. Сигнал убивает процесс мимо atexit — поэтому
   и перехватываем. */
static void on_fatal_signal(int sig)
{
    disable_raw_mode();
    _exit(128 + sig);    /* 128 + номер сигнала — так принято в шеллах */
}

/* Ctrl+Z: отдать терминал шеллу в нормальном виде и честно уснуть. */
static void on_sigtstp(int sig)
{
    (void)sig;
    disable_raw_mode();
    signal(SIGTSTP, SIG_DFL);   /* вернуть штатное поведение... */
    raise(SIGTSTP);             /* ...и остановиться по-настоящему */
}

/* Нас разбудили командой fg — снова забираем терминал под игру. */
static void on_sigcont(int sig)
{
    (void)sig;
    signal(SIGTSTP, on_sigtstp);   /* заново повесить наш обработчик */
    apply_raw_mode();
}

/* Включить «сырой» неблокирующий ввод: без ожидания Enter и без эха.
   Возвращает 1 при успехе, 0 — если ввод не терминал (пайп, файл). */
static int enable_raw_mode(void)
{
    if (tcgetattr(STDIN_FILENO, &orig_termios) == -1) {
        return 0;                              /* это не терминал */
    }
    raw_saved = 1;                             /* запомнили как было */
    apply_raw_mode();
    return 1;
}
```

Разбираем по строчкам:

- `static struct termios orig_termios;` — глобальная переменная под
  исходные настройки. Слово `static` тут значит «видна только в этом
  файле». `struct termios` — структура с настройками терминала (про
  структуры мы говорили в главе 11).
- `tcgetattr(STDIN_FILENO, &orig_termios)` — **прочитать** текущие
  настройки терминала и сложить в `orig_termios`. `&` — адрес: функция
  запишет настройки в нашу переменную (как `scanf` пишет по адресу).
  Возвращает `0` при успехе и `-1` при ошибке — и вот это возвращаемое
  значение проверять надо. Если стандартный ввод не терминал (программу
  запустили как `./snake < file.txt` или через пайп), у него просто нет
  настроек терминала: `tcgetattr` отдаст `-1`, и ничего полезного в
  `orig_termios` не окажется. Без проверки игра пошла бы дальше
  вслепую: `tcsetattr` на пайпе тоже не сработает, `read` за первый же
  кадр выгребет всё, что пришло по пайпу, а потом змейка поедет сама,
  и управлять ею будет нечем.
- `raw_saved` — флажок «в `orig_termios` лежит что-то настоящее».
  `disable_raw_mode` смотрит на него и не пытается ничего чинить, если
  чинить нечего.
- `struct termios raw = orig_termios;` — делаем **копию**. Исходник
  `orig_termios` бережём нетронутым, чтобы в конце восстановить.
- `raw.c_lflag &= ~(ICANON | ECHO);` — самая важная строка. `c_lflag`
  — поле «локальных флагов» терминала; в нём набор включённых режимов.
  - `ICANON` — флаг канонического режима (ожидание Enter).
  - `ECHO` — флаг эха (печать набранного на экран).
  - `ICANON | ECHO` — операцией `|` (побитовое ИЛИ) объединяем оба
    флага в один набор битов.
  - `~(...)` — побитовое НЕ: переворачивает биты, получая «всё, кроме
    этих двух флагов».
  - `&=` — присвоить результат побитового И. Вместе строка означает:
    «оставить все флаги как есть, но **снять** `ICANON` и `ECHO`». Эта
    связка `flag &= ~(БИТЫ)` — стандартный способ выключить биты.
- `raw.c_cc[VMIN] = 0; raw.c_cc[VTIME] = 0;` — массив `c_cc` хранит
  «спецсимволы» и параметры чтения. `VMIN = 0` и `VTIME = 0` вместе
  означают: «чтение возвращает управление **сразу**, даже если ничего
  не нажато». Это и есть неблокирующее чтение — без `fcntl`, штатными
  средствами termios.
- `tcsetattr(STDIN_FILENO, TCSANOW, &raw)` — **записать** новые
  настройки. `TCSANOW` — «применить немедленно».
- `disable_raw_mode` делает обратное: возвращает сохранённый
  `orig_termios`. Её **обязательно** вызвать в конце, иначе после игры
  терминал останется без эха и будет вести себя странно.

Зачем включение разбито на две функции — `apply_raw_mode` и
`enable_raw_mode`? Сохранять исходные настройки надо ровно **один
раз**, при старте. А вот включать игровой режим придётся ещё и потом:
когда игру усыпят по Ctrl+Z и разбудят обратно, терминал надо будет
забрать снова. Если бы обе задачи жили в одной функции, второй вызов
затёр бы `orig_termios` уже сырыми настройками — и восстанавливать
стало бы нечего.

В `main` поэтому проверяем результат и честно отказываемся играть, если
клавиатуры нет:

```c
if (!enable_raw_mode()) {
    fprintf(stderr, "Змейке нужен настоящий терминал: "
                    "запусти ./snake без пайпа и без < файла.\n");
    return 1;
}
```

`fprintf(stderr, ...)` — тот же `printf`, но пишет в **поток ошибок**
`stderr`, а не в обычный вывод. Сообщения о проблемах принято отправлять
туда: их видно на экране, но они не попадут в файл, если вывод программы
куда-то перенаправили. Проверить это легко:

```text
printf 'dddd' | ./snake
```

```text
Змейке нужен настоящий терминал: запусти ./snake без пайпа и без < файла.
```

### Страховка: терминал надо вернуть в любом случае

«Вызвать в конце» звучит просто, но конец бывает разный. Игра может
закончиться нормально — тогда мы дойдём до `disable_raw_mode` сами.
А может и не дойти: ты нажмёшь Ctrl+C, программа упадёт, ты закроешь
её из другого окна. Терминал при этом останется в сыром режиме, и
дальше в нём невозможно работать: печатаешь — букв не видно, жмёшь
Enter — ничего.

Проверь сам: запусти змейку и нажми Ctrl+C. Пока в программе нет
страховки, ты получишь ровно это (спасает команда `reset`, набранная
вслепую). Первая подпорка — `atexit`:

```c
atexit(disable_raw_mode);      /* вернуть режим при обычном выходе */
```

`atexit(функция)` из `<stdlib.h>` регистрирует функцию, которую система
вызовет **при нормальном завершении программы** — хоть через `return`
из `main`, хоть через `exit()`. Аргумент — имя функции без скобок: мы
передаём саму функцию, а не результат её вызова. Теперь, даже если мы
добавим где-то в середине `exit(1)`, терминал всё равно починится.

Но `atexit` не спасает от **сигналов**. Сигнал — это короткое
уведомление, которое ядро посылает процессу; для большинства сигналов
поведение по умолчанию — «умереть немедленно», мимо всех
зарегистрированных функций. Нас касаются пять:

- `SIGINT` — ты нажал Ctrl+C;
- `SIGTERM` — кто-то сделал `kill` (так же процессы гасит система при
  выключении);
- `SIGQUIT` — Ctrl+`\`;
- `SIGHUP` — закрыли окно терминала;
- `SIGTSTP` — ты нажал Ctrl+Z, программу не убивают, а усыпляют.

Первые четыре кончаются смертью, и всем им подойдёт один обработчик:

```c
static void on_fatal_signal(int sig)
{
    disable_raw_mode();
    _exit(128 + sig);    /* 128 + номер сигнала — так принято в шеллах */
}
```

- `int sig` — номер пришедшего сигнала; такова обязательная подпись
  обработчика. Здесь он даже пригодился: подставляем его в код выхода.
- `_exit(...)` из `<unistd.h>` завершает процесс **немедленно**.
  Почему не обычный `exit`? Внутри обработчика сигнала безопасно
  вызывать далеко не всё: сигнал может прилететь в любой момент, хоть
  посреди работы `printf`, и повторный заход в ту же функцию всё
  сломает. `_exit` — из короткого списка того, что вызывать можно
  (`tcsetattr` в нём тоже есть — иначе так починить терминал не вышло
  бы). Обратная сторона: `_exit` не сбрасывает буфер `stdout`, поэтому
  последняя недопечатанная строка на экране может оборваться на
  полуслове. Для аварийного выхода это нормальная цена.
- `128 + sig` — подражаем правилу шеллов: если программу убил сигнал
  номер `N`, шелл показывает её код завершения (переменная `$?`) как
  `128 + N`. У `SIGINT` номер 2, значит, после Ctrl+C `echo $?`
  напечатает 130 — я проверил: Ctrl+C даёт 130, Ctrl+`\` — 131,
  `kill` — 143 (у `SIGTERM` номер 15).

Вешаем его на все четыре сигнала сразу:

```c
signal(SIGINT,  on_fatal_signal);   /* Ctrl+C   */
signal(SIGTERM, on_fatal_signal);   /* kill     */
signal(SIGQUIT, on_fatal_signal);   /* Ctrl+\   */
signal(SIGHUP,  on_fatal_signal);   /* окно закрыли */
```

`signal(НОМЕР, функция)` из `<signal.h>` говорит: «когда придёт вот
этот сигнал, вызови вот эту функцию вместо поведения по умолчанию».

### Ctrl+Z — отдельная история

`SIGTSTP` (Ctrl+Z) не убивает программу, а **усыпляет**: она замирает,
а терминал возвращается шеллу, и ты снова в командной строке. Разбудить
её потом можно командой `fg`. Проблема ровно та же: пока игра спит,
терминал остаётся в сыром режиме — печатаешь и ничего не видишь.

Значит, на засыпание надо вернуть настройки, а на пробуждение — снова
их забрать. Пробуждение тоже приходит сигналом, он называется
`SIGCONT`:

```c
static void on_sigtstp(int sig)
{
    (void)sig;
    disable_raw_mode();
    signal(SIGTSTP, SIG_DFL);   /* вернуть штатное поведение... */
    raise(SIGTSTP);             /* ...и остановиться по-настоящему */
}

static void on_sigcont(int sig)
{
    (void)sig;
    signal(SIGTSTP, on_sigtstp);   /* заново повесить наш обработчик */
    apply_raw_mode();
}
```

- `(void)sig;` — номер сигнала тут не нужен, но параметр убрать нельзя,
  а `-Wextra` ругнётся на неиспользованный. Эта строка — общепринятый
  способ сказать компилятору «я знаю про параметр и намеренно его не
  трогаю».
- Хитрость в `on_sigtstp`. Мы перехватили сигнал — значит, программа
  **не** уснула, обработчик просто отработал и вернул управление в
  игру. А уснуть-то надо. Поэтому: чиним терминал, ставим `SIGTSTP`
  обратно на поведение по умолчанию (`SIG_DFL` — «как было изначально»)
  и `raise(SIGTSTP)` посылаем этот сигнал сами себе. Теперь его никто
  не перехватывает, и процесс честно засыпает.
- `on_sigcont` — зеркало: после `fg` возвращаем свой обработчик
  `SIGTSTP` на место (мы же его только что сняли) и снова включаем
  игровой режим через `apply_raw_mode`. Именно здесь и пригодилось
  разделение на две функции: `enable_raw_mode` тут звать нельзя, он бы
  перезаписал `orig_termios`.

Вешаем обе:

```c
signal(SIGTSTP, on_sigtstp);        /* Ctrl+Z   */
signal(SIGCONT, on_sigcont);        /* fg       */
```

Полностью герметично это всё равно не получится. Есть сигнал `SIGKILL`
(`kill -9`) — его перехватить нельзя в принципе, такова его роль. Если
кто-то прибьёт игру через `kill -9`, терминал останется сырым, и
спасёт только `reset`. Это не повод не ставить остальные подпорки: они
закрывают все случаи, которые случаются в жизни.

### Читаем клавишу

```c
static int read_key(void)
{
    char c;
    ssize_t n = read(STDIN_FILENO, &c, 1);
    if (n == 1) {
        return (unsigned char)c;
    }
    return -1;
}
```

- `read(STDIN_FILENO, &c, 1)` — POSIX-функция чтения: «прочитать из
  стандартного ввода в переменную `c` максимум 1 байт». Возвращает,
  сколько байт реально прочла.
- `ssize_t` — целочисленный тип для результата `read` (может быть и
  отрицательным при ошибке). Считай его «специальным `int` для
  размеров».
- Если `n == 1` — клавишу нажали, возвращаем её код. Приведение
  `(unsigned char)` нужно, чтобы коды не ушли в отрицательные.
- Если нажатия не было, `read` вернёт 0 (мы же сделали неблокирующее
  чтение), и функция вернёт `-1` — «клавиши нет».

Теперь в `main` обернём всё: включим режим в начале, выключим в
конце, а в цикле будем спрашивать `read_key`. Реверс (резкий разворот
на 180°) запрещаем — иначе змейка мгновенно врежется в себя:

```c
static int dir_x, dir_y;

static void set_dir(int nx, int ny)
{
    if (nx == -dir_x && ny == -dir_y) {
        return;   /* противоположное текущему — игнорируем */
    }
    dir_x = nx;
    dir_y = ny;
}
```

`set_dir` меняет направление, но если новое — точная
противоположность текущему (`nx == -dir_x` и `ny == -dir_y`), просто
выходит, ничего не меняя.

Выглядит убедительно. И всё-таки эта версия ломается — сейчас увидим,
как. Но сначала посмотрим, откуда берётся поломка.

В игровом цикле читаем **все** накопившиеся нажатия за кадр (вдруг ты
нажал несколько раз) и применяем их:

```c
int key;
while ((key = read_key()) != -1) {
    if (key == 'w' || key == 'W') set_dir(0, -1);
    else if (key == 's' || key == 'S') set_dir(0, 1);
    else if (key == 'a' || key == 'A') set_dir(-1, 0);
    else if (key == 'd' || key == 'D') set_dir(1, 0);
    else if (key == 'q' || key == 'Q') game_over = 1;
}
```

- `while ((key = read_key()) != -1)` — присваиваем результат
  `read_key()` переменной `key` **и тут же** сравниваем с `-1`. Пока
  клавиши есть, крутимся. Опустошили буфер — `read_key` вернёт `-1`,
  цикл закончится. Скобки вокруг `key = read_key()` обязательны.
- Дальше обычный разбор: WASD меняют направление (учитываем и
  заглавные на случай Caps Lock), `q` — выход.

### Где ломается защита от разворота

Вот здесь два куска кода и подставляют друг друга. Цикл выгребает за
кадр **все** нажатия подряд, а `set_dir` сравнивает новое направление
с `dir_x/dir_y` — то есть с результатом предыдущего нажатия, а не с
тем, куда змейка реально ползёт.

Змейка едет вправо, `dir = (1, 0)`. Ты нервно тыкаешь W, а следом A
(обе клавиши успевают попасть в один кадр):

1. `set_dir(0, -1)` — вверх. Проверка: `(0,-1)` против `-(1,0) =
   (-1,0)`. Не совпало, разрешено. Теперь `dir = (0, -1)`.
2. `set_dir(-1, 0)` — влево. Проверка: `(-1,0)` против `-(0,-1) =
   (0,1)`. Не совпало — тоже разрешено! `dir = (-1, 0)`.

Итог: за один кадр направление перевернулось с «вправо» на «влево»
через промежуточное «вверх», и следующий шаг поведёт голову ровно в
тот сегмент, который идёт сразу за ней. Мгновенный проигрыш, причём
из-за нажатия, которое игрок считает законным.

Проверить это можно, не играя. Я взял функции из итоговой программы
(её полный текст — в конце главы; `update` там уже умеет замечать
столкновения, мы разберём это в шаге 5), выбросил терминал и написал
вместо игрового цикла такой `main`:

```c
int main(void)
{
    snake_len = 3;               /* голова в (10,5), тело левее */
    snake_x[0] = 10; snake_y[0] = 5;
    snake_x[1] = 9;  snake_y[1] = 5;
    snake_x[2] = 8;  snake_y[2] = 5;
    dir_x = 1;                   /* ползём вправо */
    dir_y = 0;
    moved_x = dir_x;
    moved_y = dir_y;
    food_x = 0;                  /* еда подальше, в углу */
    food_y = 0;

    /* два нажатия за один кадр: W, потом A */
    set_dir(0, -1);
    set_dir(-1, 0);
    printf("направление после двух нажатий: (%d,%d)\n", dir_x, dir_y);
    update();
    printf("после кадра: голова (%d,%d), game_over=%d\n",
           snake_x[0], snake_y[0], game_over);
    return 0;
}
```

Запуск со старым `set_dir` (тем, что сравнивает с `dir_x/dir_y`):

```text
направление после двух нажатий: (-1,0)
после кадра: голова (10,5), game_over=1
```

Направление стало «влево», следующая клетка головы — `(9,5)`, а там
лежит первый сегмент тела. `update` увидел столкновение и закончил
игру, не сдвинув голову с `(10,5)`.

Чинится это одной идеей: сравнивать надо не с «накопленным»
направлением, а с тем, **куда змейка реально поехала в прошлом
кадре**. Заводим для этого вторую пару переменных:

```c
static int dir_x, dir_y;       /* куда голова поедет в следующем кадре */
static int moved_x, moved_y;   /* куда она реально поехала в прошлом */

static void set_dir(int nx, int ny)
{
    if (nx == -moved_x && ny == -moved_y) {
        return;   /* противоположное реальному движению — игнорируем */
    }
    dir_x = nx;
    dir_y = ny;
}
```

А `update` в самом начале запоминает, с каким направлением работает
этот кадр:

```c
static void update(void)
{
    moved_x = dir_x;
    moved_y = dir_y;
    /* ... дальше сдвиг тела и шаг головы, как было ... */
}
```

Теперь второе нажатие в том же кадре меряется от `moved = (1,0)`, и
`A` отсекается. Тот же `main` после правки:

```text
направление после двух нажатий: (0,-1)
после кадра: голова (10,4), game_over=0
```

Змейка ушла вверх — ровно то, чего игрок и хотел. Не забудь в `main`
задать `moved_x = dir_x; moved_y = dir_y;` вместе с начальным
направлением, иначе первый же `set_dir` сравнится с парой нулей и
пропустит что угодно.

Теперь змейкой можно рулить. Осталась еда, рост и проигрыш.

## Шаг 4. Еда, рост и счёт

Еда `*` лежит в случайной клетке. Съел — змейка прибавляет сегмент, а
счёт растёт. Заводим переменные `food_x, food_y, score`.

Случайные числа — `rand` из `<stdlib.h>` (глава 12). Кладём еду в
свободную клетку:

```c
static void place_food(void)
{
    int ok = 0;
    while (!ok) {
        food_x = rand() % WIDTH;
        food_y = rand() % HEIGHT;
        ok = 1;
        for (int i = 0; i < snake_len; i++) {
            if (snake_x[i] == food_x && snake_y[i] == food_y) {
                ok = 0;   /* попали в тело — выбираем заново */
                break;
            }
        }
    }
}
```

- `rand() % WIDTH` — остаток от деления случайного числа на ширину
  даёт число в диапазоне 0..WIDTH−1, то есть допустимый столбец.
  Аналогично для строки.
- Цикл `while (!ok)` повторяет выбор, пока еда не окажется в пустой
  клетке: если случайно попали в тело змейки, ставим `ok = 0` и
  бросаем кубик заново.

Здесь спрятана мина замедленного действия, и её стоит увидеть заранее.
Цикл `while (!ok)` бросает кубик, пока не найдёт свободную клетку. А
что, если свободных клеток **не осталось** — змейка выросла и заняла
всё поле до последней клетки? Тогда `ok` никогда не станет единицей, и
программа зависнет навсегда: экран замрёт, а процессор будет крутить
пустой цикл на все сто процентов.

Случай редкий: чтобы до него дожить, надо съесть 197 порций еды подряд,
ни разу не врезавшись. Но «редкий» и «невозможный» — разные вещи, а
зависшая программа — худший из возможных исходов. Проверить нехватку
места нетрудно: если сегментов уже столько же, сколько клеток на поле,
класть еду некуда.

```c
static int place_food(void)
{
    if (snake_len >= WIDTH * HEIGHT) {
        food_x = -1;              /* свободных клеток нет: убираем еду */
        food_y = -1;              /* с поля, чтобы не закрыла голову */
        return 0;
    }
    int ok = 0;
    while (!ok) {
        food_x = rand() % WIDTH;
        food_y = rand() % HEIGHT;
        ok = 1;
        for (int i = 0; i < snake_len; i++) {
            if (snake_x[i] == food_x && snake_y[i] == food_y) {
                ok = 0;   /* попали в тело — выбираем заново */
                break;
            }
        }
    }
    return 1;
}
```

Функция стала возвращать `int`: `1` — еду положили, `0` — класть
некуда. Тот, кто её зовёт, теперь может отличить одно от другого — и
превратить безвыходную ситуацию в победу, а не в зависание. Ниже, в
разборе `update`, мы так и сделаем.

Строчки `food_x = -1; food_y = -1;` убирают еду с поля: клеток с
координатой −1 нет, и `draw` её нигде не нарисует. Без них на
последнем, победном кадре еда осталась бы там, где её только что
съели, — то есть под головой. А `draw` проверяет еду раньше змейки и
нарисовал бы вместо головы `*`. Эту мелочь я поймал, когда прогнал
логику змейки до полной победы на маленьком поле 6×4: без этих строк
голова и еда на последнем кадре совпадали.

И ещё о честности жребия. Пока свободных клеток много, цикл почти
всегда попадает с первого броска. Каждый бросок выбирает любую из
`WIDTH * HEIGHT` = 200 клеток с равным шансом, а неудачные броски
просто выбрасываются. Поэтому все свободные клетки получают еду с
одинаковой вероятностью — тот же довод, что с минами в сапёре (глава
16). Цена растёт к концу игры: если свободно `k` клеток из 200, в
среднем понадобится 200 / `k` бросков. При одной свободной клетке —
около 200 бросков, и в каждом до 199 сравнений с телом: порядка
40 000 простых операций на кадр, для компьютера это мгновение.

Теперь рост. Хитрость в том, что при сдвиге тела последний сегмент
(хвост) «теряется» — его координаты затираются. Если змейка съела
еду, мы вернём этот хвост обратно, и она станет на сегмент длиннее.
Поэтому **перед** сдвигом запоминаем хвост:

```c
int tail_x = snake_x[snake_len - 1];
int tail_y = snake_y[snake_len - 1];

/* ...сдвиг тела и шаг головы как раньше... */

if (snake_x[0] == food_x && snake_y[0] == food_y) {
    if (snake_len < MAX_LEN) {
        snake_x[snake_len] = tail_x;   /* отрастили хвост обратно */
        snake_y[snake_len] = tail_y;
        snake_len++;
    }
    score += 10;
    if (!place_food()) {
        game_won = 1;                  /* поле заполнено целиком */
        game_over = 1;
    }
}
```

- `snake_len - 1` — индекс последнего сегмента (помни: нумерация с 0,
  поэтому последний — не `snake_len`, а на единицу меньше).
- Если голова попала на еду, добавляем новый сегмент в позицию
  бывшего хвоста: `snake_x[snake_len] = tail_x`, и увеличиваем длину.
- `if (snake_len < MAX_LEN)` — защита от выхода за границы массива:
  не даём длине превысить размер. `MAX_LEN` — максимум сегментов
  (все клетки поля).
- `score += 10` — за каждую еду 10 очков.
- `if (!place_food())` — а вот и обещанная развязка. Если положить еду
  некуда, значит, змейка заняла всё поле. Это не ошибка и не зависание,
  а самый настоящий выигрыш: поднимаем флаг `game_won` и заканчиваем
  партию. В конце `main` он превратится в отдельную поздравительную
  строчку.

Порядок здесь важен: сначала растим змейку, и только потом зовём
`place_food`. Тогда новая еда точно не окажется под свежим сегментом —
функция проверяет все `snake_len` клеток, включая только что добавленную.

В отрисовку добавляем еду перед проверкой змейки:

```c
if (x == food_x && y == food_y) {
    ch = '*';
} else {
    /* ...поиск сегмента змейки, как раньше... */
}
```

## Шаг 5. Столкновения и конец игры

Последний штрих — проигрыш. Игра кончается, если голова вышла за
стену или наехала на собственное тело. Напрашивается: сделать шаг, а
потом посмотреть, куда попали.

```c
/* сначала шагнули... */
snake_x[0] += dir_x;
snake_y[0] += dir_y;

/* ...потом проверяем стену */
if (snake_x[0] < 0 || snake_x[0] >= WIDTH ||
    snake_y[0] < 0 || snake_y[0] >= HEIGHT) {
    game_over = 1;
    return;
}
```

Логика верная, игра действительно заканчивается. Но запусти, не трогай
клавиши и дай змейке доехать до правой стены — вот последний кадр,
который останется на экране:

```text
######################
#                    #
#                    #
#              *     #
#                    #
#                    #
#                  oo#
#                    #
#                    #
#                    #
#                    #
######################
Счёт: 0   (WASD — движение, q — выход)

Игра окончена! Итоговый счёт: 0
```

Тело на месте, а головы нет. И понятно почему: `update` уже сдвинул
голову в клетку `x = 20`, которой на поле не существует, а `draw`
рисует только клетки `0..19` — голову просто некуда поставить. Игрок
видит обезглавленную змейку и недоумевает, обо что он вообще ударился.
Порчи памяти тут нет (в массив мы записали своё же поле `snake_x[0]`),
но картинка врёт.

Чинится сменой порядка: сначала посчитаем, **куда голова собирается**,
проверим это место — и только если оно хорошее, сделаем шаг.

```c
/* куда голова СОБИРАЕТСЯ шагнуть */
int nx = snake_x[0] + dir_x;
int ny = snake_y[0] + dir_y;

/* столкновение со стеной — проверяем ДО шага */
if (nx < 0 || nx >= WIDTH || ny < 0 || ny >= HEIGHT) {
    game_over = 1;
    return;
}

/* столкновение с собственным телом */
for (int i = 1; i < snake_len - 1; i++) {
    if (snake_x[i] == nx && snake_y[i] == ny) {
        game_over = 1;
        return;
    }
}
```

- `nx`, `ny` — «новая x», «новая y». Обычные локальные переменные:
  посчитали будущую клетку, но в змейку её пока не записали.
- Первое условие: будущая клетка левее 0, правее поля, выше 0 или ниже
  поля — это удар о стену. Раз шага не было, змейка осталась на поле
  целиком, и тот же прогон выглядит уже понятно — голова уткнулась в
  стенку:

```text
######################
#                    #
# *                  #
#                    #
#                    #
#                    #
#                 ooO#
#                    #
#                    #
#                    #
#                    #
######################
Счёт: 0   (WASD — движение, q — выход)

Игра окончена! Итоговый счёт: 0
```

(Еда лежит в разных местах просто потому, что это два разных запуска —
`srand` каждый раз даёт новое поле.)

- Цикл по телу начинается с `i = 1`: нулевой сегмент — сама голова,
  сравнивать её будущую клетку с её же текущей бессмысленно.
- А вот верхняя граница `i < snake_len - 1` — тонкость, которую легко
  проглядеть. Последний сегмент — хвост, и в этом же кадре он **уползёт**
  со своей клетки: тело вот-вот сдвинется по цепочке. Значит, наехать
  на него нельзя — к моменту, когда голова там окажется, клетка уже
  освободится. Если хвост учитывать, змейка будет ни за что проигрывать
  в тесных поворотах.
- `game_over = 1` поднимает флаг, `return` обрывает шаг: дальше ни тело
  двигать, ни еду проверять незачем.

После проверок идёт то, что мы уже разобрали: запомнили хвост, сдвинули
тело, поставили голову в `(nx, ny)`, посмотрели на еду.

Главный цикл крутится, пока `!game_over`. Как только флаг поднят (или
нажали `q`), выходим, **возвращаем терминал** и печатаем счёт. Собираем
всё вместе.

## Полная программа

Сохрани это как `code/17-snake.c`.

```c
/* Глава 17. Игра «Змейка» в терминале.
 *
 * Управление: W A S D — вверх/влево/вниз/вправо, q — выход.
 * Компиляция (macOS/Linux):
 *   cc -std=c11 -Wall -Wextra -O2 17-snake.c -o snake
 *
 * Программа интерактивная: запускать в обычном терминале, не в пайпе.
 */

/* На Linux (glibc) со строгим -std=c11 объявление usleep спрятано за
   этим макросом. На macOS он ничего не меняет — но пусть стоит, чтобы
   файл собирался одинаково на обеих системах. Ставить ДО #include. */
#define _DEFAULT_SOURCE

#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <time.h>
#include <termios.h>
#include <unistd.h>

/* ---- Размеры игрового поля (без учёта рамки) ---- */
#define WIDTH   20
#define HEIGHT  10
#define MAX_LEN (WIDTH * HEIGHT)   /* змейка не длиннее всех клеток поля */

/* ---- Состояние игры ---- */
static int snake_x[MAX_LEN];   /* координаты сегментов: [0] — голова */
static int snake_y[MAX_LEN];
static int snake_len;          /* сколько сегментов сейчас */
static int dir_x, dir_y;       /* куда голова поедет в следующем кадре */
static int moved_x, moved_y;   /* куда она реально поехала в прошлом кадре */
static int food_x, food_y;     /* где лежит еда */
static int score;              /* счёт */
static int game_over;          /* 0 — играем, 1 — конец */
static int game_won;           /* 1 — змейка заняла всё поле */

/* ---- Сырой режим терминала ---- */
static struct termios orig_termios;   /* сюда сохраним исходные настройки */
static int raw_saved;                 /* 1 — orig_termios заполнен */

/* Вернуть терминал в нормальный режим. */
static void disable_raw_mode(void)
{
    if (raw_saved) {
        tcsetattr(STDIN_FILENO, TCSANOW, &orig_termios);
    }
}

/* Применить игровой режим поверх сохранённых настроек. */
static void apply_raw_mode(void)
{
    struct termios raw = orig_termios;         /* копия для правки */

    raw.c_lflag &= ~(ICANON | ECHO);           /* снять канонику и эхо */
    raw.c_cc[VMIN]  = 0;                       /* read не ждёт символов */
    raw.c_cc[VTIME] = 0;                       /* и не ждёт по таймеру */

    tcsetattr(STDIN_FILENO, TCSANOW, &raw);    /* применить сейчас же */
}

/* Смертельный сигнал (Ctrl+C, kill, закрытие окна): чиним терминал и
   только потом умираем. Сигнал убивает процесс мимо atexit — поэтому
   и перехватываем. */
static void on_fatal_signal(int sig)
{
    disable_raw_mode();
    _exit(128 + sig);    /* 128 + номер сигнала — так принято в шеллах */
}

/* Ctrl+Z: отдать терминал шеллу в нормальном виде и честно уснуть. */
static void on_sigtstp(int sig)
{
    (void)sig;
    disable_raw_mode();
    signal(SIGTSTP, SIG_DFL);   /* вернуть штатное поведение... */
    raise(SIGTSTP);             /* ...и остановиться по-настоящему */
}

/* Нас разбудили командой fg — снова забираем терминал под игру. */
static void on_sigcont(int sig)
{
    (void)sig;
    signal(SIGTSTP, on_sigtstp);   /* заново повесить наш обработчик */
    apply_raw_mode();
}

/* Включить «сырой» неблокирующий ввод: без ожидания Enter и без эха.
   Возвращает 1 при успехе, 0 — если ввод не терминал (пайп, файл). */
static int enable_raw_mode(void)
{
    if (tcgetattr(STDIN_FILENO, &orig_termios) == -1) {
        return 0;                              /* это не терминал */
    }
    raw_saved = 1;                             /* запомнили как было */
    apply_raw_mode();
    return 1;
}

/* Прочитать одну клавишу. Если её нет — вернуть -1 (не ждём ввода). */
static int read_key(void)
{
    char c;
    ssize_t n = read(STDIN_FILENO, &c, 1);
    if (n == 1) {
        return (unsigned char)c;
    }
    return -1;
}

/* Положить еду в случайную свободную клетку.
   Возвращает 0, если свободных клеток не осталось: змейка заняла всё
   поле. Без этой проверки цикл ниже крутился бы вечно. */
static int place_food(void)
{
    if (snake_len >= WIDTH * HEIGHT) {
        food_x = -1;              /* свободных клеток нет: убираем еду */
        food_y = -1;              /* с поля, чтобы не закрыла голову */
        return 0;
    }
    int ok = 0;
    while (!ok) {
        food_x = rand() % WIDTH;
        food_y = rand() % HEIGHT;
        ok = 1;
        for (int i = 0; i < snake_len; i++) {
            if (snake_x[i] == food_x && snake_y[i] == food_y) {
                ok = 0;   /* попали в тело — выбираем заново */
                break;
            }
        }
    }
    return 1;
}

/* Нарисовать поле, змейку, еду и счёт. */
static void draw(void)
{
    printf("\033[H\033[2J");   /* курсор в угол + очистка экрана */

    /* верхняя рамка */
    for (int x = 0; x < WIDTH + 2; x++) {
        putchar('#');
    }
    putchar('\n');

    for (int y = 0; y < HEIGHT; y++) {
        putchar('#');                       /* левая стенка */
        for (int x = 0; x < WIDTH; x++) {
            char ch = ' ';
            if (x == food_x && y == food_y) {
                ch = '*';                   /* еда */
            } else {
                for (int i = 0; i < snake_len; i++) {
                    if (snake_x[i] == x && snake_y[i] == y) {
                        ch = (i == 0) ? 'O' : 'o';   /* голова / тело */
                        break;
                    }
                }
            }
            putchar(ch);
        }
        putchar('#');                       /* правая стенка */
        putchar('\n');
    }

    /* нижняя рамка */
    for (int x = 0; x < WIDTH + 2; x++) {
        putchar('#');
    }
    putchar('\n');

    printf("Счёт: %d   (WASD — движение, q — выход)\n", score);
}

/* Сменить направление, не разрешая разворот на 180 градусов.
   Сравниваем с тем, куда змейка ПОЕХАЛА в прошлом кадре (moved_x/moved_y),
   а не с уже накопленным dir_x/dir_y: иначе два нажатия за один кадр
   (вверх, потом влево, пока ползём вправо) сложились бы в разворот. */
static void set_dir(int nx, int ny)
{
    if (nx == -moved_x && ny == -moved_y) {
        return;   /* противоположное реальному движению — игнорируем */
    }
    dir_x = nx;
    dir_y = ny;
}

/* Один шаг змейки: сдвиг тела, новая голова, столкновения, еда. */
static void update(void)
{
    /* фиксируем направление этого кадра — на него будет смотреть set_dir */
    moved_x = dir_x;
    moved_y = dir_y;

    /* куда голова СОБИРАЕТСЯ шагнуть */
    int nx = snake_x[0] + dir_x;
    int ny = snake_y[0] + dir_y;

    /* столкновение со стеной — проверяем ДО шага, чтобы на последнем
       кадре змейка осталась нарисованной целиком, а не без головы */
    if (nx < 0 || nx >= WIDTH || ny < 0 || ny >= HEIGHT) {
        game_over = 1;
        return;
    }

    /* столкновение с собственным телом. Хвост (последний сегмент) в этом
       кадре уползёт, поэтому его не считаем — вот почему i < snake_len-1. */
    for (int i = 1; i < snake_len - 1; i++) {
        if (snake_x[i] == nx && snake_y[i] == ny) {
            game_over = 1;
            return;
        }
    }

    /* запомним хвост — он пригодится, если змейка вырастет */
    int tail_x = snake_x[snake_len - 1];
    int tail_y = snake_y[snake_len - 1];

    /* сдвигаем тело: каждый сегмент встаёт на место предыдущего */
    for (int i = snake_len - 1; i > 0; i--) {
        snake_x[i] = snake_x[i - 1];
        snake_y[i] = snake_y[i - 1];
    }

    /* голова делает шаг в текущем направлении */
    snake_x[0] = nx;
    snake_y[0] = ny;

    /* съели еду? */
    if (nx == food_x && ny == food_y) {
        if (snake_len < MAX_LEN) {
            snake_x[snake_len] = tail_x;   /* отрастили хвост обратно */
            snake_y[snake_len] = tail_y;
            snake_len++;
        }
        score += 10;
        if (!place_food()) {
            game_won = 1;                  /* поле заполнено целиком */
            game_over = 1;
        }
    }
}

int main(void)
{
    srand((unsigned)time(NULL));   /* разный «случай» при каждом запуске */

    if (!enable_raw_mode()) {      /* переключаем терминал в игровой режим */
        fprintf(stderr, "Змейке нужен настоящий терминал: "
                        "запусти ./snake без пайпа и без < файла.\n");
        return 1;
    }
    atexit(disable_raw_mode);      /* вернуть режим при обычном выходе */
    signal(SIGINT,  on_fatal_signal);   /* Ctrl+C   */
    signal(SIGTERM, on_fatal_signal);   /* kill     */
    signal(SIGQUIT, on_fatal_signal);   /* Ctrl+\   */
    signal(SIGHUP,  on_fatal_signal);   /* окно закрыли */
    signal(SIGTSTP, on_sigtstp);        /* Ctrl+Z   */
    signal(SIGCONT, on_sigcont);        /* fg       */

    /* начальная змейка из 3 сегментов в центре, ползёт вправо */
    snake_len = 3;
    int cx = WIDTH / 2;
    int cy = HEIGHT / 2;
    snake_x[0] = cx;     snake_y[0] = cy;
    snake_x[1] = cx - 1; snake_y[1] = cy;
    snake_x[2] = cx - 2; snake_y[2] = cy;
    dir_x = 1;
    dir_y = 0;
    moved_x = dir_x;
    moved_y = dir_y;
    score = 0;
    game_over = 0;
    game_won = 0;

    place_food();
    draw();                        /* показываем стартовое поле сразу */

    while (!game_over) {
        /* считываем все накопившиеся нажатия */
        int key;
        while ((key = read_key()) != -1) {
            if (key == 'w' || key == 'W') set_dir(0, -1);
            else if (key == 's' || key == 'S') set_dir(0, 1);
            else if (key == 'a' || key == 'A') set_dir(-1, 0);
            else if (key == 'd' || key == 'D') set_dir(1, 0);
            else if (key == 'q' || key == 'Q') game_over = 1;
        }

        if (game_over) {
            break;             /* нажали q */
        }

        update();
        draw();

        usleep(150000);        /* пауза 0,15 с между кадрами */
    }

    disable_raw_mode();        /* ОБЯЗАТЕЛЬНО вернуть терминал как было */

    if (game_won) {
        printf("\nПоле заполнено целиком — ты прошёл игру!\n");
    }
    printf("\nИгра окончена! Итоговый счёт: %d\n", score);
    return 0;
}
```

## Как это работает

Проследим один оборот игрового цикла, пока `game_over` равен 0:

1. **Ввод.** Внутренний `while` вытягивает из буфера все нажатые
   клавиши. WASD меняют `dir_x/dir_y` через `set_dir` (он сверяется с
   `moved_x/moved_y` — направлением прошлого кадра — и не пускает
   разворот), `q` поднимает `game_over`. Нет нажатий — `read_key`
   сразу отдаёт `-1`, и мы не зависаем.
2. **Шаг.** `update` фиксирует `moved_x/moved_y`, считает будущую
   клетку головы `(nx, ny)` и проверяет её на стену и на тело — при
   ударе ставит `game_over` и выходит, ничего не сдвинув. Если клетка
   хорошая, запоминает хвост, сдвигает тело по цепочке и переносит
   голову в `(nx, ny)`. Если там лежала еда — отращивает хвост обратно,
   плюсует счёт и кладёт новую еду.
3. **Отрисовка.** `draw` чистит экран `\033[H\033[2J` и заново рисует
   рамку, еду `*`, голову `O`, тело `o` и строку счёта.
4. **Пауза.** `usleep(150000)` ждёт 0,15 секунды — иначе кадры
   мелькали бы слишком быстро, чтобы что-то разглядеть.

Цикл повторяется, и из быстрой смены кадров рождается плавное
движение. Как закончили — `disable_raw_mode` возвращает терминал в
нормальный вид, и печатается итоговый счёт.

Глобальные переменные (`snake_x`, `dir_x` и прочие) вынесены наружу,
чтобы все функции (`update`, `draw`, `place_food`) работали с одним и
тем же состоянием, не передавая кучу аргументов. Для маленькой игры в
один файл это нормально.

## Проверяем

Скомпилируй и запусти:

```text
cc -std=c11 -Wall -Wextra -O2 17-snake.c -o snake
./snake
```

Команда `-std=c11` задаёт стандарт языка, `-Wall -Wextra` включают все
предупреждения (их быть не должно), `-O2` — оптимизацию. Благодаря
`#define _DEFAULT_SOURCE` в начале файла никакие лишние флаги для POSIX
не нужны — собирается чисто, без предупреждений.

Запусти `./snake` **в обычном окне терминала**. Через пайп змейка
играться не будет и честно об этом скажет — мы это специально
предусмотрели. Увидишь поле, змейку в центре и еду. Управляй клавишами
W, A, S, D — Enter нажимать **не надо**, змейка поворачивает сразу.
Наводи голову на `*`: змейка растёт, счёт растёт на 10. Врежешься в
стену или в себя — игра закончится и покажет счёт. Выйти в любой момент
— клавиша `q`.

Вот настоящий кадр из партии: одна еда уже съедена, змейка ползёт
влево (голова `O` слева), следующая порция лежит в правом верхнем углу.

```text
######################
#                   *#
#          Oooo      #
#                    #
#                    #
#                    #
#                    #
#                    #
#                    #
#                    #
#                    #
######################
Счёт: 10   (WASD — движение, q — выход)
```

Кстати, полезная проверка на внимательность: по картинке всегда можно
пересчитать счёт. Стартовая змейка — 3 сегмента, каждая еда даёт `+1`
сегмент и `+10` очков. Здесь сегментов четыре (`Oooo`), значит, съедена
ровно одна порция, значит, счёт — 10. Если у тебя в игре числа
разошлись, ищи ошибку в `update`: скорее всего, счёт растёт не там, где
растёт длина.

### Проверяем, что терминал возвращается

Самое неприятное в этой главе — испорченный терминал, поэтому проверь
все выходы явно, один за другим. После каждого пункта просто набери в
терминале любую команду: если буквы видно и Enter работает — всё
хорошо.

1. Обычный конец: врежься в стену. Или нажми `q`.
2. Ctrl+C прямо во время игры.
3. Ctrl+Z во время игры — игра замрёт и вернёт тебя в командную
   строку в нормальном режиме. Набери `fg` — игра проснётся и
   продолжится ровно с того места, снова забрав терминал под себя.
4. Из **другого** окна терминала: `kill НОМЕР` (номер процесса покажет
   `ps` или `pgrep snake`). Игра умрёт, терминал останется рабочим.

Единственный случай, который не чинится, — `kill -9`: этот сигнал
перехватить нельзя. Если так вышло, набери вслепую `reset` и нажми
Enter.

## Частые ошибки

**Забыл вернуть режим терминала.** Если программа завершится (или
упадёт) до `disable_raw_mode`, терминал останется в сыром режиме: ты
печатаешь, а букв не видно, Enter не срабатывает как обычно. Это не
поломка навсегда — набери вслепую команду `reset` и нажми Enter,
терминал починится. Чтобы такого не было, зови `disable_raw_mode`
перед выходом и подстрахуйся `atexit` плюс обработчиками сигналов:
одного явного вызова в конце `main` мало, потому что до конца `main`
можно и не добраться.

**Подстраховались только от Ctrl+C.** Самая частая половинчатая
починка: повесили обработчик на `SIGINT` и успокоились. А программу
гасят не только с клавиатуры. Проверь сам — запусти игру, найди её
номер (`pgrep snake`) и из другого окна сделай `kill НОМЕР`: если
`SIGTERM` не перехвачен, терминал останется сырым. То же самое с
Ctrl+Z: игра уснёт, а настройки терминала останутся игровыми, и
командная строка будет вести себя как сломанная. Закрывай все выходы
сразу: `SIGINT`, `SIGTERM`, `SIGQUIT`, `SIGHUP` — на общий обработчик,
`SIGTSTP`/`SIGCONT` — на пару «отдал терминал / забрал обратно».

**Не проверил, что ввод вообще терминал.** `tcgetattr` на пайпе или
файле возвращает `-1`, и в структуре не оказывается ничего полезного.
Если результат не проверить, игра запустится с вводом, которым нельзя
управлять: всё, что пришло по пайпу, прочитается в первом кадре, и
змейка уедет в стену сама. Проверяй возвращаемое значение и выходи с
понятным сообщением.

**Змейка на последнем кадре осталась без головы.** Значит, проверка
стены стоит **после** шага головы: голова уже уехала за поле, а `draw`
рисует только клетки внутри рамки. Считай будущую клетку в отдельные
`nx`, `ny`, проверяй их — и шагай только если проверка прошла.

**Картинка мерцает или «лесенкой» уезжает вниз.** Значит, ты не
очищаешь экран перед отрисовкой. Каждый кадр должен начинаться с
`printf("\033[H\033[2J")`. Если мерцание сильное, проверь, что не
печатаешь лишних пустых строк между кадрами.

**Выход за границу массива сегментов.** Если растить змейку без
проверки `if (snake_len < MAX_LEN)`, при заполнении всего поля длина
вылезет за размер массивов `snake_x/snake_y` — порча памяти. Граница
обязательна.

**Поиск свободной клетки крутится вечно.** `place_food` бросает кубик,
пока не попадёт в пустую клетку. Когда пустых клеток не осталось, этот
цикл уже не закончится никогда: программа замирает, а процессор уходит
в потолок. Любой цикл «бросай кубик, пока не повезёт» надо
сопровождать вопросом: «а бывает ли, что не повезёт никогда?» Если
бывает — проверь это условие до цикла и верни отдельный ответ.

**Змейка проигрывает в тесном повороте.** Если в проверке на укус
самой себя дойти циклом до последнего сегмента (`i < snake_len`, а не
`i < snake_len - 1`), змейка будет «врезаться» в собственный хвост,
который в этом же кадре и так уползёт. Хвост — единственный сегмент,
на место которого шагнуть можно.

**Змейка мгновенно проигрывает при развороте.** Без защиты в
`set_dir` нажатие в обратную сторону вгоняет голову в свой второй
сегмент — и сразу «конец игры». Поэтому развороты на 180° запрещены.
И сверяться при этом надо с `moved_x/moved_y` — направлением, в
котором змейка реально сделала прошлый шаг. Если сравнивать с
`dir_x/dir_y`, два быстрых нажатия за один кадр (W, потом A на
движении вправо) проскочат проверку по очереди и всё равно сложатся
в разворот.

**Цикл сдвига тела «съедает» змейку.** Если сдвигать сегменты от
головы к хвосту (а не от хвоста к голове), координаты затрутся раньше
времени, и тело схлопнется. Иди в цикле от `snake_len - 1` к `1`.

**`implicit declaration of function 'usleep'` при `-std=c11`.** Это
сообщение ты увидишь на Linux с glibc: там объявление `usleep` спрятано
за макросом. Добавь `#define _DEFAULT_SOURCE` в самом начале файла (до
всех `#include`) или собирай с флагом `-D_DEFAULT_SOURCE`. На macOS
такого предупреждения не будет — там `usleep` объявлен без условий, и
файл соберётся даже без макроса. Не удивляйся, если у тебя и товарища
на разных системах поведение разное: это не магия, а разные заголовки.

## Упражнения

1. **Ускорение.** Сделай так, чтобы с каждой съеденной едой игра шла
   быстрее: заведи переменную задержки (например, начать с `150000`) и
   уменьшай её на немного при росте, но не ниже какого-то минимума,
   чтобы змейка не стала неуправляемой. Передавай это значение в
   `usleep`.
   *Что должно получиться:* если начать со `150000` и отнимать `5000`
   за каждую еду до минимума `60000`, то после 18-й порции
   ((150 000 − 60 000) / 5000 = 18) скорость перестанет расти: кадр
   будет идти 0,06 секунды вместо 0,15, то есть в 2,5 раза быстрее.

2. **Пауза.** Добавь клавишу `p` — пауза. По нажатию игра замирает
   (цикл крутится, но `update` не вызывается и рисуется надпись
   «ПАУЗА»), повторное нажатие `p` продолжает.
   *Что должно получиться:* пока пауза, змейка стоит, счёт не
   меняется, клавиши WASD не должны менять направление (иначе на
   паузе можно «накопить» разворот). После второго `p` змейка
   продолжает с той же клетки в прежнюю сторону. Флажок паузы удобно
   переключать так: `paused = !paused;`.

3. **Стены-телепорты.** Сделай режим, где змейка не разбивается о
   стену, а появляется с противоположной стороны. Подсказка: вместо
   проверки на проигрыш заверни будущие координаты по модулю —
   `nx = (nx + WIDTH) % WIDTH; ny = (ny + HEIGHT) % HEIGHT;`. Прибавка
   `+ WIDTH` тут не для красоты: в Си остаток от отрицательного числа
   отрицателен (`-1 % 20` даёт `-1`, а не `19`), и без неё змейка
   уедет в индекс `-1`. Проверь на всех четырёх стенах.
   *Что должно получиться:* решение ниже.

4. **Рекорд.** Запоминай лучший счёт за сессию и показывай его рядом с
   текущим. Усложнение: сохраняй рекорд в файл (`fopen`, `fprintf`,
   `fscanf`) и читай при старте, чтобы он жил между запусками.
   *Что должно получиться:* сыграй на 30 очков и выйди — в файле
   (например, `snake-record.txt`) лежит `30`. Следующий запуск
   показывает «Рекорд: 30», партия на 20 очков его не трогает, на 40 —
   переписывает. Если файла ещё нет, `fopen(..., "r")` вернёт `NULL` —
   это не ошибка, рекорд просто равен нулю.

5. **Две еды.** Добавь второй вид еды, которая даёт больше очков, но
   живёт на поле ограниченное число кадров и потом исчезает.
   *Что должно получиться:* например, `$` на 30 очков, живёт 40 кадров
   (40 · 0,15 = 6 секунд). Она не должна появляться ни на теле змейки,
   ни на обычной еде, а съеденная `$` тоже удлиняет змейку. Проверка
   на победу при этом не меняется: сегментов всё так же не больше
   `WIDTH * HEIGHT`.

6. **Размер поля.** Вынеси `WIDTH` и `HEIGHT` в аргументы командной
   строки (`int main(int argc, char *argv[])`), чтобы запускать
   `./snake 30 15`. Подумай, как тогда задать размеры массивов
   (подсказка: `malloc`).
   *Что должно получиться:* `./snake 30 15` рисует рамку шириной
   32 символа и высотой 17 строк (поле плюс по клетке рамки с каждой
   стороны), массивы сегментов — на 30 · 15 = 450 элементов.
   Слишком маленькое поле (скажем, `./snake 2 2`) программа должна
   отклонить: стартовая змейка из трёх клеток в ряд туда не влезет.
   Не забудь `free` перед выходом.

### Решение упражнения 3

В `update` вместо расчёта `nx`, `ny` и проверки стены пишем:

```c
/* стены-телепорты: вышли за край — появились с другой стороны */
int nx = (snake_x[0] + dir_x + WIDTH) % WIDTH;
int ny = (snake_y[0] + dir_y + HEIGHT) % HEIGHT;
```

Проверка на укус самой себя остаётся как была. Разберём числа.
Голова в `x = 19` (последний столбец) едет вправо:
`(19 + 1 + 20) % 20 = 40 % 20 = 0` — вынырнула в столбце 0. Голова в
`x = 0` едет влево: `(0 - 1 + 20) % 20 = 19 % 20 = 19` — последний
столбец. Без `+ 20` получилось бы `-1 % 20 = -1`: в Си знак остатка
совпадает со знаком делимого, и `%` здесь не математический остаток
от деления (тот всегда от 0 до 19), а просто то, что осталось после
деления с отбрасыванием дробной части.

Я проверил все четыре стены, подставив голову к краю и сделав один
шаг `update`:

```text
-1 % 20 = -1, (-1 + 20) % 20 = 19
(19,5) шаг (1,0) -> (0,5), game_over=0
(0,5) шаг (-1,0) -> (19,5), game_over=0
(10,0) шаг (0,-1) -> (10,9), game_over=0
(10,9) шаг (0,1) -> (10,0), game_over=0
```

## Что мы получили

Ты собрал полноценную аркадную игру: поле, самодвижущаяся змейка,
мгновенное управление без Enter, случайная еда, рост, счёт и честный
проигрыш. По дороге разобрал по-настоящему важную тему — **управление
терминалом**: сырой и неблокирующий ввод через `termios`, очистку
экрана управляющими последовательностями и игровой цикл с паузой
`usleep`.

И отдельно — о том, чему научила именно эта глава: **программа
отвечает за то, что она оставит после себя**. Змейка меняет настройки
чужого терминала — значит, обязана вернуть их назад, чем бы дело ни
кончилось: обычным выходом, Ctrl+C, `kill` или Ctrl+Z. Отсюда и
`atexit`, и обработчики сигналов, и проверка `tcgetattr`. Тот же
принцип действует всюду, где программа берёт что-то общее: открытый
файл, выделенную память, запись в базе.

Это тот самый набор, на котором держатся все текстовые
игры — от «Тетриса» до рогаликов.
