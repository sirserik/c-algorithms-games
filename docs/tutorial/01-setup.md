# Глава 1. Компилятор и первая программа

В этой главе мы поставим инструмент, который превращает наш текст в
работающую программу, напишем классическое «Привет, мир!» и разберём
в нём **каждый символ** — от первой решётки до последней точки с
запятой. К концу главы ты будешь уметь скомпилировать и запустить
программу на Си.

## Что такое компилятор

Компьютер не понимает Си напрямую. Процессор понимает только
**машинный код** — наборы чисел, команды вроде «сложи», «положи в
память», «прыгни сюда». Писать в таких числах человеку невозможно.

Поэтому мы пишем на Си — понятном человеку языке, — а специальная
программа переводит наш текст в машинный код. Эта программа-переводчик
называется **компилятор** (compiler, от англ. *compile* — собирать).

Схема такая:

```text
наш текст (file.c)  →  [компилятор]  →  исполняемый файл  →  запускаем
```

Файл с нашим кодом имеет расширение `.c`. Результат компиляции —
**исполняемый файл**, готовая программа, которую можно запустить.

## Ставим компилятор

Нам нужен компилятор `clang` или `gcc` — подойдёт любой, команды
одинаковые. Проверим, есть ли он уже.

### macOS

Открой терминал и набери:

```text
cc --version
```

`cc` — это «C Compiler», стандартное имя компилятора в системе. Если
увидишь что-то вроде `Apple clang version ...` — всё готово, переходи
дальше. Если система предложит установить «Command Line Tools» —
соглашайся, это и есть компилятор. Можно поставить и вручную:

```text
xcode-select --install
```

Откроется окно установки, жми «Установить» и жди.

### Linux

```text
cc --version
```

Если не установлен, на Ubuntu/Debian:

```text
sudo apt update
sudo apt install build-essential
```

`build-essential` — набор инструментов для сборки программ, включая
компилятор `gcc`.

### Windows

На Windows проще всего поставить **MSYS2** или **WSL** (подсистема
Linux внутри Windows) и работать как в Linux. Либо MinGW-w64, который
даёт `gcc`. Дальше в книге команды одинаковые, кроме главы про змейку —
там есть пометка про отличия Windows.

## Первая программа

Создай папку для книги, например `c-book`, зайди в неё и создай файл
`hello.c`. Содержимое:

```c
#include <stdio.h>

int main(void)
{
    printf("Привет, мир!\n");
    return 0;
}
```

Сохрани. Теперь разберём **каждую строчку**.

### `#include <stdio.h>`

Эта строка подключает к нашей программе чужой готовый код.

- `#include` — это **директива препроцессора**. Препроцессор —
  помощник компилятора, который срабатывает первым и подготавливает
  текст. Всё, что начинается с `#`, — команды для него. `include`
  по-английски «включить».
- `<stdio.h>` — имя файла, который мы включаем. Это **заголовочный
  файл** (header, расширение `.h`). `stdio` расшифровывается как
  *standard input/output* — стандартный ввод-вывод. В нём описана,
  среди прочего, функция `printf`, которой мы будем печатать на экран.
- Угловые скобки `<...>` означают «ищи этот файл среди системных», то
  есть среди тех, что идут вместе с компилятором.

Без этой строки компилятор не знал бы, что такое `printf`, и выдал бы
ошибку.

### Пустая строка

Просто для читаемости. Пустые строки Си игнорирует — они для людей,
не для машины.

### `int main(void)`

Это объявление **функции** по имени `main`. Функция — это кусок кода с
именем, который можно выполнить. `main` — особенная: с неё начинается
выполнение **любой** программы на Си. Когда ты запускаешь программу,
система ищет `main` и выполняет то, что внутри.

Разберём по частям:

- `int` — это **тип** значения, которое функция вернёт в конце.
  `int` (от *integer* — целое) означает целое число. То есть `main`
  пообещала вернуть целое число.
- `main` — имя функции. Менять его нельзя: система ищет именно `main`.
- `(void)` — в скобках перечисляют, что функция принимает на вход.
  `void` по-английски «пустота, ничто». Значит, `main` ничего на вход
  не принимает.

### `{` и `}`

Фигурные скобки обрамляют **тело** функции — всё, что она делает.
Открывающая `{` — «здесь начинается код функции», закрывающая `}` —
«здесь он заканчивается». Всё между ними выполняется по порядку,
сверху вниз.

### `printf("Привет, мир!\n");`

Это вызов функции `printf` — той самой, что описана в `stdio.h`.
`printf` (от *print formatted* — печать с форматированием) выводит
текст на экран.

- В круглых скобках — **аргумент**, то, что передаём функции. Здесь
  это текст `"Привет, мир!\n"`.
- Двойные кавычки `"..."` обрамляют **строку** — последовательность
  символов. Сам текст между кавычками появится на экране.
- `\n` — это **один** специальный символ, перевод строки (от *new
  line*). Обратный слеш `\` говорит: «следующий символ читай особым
  образом». `\n` означает «перейти на новую строку», как нажать
  Enter. Без него следующий вывод прилип бы к нашему тексту.
- `;` — **точка с запятой**. В Си ею заканчивается почти каждая
  команда (её называют *инструкция*, англ. *statement*). Это как
  точка в конце предложения. Забыть её — самая частая ошибка новичка,
  и компилятор сразу ругается.

### `return 0;`

- `return` (англ. «вернуть») завершает функцию и возвращает значение
  туда, откуда её вызвали. Помнишь, `main` обещала вернуть `int` —
  целое число? Вот мы и возвращаем целое `0`.
- `0` по соглашению означает «программа отработала успешно, без
  ошибок». Любое другое число — сигнал, что что-то пошло не так. Этим
  кодом пользуется система и другие программы.
- И снова `;` в конце.

## Компилируем и запускаем

В терминале, находясь в папке с `hello.c`:

```text
cc hello.c -o hello
```

Разберём команду:

- `cc` — вызываем компилятор.
- `hello.c` — наш исходный файл.
- `-o hello` — **флаг** `-o` (от *output* — вывод) задаёт имя
  результата. Получится исполняемый файл `hello`. Без `-o` компилятор
  назвал бы результат `a.out` (историческое имя по умолчанию).

Если ошибок нет, команда отработает молча — это хорошо. Теперь
запускаем:

```text
./hello
```

`./` означает «файл в текущей папке». Без него система искала бы
программу `hello` среди системных и не нашла. Результат:

```text
Привет, мир!
```

Поздравляю — первая программа работает.

## Включаем предупреждения (важная привычка)

Компилятор умеет предупреждать о подозрительных местах в коде, но по
умолчанию молчит о многом. Заведём привычку компилировать с флагами:

```text
cc -std=c11 -Wall -Wextra -O2 hello.c -o hello
```

- `-std=c11` — использовать стандарт языка **C11** (версия Си 2011
  года). Так все будут на одной волне.
- `-Wall` — *warnings all*, включить основные предупреждения.
- `-Wextra` — добавить ещё дополнительные.
- `-O2` — *optimize level 2*, попросить компилятор сделать программу
  быстрее. Для учёбы не обязательно, но пусть будет.

Предупреждение (*warning*) — это не ошибка: программа соберётся. Но
это компилятор говорит «тут что-то подозрительное, посмотри». **В этой
книге мы пишем код так, чтобы предупреждений не было.** Считай их
маленькими ошибками.

## Частые ошибки

**Забыл `;` в конце строки.** Компилятор покажет что-то вроде
`expected ';'`. Добавь точку с запятой.

**Забыл `#include <stdio.h>`.** Будет жалоба на `printf` —
`implicit declaration of function 'printf'`. Подключи заголовок.

**Перепутал кавычки.** Текст печатается в **двойных** кавычках `"..."`.
Одинарные `'...'` в Си — это один символ, а не строка. `'Привет'` —
ошибка.

**Запускаешь без `./`.** Наберёшь `hello` — система ответит
`command not found`. Нужно `./hello`.

**Файл не сохранён.** Изменил код, но забыл сохранить — компилируется
старая версия. Сохраняй перед каждой компиляцией.

## Упражнения

1. Сделай так, чтобы программа печатала две строки: «Привет, мир!» и
   на следующей строке «Я учу Си». (Подсказка: можно два `printf`, а
   можно один с двумя `\n`.)
2. Убери `\n` из `printf` и посмотри, как изменится вывод. Где теперь
   оказывается приглашение терминала?
3. Намеренно убери `;` и прочитай, что скажет компилятор. Запомни этот
   текст ошибки — увидишь его ещё не раз.
4. Скомпилируй с `-Wall -Wextra` и убедись, что предупреждений нет.
